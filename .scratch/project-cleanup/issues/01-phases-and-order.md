# 階段切法與順序

Type: grilling
Status: resolved

## Question

整理工作要切成哪幾個階段、什麼順序、每階段的驗收是什麼？
要決定的點：
- app 在階段之間要不要保持可跑（增量）還是允許一段時間跑不動（大改一次收）。
- 候選階段：A 新格式＋flowfile 重寫＋轉換工具；B profile 退場與打包版佈局；C UI 瘦身（主視窗、流程設定對話框、
  步驟編輯器、範本面板）；D 影片轉流程改規則＋agent 文件；E 基準集重製＋引擎刪 multi_capture；F 死碼清理與文件重寫；
  G 模型暖機。哪些可以併、哪些必須先後。
- 每個階段的驗收：例如 A＝四份流程轉完在新版 app 開得起來並實跑一份；C＝使用者看過版面；E＝基準集成績不低於現在。
- 每階段對應一次 `/to-spec`（一階段一份 spec）還是幾階段合一份。

產出：階段清單＋順序＋相依＋驗收，寫在本票的 Answer；地圖的 Decisions so far 放一行指回來。

## Answer

（2026-10-10 grilling）

通則：
- **每階段結束 app 可跑、可打包**（增量）。過渡期要寫的少量過渡碼接受。
- **一階段一份 spec**，輪到該階段才寫（`/to-spec` → `/to-tickets` → `/implement`）。
- **死碼與測試改寫誰的地盤誰做**，不另開清理階段；最後一階段只剩文件。
- 階段開工前，下表「等」欄的 wayfinder 票要先解完。

| 0 | ~~模型暖機~~（**取消**；改成背景預載併進格式階段，見 [03](03-diagnose-post-preload-wait.md)） | — | — | — |
| 1 | 格式階段 | flow.yaml＋flowfile 重寫＋一次性轉換工具＋profile 退場＋打包版佈局＋存檔語意（記憶體、按存檔才寫、關閉提示、templates/＝引用集合）＋背景預載（讀取流程即預載，規則見 03）。順手刪：沒資料可存的 UI 控制項（按鍵步驟、絕對座標、滑鼠鍵、連點、原點矩形、出現等候上限、補做／忙碌 spinbox、啟動延遲、避開游標、profile 下拉與建立鈕、開啟資料夾）、執行器對應路徑、舊格式讀寫、profile_store、工作區、步驟草稿、stage.py 舞台接縫。 | 02、09、11 | 轉換工具自對全過（步數、每步欄位、範本圖逐位元相同）；新打包版開得起四份；讀取後紀錄出現「範本就緒」再按執行，約 3.5 秒開始第一步；使用者早晚班四份各實跑一次全過。過關前舊打包版保留當備援。 |
| 2 | 影片轉流程規則＋agent 文件 | 影片轉流程直接產固定矩形與忙碌檢查、刪過期規則；flow.yaml 格式規範、手寫／修改流程 skill、影片 skill 瘦身。 | 04、10 | 重轉一支已轉過的示範影片（例：add5.mp4）：產出只含固定矩形與忙碌檢查、拾取檢查三項全過、使用者在遊戲實跑通過。 |
| 3 | UI 瘦身 | 主視窗重排、流程設定對話框、步驟編輯器依動作顯示欄位、範本面板。格式階段沒刪的 UI 控制項在這裡處理。 | 05、06 | 使用者在新打包版走一份情境清單（開流程、改一步、重截範本、改校準對、存檔、關閉提示、跑一整輪）沒意見；元件數對照原型。 |
| 4 | 基準集重製＋引擎刪 multi_capture | 根目錄 `benchmark/` 從四份流程範本＋影片影格重製；引擎刪多張圖路徑；bench loader 改讀新格式。不碰 app，可插隊。 | 07、08 | 新集重製、使用者審過答案；用尚未刪 multi_capture 的引擎量一次當底線；刪碼後逐案成績不變。新集失敗案例列清單但不擋關。 |
| 5 | 文件 | README＋app/CLAUDE.md 重寫。 | 前面全部 | 文件裡每個指令與路徑實際跑得通。 |

順序理由：先完成「對 agent 友善」這條線（流程多半由 agent 用影片轉出），再做使用者看得到的 UI；
引擎內部整理不影響使用者，放後面但可插隊。暖機最先做，因為小、且重新打包後日常版本馬上受惠。
