# 一份流程一個尺度,每次執行開頭自動校準(flow-scale)

Status: ready-for-agent

詞彙見 `app/CONTEXT.md` 的「尺度與畫面倍率」(流程尺度、校準對、基準距離、校準、畫面倍率)與根目錄 `CONTEXT.md` 的「預期尺度」;決策紀錄見 ADR 0009(取代 ADR 0005)。順序上排在 B1(候選合併去重,不寫規格)之後、effect-confirm 之前。

## Problem Statement

使用者有兩個明日方舟客戶端:簡中是 1696 寬的視窗,繁中是 1920 最大化。兩邊各用一份流程,但共用同一個 arknights profile,所以出了三個問題。

1. **換客戶端要先校準**。畫面倍率是 profile 共用的一個值(簡中約 0.81、繁中約 0.91,相對一個更大的舊視窗)。倍率只能對其中一邊正確,忘了按校準,點擊就整批點偏。
2. **找圖慢**。一個「找到→點→確認」步驟要 1.5～2 秒。引擎每次查詢都掃 0.6～1.5 倍、共 12 個尺度,因為它不知道範本在畫面上該多大。
3. **兩種尺度互相矛盾**。流程座標存的是舊基準尺度,範本圖卻是各客戶端的實際畫面尺寸。實跑時範本匹配尺度都在 1.00～1.06,倍率卻是 0.805。所以倍率不能拿來告訴引擎「範本大概多大」;硬拿去用,找圖會全部失敗。

## Solution

一份流程只有一個尺度:座標與範本圖都是建立這份流程時的畫面大小。流程存檔自帶校準對(例:遊戲視窗標題列的圖示與關閉鈕)與基準距離。

- **每次執行開頭自動校準**:在畫面上找到校準對兩張圖,由兩者距離得出這次的畫面倍率。任一張找不到就不執行,並說明原因。
- **一個倍率兩個用途**:座標乘上它換算落點;每次找圖把它交給引擎當預期尺度。引擎只掃以它為中心的 5 個尺度,查詢快約 1.8 倍。
- **編輯器**:倍率預設 1,使用者按「校準」才更新。拾取的座標與截下的範本圖都除以倍率,換回流程尺度再存。
- **退場**:profile 層級的校準資料、機器指紋、未校準狀態、存檔時的重定基準、開外來檔時的匯入換算全部退場。流程搬到哪台機器,都只需要在執行開頭量一次。
- **現有流程**:四份在用的流程一次換算到各自的流程尺度。四份舊流程廢棄,可以開、可以看,不能執行。

## User Stories

1. 身為使用者,我想要每份流程記住自己的尺度,這樣在簡中與繁中之間切換時不必先按校準。
2. 身為使用者,我想要按下執行後,程式先自動量這次的畫面倍率,這樣視窗大小變了,點擊仍然點對位置。
3. 身為使用者,我想要校準對找不到時流程不執行,並告訴我哪一張找不到,這樣不會在錯的畫面上靜靜點偏。
4. 身為使用者,我想要沒有校準對的流程不能執行,並告訴我要先設定校準對,這樣我知道下一步要做什麼。
5. 身為使用者,我想要測試選取的執行也在開頭自動校準,這樣測試結果跟正式執行一致。
6. 身為使用者,我想要執行紀錄寫出這次量到的倍率與兩張校準圖的位置,這樣事後可以判斷點偏是不是倍率的問題。
7. 身為使用者,我想要找圖時引擎只在預期尺度附近找,這樣每一步更快。
8. 身為使用者,我想要預期尺度剛好是引擎掃描的其中一格,這樣找到的框不會偏幾 px 害比色失敗。
9. 身為使用者,我想要確認圖、分岔條件、下一步的圖等所有找圖目標都用同一個預期尺度,這樣整份流程行為一致。
10. 身為使用者,我想要在建立流程時的視窗大小下執行時倍率剛好是 1,這樣座標原樣使用、不會有捨入誤差。
11. 身為使用者,我想要編輯器開流程時倍率預設 1,不自動量,這樣遊戲沒開也能順暢編輯。
12. 身為使用者,我想要在編輯器按「校準」更新倍率,並看到目前用的倍率,這樣視窗大小變了時我自己決定何時重量。
13. 身為使用者,我想要編輯器的校準失敗時保留原本的倍率並說明原因,這樣不會因為一次失敗就改壞拾取。
14. 身為使用者,我想要在編輯器切換到另一份流程時倍率回到 1,這樣不會把上一份流程的倍率帶過來。
15. 身為使用者,我想要拾取的座標(點擊、拖曳、限定範圍、指定點)自動除以目前倍率再存,這樣流程裡只有流程尺度。
16. 身為使用者,我想要倍率不是 1 時截下的新範本自動縮放回流程尺度再存,這樣同一份流程裡的範本尺度一致。
17. 身為使用者,我想要比對測試用編輯器目前的倍率當預期尺度,這樣測試結果與執行時一致。
18. 身為使用者,我想要從這份流程的範本裡挑兩張當校準對,這樣校準對跟著流程一起搬。
19. 身為使用者,我想要第一次設定校準對時,以當下畫面為流程尺度、直接量出基準距離,這樣新流程設定一次就好。
20. 身為使用者,我想要更換校準對時,程式先用舊的那對量出倍率,再換算新那對的基準距離,這樣換對不會改變流程尺度。
21. 身為使用者,我想要舊校準對量不到時拒絕更換並說明原因,這樣不會寫進錯的基準距離。
22. 身為使用者,我想要校準對的兩張範本不會被「刪除未使用範本」清掉,這樣流程不會因整理範本而不能執行。
23. 身為使用者,我想要存檔不再改寫 profile 裡的其他流程,這樣存一份流程不會動到別份。
24. 身為使用者,我想要開啟別台電腦或別個 profile 的流程時原樣使用、不換算,這樣同一個檔案到哪裡都一樣。
25. 身為使用者,我想要舊格式的流程(沒帶校準對)可以開、可以看步驟,只是不能執行,這樣廢棄的舊流程仍能當參考。
26. 身為使用者,我想要 profile 裡不再有校準資料檔與校準圖資料夾,這樣 profile 只剩引擎參數、流程與工作區。
27. 身為使用者,我想要現在在用的四份流程(基建換班簡中/繁中、日常簡中/繁中)換算完就能直接跑,這樣升級後不用重建流程。
28. 身為使用者,我想要換算前先備份正式資料,這樣出問題可以還原。
29. 身為使用者,我想要繁中流程也有自己的校準對(繁中客戶端的標題列圖示與關閉鈕),這樣兩邊都能自動校準。
30. 身為使用者,我想要影片轉流程產出的流程直接帶校準對與基準距離(從影片挑、在影片上量),這樣新流程一產出就能執行。
31. 身為使用者,我想要影片轉流程不再讀 profile 的校準、也不再換算座標,這樣影片尺度就是流程尺度。
32. 身為使用者,我想要沒給預期尺度的查詢(基準測試集、引擎自己的工具)照 profile 設定的尺度範圍全掃,這樣既有的準確度紀律不受影響。
33. 身為使用者,我想要開頭校準本身用全範圍找校準對,這樣倍率差很多(例如視窗縮到一半)也量得到。
34. 身為使用者,我想要開頭校準只多花兩次查詢的時間,這樣整體還是比現在快。
35. 身為維護者,我想要「開頭校準、決定跑不跑」在執行器裡完成,這樣用執行器測試替身就能測完整行為。
36. 身為維護者,我想要詞彙表、ADR 與 agent 文件都描述新模型,這樣之後的 agent 不會照舊模型改程式。

## Implementation Decisions

- **流程存檔格式升一版**:流程層級多一筆校準資料,內容是校準對兩張範本的名稱與基準距離。兩張都是這份流程自己的範本,存在一般範本區,不再有另一個校準圖區。
  - 讀到舊版(沒有校準資料)照常遷移步驟,但這份流程「沒有校準對」。
  - 不寫通用的「補校準對」自動遷移。
- **校準對算「被引用的範本」**:列入流程引用的範本清單,所以會被範本預載、不會被整理範本刪掉、改名時跟著改。
- **執行器收的是流程的校準資料,不是倍率**:執行器的啟動介面改成接收「校準對+基準距離」,開頭自己校準。
  - 開頭校準:依搜尋範圍截一張圖,用全範圍(不帶預期尺度)查兩張校準圖,以中心距離 ÷ 基準距離得出倍率。
  - 任一張找不到、或沒有校準資料,就送出零個輸入、以明確訊息結束,並記入執行紀錄。
  - 量到的倍率當作這次執行唯一的倍率。
  - 測試選取走同一條路。
- **倍率的兩個用途**:
  - 座標換算沿用現有的換算規則,範圍包括偏移、相對/絕對座標、限定範圍、指定點、拖曳端點。
  - 每次找圖把倍率當預期尺度交給偵測器;所有找圖目標都一樣,包括確認圖、分岔條件、等待消失、下一步的圖。
- **偵測器查詢介面多一個可選參數「預期尺度」**:
  - 引擎查詢與 app 的引擎中樞都加這個參數;測試替身與其他實作同步改形狀,包括引擎中樞測試的假引擎、影片轉流程的偵測器、基準測試。
  - 校準量測自己查詢時不帶預期尺度。
- **引擎的預期尺度語意**:給了預期尺度 s,粗篩只掃 s×1.09^k(k = −2…2)這 5 個尺度,網格以 s 為中心、s 本身一定在網格上;精修照舊。
  - 寬度寫死在引擎,不進 profile config。
  - 沒給時照 profile config 的尺度範圍全掃,行為與現在相同。
  - 登錄不受影響:尺度範圍仍是登錄產物的失效條件。
- **編輯器的倍率**:
  - 狀態屬於「這次編輯這份流程」:開流程或切換流程時為 1。
  - 按「校準」用這份流程的校準對量一次;成功就更新,失敗就保留原值並說明。介面顯示目前倍率。
  - 拾取不再有「未校準擋下」這道門。
- **拾取反除**:座標類拾取沿用現有的反除規則,倍率來源改成編輯器倍率。
  - 截範本(主視窗截圖、選範本對話框的拍攝)存檔前把圖除以倍率縮放;倍率是 1 時原圖照存。
  - 上傳的圖照原樣存,因為不知道它的來源尺度。
  - 預設原點推算與比對測試用編輯器倍率。
- **設定/更換校準對**:從這份流程的範本挑兩張。
  - 還沒有校準對:量當下距離作為基準距離。
  - 已有校準對:先用舊的那對量出倍率,新基準距離＝新距離 ÷ 倍率;舊的那對量不到就拒絕。
  - 兩張中心距離太近(現有下限)也拒絕。
- **退場的程式與資料**:
  - profile 校準資料檔與校準圖資料夾、機器指紋、未校準判定與執行前警告、拾取閘門。
  - 存檔時的重定基準(改寫整個 profile 的流程與步驟草稿)。
  - 開外來檔與匯入舊包時的換算與來源基準標記(外來流程原樣複製)。
  - 引擎來源清單裡併入的 profile 校準圖。
- **執行紀錄**:開頭校準寫一筆檔案日誌,內容是兩張圖的位置、距離、倍率;失敗時寫是哪一張、最高分數。
- **影片轉流程**:
  - 移除讀取目標 profile 校準與「座標 ÷ 倍率」的換算。
  - 組裝時從影片挑校準對(標題列圖示＋關閉鈕),在影片影格上量基準距離,寫進流程。
  - 自我驗證以預期尺度 1 查詢。
  - 交付報告列出校準對與基準距離。
- **一次性遷移四份在用流程**(Claude 執行,不是 app 功能):
  - 先備份正式 profile,做法比照 find-target/09。
  - 簡中流程的座標乘上簡中量得的倍率(0.8057),繁中流程乘上繁中倍率(從繁中客戶端量:標題列距離 ÷ 舊基準距離)。
  - 各自放入該客戶端的校準對範本(繁中從 demo3 截),基準距離＝流程尺度下的距離。
  - 完成後移除正式 profile 的校準資料檔與校準圖。
  - 用示範影片影格自我驗證:找圖照常找到、相對座標換算後落點與影片一致。
- **文件**:
  - app 的 agent 文件、影片轉流程 skill、ADR 0006 裡描述 profile 校準與存檔帶校準圖的段落,改成新模型。
  - 詞彙表與 ADR 0009 已在 grilling 時更新。

## Testing Decisions

- **好測試只看外部行為**:送出了哪些輸入、落點、每次查詢帶的預期尺度、流程有沒有執行、存檔讀回來的內容、紀錄寫了什麼。不測私有函式或中間資料結構。
- **主接縫:執行器測試替身**(既有的 runner harness:假偵測器依查詢序列回結果、記錄所有輸入事件、虛擬時鐘、檔案日誌)。要讓假偵測器記錄每次查詢收到的預期尺度。涵蓋:
  - 校準對兩張都找到:倍率＝距離比,座標落點乘上倍率,之後每次查詢的預期尺度都是這個倍率。
  - 其中一張找不到、或流程沒有校準資料:零輸入,紀錄寫明原因。
  - 倍率 1 時落點與現在完全相同(回歸線)。
  - 測試選取也先校準。
  - 前例:現有的執行器倍率測試、找圖目標測試、執行紀錄測試。
- **引擎查詢**(既有接縫):
  - 真實影格測試比照「小圖示不被別的尺度擠出候選」那組:以預期尺度 1 查詢,「X站1列」開比色仍找到、框與全範圍一致。
  - 給定預期尺度時只掃以它為中心的 5 格,網格必含預期尺度本身。
  - 沒給時與現在相同。
  - 前例:多尺度測試、所有匹配的真實影格測試。
- **流程存檔讀寫**(既有接縫):
  - 校準資料往返。
  - 舊版讀進來沒有校準對。
  - 校準對算被引用、不被整理刪除、改名跟著改。
  - 外來檔原樣複製不換算。
  - 前例:現有的流程存檔測試、開檔存檔測試。
- **編輯器校準 UI**(既有接縫):
  - 預設倍率 1;按校準成功/失敗。
  - 切換流程回到 1。
  - 拾取座標與截範本除以倍率。
  - 設定與更換校準對的兩條路。
  - 前例:現有的校準 UI 測試。
- **影片轉流程**(既有 tools 測試):
  - 產出的流程帶校準對與基準距離。
  - 不再讀 profile 校準。
- **改寫或刪除**:重定基準、機器指紋、未校準、來源基準、匯入換算相關的測試,隨功能一起移除。
- **驗收**:跑全部 pytest、基準測試集,重新打包;使用者以兩個客戶端各實跑一次基建換班。

## Out of Scope

- B1 候選合併去重(獨立的效能修正,先做)。
- effect-confirm(生效確認、補做、忙碌指示),排在本規格之後,另一份規格。
- 四份廢棄流程(日常_影片、arknight* 三份)的換算或修復。
- 非等比縮放、黑邊裁切。
- 讓 profile 的尺度範圍或預期尺度寬度可調。
- 自動偵測「這份流程屬於哪個客戶端」。

## Further Notes

- 預期尺度寬度的依據是 2026-10-05 用 demo1～5 影格的實測:沒對準的 [0.9,1.12] 網格沒有一格落在 1.0,框偏 2～4px,比色從 0.99 掉到 0.94(門檻 0.95),「X站1列」整個找不到。以 1.0 為中心的網格在基建換班兩份流程 0 漏。數據與腳本在 grilling session 的 scratchpad(可能已清除)。
- 校準對用標題列圖示與關閉鈕:兩者距離＝視窗寬,繁中最大化也有標題列。全螢幕模式沒有標題列,這種情況要另選校準對。
- 實跑監看與打包的坑見 memory:build-bat-encoding、repackage-move-user-data-out、packaged-smoke-user-present。
