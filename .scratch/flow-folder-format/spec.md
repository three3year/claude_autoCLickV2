新流程要到第一次存檔才選資料夾（ADR 0014 決策 3），但在那之前就可能截圖新增範本、做拾取檢查。這段期間的圖與登錄產物需要一個落點。

## Problem Statement

一份流程現在是一個 `.autoclickpack` zip，裡面的 `flow.json` 用舊鍵名（`onNotFound`、`limit: {kind: rect}`、毫秒、`find_click`＋`action`…），而且預設值散在各讀取點、互相不一致。四份在用流程都是 agent 用影片轉流程產出的，之後的修補也多半由 agent 做；但 agent 每改一步都要解壓、改 JSON、重包，不能 diff，使用者在檔案總管也看不到範本圖。

流程又被包在 profile 裡：`profiles/arknights/` 底下放著引擎參數、流程存檔、工作區，打包版每次重打包（`--noconfirm`）都會把它整個刪掉，使用者資料得先搬出去。profile 本身沒有任何真正屬於遊戲的資訊，卻在主視窗佔一個下拉與一顆建立鈕。

還有自動存檔的步驟草稿、工作區解壓，以及一批從未用過的步驟選項（按鍵步驟、絕對座標、滑鼠鍵、連點、原點矩形、出現等候上限、補做間隔與忙碌出現等候設定、啟動延遲、避開游標開關）和永遠不會走到的舞台接縫，讓 app、執行器、編輯器多出好幾條要維護的路徑。

最後，讀取流程時工作區會整個清空、連登錄產物一起刪，所以讀取後第一次按執行要現場登錄全部範本（82 張約 7.5 秒），第一步要到按下後約 8 秒才開始。

## Solution

一份流程變成一個資料夾：`flow.yaml`（區段巢狀、一步一行、預設不寫、時間一律秒）＋`templates/<範本名>.png`＋可重建的 `.cache/`。agent 可以直接讀、改、diff `flow.yaml`；使用者在檔案總管看得到圖；複製資料夾就搬完。

app 記憶體裡的步驟改用跟 yaml 相同的鍵名與單位（形狀照舊，仍是平面區段標記），預設值只剩一張表。存檔變成明確的動作：改動留在記憶體，按存檔才寫，關閉時提示未存檔；開 app 自動讀上次開的流程。

profile 整個退場：開檔直接選任何位置的 `flow.yaml`，流程預設放 `%USERPROFILE%\AutoClick\`，本機狀態與日誌放 `%LOCALAPPDATA%\AutoClick\`，打包版資料夾裡沒有任何使用者資料，部署就是整個換掉。引擎參數改成內建預設＋流程的 `engine:` 段覆蓋。

沒有資料可存的步驟選項與控制項，連同執行器路徑、舊格式讀寫、工作區、步驟草稿、舞台接縫一起刪掉。讀取流程就在背景預載範本，讀取後按執行約 3.5 秒就開始第一步。

四份在用流程用一次性轉換工具轉成新資料夾，逐步核對過後放到 `%USERPROFILE%\AutoClick\`。

## User Stories

1. 身為使用者，我想用「開檔」選任何位置的 `flow.yaml` 開啟它所在的流程資料夾，這樣流程放哪裡都能開。
2. 身為使用者，我想讓開檔與新流程第一次存檔的對話框從 `%USERPROFILE%\AutoClick\` 開始（不存在就自動建），這樣不必每次找位置。
3. 身為使用者，我想開 app 時自動開啟上次開的流程，這樣每天打開就能直接執行。
4. 身為使用者，我想在上次的流程已經不在時，開 app 得到空白新流程並在執行紀錄看到一行說明，這樣我知道發生了什麼。

## Implementation Decisions

### 子步驟順序

每一步結束都可跑、測試全綠（[記憶體步驟模型與 yaml 鍵名](../project-cleanup/issues/12-in-memory-step-model-keys.md) 決策 7）：

1. **刪路徑**：按鍵步驟、絕對座標模式、滑鼠鍵、連點數、原點矩形、出現等候上限從執行器、編輯器、清單摘要刪掉，連同只測這些路徑的測試；補做間隔與忙碌出現等候改成程式常數 1 秒，啟動延遲固定 3 秒，避開游標一律開，各自的 UI 控制項刪掉；刪舞台接縫與它的測試。
2. **機械改名**：記憶體模型改用新鍵（見下表），範圍包含執行器、app 清單與結構檢查、編輯器（tk 變數同名）、找圖目標、拾取檢查、影片轉流程工具、測試 builder 與測試資料。不改行為；剩下的測試全綠就是回歸網。
3. **預設表統一**：一個模組放「沒寫＝」表，讀取點的 `.get(鍵, 預設)` 改成依賴補齊後的完整步驟。這是行為變更（例如找圖缺 `on_fail` 從 skip 變 stop、拖曳缺值統一 0.5 秒），單獨一步，補測試。
4. **讀寫換成流程資料夾**：新的讀寫模組、存檔語意、`.cache/`、profile 退場、本機狀態與日誌位置；同一步刪舊 zip 讀寫、format 檢查、工作區、步驟草稿、profile_store。影片轉流程工具同時改寫到流程資料夾。
5. **背景預載**：讀取流程就預載，規則見下方。
6. **轉換四份流程**：跑轉換工具、自我核對全過。
7. **打包與驗收**：先把舊打包版整份搬到 `dist` 外，改 `build.bat`、重打包，跑驗收。

### 流程資料夾與 flow.yaml

- 資料夾內容：`flow.yaml`、`templates/<範本名>.png`、`.cache/`（登錄產物與未存檔截圖，可重建），影片轉流程產的資料夾另有 `交付報告.md`（app 不讀不寫，存檔不動它）。
- `flow.yaml` 的欄位、預設、排版以[flow.yaml 具體 schema](../project-cleanup/issues/02-flow-yaml-schema.md) 的欄位表與定案樣本為準：頂層 `format`（必填、為 1）、`run`、`scan_region`、`calibration`（`pair`、`baseline` 四捨五入到小數 1 位、`fallback`）、`busy`、`template_pos`、`engine`、`steps`；區段巢狀、一步一行（flow-style mapping）、行尾 `# N` 為存檔程式產生的步驟編號；中文範本名直接當值。
- 讀寫只做三種形狀轉換：巢狀↔平面標記、開頭鍵↔`type`、步驟層的 `within`／`pick`／`color`↔`target` 子 dict（確認圖 `confirm: {appear: 名, …}`↔`confirm: appear`＋`confirm_target`）。原型的 `nest()`／`flatten()` 是起點。
- 讀檔是唯一的入口驗證：yaml 語法錯、`format` 不是 1、未知的鍵（步驟、找圖目標、頂層、`engine:` 段）、型別錯、區段不完整、`branch` 的 `if` 不是找圖三態，都報錯並指出步驟編號與鍵；報錯時不開啟、目前開著的流程不動。
- 寫檔：等於預設的值不寫；整份重寫、不保留手寫註解；先寫暫存檔再取代，寫到一半失敗不留半份 `flow.yaml`。
- 範本名＝檔名。新增與重新命名時擋下非法名（`\ / : * ? " < > |`、開頭或結尾空白、結尾句點）。

### 記憶體模型

步驟仍是 dict＋平面區段標記；欄位名、值、單位一律跟 `flow.yaml` 相同，另加 `type`＝yaml 開頭的鍵，開頭鍵的值放在同名欄位。

| type | 記憶體例子 |
|---|---|
| `find_click`／`find`／`wait_gone` | `{type, target: {template, within, pick, color}, confirm, confirm_target, on_fail, timeout, interval, offset, busy_check, update_origin}` |
| `click` | `{type: click, click: [x, y], confirm, …}` |
| `drag` | `{type: drag, drag: [x, y], to: [x, y], duration, hold, …}` |
| `wait` | `{type: wait, wait: 0.5}` |
| `repeat_start`／`repeat_end` | `{type: repeat_start, repeat: 3}`、`{type: repeat_end, on_break}` |
| `branch_start`／`branch_or`／`branch_end` | `branch_end` 帶 `on_break` |

- 找圖目標（`target`／`confirm_target`）仍是子 dict：`{template, within: [x, y, w, h], pick: {top: N}｜{left: N}｜{near: [x, y]}, color: true}`；`confirm` 仍是 `none`／`gone`／`next`／`appear`。
- 流程層的記憶體 dict＝yaml 頭部（`run`、`scan_region`、`calibration`、`busy`、`template_pos`、`engine`）＋`steps`。拍攝位置住在 `template_pos`，不再另外傳。
- 退場的欄位：`action`、`key` 步驟、`loop_*`、`mode`、`button`、`clicks`、`appearLimitMs`、`limit.kind`、所有毫秒欄位、`avoidHover`、`coordSpace`、`flowFormat`、`retryIntervalMs`、`busyAppearMs`、`runMode`／`runCount`。

### 預設表

- 一張表＝02 欄位表的「沒寫＝」：`on_fail` stop、`timeout` 10、`interval` 0.3、`confirm` none、拖曳 `duration`／`hold` 0.5、`on_break` continue、`run` 1、`busy_check` false、`update_origin` true、沒有 `pick`＝分數最高、沒有 `within`＝整個搜尋範圍。
- 讀檔與新增步驟時補齊成完整步驟；存檔時等於預設的不寫。執行器、編輯器、影片轉流程工具不自帶預設；影片轉流程工具自己的預設模組收掉。
- `timeout`／`interval`／`on_fail` 只在有等待的步驟上補（找圖三態；點擊與拖曳設了 `confirm` 才有）。

### 存檔語意

- 改動留在記憶體；任何改動（步驟、範本新增／重截／改名／刪除、校準對、備用校準對、忙碌指示、搜尋範圍、執行輪數）都標記為未存檔。
- 按存檔：`flow.yaml` 整份重寫；`.cache/` 裡的未存檔截圖搬進 `templates/`；`templates/` 刪掉不再被引用的圖（引用＝步驟的找圖目標與確認圖＋校準對＋備用校準對＋忙碌指示）；`template_pos` 只留被引用的範本。
- 關閉 app、開檔、新流程時有未存檔改動：問「存檔／不存／取消」。
- 新流程第一次存檔才選位置與名字：輸入流程名，app 在選的位置建 `<流程名>\`；已有同名資料夾就拒絕並請換名，什麼都不寫。
- 開流程時被引用的範本圖不見了：照樣開，彈窗加執行紀錄列出缺哪幾張；執行時照範本預載的規則拒絕開跑；可在 app 重截同名圖補回。
- 不再有步驟草稿與自動存檔。

### 範本與快取

- 引擎收的範本清單由 app 組：`templates/` 的圖＋`.cache/` 的未存檔截圖，扣掉記憶體裡已刪的；引擎不掃目錄（ADR 0006）。登錄產物放 `.cache/`。
- 重開 app 或讀取流程時清掉 `.cache/` 裡的未存檔截圖；登錄產物保留（過期自動重算）。
- 新流程還沒存檔時，截圖與登錄產物放本機狀態資料夾裡固定的「未存檔」快取（打包版在 `%LOCALAPPDATA%\AutoClick\` 底下，原始碼執行在 repo `.local\` 底下）；第一次存檔時截圖搬進新資料夾的 `templates/`、登錄產物搬進 `.cache/`；開新流程、讀取別的流程或重開 app 時清空（`app/CONTEXT.md`「快取」詞條已補）。
- 新增或重截範本只丟那幾張的登錄產物（拾取檢查或校準檢查時重新登錄），其他留在記憶體。

### 引擎參數

- 引擎參數＝引擎內建預設（`default_config.yaml`）＋流程 `engine:` 段覆蓋，由 app 合併後交給引擎；引擎公開 API 形狀不變（ADR 0015 決策 4）。
- app 不提供編輯 `engine:` 的 UI；讀進來原樣保留、存檔原樣寫回。

### 背景預載

規則照[診斷「預載完還再等 3 秒」](../project-cleanup/issues/03-diagnose-post-preload-wait.md)的決定：

1. 讀取流程就開始背景預載（引擎還沒就緒就等就緒後開始，包括 app 啟動時自動開的上次流程）。
2. 還沒載完就按執行：接著等同一份；開始延遲仍是從按下起算的 3 秒下限。
3. 新增或重截範本只丟那幾張的登錄產物。
4. 執行紀錄只印「開始準備範本」「範本就緒」兩行，狀態列不加東西。
5. 預載中換流程＝丟掉舊的、開始新的；背景預載發現壞圖＝當下在執行紀錄印警告，按執行時照舊不開跑並報錯。

### profile 退場、本機狀態與日誌

- 刪 profile 概念、profile_store 模組、`profiles/` 目錄、主視窗的 profile 下拉與建立鈕、開啟資料夾鈕。
- 開檔：一般開檔視窗、篩選 `flow.yaml`，開它所在的資料夾；不做檔案關聯、不做命令列參數。
- 本機狀態只記上次開的流程，存 `state.json`；主視窗維持固定開啟大小，不記位置。
- 打包版的狀態與 `autoclick.log` 放 `%LOCALAPPDATA%\AutoClick\`；從原始碼執行放 repo `.local\`，`.gitignore` 加 `.local/`。
- 基準測試集不在本階段搬動或重製（見 [Out of Scope](<#Out of Scope>)）；依賴 profile 路徑的部分只做到讓它照舊能跑。

### 影片轉流程工具（過渡）

- 計畫格式照舊（舊鍵）；計畫裡出現原點矩形、按鍵、出現等候上限、非預設滑鼠鍵或連點數時報錯，說明已退場、影片轉流程階段改用固定矩形。
- 組好的流程是新記憶體模型，交 app 的寫檔函式存成流程資料夾；交付報告寫成資料夾裡的 `交付報告.md`。
- 輸出位置預設 `%USERPROFILE%\AutoClick\<流程名>\`，可用參數指定；不再需要 profile 參數與步驟草稿。
- 不寫搜尋範圍（＝全螢幕）；影片比搜尋範圍大的提醒跟著拿掉。
- 不再幫範本加 `待重拍_` 前綴；待重拍清單只寫在交付報告。

### 轉換工具

照[轉換工具規則與驗收](../project-cleanup/issues/11-converter-rules-and-acceptance.md)：

- 一次性腳本放本 spec 同目錄（`convert.py`），跟著提交當紀錄；不進 `tools/`、不寫正式測試、之後不維護。起點是 02 的原型轉換腳本。
- 自己開 zip 讀 `flow.json` 與 `templates/_meta.json`；組成新記憶體模型交 app 的寫檔函式。所以在子步驟 4 完成後才跑。
- 只處理四份實際出現的欄位與值；`mode`、`button`、`clicks` 直接丟。舊檔缺值套新預設（四份缺值為零，轉完行為不變）。
- 四份各寫 `engine: {scale_range: [0.6, 1.5]}`。
- 舊 `.md` 逐位元複製成 `交付報告.md`；`_autosave.json` 不轉。
- 輸出 `%USERPROFILE%\AutoClick\<流程名>\`；資料夾已存在就報錯停下、什麼都不寫。
- 自我核對（每份）：用 app 讀檔函式讀回 → 轉換工具裡獨立寫的反向對映轉回舊鍵 → 與原檔逐步比（步數相同、每步欄位相同）；`templates/*.png` 與原 zip 逐位元相同、集合相同；`template_pos`、校準（主對＋備用對，`baseline` 允許 0.05 內的差）、忙碌指示、`run`、`scan_region`、`engine` 逐項比。任一項不過就報錯；全過印每份步數與範本數。

## Testing Decisions

- 好的測試只看外部行為：檔案的內容、讀檔得到的記憶體流程、執行器的事件序列（誰在什麼順序做了什麼）、App 操作後資料夾與記憶體的狀態。不測內部欄位與私有函式。
- **接縫一：流程資料夾讀寫。** 用 tmp_path 建資料夾：讀寫往返；讀進來補齊預設、寫出去等於預設的不寫；缺圖、`format` 不對、未知鍵、yaml 語法錯、區段不完整各報出步驟編號與鍵；非法範本名被擋；`engine:` 段原樣往返。定案樣本（晚_簡中，已在 git）讀進來再寫回，除了開頭的原型註解外文字相同——它就是排版的規格。前例：現有存檔模組的資料進資料出測試。
- **接縫二：執行器 harness。** 現有的假偵測器＋虛擬時鐘照用；builder 改新鍵名。執行器、校準、找圖目標、拾取檢查的測試在機械改名步驟整套當回歸網；刪掉路徑（按鍵、絕對座標、出現等候上限、補做與忙碌設定、啟動延遲、避開游標開關、舞台接縫）的測試跟著刪；預設表統一那步補新預設的行為測試（例如找圖缺 `on_fail`＝停止）。
- **接縫三：App 存讀檔。** 沿用現有開檔存檔測試的做法：子類跳過重量級建構、對話框以樁取代（使用者選了哪個檔、按了哪個鈕）、假引擎。測：開檔、存檔只寫引用集合（含校準對與忙碌指示的圖）、未存檔截圖存檔後才進 `templates/`、重新命名連動、關閉／開檔／新流程時的未存檔提示三種回答、新流程第一次存檔才選位置、上次流程自動開與不在時的處理、讀取就開始背景預載、預載中換流程、重截只換那幾張。前例：現有開檔存檔測試、流程預載測試。
- 影片轉流程工具的現有測試改成斷言輸出的流程資料夾（經 app 讀回），並補「計畫含已退場欄位會報錯」。
- profile_store、工作區、步驟草稿、舊格式拒絕、舞台接縫的測試整檔刪掉。
- 會開 Tk 視窗的測試照 memory 的做法在隱藏桌面跑，或先確認使用者不在玩遊戲。
- 轉換工具不寫正式測試，靠自我核對。
