# 生效確認擴及座標點擊與拖曳,補做受忙碌指示把關(effect-confirm)

Status: ready-for-agent

詞彙見 `app/CONTEXT.md`:生效確認、原點的圖離開、點到下一步的圖出現、找圖相連、補做、補做間隔、忙碌指示、等待消失、出現等候上限、找不到時。決策紀錄見 ADR 0008。順序上排在 flow-scale 之後:重寫流程時,座標已經是流程尺度。

## Problem Statement

網路延遲時,遊戲畫面已經畫好(圖找得到),但伺服器還沒回應,遊戲不接受輸入,點擊與拖曳被靜靜吃掉。2026-10-05 實跑 `基建換班_簡中` 時發生兩次:

- **鈴鐺沒點開**:步驟 2 點了待辦鈴鐺,待辦列沒開。後面的分岔只等 3 秒就跳出,整段待辦都沒收。
- **拖曳沒捲動**:發電站 2 換班後,伺服器還沒回傳,步驟 63 的捲動拖曳沒效果。接下來「相對 1 列 +519」的點擊落到空白處,發電站 3 沒換班。

根本原因:

- 只有找圖點擊能檢查「有沒有生效」;座標點擊、拖曳完全沒有檢查。
- 流程只能靠固定等待(換班後 1500ms)賭伺服器夠快。四份在用流程合計約 70 個不確認的找圖點擊、30 多個座標點擊、12 個拖曳。
- 拖曳被吃掉後,後面會靜靜點錯列。
- 現有找圖點擊的補點每個輪詢間隔就補一次。遊戲只是慢、不是吃掉時,會重複操作:拖曳捲過頭、鈴鐺被點回關閉、換班 ⇌ 換到下一隊。
- 座標點擊與拖曳不寫檔案日誌,「拖曳被吃」只能從前後兩次找圖的位置推論。

## Solution

- **`生效確認`涵蓋三種步驟**:找圖點擊、座標點擊、拖曳。生效條件如下:
  - 目標圖消失:只限找圖。
  - `原點的圖離開`:只限座標點擊與拖曳。產生目前原點的那個找圖目標,不在它原本的框了。不必另選圖,也不多查一次。
  - 確認圖出現。
  - 下一步的圖出現。
- **沒生效就`補做`**:重送同一個輸入。前提有兩個:距上次輸入已過`補做間隔`(流程設定,預設 1000ms),且畫面上沒有`忙碌指示`。現有找圖點擊的補點一併改用這套規則。
- **`忙碌指示`**:流程層級的一個找圖目標,例如明日方舟底部的「正在提交反饋至神經……」字樣。只在補做之前查,一般輸入前不查,不拖慢每一步。
- **`等待消失`加`出現等候上限`**:在上限內一次都沒看到,也算通過。換班 ⇌ 後用它等忙碌指示,取代固定 1500ms:網路慢就等指示消失,網路快約 1 秒就放行。
- **逾時處置**:座標點擊與拖曳的生效確認逾時,預設停止流程,不再靜靜點錯。
- **日誌**:記下確認結果、輸入次數、因忙碌延後補做的時間;沒開確認的點擊與拖曳也記座標。
- **影片轉流程跟著支援**:產出的拖曳預設「原點的圖離開」,影片裡看得到忙碌指示時,也自動設定忙碌指示與等待。
- **重寫四份在用流程**:基建換班簡中/繁中、日常簡中/繁中。鈴鐺的確認圖用左下角「待辦事項」標籤。

## User Stories

1. 身為使用者,我想要座標點擊可以設定生效確認,這樣點擊被吃掉時程式會補點,不是靜靜往下走。
2. 身為使用者,我想要拖曳可以設定生效確認,這樣捲動被吃掉時程式會重拖。
3. 身為使用者,我想要拖曳的生效條件可以選「原點的圖離開」,這樣「找 1 列 → 拖曳」不必另選一張確認圖就能判斷有沒有捲動。
4. 身為使用者,我想要「原點的圖離開」不必在操作前多找一次,這樣不增加每一步的時間。
5. 身為使用者,我想要「原點的圖離開」沿用來源找圖目標的限定範圍、挑選規則與比色,這樣發電站 2 捲到 1 列的舊位置時,不會被誤判成「沒捲動」。
6. 身為使用者,我想要原點不是來自找圖時,「原點的圖離開」在編輯器顯示警告、執行時擋下,這樣我不會設了一個永遠判斷不了的確認。
7. 身為使用者,我想要座標點擊與拖曳也能選「確認圖出現」,這樣關彈窗、切頁籤這類操作可以用新出現的畫面確認。
8. 身為使用者,我想要座標點擊與拖曳也能選「下一步的圖出現」,這樣不必重複設定下一步已經有的找圖目標。
9. 身為使用者,我想要「下一步的圖出現」在下一步不是找圖時顯示警告、執行時擋下,這樣跟找圖點擊的規則一致。
10. 身為使用者,我想要補做時送出跟第一次相同的輸入(同樣的起點、終點、按鍵),這樣重拖的距離不會因為原點已經更新而改變。
11. 身為使用者,我想要拖曳生效後原點才是拖曳終點,這樣後面的相對點擊以正確的位置為準。
12. 身為使用者,我想要距上次輸入未滿補做間隔時不補做,這樣遊戲只是慢時不會重複操作。
13. 身為使用者,我想要補做間隔是流程層級的一個設定、預設 1000ms,這樣一個地方就能調整。
14. 身為使用者,我想要畫面上有忙碌指示時先不補做、等它消失,這樣不會在伺服器忙的時候又送一次輸入。
15. 身為使用者,我想要在流程設定裡指定忙碌指示(範本、限定範圍、比色),這樣簡中與繁中各用自己的字樣。
16. 身為使用者,我想要忙碌指示可以不設,不設時只看補做間隔,這樣沒有這種指示的遊戲也能用。
17. 身為使用者,我想要忙碌指示只在要補做之前才查,這樣一般步驟不多花時間。
18. 身為使用者,我想要現有找圖點擊的補點也遵守補做間隔與忙碌指示,這樣鈴鐺這種開關不會被連點兩次。
19. 身為使用者,我想要找圖點擊在目標已離開原位、確認圖還沒出現時照舊不補點,這樣行為跟現在一致。
20. 身為使用者,我想要生效確認逾時就走「找不到時」的處置,這樣可以選跳過、跳出或停止。
21. 身為使用者,我想要座標點擊與拖曳的「找不到時」預設是停止流程,這樣捲動失敗時不會在後面點錯列。
22. 身為使用者,我想要座標點擊與拖曳開了生效確認後,有自己的逾時與輪詢間隔,預設跟找圖一樣,這樣可以個別調整。
23. 身為使用者,我想要沒開生效確認的座標點擊與拖曳行為完全不變,這樣既有流程不受影響。
24. 身為使用者,我想要等待消失可以設出現等候上限,這樣「可能出現、也可能不出現」的忙碌指示不會讓流程空等到逾時。
25. 身為使用者,我想要出現等候上限內看到圖之後照常等它消失、受步驟逾時限制,這樣網路慢時確實等到伺服器回應。
26. 身為使用者,我想要沒設出現等候上限的等待消失維持「從未出現＝逾時失敗」,這樣既有流程行為不變。
27. 身為使用者,我想要換班 ⇌ 之後用「等待消失+出現等候上限」等忙碌指示,取代固定 1500ms,這樣網路快時更快、網路慢時更穩。
28. 身為使用者,我想要執行紀錄寫出座標點擊與拖曳的生效確認結果(生效或逾時、送了幾次輸入),這樣事後看得出是被吃掉還是只是慢。
29. 身為使用者,我想要執行紀錄寫出補做因忙碌指示延後了多久,這樣可以判斷忙碌指示有沒有作用。
30. 身為使用者,我想要沒開生效確認的座標點擊與拖曳也在檔案日誌記一行座標,這樣事後能對照前後的找圖位置。
31. 身為使用者,我想要編輯器的座標點擊與拖曳對話框有生效確認的選項(不確認、原點的圖離開、確認圖出現、下一步的圖出現)、確認圖選擇、逾時與找不到時,這樣在介面上就能設定。
32. 身為使用者,我想要步驟清單的摘要顯示座標點擊與拖曳的生效確認方式,這樣一眼看出哪些步驟有確認。
33. 身為使用者,我想要流程設定區可以設補做間隔與忙碌指示,這樣不用改存檔。
34. 身為使用者,我想要忙碌指示與座標點擊、拖曳的確認圖所用的範本被當成「被引用的範本」,這樣會被預載、不會被整理刪掉、改名時跟著改。
35. 身為使用者,我想要影片轉流程產出的拖曳,在原點來自找圖時預設「原點的圖離開」,這樣新流程不會再犯拖曳被吃的問題。
36. 身為使用者,我想要影片轉流程在影片裡看得到忙碌指示時,自動設定流程的忙碌指示,並在送伺服器的操作後用「等待消失+出現等候上限」取代固定等待,這樣產出的流程又快又穩。
37. 身為使用者,我想要四份在用流程重寫,補上生效確認、忙碌指示,拿掉可以拿掉的固定等待,這樣日常與基建換班不再因延遲失敗。
38. 身為使用者,我想要鈴鐺點擊用「確認圖出現」、確認圖是左下角的「待辦事項」標籤,這樣待辦列沒開時會補點,有沒有東西可收都一樣。
39. 身為使用者,我想要每個捲動拖曳都設「原點的圖離開」,並把逾時設成停止流程,這樣拖曳失敗不會點錯列。
40. 身為維護者,我想要所有執行行為都能用同一個執行器測試替身測,這樣不必為這個功能加新的測試接縫。
41. 身為維護者,我想要 agent 文件與影片轉流程 skill 改用「生效確認」一詞,這樣之後的 agent 用同一套詞彙。

## Implementation Decisions

- **步驟資料**:座標點擊與拖曳多出可選欄位,讀不到就是預設值,舊存檔不需要遷移。
  - 生效確認方式:不確認、原點的圖離開、確認圖出現、下一步的圖出現。存檔沿用找圖步驟的同一組鍵與值。「原點的圖離開」在座標點擊與拖曳上,使用找圖「目標圖消失」的那個值。
  - 確認圖。
  - 逾時、輪詢間隔:預設同找圖。
  - 找不到時:預設停止。
  - 找圖步驟的欄位不變。
- **流程層級設定**:新增補做間隔(毫秒,預設 1000)與忙碌指示(一個找圖目標,可不設)。存檔方式比照現有的避開游標。
- **等待消失的新選項**:出現等候上限(毫秒,預設不設)。
- **原點來源**:執行器記住目前原點是誰產生的。
  - 由找圖步驟產生時,記下該找圖目標、它當時挑中的框、查詢它時用的原點(供限定範圍換算)。
  - 由座標點擊或拖曳產生時,記成「非找圖來源」。
  - 「原點的圖離開」在操作後用相同條件重查來源找圖目標,看原本的框還有沒有匹配(沿用等待消失的同位置判定)。
  - 編輯器沿用現有的「預設原點推算」,靜態判斷原點來源是不是找圖,用來顯示警告。
- **共用的確認與補做流程**:三種步驟送出第一次輸入後,進入同一個迴圈:
  1. 每個輪詢間隔截圖並檢查生效條件。
  2. 沒生效時,判斷要不要補做:找圖「目標圖消失」只在目標仍在原位時補,其餘方式一律補;已滿補做間隔;設了忙碌指示時,畫面上沒有忙碌指示。條件都成立就補做。
  3. 期間記錄輸入次數與因忙碌延後的時間。
  4. 逾時走找不到時。
  - 補做送出的輸入與第一次相同:座標點擊與拖曳的落點,以第一次輸入前的原點計算。原點在生效之後才更新。
  - 「確認圖出現」與「下一步的圖出現」的確認,以操作後的原點為準。
- **忙碌指示查詢**:用流程的忙碌指示找圖目標(含限定範圍,預設應框在畫面底部中央)。只在補做判斷時查,不在一般輸入前查;也不讓出`舞台`(找圖到補做仍是一個原子區段)。
- **輸入入口收斂**:執行器所有實際送出輸入的地方,都經過同一個內部入口,方便記錄「上次輸入時間」。
- **執行紀錄**:
  - 座標點擊與拖曳的生效確認寫一筆檔案日誌,欄位比照找圖的確認紀錄:步驟、確認方式、結果、輸入次數、輪詢次數,另加延後補做的總時間。
  - 沒開確認的座標點擊與拖曳寫一行座標。
  - 找圖的確認紀錄也加上延後補做的時間。
- **編輯器**:
  - 座標點擊與拖曳對話框加生效確認區塊(方式、確認圖、逾時、找不到時),做法參考找圖對話框現有的確認區塊。
  - 流程設定區加補做間隔與忙碌指示(用找圖目標編輯介面設定)。
  - 等待消失加出現等候上限。
  - 步驟摘要與警告標記涵蓋新情況:「原點的圖離開」原點不是找圖、「下一步的圖出現」不相連;測試選取與執行前檢查一樣會擋。
- **被引用的範本**:流程引用的範本清單納入忙碌指示、座標點擊與拖曳的確認圖;改名、整理、預載跟著涵蓋。
- **影片轉流程**:
  - 計畫格式的欄位白名單,允許座標點擊與拖曳的確認欄位、流程層級的補做間隔與忙碌指示、等待消失的出現等候上限。
  - 預設值:拖曳的原點來自找圖時,用「原點的圖離開」、找不到時停止。
  - 忙碌指示的偵測與設定寫進 skill:Claude 在影片裡找底部指示字樣、截範本,在送伺服器的操作之後放等待消失+出現等候上限。
  - 交付報告列出忙碌指示。
- **重寫四份在用流程**(Claude 執行,flow-scale 遷移之後;先備份):
  - 鈴鐺(基建換班 2、日常簡中 19、日常繁中 9):確認圖出現,用「待辦事項」標籤(簡中 demo4、繁中 demo3 截)。
  - 每個捲動拖曳:原點的圖離開。
  - 換班 ⇌ 後的固定 1500ms:改成等待消失(忙碌指示,出現等候上限 1000ms)。
  - 其他不確認的找圖點擊與座標點擊:能確認的補上確認,下一步已有確認的拿掉固定等待。
  - 忙碌指示範本用文字那段(簡中、繁中各一張)。
  - 改完後用示範影片自我驗證,再請使用者實跑。
- **文件**:app 的 agent 文件與影片轉流程 skill 裡的「點擊後確認」改成「生效確認」,補上新規則;詞彙表與 ADR 0008 已在 grilling 時更新。

## Testing Decisions

- **好測試只看外部行為**:送出的輸入事件(種類、座標、次數、順序)、虛擬時鐘上的時間點、後續步驟有沒有執行、流程是否停止、檔案日誌欄位。不測內部狀態或私有函式。
- **唯一的執行接縫:執行器測試替身**(既有的 runner harness)。忙碌指示就是假偵測器裡另一張安排好查詢序列的範本,補做間隔用虛擬時鐘。涵蓋:
  - 拖曳+原點的圖離開:來源框仍有匹配就在補做間隔後重拖、兩次拖曳座標相同;框不見就生效、原點變成終點;原點來自點擊時無法執行。
  - 座標點擊+確認圖出現、+下一步的圖出現:生效、補點、逾時預設停止(後續步驟沒執行)。
  - 補做間隔:未滿間隔不補,滿了才補。
  - 忙碌指示:補做時畫面上有指示就延後,指示消失才補;沒設忙碌指示只看間隔;一般第一次輸入前不查忙碌指示(查詢紀錄裡沒有它)。
  - 找圖點擊的既有確認改走新規則:補點時機受間隔與忙碌把關;既有確認測試的期望隨之調整。
  - 等待消失+出現等候上限:上限內沒看到就通過;看到後消失就通過;看到但沒消失就逾時。
  - 沒開確認的座標點擊與拖曳行為不變,並在檔案日誌記一行。
  - 日誌欄位:確認結果、輸入次數、延後時間。
  - 舞台:找圖到補做仍是原子區段。
  - 前例:現有的執行器步驟測試(確認、等待消失)、下一步確認測試、找圖目標測試、執行紀錄測試、舞台測試。
- **編輯器**:沿用既有對話框測試。
  - 新欄位的往返。
  - 警告標記(原點不是找圖、下一步不相連)。
  - 執行前檢查擋下。
- **流程存檔**:
  - 新欄位往返。

- 換班 ⇌ 本身生效與否的確認:沒有可用的確認圖,只靠等忙碌指示避免下一個輸入被吃。

## Further Notes

- 忙碌指示的觀察(demo4 簡中、demo3 繁中):
  - 樣子:底部半透明深色帶、正中菱形,加上「正在提交反饋至神經……」字樣,位置固定。
  - 比對穩定度:文字 0.87～1.00,比菱形穩;菱形翻轉的那幾幀掉到 0.63。
  - 時間:點擊後 0.3～0.8s 才出現,顯示約 1s;伺服器快時完全不出現。
  - 繁中字樣是繁體;demo3 換班時沒錄到指示。
  - 信用交易所購買會連出兩次指示,第二次出現時「獲得物資」彈窗還在。
