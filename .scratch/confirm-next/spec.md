# Spec: 點擊後確認第四態「點到下一步的圖出現」（confirm: "next"）

Status: implemented (2026-08-16, tickets 01–05 resolved)

## Problem Statement

流程作者常遇到「點某張圖、直到畫面前進為止」的情境：點擊不一定一次生效，
要一直補點，直到下一個畫面出現。現有的「點到確認圖出現」（appear）可以做到，
但確認圖幾乎總是**下一個找圖步驟本來就要找的那張圖**——作者被迫把同一張圖
再截一次（或再選一次）當確認圖，範本庫出現重複、兩處引用也可能改到不同步。

## Solution

「點擊後確認」新增第四態**「點到下一步的圖出現」**：以「找圖相連」的下一個
找圖步驟的範本圖出現為點擊生效條件，不必另選確認圖。確認對象依清單位置跟隨
（不記名）——排序、複製貼上後自動指向新的下一步。

前提是**找圖相連**：緊接的下一個步驟必須是找圖步驟（三態皆可）。不相連時
（最後一步、下一步是區段標記或其他類型）：步驟編輯對話框按確定**擋下存檔**、
按執行（含測試選取）**擋下執行**；清單上平時只顯示 ⚠ 警告標記，不彈窗。

## User Stories

1. 身為流程作者，我想在「點擊後確認」下拉選到「點到下一步的圖出現」，讓點擊生效條件直接沿用下一步要找的圖，不必再選一張確認圖。
2. 身為流程作者，我想讓找圖點擊在沒生效時每隔 interval 自動補點、直到下一步的圖出現，讓「點到畫面前進為止」不需要手動重試。
3. 身為流程作者，我想在逾時仍未見下一步的圖時走該步驟的「找不到時」處置（跳過／跳出／停止），讓失敗行為與其他確認模式一致。
4. 身為流程作者，我想在重新排序或複製貼上步驟後，確認對象自動指向新的下一步，讓我不必逐一修正凍結的範本名。
5. 身為流程作者，我想在下一步不是找圖時於清單該列看到 ⚠ 警告標記，讓我平時編輯不被彈窗打斷也能發現失效。
6. 身為流程作者，我想在步驟編輯對話框按確定時、若下一步不是找圖就被警告並擋下存檔，讓我當場知道要先把兩步排相連。
7. 身為流程作者，我想在按執行時、若有步驟不相連就被警告並擋下執行，讓流程不會在執行中途遇到未定義行為。
8. 身為流程作者，我想在「測試選取」的片段恰好結束在該步驟時同樣被警告擋下，讓我知道要把下一步一起選進來。
9. 身為流程作者，我想讓下一步是「僅等待出現」的找圖也能當確認條件，讓「點 A 直到 B 出現、再對 B 做別的事」成立。
10. 身為流程作者，我想讓下一步是「等待消失」的找圖也能當確認條件，讓「點 A 直到 B 出現、接著等 B 消失」成立。
11. 身為流程作者，我想讓補點沿用該步驟原本的逾時／重試秒數（與 gone/appear 相同的預算規則），讓我不用學新的時間設定。
12. 身為流程作者，我想讓補點時的原點更新行為與其他確認模式一致（含可勾掉「更新原點」），讓相對座標語意不因確認模式而異。
13. 身為流程作者，我想在確認迴圈進行中仍能用 F12 急停，讓失控的補點隨時可以中止。
14. 身為流程作者，我想讓逾時訊息明確說「點擊後 X 秒內未見下一步的圖『B』」，讓我一眼分辨是找不到目標圖還是等不到下一步的圖。
15. 身為流程作者，我想讓分岔條件步驟也能用這個選項（下一步＝分支內緊接的找圖），讓分支內的補點邏輯與平地一致。
16. 身為流程作者，我想讓既有流程檔（沒有用到新選項的）載入與執行完全不受影響，讓升級零風險。
17. 身為流程作者，我想讓 flow pack 匯出入不因新選項多出範本引用（確認對象不記名），讓封裝內容維持精確。
18. 身為流程作者，我想在改掉、刪掉或搬走下一步之後，清單立即重算並顯示 ⚠ 標記，讓失效不會安靜地潛伏到執行才爆。
19. 身為流程作者，我想在選「不點擊」的三態時看不到（也不會存出）確認選項，讓無意義的組合不出現——與既有慣例一致。
20. 身為使用者，我想讓萬一執行期仍遇到不相連的步驟時（防禦線），流程記錄警告並以「不確認」退化執行而不是崩潰，讓例外情況可診斷。

## Implementation Decisions

- `confirm` 欄位新增第四個值 `"next"`；UI 下拉顯示名稱為**「點到下一步的圖出現」**，
  與既有選項同句型。`confirmTemplate` 在此模式一律存空字串（確認對象不記名）。
- 執行語意沿用既有的點擊後確認補點迴圈：找到本步的圖 → 點一次 → 每隔 interval
  查一次「執行清單中下一步（index+1）的範本圖」，出現＝生效；目標圖仍在就補點；
  逾時／interval 為**重新起算的一份預算**（與 gone/appear 相同）；逾時走「找不到時」。
- 「下一步的圖」**執行當下依位置現算**，存檔不凍結範本名。找圖步驟的執行器因此
  需要拿得到執行中的步驟清單與自身索引（簽名擴充）。
- **找圖相連**規則：緊接的下一個步驟型別必須是找圖（三態皆可）。最後一步、
  下一步是區段標記（重複／分岔標記）或其他步驟類型＝不相連。
- 三個檢查點共用**同一個相連檢查純函式**（模組層級、不依賴 GUI）：
  1. 步驟編輯對話框按確定：不相連 → 警告彈窗並擋下存檔（注意新增與編輯兩種
     情境下「下一步」索引語意不同，新增時步驟尚未入清單）。
  2. 執行前檢查（含測試選取片段）：不相連 → 警告彈窗並擋下執行；片段結束在
     該步驟即視為不相連。
  3. 步驟清單渲染：不相連 → 該列型別標籤旁插 ⚠ 段（warn 色），每次清單重繪
     重算；不得動到號碼欄的 tab 對齊。
- runner 保留執行期防禦線：遇到不相連（理論上已被擋）記錄警告並退化為
  「不確認」，風格比照分岔的執行期檢查。
- 逾時訊息措辭區分：「點擊『A』後 X 秒內未見下一步的圖『B』」。
- 不新增任何範本引用欄位 → pack 匯出入的範本收集、範本改名的引用同步皆不需
  變動。下一步自身的範本存在性由既有的執行前範本檢查涵蓋。
- 讀檔遷移不需變動（純新增值，舊檔無此值）。
- 詞彙表已更新（「點擊後確認」擴充、新增「點到下一步的圖出現」「找圖相連」
  條目）；不立 ADR（決策可逆、無深層取捨）。

## Testing Decisions

- 只測外部行為：給定步驟清單與假畫面安排，驗「點了幾次、點在哪、何時通過、
  逾時走哪條處置」，不驗內部函式呼叫順序。
- **Runner 行為**走既有 harness 接縫（假偵測器 `vision.plan` 安排第幾次查詢
  找到、虛擬時鐘、記錄式滑鼠）：補點直到下一步的圖出現、逾時走找不到時、
  排序後依位置現算、防禦退化。先例＝既有點擊後確認（gone/appear）的
  runner 回歸測試。
- **相連檢查純函式**直接 pytest：下一步為三態各種找圖＝合法；最後一步／
  區段標記／其他類型／片段截尾＝不相連。這是本功能唯一新增的測試接縫。
- **UI 層只做輕量驗證**：清單 ⚠ 標記渲染一例（monkeypatch 自動存檔的既有
  模式）；對話框擋存檔行為主要由純函式覆蓋，不建整套 GUI 測試。

## Out of Scope

- 找圖階段的提前結束（等待本步的圖時先看到下一步的圖就跳過點擊）——已在
  需求對齊時排除，只做點擊後確認。
- 測試選取片段的自動擴充（自動把下一步補進片段）——一律擋下提示。
- ⚠ 標記的 tooltip 或 per-row 圖示基礎建設——只插文字段。
- 步驟 ID／凍結範本名等任何跨步驟的記名參照機制。
- 其他確認模式（none/gone/appear）的行為變動。
- 並行執行（本輪未移植）相關的互動。

## Further Notes

- 對話框擋存檔只能保證「按確定那一刻」合法；之後移動／刪除／改掉下一步仍會
  讓已存步驟失效——那時靠 ⚠ 標記與執行前攔截，這是拍板時已接受的行為。
- 需求對齊紀錄：點擊後確認第四態、執行當下現算、執行與存檔皆擋下、三態皆可
  相連、測試選取同樣擋下、選項命名——皆於 grilling session 拍板（2026-08-16）。
