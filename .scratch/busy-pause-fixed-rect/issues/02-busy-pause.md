# 02 — 忙碌暫停

**What to build:** 流程有設忙碌指示時,找圖在等待期間看到忙碌指示,那段時間不算進逾時,也不算進等待消失的出現等候上限。同一步驟累計最多暫停 60 秒,超過後照常計時。網路慢時,流程不會在下一個畫面還沒出來前就判定找不到。

規格:`.scratch/busy-pause-fixed-rect/spec.md`(忙碌暫停一節、接縫一);ADR 0010;詞彙「忙碌暫停」見 `app/CONTEXT.md`。

**Blocked by:** 01 — 執行器的找圖等待共用一個等待時鐘

**Status:** ready-for-agent

- [ ] 適用範圍:分岔的輪詢、一般找圖(三態)、生效確認(找圖點擊、座標點擊、拖曳)、等待消失(含出現等候上限)。
- [ ] 只在這一輪沒達成時才用同一張截圖查忙碌指示;找到或生效的那一輪不查。
- [ ] 生效確認裡,補做門檻與暫停共用同一次忙碌查詢,不重複查。
- [ ] 計算方式:
  - 分岔整個算一步,所有分支共用一個 60 秒額度。
  - 找圖階段和它的確認階段各自一個額度。
  - 出現等候上限跟步驟逾時共用那一步的額度。
- [ ] 目標就是忙碌指示本身的等待消失步驟,同樣適用,沒有例外。
- [ ] 沒設忙碌指示,或範本不在流程裡時:行為、時間點跟現在相同,也不多查。
- [ ] `find.target` 與 `input.confirm` 加 `busy_pause` 欄位,記暫停秒數;`busy_delay` 保留,意思不變。
- [ ] pytest 劇本(harness:假畫面、虛擬時鐘)至少涵蓋規格接縫一列出的忙碌暫停各項。
- [ ] `app/CLAUDE.md` 中「忙碌指示只在補做前查」以及用等待消失加出現等候上限來等忙碌指示的說明,改成符合 ADR 0010。
- [ ] 全部 pytest 通過。
