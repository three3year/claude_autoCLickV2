# 快速置入前先查線索(quick-place-clue-check)

Status: ready-for-agent

詞彙見 `app/CONTEXT.md`:流程存檔、範本、找圖目標、限定範圍、固定矩形、原點、生效確認、補做、找不到時、分岔、重複區段、草稿、忙碌檢查。相關決策:ADR 0009(一份流程一個尺度)、ADR 0011(忙碌檢查)。

來源:2026-10-08 早班實跑,`早_繁中` 在「交流中」時仍按了快速置入(見 `.scratch/busy-check/issues/06-live-acceptance.md` Comments);2026-10-09 使用者給示範影片 `oCam Video/add3.mp4`(簡中視窗)、`add4.mp4`(繁中最大化),同日 `/grill-with-docs` 定案。

## 需要你決定的

### 點 1–7 號篩選鈕要不要確認點到了?

決定(2026-10-09):(b)確認點到。

點了某一號、點擊卻被吃掉時,清單還停在上一號(上一號已經確認有卡片),這一號就會被誤判成「有」,最後可能誤按快速置入。

- (a)不確認:只用一張「開面板鈕」範本加相對座標點 1–7 號,範本最少;點擊被吃掉就可能誤按。影片裡面板不出忙碌指示、清單下一幀就換好,被吃掉的機會小,但不是零。
- (b)確認點到(建議):每一號點完等「選中的 N 號鈕」(白底實心)出現,沒出現就補做,補做後還沒出現就當成沒有、不按。每個客戶端多 7 張小範本,都從影片裁;符合「判不出來就不按」的原則。

### 「1–7 都有」是指什麼?

決定(2026-10-09):7 個號碼每一號都至少一張才按;依序查,第一個沒有的號碼就停。

### 「交流中」分支留不留?

決定(2026-10-09):拿掉,只靠線索面板判斷。

### 改哪幾份?

決定(2026-10-09):`早_簡中` 照 add3、`早_繁中` 照 add4;晚班兩份沒有快速置入,不動。

### 怎麼判斷某一號「有」?

決定(2026-10-09):開線索面板逐號點篩選鈕,看清單第一格有沒有卡片;用每張卡片都一樣的元素判斷「確實看到卡片」,不用「是不是空背景」。

### 判斷不出來時算哪邊?

決定(2026-10-09):當成沒有、不按。出錯時只會少按一次,不會誤按。

### 查哪個分頁?

決定(2026-10-09):「全部」。新開的面板預設就是「全部」,不用另外點。

### 線索板上已經放了一部分要不要處理?

決定(2026-10-09):不會發生,不處理。

### 收線索和檢查的先後?

決定(2026-10-09):先接收(全部收取),再檢查、置入;當天收到的線索當天就能用。

### 驗證做到哪?

決定(2026-10-09):真引擎影格、無頭執行器、讀回,三種都做,最後由使用者實跑。

## Problem Statement

使用者每天早上用 AutoClick 跑明日方舟早班,簡中、繁中各一份流程(`早_簡中`、`早_繁中`)。會客室那段現在的規則是「線索板下方顯示交流中就不按快速置入,否則就按」。這條規則有兩個問題:

- 「交流中」認不出來時就會誤按。2026-10-08 `早_繁中` 實跑,畫面明明是交流中,分岔第一輪就走了快速置入。
- 就算沒在交流中,手上的線索不一定湊得齊 1–7 號。湊不齊時按快速置入只會放進一部分,沒有意義;使用者的實際做法是先看 1–7 號是不是都有,都有才按。

另外,流程現在是先按快速置入、最後才接收好友送的線索,當天收到的線索要隔天才用得到。

## Solution

會客室那段改成照 add3/add4 的手動做法:

1. 每日線索 → 領取(照舊)。
2. 先收線索:接收线索 → 全部收取 → 暂未收到新的线索 → 點外面關掉(這段從後面搬到前面)。
3. 點線索板右下角、快速置入正上方的「线索」(CONFIDENTIAL)鈕,打開線索面板;預設就是「全部」分頁。
4. 依序點 1→7 號篩選鈕,每一號看清單第一格有沒有卡片:
   - 確實看到卡片 → 查下一號。
   - 時限內沒看到 → 當成沒有,立刻停止檢查。
5. 不管結果如何都點面板外的線索板空白處,把面板關掉。
6. 7 號都有才按快速置入(簡中按鈕文字是「快捷置入」);有任何一號沒有就不按。
7. 解鎖線索分岔、回到線索板、傳遞線索照舊。

## User Stories

1. 身為早上跑基建的玩家,我想讓流程只在 1–7 號線索都有時才按快速置入,這樣不會放進半套線索。
2. 身為早上跑基建的玩家,我想讓流程不再依賴「交流中」的字樣判斷,這樣交流中認不出來時也不會誤按。
3. 身為玩家,我想讓流程先收好友送的線索再檢查,這樣當天收到的線索當天就能湊進 1–7 號。
4. 身為玩家,我想讓流程依序查 1、2、3…7 號,遇到第一個沒有的號碼就停,這樣缺號時不用把 7 號都點完。
5. 身為玩家,我想讓「判斷不出來」一律當成沒有,這樣出錯時只是少按一次,不會誤按。
6. 身為玩家,我想讓每一號只看清單第一格有沒有卡片,這樣有幾張都一樣快。
7. 身為玩家,我想讓「有沒有卡片」用每張卡片都一樣的元素判斷,這樣 1–7 號共用一張範本,不用每號各截一張。
8. 身為玩家,我想讓面板打開後直接查,不用再點「全部」分頁,因為新開的面板預設就是「全部」。
9. 身為玩家,我想讓不管 7 號有沒有湊齊,檢查完都把面板關掉,這樣後面的解鎖、傳遞線索看得到線索板。
10. 身為玩家,我想讓 7 號都有時,面板關掉後才按快速置入,因為快速置入鈕被面板蓋住。
11. 身為玩家,我想讓沒按快速置入時,後面的解鎖線索分岔自然逾時跳過、傳遞線索照做,這樣缺號的日子流程也能一路跑完。
12. 身為簡中客戶端(視窗)使用者,我想讓 `早_簡中` 的新範本都從 add3 裁,這樣尺度和我的視窗一致。
13. 身為繁中客戶端(最大化)使用者,我想讓 `早_繁中` 的新範本都從 add4 裁,這樣尺度和我的全螢幕一致。
14. 身為使用者,我想讓面板上的鈕、卡片的檢查位置都用固定矩形限定範圍,這樣找圖快,也不會找到別處長得像的東西。
15. 身為使用者,我想讓「有」的號碼第一輪就判定、往下走,只有「沒有」的號碼才等滿時限,這樣湊齊的日子幾乎不多花時間。
16. 身為使用者,我想讓點篩選鈕後確認那一號真的選中了、被吃掉就補做,補做後仍沒選中就當成沒有,這樣不會因為一次點擊失敗就誤按。
17. 身為使用者,我想讓兩份流程原本的其他步驟內容完全不變,這樣以前的實跑紀錄還對得起來。
18. 身為使用者,我想讓 app 啟動讀到的草稿與工作區範本也同步更新,這樣打開編輯器看到的就是新版,不會被舊草稿蓋回去。
19. 身為使用者,我想讓改之前留一份 profiles 備份,這樣實跑出問題可以換回舊版。
20. 身為使用者,我想讓兩份流程的交付報告各記一節改了什麼、怎麼驗的、已知風險、備份位置,這樣以後回頭查有據可循。
21. 身為使用者,我想讓實跑日誌看得出查到第幾號停、是看到卡片還是逾時、有沒有按快速置入,這樣能確認行為對不對。
22. 身為使用者,我想讓早班 08:44 那類開頭問題、繁中忙碌指示範本等其他待辦不混進這次,這樣這次的改動好驗收。

## Implementation Decisions

- **只改流程存檔,不改程式碼**:執行器、找圖目標、存檔格式都不動。改的是 `早_簡中`、`早_繁中` 兩份存檔,以及目前的草稿與工作區範本。
- **新範本**(每個客戶端各一套,從自己的影片裁,不跨客戶端換算):
  - 開面板鈕:線索板右下角的 CONFIDENTIAL「线索」圖示。現有流程裡叫「线索」/「線索面板」的範本是基建總覽上會客室那格的入口圖示,不是這顆,要另外取名。
  - 卡片標籤:每張卡片都有的灰底標籤,「相关搜集者」/「相關蒐集者」或「来自」/「來自」二選一,實作時在影格上比過分數挑穩的那個。不用線索圖(每號陣營不同)、不用垃圾桶(只有部分卡片有)。
  - 面板開著的標記:用來確認面板已經打開、也用來判斷檢查後面板還開著沒(例如「all」篩選鈕)。
  - 選中的 1–7 號鈕(白底實心):每個客戶端 7 張,當點篩選鈕的生效確認。
- **新步驟的形狀**:
  - 打開面板:找圖點擊開面板鈕,點到「面板開著的標記」出現。
  - 檢查區段:用一個分岔把 1–7 號的檢查包起來,分支條件是面板開著的標記。每一號是「點 N 號篩選鈕,點到「選中的 N 號鈕」出現(補做;仍沒出現=跳出)」加「找卡片標籤 → 僅等待出現,找不到時=跳出」。點篩選鈕用相對面板標記的座標,不更新原點,7 號共用同一個原點。7 號都過了才在區段裡關面板、按快速置入。
  - 跳出後補關面板:區段後面接一個短逾時的分岔,面板開著的標記還在就點面板外關掉,不在就跳過。
  - 關面板的點擊:點面板左邊的線索板空白處(影片裡簡中約 (1095,215)、繁中約 (1200,690)),位置用相對座標或固定位置,實作時定。
- **時限**:清單在點擊後下一幀就換好。卡片標籤的等待時限取短值(約 1 秒),「有」的號碼第一輪就找到;「沒有」只會發生一次(查到就停)。
- **移動與刪除**:
  - 「接收线索 → 全部收取 → 點外面關掉」那個分岔整段搬到「領取」之後、開面板之前,內容不變。
  - 刪掉「交流中 / 快速置入」分岔(`早_簡中` 第 55–59 步、`早_繁中` 第 46–50 步,以 2026-10-09 存檔為準)。
  - 解鎖線索分岔、之後再點「线索」入口回線索板、傳遞線索,照舊接在後面。
  - 其餘步驟內容一字不改,編號隨插入/刪除變動。
- **建構方式**:跟前幾張票一樣,寫一支可以重跑的腳本放在本功能的 `.scratch` 資料夾,以內容定位步驟(不靠編號),寫回存檔與草稿後讀回驗證。AutoClick 要先關著。
- **備份**:改之前把 profiles 複製到 dist 底下新的備份資料夾(日期+功能名)。
- **交付報告**:兩份流程報告最上面各加一節。

## Testing Decisions

- 好的驗證只看外部行為:找圖有沒有找到、找到的位置、執行時點了哪裡、走了哪個分支、按了沒。
- 不加 pytest:這次沒改程式碼。驗證腳本放在本功能的 `.scratch` 資料夾,可以重跑。

### 接縫一:真引擎+影片影格

- 用 app 的真實偵測路徑與 arknights profile 的門檻,影格換成實機搜尋範圍的畫布。
- 卡片標籤:在每一號「有」的影格找得到、位置在第一格的固定矩形內;在「暂无线索」/「暫無線索」的影格找不到。
  - add3:1、2、4 號空,3、5、6、7 號有。
  - add4:1 號空,2–7 號有。
- 開面板鈕、面板開著的標記、快速置入:在對應影格找得到;面板標記在面板關掉後的影格找不到。
- 選中的 N 號鈕:在選中 N 號的影格找得到,在選中其他號的影格找不到。
- 先例:evening-notice-close 的 `frames.py`、busy-pause-fixed-rect 票 08 的固定矩形驗證。

### 接縫二:無頭執行器

- 用 app 測試用的無頭 harness(假畫面、假輸入、虛擬時鐘),從改好的存檔切出會客室那段跑劇本:
  - 7 號都有 → 依序點 1–7、關面板、按快速置入。
  - 第 N 號空(N 取 1、4、7)→ 點到 N 號就停、關面板、不按。
  - 卡片標籤一直找不到(判不出)→ 第 1 號就停、關面板、不按。
  - 某號點擊被吃掉一次 → 補做後繼續;一直沒選中 → 停、關面板、不按。
  - 每個劇本最後都接到解鎖線索分岔與傳遞線索。
- 先例:evening-notice-close 的 `sim.py`。

### 接縫三:讀回檢查

- 兩份存檔和草稿讀回後確認:新步驟的設定和上面寫的一樣;搬動的接收段內容不變;交流中分岔已刪;其他步驟依序原封不動;新範本都在存檔裡。

### 最終驗收

使用者用打包版實跑兩份早班,我看 `autoclick.log`:

- 查到第幾號停、每號是找到還是逾時,和使用者當天畫面上的線索一致。
- 缺號時沒按快速置入;湊齊時有按,而且之後解鎖線索找得到。
- 接收线索在檢查之前。

## Out of Scope

- 晚班兩份流程不動。
- 線索板上已放一部分的情況。
- 繁中忙碌指示範本、簡中收取信用點擊沒生效、早_簡中開頭卡住等其他 10/08 待辦(見 `.scratch/busy-check/issues/06-live-acceptance.md`)。
- 用快速置入鈕上的紅色數字或線索板上的橘色菱形判斷(影片裡看起來對得上,但沒看過 7 的樣子)。
- 不重新打包;流程存檔在打包版資料夾裡,改完直接生效。

## Further Notes

- 影片分析的細節(各號影格、座標、按鈕文字)在本功能資料夾的 `video-notes.md`。範本實作時從影片重新抽影格裁。
- 現有流程在解鎖線索後會再點一次「线索」入口回線索板,推測解鎖後畫面會離開線索板;新順序保留這一步。
- 實跑時使用者常在玩遊戲:冒煙或實跑前先確認使用者在不在、前景是哪個視窗。
