# 06 — 失敗跳過與急停

**What to build:**

- **失敗**：串接中某份失敗時，後面`同一個目標程式`（正規化路徑相同）的流程全部跳過，其他目標程式的照跑。失敗包括執行器錯誤、開頭校準失敗、倍率出界、找不到視窗、移不到前景。
- **急停**：按 F12 或停止鈕，整條串接立刻停止，在兩份之間按下也一樣停得住。
- **總結**：每份一行，結果有完成、失敗（原因）、跳過（因為第 N 份〈流程名〉失敗）、中斷（急停）、未執行（急停）。
- **結束時**：主視窗停在最後實際跑過的那份。

詳見[規格](../spec.md)「已定的決策」的失敗與急停、「串接的進行規則」、「主視窗整合」的急停、User Stories 45–51。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] 進行規則接收「失敗（附原因）」結果：之後所有同目標程式的項目標為跳過，不交給呼叫端；不同目標程式的照常交出。
- [ ] 進行規則接收急停通知，不論在某份執行中還是兩份之間：
  - 正在跑的記為中斷（急停）。
  - 還沒判定的記為未執行（急停）。
  - 已跳過的維持跳過。
  - 之後不再交出任何項目。
- [ ] 進行規則提供「最後實際跑過的那份」：最後一項被跳過時，回報它前面跑過的那份；一份都沒跑過時沒有。
- [ ] 進行規則測試涵蓋：
  - 同目標程式跳過，路徑大小寫或斜線不同也算同一個。
  - 不同目標程式照跑。
  - 執行中急停。
  - 兩份之間急停。
  - 已跳過的項目遇到急停。
  - 五種總結文字。
  - 最後實際跑過的那份。
- [ ] 主視窗：
  - F12 與停止鈕除了停執行器，也通知串接急停。串接自己記住急停，輪詢時先看它，因為執行器每次 `start` 都會清掉自己的停止旗標。
  - 找不到視窗、移不到前景、執行器錯誤都以「失敗＋原因」回報，原因取自 02。
  - 結束後切到進行規則回報的最後實際跑過的那份。
- [ ] UI 測試（隱藏桌面）涵蓋：
  - 第一份失敗時，同目標程式的第三份被跳過，不同目標程式的第二份照跑，總結正確。
  - 移不到前景時該份記為失敗。
  - 兩份之間急停時，下一份不會開始。
  - 結束時停在最後實際跑過的那份。
