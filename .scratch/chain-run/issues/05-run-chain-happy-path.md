# 05 — 執行串接（順利的情況）

**What to build:** 使用者在主視窗的下拉選單選一份串接檔，按「執行串接」。

1. 有未存檔改動就先問存或丟。
2. 準備檢查：對每份流程做單獨執行會擋的檢查，再確認目標程式有設、正在執行。有任何問題就整條不開始，並依流程列出。
3. 依序執行每一份：
   - 主視窗切到那份流程。
   - 把它的目標程式移到最上層，確認真的成為前景。
   - 用串接檔的輪數執行：3 秒開始延遲、範本預載、開頭校準、各輪步驟，跟單獨執行一樣。
4. 迷你視窗全程顯示「串接 第幾份/共幾份：流程名」，兩份之間不關。
5. 結束後執行紀錄印總結，檔案日誌記一筆 `chain`，主視窗停在最後一份。

本票建立`串接`的進行規則模組，先涵蓋「每份都完成」與準備檢查不過兩種情況。失敗跳過與急停在 06：本票遇到失敗或急停時，可以先單純結束整條串接，但不能接著跑下一份。詳見[規格](../spec.md)「串接的進行規則」「主視窗整合」、User Stories 29–44、50–53。

**Blocked by:** 01、02、04

**Status:** ready-for-agent

- [ ] 進行規則模組（純邏輯，不碰 Tk、Win32、執行器），放在 `automation`：
  - 輸入是串接項目（流程名、輪數、目標程式路徑）、每份的檢查問題、執行中的程式路徑。
  - 準備階段要做到：
    - 空串接不開始。
    - 各份問題、「未設目標程式」、「目標程式沒在執行：〈路徑〉」依流程分組回報。
    - 有任何問題就不開始。
  - 開始後提供下一份要跑的項目、進度（第幾份、共幾份、流程名），接收「完成」結果，產生總結（每份一行）。
- [ ] 進行規則測試（純資料）涵蓋：
  - 準備不過的各種情況（含沒設目標程式、程式沒開）。
  - 空串接。
  - 全部完成的順序、進度與總結文字。
  - 同一份流程出現兩次。
- [ ] 主視窗：
  - 執行區加串接檔下拉選單與「執行串接」鈕。
  - 開始順序：辨識中與引擎就緒的 gate → `confirm_discard` → 讀串接檔 → 逐份從磁碟讀流程，跑 01 的檢查函式 → 列出執行中的程式路徑 → 交給進行規則。
  - 不合格時，一個警告視窗列出全部問題。
- [ ] 進行中由主視窗既有的輪詢驅動：
  1. 在介面執行緒切換流程，走不跳對話框的路徑。
  2. 用 03 的方法移到最上層。
  3. 直接以串接檔的輪數、次數模式啟動執行器，不讀主視窗的輪數欄位。
  4. 看到執行器結束，就讀 02 的結果回報給進行規則，再接下一份。
- [ ] 移不到前景或找不到視窗：本票先記為該份失敗並結束串接。跳過規則在 06。
- [ ] 迷你視窗在串接中顯示進度，兩份之間不關，整條結束才關。
- [ ] 結束時：執行紀錄印總結，檔案日誌寫一筆 `chain`（內容同總結），主視窗停在最後跑的那份。
- [ ] UI 測試（隱藏桌面，用 harness 假件或替身執行器，加上假的「列視窗、移到最上層」）涵蓋：
  - 依序切流程，每份用串接檔的輪數，不受主視窗輪數欄位影響。
  - 準備檢查不過時有警告、沒有開始。
  - 未存檔時先問。
  - 迷你視窗的進度文字，兩份之間不關。
  - 執行紀錄的總結與檔案日誌的 `chain` 一筆。
  - 結束後停在最後一份。
- [ ] app 全套 pytest 綠。
