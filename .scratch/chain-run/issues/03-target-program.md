# 03 — 目標程式

**What to build:** 流程作者能在「流程設定…」為流程指定`目標程式`。新的第四列「目標程式」：

- 「設定…」打開選程式清單，從開著的程式視窗裡點選一個，記下完整路徑。
- 「清除」移除設定。
- 「測試」把那個程式的視窗移到最上層約 2 秒，再自動回到 AutoClick。

存檔後寫進 `flow.yaml` 的 `program:`。單獨執行完全不讀這個欄位。

詳見[規格](../spec.md)「流程存檔：目標程式欄位」「找視窗、移到最上層」「流程設定：目標程式列」、User Stories 1–16，以及 [ADR 0019](../../../docs/adr/0019-chain-target-program-by-full-path.md)。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] `flow.yaml` 新增頂層鍵 `program:`，值是路徑字串，沒寫＝沒設。讀寫只經 `flowfile`，讀寫來回不變，沒設時不寫出。格式規範的欄位表加一列，欄位表一致性測試照過。
- [ ] 提供「同一個目標程式」的路徑比對：正規化後比較，大小寫不分、斜線統一。
- [ ] `win` 能做這幾件事：
  - 列出所有可見的頂層視窗（含最小化），附標題、還原後的大小、所屬程式的完整路徑；讀不到的路徑要標出來。
  - 依路徑挑視窗：取還原後面積最大的那個。挑選邏輯跟列舉分開。
  - 移到最上層：最小化就先還原，不改大小與位置；設為前景後，輪詢確認前景確實是它，約 2 秒內沒成功就回報失敗。要用能穩定取得前景的做法，以「確認前景」的結果為準。
- [ ] 單元測試（假的視窗清單）涵蓋三件事：
  - 挑到還原後面積最大的那個，最小化不吃虧。
  - 路徑比對不分大小寫與斜線。
  - 沒有符合的就回報找不到。
- [ ] 「流程設定…」第四列「目標程式」：
  - 文字欄顯示「檔名（所在資料夾）」，太長就中間省略，滑鼠移上去顯示完整路徑；沒設時顯示「未設定（串接時必須有）」。
  - ⓘ 說明：串接輪到這份流程時要移到最上層的程式，單獨執行不使用。
  - 不登記為圖片類動作，辨識中不反灰。
  - 改動標為未存檔。
- [ ] 選程式對話框：
  - 欄位為標題、程式、大小、路徑。
  - 排除 AutoClick 自己這個程序，以程序判斷、不以路徑。
  - 有設定時預先選中路徑相同的列；設定的程式沒開時，最上面加一列反灰的「目前設定：…（沒在執行）」。
  - 讀不到路徑的列反灰、不能選。
  - 有「重新整理／確定／取消」。
- [ ] 「測試」：
  - 移到最上層，執行紀錄寫「目標程式已移到最上層：〈程式〉（〈大小〉）」。
  - 約 2 秒後把 AutoClick 主視窗移回前景。
  - 找不到時寫「找不到：〈路徑〉沒在執行」。
- [ ] UI 測試（隱藏桌面，假的「列視窗、移到最上層」，假時鐘或 `after` 替身）涵蓋：
  - 設定、清除、顯示文字。
  - 未存檔標記。
  - 測試鈕的移上去、移回來與找不到。
  - 對話框不列出自己這個程序、預先選中、反灰列。
- [ ] app 全套 pytest 綠。
