# 02 — 建構腳本骨架：一般正例＋易誤判負樣本＋卡片頁

**What to build:** 一次性建構腳本（放本階段 `.scratch`，不進 `tools/`）第一次從頭走到尾：讀 `flows/` 四份在用流程現在的範本與`示範影片`（只用順序讀幀），產出兩個客戶端的**一般正例**與**易誤判負樣本**候選案例資料夾（新格式，含來源欄位），篩掉游標碰到答案框、轉場模糊的幀，並產一頁本機 HTML 卡片頁。agent 逐張先審，有疑問的排前面。見 [spec](../spec.md)「Implementation Decisions」的一次性建構腳本與審核流程。

**Blocked by:** 01 — 基準集執行器改讀 benchmark/

**Status:** ready-for-agent

- [ ] 腳本讀四份流程的範本、示範影片（路徑含中文用 imdecode；幀號一律順序讀）
- [ ] 答案優先取人工判定過的資料（quick-place 線索判定、repo 內 demo2／add5 計畫），其餘用現在的範本在影格上配對
- [ ] 一般正例與易誤判負樣本（同畫面前後狀態、長得像的東西）兩類，簡中、繁中各半，四份流程都分到；數量照 spec 配額（每類 6–12）
- [ ] 用 quick-place 票的游標偵測篩掉游標碰到答案框的幀；轉場、模糊、半透明的幀不收（當困難負樣本時除外）
- [ ] 每個案例寫來源欄位；候選先放 scratchpad，不進 `benchmark/`
- [ ] 卡片頁：範本小圖＋影格畫紅框、負樣本不畫框標「應該沒有」、每張有編號；放 scratchpad、不上傳
- [ ] agent 逐張看過，有疑問的排在卡片頁最前面並寫一句原因
- [ ] 用 01 的執行器跑一次候選，結果記在本票 Comments
