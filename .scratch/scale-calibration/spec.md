# 畫面倍率校準(scale calibration)

Status: ready-for-agent

## Problem Statement

找圖本身對一定比例的縮放有抗性(引擎多尺度比對),但流程裡儲存的座標沒有:找圖偏移(offsetX/Y)、相對座標(mode:prev)、絕對座標(mode:abs)都是建立流程那台機器上的實體像素。把流程用 flow pack 匯到另一台電腦(或同一台換了螢幕/視窗尺寸)後,找圖找得到、點擊卻點偏——偏移量沒有跟著畫面縮放。使用者希望流程匯入別台電腦後可以直接用,不必逐步重拾座標。

## Solution

提供「校準」功能。使用者在 profile 裡指定兩個會同時出現在同一畫面的既有範本作為**校準對**(比例尺);指定當下立刻校準一次,量得兩張圖匹配框中心的直線距離作為**基準距離**,本機**畫面倍率**記為 1。

換到另一台電腦後,使用者按主視窗的校準按鈕:在畫面上找到校準對兩張圖、以當前距離 ÷ 基準距離得出本機畫面倍率。執行流程時,所有步驟偏移(找圖偏移、相對座標、絕對座標,含拖曳端點)乘上倍率換算落點,點擊便落在正確位置。

流程檔座標永遠維持「當前基準機器」的尺度:在倍率≠1 的機器上存檔會自動**重定基準**(全部流程座標換算改寫、基準距離更新、倍率歸 1)。flow pack 連校準對與基準距離一起帶,匯入時依兩邊基準比值自動換算座標,跨機來回搬遷不會亂。

## User Stories

1. 身為換電腦的使用者,我想要匯入 flow pack 後點擊落點自動符合新螢幕的縮放,這樣我不必逐步重新拾取座標。
2. 身為流程作者,我想要從範本庫指定兩個既有範本作為校準對,這樣不必為校準另外截圖。
3. 身為流程作者,我想要在指定校準對的當下立刻完成第一次校準(建立基準距離、本機倍率記 1),這樣基準與日後校準用的是同一把尺。
4. 身為新機器上的使用者,我想要按一個校準按鈕就量出本機畫面倍率,這樣一次校準、整個 profile 的所有流程共用。
5. 身為使用者,我想要主視窗常駐顯示當前倍率(或「未校準」狀態),這樣我隨時知道座標換算是否生效。
6. 身為使用者,當校準找不到兩張圖(或只找到一張)時,我想要看到明確的失敗原因、且舊倍率維持不動,這樣切到正確畫面後重試即可,不會被錯誤的回退值搞壞。
7. 身為未校準機器上的使用者,我想要執行流程時收到「尚未校準,座標可能偏移」的警告但仍可執行(以倍率 1 代入),這樣兩台螢幕相同的機器零阻力。
8. 身為使用者,當我把整個 profile 資料夾複製到另一台電腦時,我想要系統靠機器指紋認出「倍率是別台機器量的」並視同未校準,這樣警告機制不會被舊倍率騙過。
9. 身為找圖點擊的使用者,我想要 offsetX/Y 依倍率縮放,這樣「點在圖旁邊」的落點在縮放後的畫面上仍然正確。
10. 身為使用相對座標的使用者,我想要 mode:prev 的偏移依倍率縮放,這樣以原點出發的落點在縮放後仍然正確。
11. 身為使用絕對座標的使用者,我想要 mode:abs 的偏移依倍率縮放,這樣重框搜尋範圍後,框內版面縮放也能對準。
12. 身為使用拖曳的使用者,我想要拖曳起訖點(兩種座標基準)都依倍率縮放,這樣拖曳軌跡與距離在縮放後仍然正確。
13. 身為在已縮放機器上編輯流程的使用者,我想要存檔時自動重定基準並收到告知訊息,這樣流程檔回到單一尺度、不會雙重縮放。
14. 身為在未校準機器上編輯流程的使用者,我想要拾取座標前被擋下並要求先校準,這樣不會把無法歸位的座標存進檔案。
15. 身為匯出 flow pack 的使用者,我想要 pack 自動附帶校準對範本與基準距離,這樣收到 pack 的人開箱就能校準。
16. 身為匯入 flow pack 的使用者,當目標 profile 沒有校準資料時,我想要自動採用 pack 帶來的校準對與基準(倍率留空=未校準),這樣不必手動搬校準設定。
17. 身為匯入 flow pack 的使用者,當目標 profile 已有同一對校準圖時,我想要流程座標依兩邊基準距離的比值自動換算落地,這樣匯進來的流程直接是本 profile 的尺度。
18. 身為匯入 flow pack 的使用者,當兩邊校準對不同(無共同比例尺)時,我想要流程照 pack 尺度落地並收到警告,這樣我知道這份流程還沒歸位。
19. 身為使用者,對「不同校準對」匯入的流程,我想要在存檔前被要求先完成校準換算、或明確確認以匯入的基準存檔,這樣混尺度不會被安靜寫進 profile。
20. 身為使用者,我想要校準的找圖行為與一般找圖一致(有搜尋範圍就在範圍內找,否則全螢幕;截圖前照常清場),這樣不用學第二套規則。
21. 身為沒有用到校準功能的使用者,我想要沒有校準對的 profile 行為與現狀完全相同(不警告、不換算),這樣舊 profile 零影響。
22. 身為明日方舟使用者,我想要校準完成後既有流程在原機器上行為不變(倍率 1 = 恆等換算),這樣加上校準不會弄壞已經調好的流程。

## Implementation Decisions

- **尺度來源採兩圖比例尺,不使用引擎匹配尺度**。引擎 QueryResult 不新增欄位、引擎 context 不動;校準完全在 app context 實作。
- **新增一個校準模組**,集中全部純邏輯:校準資料的載入/儲存、倍率計算、機器指紋產生與比對、重定基準的流程檔改寫、pack 匯入換算。UI 與 runner 只呼叫它,不各自實作。
- **校準資料存在 profile 內**(隨 profile 資料夾搬遷),內容:校準對兩個範本名、基準距離、本機倍率、機器指紋。範本以正式名稱(相對路徑不含副檔名)引用,與流程引用一致。
- **量測走辨識單一路徑**(ADR 0002):校準用與 runner 相同的偵測器接縫(`query(範本名, 搜尋區域) → QueryResult`)找兩張圖,不開第二條比對路徑。量測前先確保登錄完成(與其他引擎查詢入口相同的前置)。
- **距離 = 兩匹配框中心的直線距離**;倍率 = 當前距離 ÷ 基準距離,單一等比值,不分 x/y。
- **校準的截圖與找圖語意與一般找圖相同**:有搜尋範圍就在範圍內找、否則全螢幕;截圖前走清場(ADR 0003 的 screen_clear session),避免自家視窗入鏡。
- **倍率套用在執行期**:runner 換算落點時,把找圖偏移(offsetX/Y)、座標點擊/拖曳的偏移(abs 與 prev 兩種基準、拖曳含兩端點)乘上倍率後四捨五入為整數像素。倍率 1(含未校準代入值)為恆等換算,走原路徑等價。搜尋範圍本身、原點等執行期螢幕座標不換算(它們本來就是本機量測值)。
- **未校準的定義**:有校準對、但本機沒有有效倍率(從未校準,或機器指紋不符)。執行=警告一次後以 1 代入;拾取=擋下並要求先校準。**沒有校準對的 profile 完全不受影響**(不警告、不換算、UI 只顯示可指定校準對)。
- **機器指紋**取自螢幕配置(虛擬桌面幾何等當下可查的組態),存倍率時一併記錄;執行/拾取前比對,不符視同未校準。
- **重定基準**:在倍率≠1 的機器上存流程檔時自動觸發並告知——profile 內所有流程檔(含自動存檔)座標乘上現行倍率改寫、基準距離改為本機量值、倍率歸 1、指紋更新。流程檔內的座標因此永遠是「當前基準機器」的尺度,檔案格式不需要新的座標空間標記。
- **編輯期不混尺度**:拾取到的本機像素先以現行倍率反除、歸一到現行基準暫存於步驟中;存檔時再整體重定基準。淨效果等同「以本機為 1 重新存檔」,但檔內與記憶體中任一時刻都只有單一尺度,重定改寫不需要分辨新舊步驟。
- **flow pack 攜帶校準對**:匯出時附上校準對兩個範本(依既有範本打包規則)與基準距離。匯入時:
  - 目標 profile 無校準資料 → 採用 pack 的(補進缺的範本、寫入基準距離;倍率留空=未校準)。
  - 目標已有且為**同一對**校準圖(以範本名判定,同名沿用現行「已存在不覆蓋」規則)→ 流程座標 ×(目標基準距離 ÷ pack 基準距離)換算後落地。
  - 目標已有但**不同對** → 流程照 pack 尺度落地、在流程上記「來源基準」標記(pack 校準對名與基準距離)並警告;帶此標記的流程存檔前必須先完成換算(對 pack 的校準對做一次量測),或由使用者明確確認以匯入的基準存檔(確認後移除標記)。
- **UI 入口為主視窗常駐按鈕區**:指定校準對、執行校準兩個動作,按鈕上顯示當前倍率或「未校準」。指定校準對的流程即是「選兩個範本→立刻校一次」;失敗訊息需指明哪一張沒找到。
- 匯入舊 autoClick 格式與既有 pack(無校準資料)照舊匯入,不產生校準資料。

## Testing Decisions

- 好測試只驗外部行為:給定流程與倍率,斷言最終送進假 `win.click`/`win.drag` 的落點;給定檔案狀態,斷言改寫後的檔案內容。不驗模組內部函式呼叫順序。
- **執行期套用與校準量測**走既有 runner harness(`app/tests/harness.py`)的假引擎 `query` + 假輸入 + 虛擬時鐘——全 repo 唯一假件點,不新增假件形狀。量測測試用 `vision.plan` 安排兩張校準圖的位置,斷言算出的倍率;套用測試安排倍率後斷言落點等於「中心 + 偏移×倍率」。倍率 1 的恆等回歸(現有 runner 測試全數不變)是最重要的一條線。
- **檔案邏輯**(校準資料存取、指紋比對、重定基準改寫、pack 匯出攜帶與匯入三分支換算)照 `test_profile_store.py`、`test_flowpack.py` 的手法:暫存目錄真檔案,不 mock。先寫入含各類步驟的流程檔,重定基準後斷言每個座標欄位的值。
- **UI 薄殼**:該擋/該警告/該換算的判斷全部下沉為校準模組的純函式直接測;UI 只留最小驗證,新色票/樣式由 `test_ui_palette.py` 的掃描測試自動涵蓋;涉及 `render_steps` 的測試照慣例先 monkeypatch `App._autosave`。
- 先行案例:`test_runner_steps.py`(落點斷言)、`test_coord_space.py`(座標空間遷移改寫)、`test_flowpack.py`(匯入分支)、`test_profile_store.py`(profile 檔案結構)。

## Out of Scope

- 搜尋範圍(scanRegion)的跨機處理——維持現狀由使用者重框,位置本來就無法從倍率推得。
- 引擎 `QueryResult` 回傳匹配尺度(升為正式欄位)——本設計不使用,留待未來需要再議。
- x/y 各自倍率(非等比縮放、拉寬視窗、黑邊裁切)。
- 自動校準、定期翻新、執行中即時翻新——翻新只有手動按鈕一途。
- 整包 profile 匯出/匯入的 UI(仍靠檔案總管複製)。
- 並行執行相關的校準語意(並行執行本輪未移植)。

## Further Notes

- 詞彙已入 `app/CONTEXT.md`「校準與畫面倍率」一節:校準對、基準距離、校準、畫面倍率、機器指紋、未校準、重定基準、匯入換算。規格與程式碼註解沿用這套詞。
- 「流程檔座標以當前基準機器尺度儲存+存檔時重定基準」是難回頭的決策(改寫所有流程檔、定義跨機語意,且捨棄了歸一化儲存方案)——實作時應補一篇 ADR 記錄取捨。
- 重定基準的整數化改寫在多次重定後有 ≤1px 級的累積捨入,接受之(點擊目標遠大於 1px)。
- 收尾記得重新打包(`app\build.bat`),使用者用的是打包版;打包注意事項見 `app/CLAUDE.md`。
