# 01 — 校準模組與執行期倍率套用

**What to build:** profile 內存在校準資料(校準對範本名、基準距離、畫面倍率、機器指紋)時,執行流程的所有落點偏移——找圖偏移(offsetX/Y)、相對座標(mode:prev)、絕對座標(mode:abs)、拖曳兩端點——乘上畫面倍率後四捨五入為整數像素再落點。沒有校準資料或倍率為 1 時,行為與現狀完全相同。手寫一份倍率≠1 的校準資料即可在測試中驗證落點縮放。

新增單一校準模組統籌純邏輯(本票先涵蓋:校準資料格式定義與載入/儲存、倍率取得含未校準判定的資料面);UI 與 runner 只呼叫它。倍率經由 runner 既有的建構參數/上下文傳入,不讓 runner 自己讀檔。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 校準模組定義校準資料的存取:能在 profile 內寫入/讀回校準對範本名、基準距離、倍率、機器指紋;缺檔=沒有校準對
- [ ] runner 落點換算:三類偏移(含拖曳兩端點)×倍率、四捨五入為整數;搜尋範圍與原點等執行期螢幕座標不換算
- [ ] 無校準資料、或倍率=1 時為恆等換算:既有 runner 測試全數不改仍綠(最重要的回歸線)
- [ ] harness 測試:安排倍率後斷言假 win.click/win.drag 收到的落點=中心+偏移×倍率(找圖偏移、prev、abs、drag 各至少一條)
- [ ] 檔案測試(暫存目錄真檔案,照 profile 檔案邏輯測試慣例):校準資料 roundtrip
