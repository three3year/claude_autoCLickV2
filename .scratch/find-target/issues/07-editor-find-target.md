# 07 — 編輯器:找圖目標設定與比對測試

**What to build:** 找圖步驟與確認圖共用一個找圖目標子表單:範本、限定範圍(框選原點矩形並預先標示預設原點/3×3 勾選)、
挑選規則(種類、N、點選指定點與基準)、比色勾選。未校準時擋下像素類拾取並要求先校準。
「立即比對測試」照找圖目標完整執行(經找圖目標模組),畫出限定矩形、所有匹配與各自分數(含比色)、
會被挑中的那個。步驟清單對有設比色、挑選規則或限定範圍的找圖步驟加簡短標記。

UI 不寫自動測試,由使用者實跑驗收;非 UI 的換算邏輯若有新增仍要測。

**Blocked by:** 04、05

**Status:** ready-for-human

- [x] 原點矩形與指定點以基準尺度存檔(除以畫面倍率),與相對座標拾取一致
- [x] 未校準時拾取原點矩形與指定點被擋下

## Comments

- 找圖步驟對話框多一列「找圖設定」(摘要＋「設定…」); 確認圖那列也有「設定…」與摘要。
  兩者開同一個子對話框 `edit_target_opts`: 限定範圍 (不限定/原點矩形＋框選/九宮格 3×3)、
  挑選規則 (分數最高/由上到下第 N/由左到右第 N/最接近指定點＋點選與基準)、比色。
  框選與點選畫面預先標 ◎ 預設原點 (推算不出時先請使用者點原點), 未校準時擋下
  (`_cal_state`), 拾取值反除畫面倍率 (`findtarget.rect_from_screen` / `offset_from_screen`, 有測試)。
- 確認圖的預設原點＝點擊後的原點 (本步驟更新原點時: 即時找本步驟的找圖目標＋偏移)。
- 「立即比對測試」與子對話框的「以這組設定比對測試」都走 `findtarget.find`:
  藍＝限定範圍、綠＝匹配 (分數/比色)、紅＝比色不符、黃粗框＝挑中 (執行時會點的)、◎＝原點。
- 步驟清單: 有特別設定的找圖目標在範本名後加〔限定、由上到下第3、比色〕這類標記。
- 程式化冒煙 (event_generate) 沒走完: 驅動腳本在格子尚未映射前就送點擊,
  觸發了對話框自己的「九宮格至少要勾一格」驗證 (使用者當時在電腦前看到);
  已停止 GUI 冒煙。UI 交給使用者實跑驗收 (最後一項)。
