# 找圖目標:比色、挑選規則、限定範圍(find-target)

Status: ready-for-agent

詞彙見 `app/CONTEXT.md`(找圖目標、匹配、挑選規則、比色、限定範圍)與根目錄 `CONTEXT.md`
(查詢、匹配、比色);決策紀錄見 ADR 0007。

## Problem Statement

使用者的流程現在主要由 Claude 看`示範影片`生成(`影片轉流程`),再由使用者在編輯器修、
實跑。實跑 `日常_繁中` 時出現三種點錯,根因都在「找圖」本身,不是流程寫錯:

1. **只差顏色的圖分不開**。會客室線索板的「快速置入」在線索已滿時變灰、不該按,程式仍
   判定找到並按下去;進駐總覽的「貿易站1」列在沒有貿易站的畫面上匹配到「製造站1」列,
   換班靜靜點到別列。引擎刻意只看形狀(梯度)不看顏色,橘與灰、藍與黃在它眼裡一樣。
2. **同款多張時點到哪一張是碰運氣**。無人機加速要點第三排的製造站卡,畫面上四張一模一樣,
   引擎只回報分數最高的一張,誰贏取決於細微像素差,程式也沒有辦法表達「我要第三張」。
3. **沒辦法說「只在這一塊找」**。目標列不在畫面上時,程式會在畫面別處找到相似的東西去點,
   而不是承認沒找到。

此外,實跑後回報「點錯了」時,執行紀錄不記找圖結果,事後查不出當時找到了什麼、為什麼選那個。

這些都需要能由 Claude 在影片轉流程時直接寫進流程,也要能讓使用者在編輯器裡看到、修改。

## Solution

把「找一張圖」做成一個通用單位——**找圖目標**:範本+限定範圍+挑選規則+比色。
找圖步驟(含當作分支條件時)、確認圖各帶一個找圖目標;「點到下一步的圖出現」沿用下一步的。

- **比色**:開了之後,找到的每一處再以顏色確認一次,顏色不符就不算匹配。灰色的「快速置入」
  就是「沒找到」,「點到目標圖消失」也因按鈕變灰而成立。
- **挑選規則**:畫面上有多個匹配時取哪一個——分數最高(預設,舊行為)、由上到下第 N 個、
  由左到右第 N 個、最接近指定點。數不到 N 個就當作還沒找到,絕不退而點別個。
- **限定範圍**:只在搜尋範圍的一部分找——以原點為基準的矩形(跟著前一個定位找圖走),
  或搜尋範圍九宮格勾選的格子。
- 引擎改成一次查詢回報**所有匹配**,並可對單次查詢要求比色。
- 執行紀錄檔每個找圖目標結束時記一筆:限定範圍、每個匹配的位置與分數、挑中哪個、點在哪。
- 影片轉流程的計畫能寫這三個屬性,自我驗證照執行時同一套邏輯判斷;skill 寫明何時用。
- 編輯器能設定這三個屬性,「立即比對測試」畫出限定範圍、所有匹配與會被挑中的那個。

## User Stories

### 比色

1. As a 流程使用者, I want 停用(灰色)的按鈕不被當成可按的按鈕, so that 流程不會在不該按的時候按下去。
2. As a 流程使用者, I want 同列名但顏色不同的設施列不互相匹配, so that 換班不會點到別種設施的列。
3. As a 流程使用者, I want 比色只在我指定的找圖目標上生效, so that 夜間模式、變暗、半透明背景這些原本容忍的變化不會讓其他步驟漏抓。
4. As a 流程使用者, I want 同一張範本在點擊時開比色、在等待消失時不開, so that 我能依用途決定「變灰算不算還在」。
5. As a 流程使用者, I want 開了比色的點擊步驟在按鈕變灰後就判定「目標圖消失」, so that 點擊後確認不會一直補點變灰的按鈕。
6. As a 流程使用者, I want 未校準時比色照常運作, so that 我換視窗大小後不必先校準才不會全部找不到。
7. As a profile 維護者, I want 比色門檻是 profile config 裡的一個值, so that 它跟匹配門檻一樣以基準測試集調整,不會散落在各步驟。
8. As a 流程使用者, I want 比色門檻改了之後不必重新登錄範本, so that 調參是即時的。

### 多個匹配與挑選規則

9. As a 流程使用者, I want 畫面上四張同款卡片時能指定「由上到下第 3 張」, so that 每次都點到同一張。
10. As a 流程使用者, I want 能指定「由左到右第 N 個」, so that 橫排的同款格子也能指定。
11. As a 流程使用者, I want 同一列並排的匹配在「由上到下」時再依由左到右排序, so that 規則在格狀排列時有確定的順序。
12. As a 流程使用者, I want 能指定「最接近某個點」並選擇這個點以原點或搜尋範圍為基準, so that 我能說「離製造站標題下方最近的那個」或「靠畫面右下的那個」。
13. As a 流程使用者, I want 匹配數不到 N 個時繼續等到逾時、逾時走「找不到時」, so that 畫面還在載入時不會先點錯。
14. As a 流程使用者, I want 沒設挑選規則的舊步驟行為不變(分數最高), so that 既有流程不受影響。
15. As a 流程使用者, I want 點擊後確認「目標圖消失」只看被點的那個位置, so that 點了一張卡片後其他同款卡片仍在也不會一直補點。
16. As a 流程使用者, I want 等待消失只看先前挑中的那個位置, so that 畫面別處的同款圖不會讓等待永遠不結束。
17. As a 流程使用者, I want 比色不符的不算進「第 N 個」的計數, so that 規則數的是真正符合的東西。
18. As a 流程使用者, I want 引擎能把同一尺度上的多個同款都找出來, so that 第二、第三張不會因為「每個尺度只取一個峰」而被漏掉。

### 限定範圍

19. As a 流程使用者, I want 指定「只在原點附近這塊矩形裡找」, so that 先定位「製造站」標題後只在它底下找「1 列」,目標不在時就是沒找到而不是點到別列。
20. As a 流程使用者, I want 原點矩形隨畫面倍率換算, so that 換到不同大小的視窗時範圍一起縮放。
21. As a 流程使用者, I want 沒有原點時以原點為基準的限定範圍無法執行並清楚報錯, so that 行為與相對座標一致。
22. As a 流程使用者, I want 勾選搜尋範圍九宮格的一格或多格(取包住它們的最小矩形), so that 「右下角的按鈕」這種固定位置的東西不必另外定位。
23. As a 流程使用者, I want 限定範圍超出搜尋範圍的部分被裁掉, so that 不會截到搜尋範圍外的畫面。
24. As a 流程使用者, I want 重定基準與匯入換算時原點矩形與指定點的像素值一起換算, so that 換基準機器後限定範圍不會歪。

### 找圖目標的套用位置

25. As a 流程使用者, I want 確認圖也能設限定範圍、挑選規則、比色, so that 「確認圖出現」不會被畫面別處的同款圖提前滿足。
26. As a 流程使用者, I want 「點到下一步的圖出現」完全照下一步的找圖目標判斷(原點用點擊後的), so that 它的意思就是「下一步找得到」。
27. As a 流程使用者, I want 分支條件照該找圖步驟的找圖目標判斷, so that 分岔不會被別處的相似圖誤導。

### 執行紀錄

28. As a 流程使用者, I want 每個找圖目標結束(找到或逾時)時在 `autoclick.log` 記一筆, so that 實跑後回報問題時 Claude 能查到當時找到什麼。
29. As a Claude(協助除錯), I want 紀錄包含步驟位置、範本、限定範圍、每個匹配的位置與分數(含比色分數)、挑選規則挑中哪個、點擊落點, so that 能分辨「點錯列」與「沒找到」。
30. As a Claude(協助除錯), I want 逾時時記最後一次查詢的最高分與未過的原因(未過匹配門檻/驗證門檻/比色門檻、數不到 N 個、沒有原點), so that 知道該調範本還是調規則。
31. As a 流程使用者, I want 紀錄不逐次輪詢地寫, so that 一輪跑下來的紀錄檔不會爆量。

### 影片轉流程

32. As a Claude(影片轉流程), I want 計畫的找圖步驟與確認圖能寫比色、挑選規則、限定範圍, so that 生成的流程直接用上新功能。
33. As a Claude(影片轉流程), I want 計畫裡的限定範圍矩形與指定點一律寫影片像素的畫面位置、由組裝換算成相對原點或搜尋範圍, so that 寫法與 `at` 一致、不用自己算相對值。
34. As a Claude(影片轉流程), I want 自我驗證用與執行時同一套找圖目標邏輯(裁範圍→查詢→比色→挑選), so that 驗證通過就代表執行時會挑到同一個。
35. As a Claude(影片轉流程), I want 驗證檢查「挑中的那個」在預期位置、absent 幀上挑不到任何東西, so that 規則或範圍設錯時會被標成待重拍。
36. As a Claude(影片轉流程), I want 組裝拒絕不完整的設定(以原點為基準卻沒有原點、規則 N < 1、九宮格格號無效), so that 錯誤在組裝時就被擋下。
37. As a Claude(影片轉流程), I want skill 寫明何時開比色、何時用哪種挑選規則、何時設限定範圍, so that 判斷有一致的依據(工具本身不給提示,全由我判斷)。

### 編輯器

38. As a 流程使用者, I want 找圖步驟與確認圖用同一組找圖目標設定(範本、限定範圍、挑選規則、比色), so that 兩處操作一致。
39. As a 流程使用者, I want 用框選拾取原點矩形、畫面上預先標出預設原點, so that 我知道矩形是相對哪裡。
40. As a 流程使用者, I want 用 3×3 勾選格設九宮格限定範圍, so that 不必量座標。
41. As a 流程使用者, I want 用點選拾取指定點, so that 「最接近指定點」好設定。
42. As a 流程使用者, I want 未校準時拾取原點矩形與指定點被擋下並要求先校準, so that 與拾取相對座標的規則一致。
43. As a 流程使用者, I want 「立即比對測試」畫出限定範圍、所有匹配(各自分數與比色分數)、挑選規則會挑中的那個, so that 修 Claude 生成的流程時當場看到執行時會點哪個。
44. As a 流程使用者, I want 步驟清單上看得出這個找圖步驟設了比色、規則或限定範圍, so that 一眼知道哪些步驟有特別設定。

### 存檔

45. As a 流程使用者, I want 舊的流程存檔與步驟草稿開啟時自動轉成新格式、行為不變, so that 升級後不必手動處理舊流程。
46. As a 流程使用者, I want 匯入舊 JSON 與舊 `.autoclickpack` 仍可用, so that 舊資料的匯入路徑不斷。
47. As a 流程使用者, I want 存檔只收被任何找圖目標(含確認圖)引用到的範本, so that 搬檔仍然自包自足。

## Implementation Decisions

### 引擎(主體偵測)

- `Engine.query` 的結果改為**所有匹配**:每個匹配帶邊界框、驗證分數,開比色時另帶比色分數;
  沒有匹配時仍提供最高分與未過哪一關的資訊供紀錄使用。`debug` 保留,格式不承諾穩定。
  引擎不排序偏好、不知道挑選規則。
- 查詢多一個可選參數「比色」(預設關)。比色只影響匹配是否成立,不影響粗篩與驗證。
- 粗篩不再每個尺度只取一個峰:每個尺度取所有過 `match_threshold` 的局部峰(含同尺度 NMS),
  跨尺度 NMS 後保留的候選上限調高(足以涵蓋一排十來個同款);每個候選照舊精修、
  批次嵌入驗證,過 `verify_threshold` 的全部成為匹配。
- 比色:對每個驗證通過的候選,把彩色模板縮放到候選精修後的框尺寸,在框附近小範圍
  (數 px)局部搜尋彩色 `TM_CCOEFF_NORMED` 取最高值;不套登錄遮罩;未達 profile 的
  `color_threshold`(新 config 鍵,預設 0.95)就不算匹配。比色只在查詢時讀,
  不屬於登錄失效鍵。不使用校準倍率(範本保持拍下當時的尺度,ADR 0007)。
- 引擎仍遊戲無關;比色是通用機制,不含任何模板特例。

### 偵測器接縫(app → 引擎)

- runner 注入的偵測器介面變成:查詢(範本名、搜尋區域、是否比色)→ 所有匹配+最高分資訊。
  `EngineHub` 照轉呼叫;測試 harness 的假偵測器改成可安排「每次查詢回傳哪些匹配」。
  仍是唯一一條辨識路徑(ADR 0002)。

### 找圖目標模組(新的共用深模組,app 端)

- 一個模組負責「解析並執行一個找圖目標」:輸入找圖目標、偵測器、整張搜尋範圍截圖與其
  螢幕原點、目前原點(可能沒有)、畫面倍率;輸出找圖結果——實際的限定矩形(螢幕座標)、
  所有匹配(螢幕座標)、挑中的那個(或沒有)、沒挑到的原因。
- 內部步驟:算限定矩形(原點矩形 × 倍率、或九宮格格子聯集,再裁到搜尋範圍)→ 裁圖 →
  查詢(帶比色)→ 座標換回螢幕 → 依挑選規則挑。
- 挑選規則語意:分數最高;由上到下第 N(依中心 y 排序,y 差小於半個框高視為同列,
  同列再依 x);由左到右第 N(對稱);最接近指定點(指定點以原點或搜尋範圍左上為基準,
  × 倍率)。N 從 1 起算;匹配不足 N ＝沒挑到。
- 另提供「這個位置是否仍有匹配」的判定(容差約半個框),供點擊後確認「目標圖消失」與
  等待消失使用:記住挑中的位置,之後該位置沒有匹配即為消失。
- 使用者:runner 的所有找圖呼叫點(找圖三態、點擊後確認三種、分支條件)、編輯器的
  「立即比對測試」、影片轉流程的自我驗證。三處行為一致由此保證。
- 以原點為基準的設定(限定範圍或指定點)在沒有原點時:runner 視為該步驟無法執行
  (與相對座標同處理);自我驗證與組裝直接報錯。

### 執行器

- 每個找圖呼叫點改走找圖目標模組。點擊落點＝挑中匹配的框中心+偏移 × 倍率(不變)。
- 「點到下一步的圖出現」用下一步的找圖目標與點擊後的原點;「確認圖出現」用確認圖的找圖目標。
- 執行紀錄:每個找圖目標的判定結束時(找到、逾時、無法執行)寫一筆到 `autoclick.log`,
  內容見 User Stories 28–30;不逐次輪詢寫。UI 執行紀錄維持現有訊息,可附上匹配數。

### 存檔格式(flowFormat 3)

- 找圖步驟的找圖目標收成巢狀物件:範本名、限定範圍(無/原點矩形/九宮格格子清單)、
  挑選規則(種類、N 或指定點及其基準)、比色(布林)。確認圖同樣是一個巢狀找圖目標。
  缺欄位＝不限定/分數最高/不比色。
- 讀檔時 v2 → v3 單向遷移:原 `template` 與 `confirmTemplate` 移入對應的找圖目標;
  步驟草稿同樣遷移;舊 JSON 與 `.autoclickpack` 的匯入照舊鏈接到這個遷移。
- 範本引用收集(決定存檔收哪些圖)改為走訪所有找圖目標。
- 重定基準與匯入換算的座標換算涵蓋原點矩形與指定點的像素值(九宮格是比例,不換算)。
- 寫檔蓋章 3。

### 影片轉流程

- 計畫格式:找圖步驟與確認圖可寫 `colorCheck`、挑選規則、限定範圍;矩形與指定點寫影片
  像素的畫面位置並註明基準(原點或搜尋範圍),組裝依該步的原點推算換成相對值並換回基準尺度。
- 自我驗證改用找圖目標模組:取材幀與 present 幀上挑中的匹配要在預期位置;absent 幀上挑不到;
  引用它的步驟幀上照步驟的找圖目標挑。
- 工具不自動判斷該不該開比色或設規則,也不額外給提示(全由 Claude 判斷);
  skill 與 `plan-format.md` 加上判斷規則與欄位說明。

### 編輯器

- 找圖目標子表單(範本、限定範圍、挑選規則、比色)給找圖步驟與確認圖共用。
  原點矩形用框選拾取並預先標示預設原點;九宮格用 3×3 勾選;指定點用點選拾取。
  未校準時擋下像素類拾取。新的步驟欄位名不得與舊版被丟棄的 `region` 衝突。
- 立即比對測試照找圖目標完整執行,畫出限定矩形、所有匹配、挑中者與分數。
- 步驟清單對有設定的找圖目標加簡短標記。

## Testing Decisions

- 好的測試只驗外部可見行為:給定畫面/假偵測結果與設定,斷言挑中哪個、點在哪、是否算消失、
  紀錄寫了什麼;不斷言內部排序函式或中間影像。
- **引擎 `Engine.query`**:用真實影格做固定素材——問題 1 的「快速置入」(demo2 f960 可按、
  f1064/f1085 灰色)、問題 2 的製造站卡(demo3 f300、demo2 f662/f683,四張同款要全部找到)、
  問題 3 的列名(demo3 f490/f552/f600)。斷言:同款多張全部回報;開比色時灰色/別種列不是匹配、
  正確目標是;不開比色時行為與現在一致。既有基準測試集維持全過,另把這幾個案例補進基準集。
  先例:`tests/test_multiscale.py`、`tests/test_bench.py` 與 `profiles/arknights/benchmark/` 的案例格式。
- **找圖目標模組(單獨測)**:用假偵測器直接驅動——各挑選規則的排序與同列判定、N 不足、
  指定點兩種基準、原點矩形 × 倍率、九宮格多格聯集、裁到搜尋範圍、沒有原點、
  「位置是否仍有匹配」的容差、比色參數有傳到偵測器。
- **執行器**:經 `app/tests/harness.py` 的假偵測器(改成可安排多個匹配)——點擊後確認「消失」
  在同款仍在時成立、等待消失的位置語意、「下一步的圖出現」用下一步的找圖目標與點擊後原點、
  確認圖的找圖目標、分支條件、無原點時的處置、`autoclick.log` 的紀錄內容與「不逐次輪詢」。
  先例:`test_runner_steps.py`、`test_confirm_next.py`、`test_runner_origin.py`、`test_runner_scale.py`。
- **存檔**:v2 → v3 遷移(含草稿、舊 JSON、`.autoclickpack`)、範本引用收集涵蓋確認圖的找圖目標、
  重定基準換算新像素欄位。先例:`test_flowfile.py`、`test_calibration.py`、`test_flow_open_save.py`。
- **影片轉流程**:合成影片測試(組裝與自我驗證吃新欄位、同款多張時規則挑對、absent 幀、
  組裝拒絕不完整設定)。先例:`tools/tests/test_vtf_*.py` 與 `vtf_synth`。
- 編輯器 UI 不寫自動測試,由使用者實跑驗收。

## Out of Scope

- 用新功能重做 `日常_繁中` / `日常_簡中` 的問題步驟(下一輪以影片轉流程另做)。
- 影片轉流程工具自動判斷或提示該開比色/設規則(全由 Claude 判斷)。
- 步驟或範本層級的門檻;比色套遮罩;以校準倍率鎖定比色尺度。
- 查詢速度優化(多實例會讓驗證變慢;實測太慢再開票)。
- 並行執行、編輯器 UI 自動測試。
