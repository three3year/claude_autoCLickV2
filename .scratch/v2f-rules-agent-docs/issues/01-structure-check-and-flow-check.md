# 01 — 結構檢查抽出＋檢查指令

**What to build:** agent 對任何一個流程資料夾跑檢查指令（不載引擎、不開視窗），就知道這份流程 app 讀不讀得進來、執行時會不會一開始就出錯。

- 錯誤：列出步驟與原因，以非零結束。
- 缺圖：引用了但缺圖的範本列成「要在 app 截的範本」，不算錯。
- `--normalize`：沒有錯誤時，經 app 的讀寫把 `flow.yaml` 重寫一次，讓手改後過期的行尾步驟編號與排版回到標準。

做法：先把 App 執行前的區段結構檢查抽成不依賴視窗的模組函式，App 與檢查指令共用。見 spec「結構檢查與檢查指令」、子步驟順序第 1 步。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 區段結構檢查（成對、不交錯、分岔每個分支開頭是找圖點擊、「或」直接在分岔內）是一個模組函式；App 執行前改呼叫它，訊息與行為不變，現有測試全綠
- [ ] 檢查指令依序跑：讀檔（鍵、型別、`format`）、結構檢查、每個相對座標點擊／拖曳前有原點來源、勾 `busy_check` 但沒設 `busy`、缺圖
- [ ] 每類錯誤各有一個測試（tmp_path 裡手寫的流程資料夾）：結束碼非零，訊息含步驟與原因
- [ ] 缺圖：列出清單，結束碼為零
- [ ] `--normalize`：手改過、編號過期的檔被寫回標準排版；有錯誤時不寫；不加旗標時一個檔都不寫
- [ ] 四份在用流程（`%USERPROFILE%\AutoClick\`）跑檢查指令都沒有錯誤（只讀，不加 `--normalize`）
