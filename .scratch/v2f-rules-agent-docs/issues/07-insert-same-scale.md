# 07 — 補充插入 `insert`（同倍率）

**What to build:** 使用者只錄一小段影片，agent 寫一份補充計畫，跑 `insert <計畫> <流程資料夾>`，就把量好的步驟插進既有流程的指定位置。

- **插入點**：用 `after: N`／`into: N` 指定，加上 `expect`（第 N 步的開頭鍵＋範本）核對。
- **原點**：
  - 插入段第一個座標點擊／拖曳之前，段內必須有找圖。
  - 插入後，插入點後面的舊步驟在重新找圖之前用到的原點來源不得改變。
- **範本**：
  - 步驟可引用既有範本（不重裁，照跑拾取檢查）。
  - 新範本撞名報錯。
  - 新範本跟既有範本幾乎一樣時，建議改用既有的。
- **沿用**：校準對與忙碌指示沿用既有流程。
- **寫回**：
  - 經 app 讀檔 → 記憶體插入 → 經 app 寫檔。
  - 任何報錯都在寫檔前；失敗時既有資料夾一個位元都不變。
  - 不備份。
- **報告**：插入處那份與總覽更新。

本票只處理影片與流程同尺度（倍率 1）。見 spec「補充插入」、13 規則 6–10。

## Comments

- 2026-10-11（agent）：`tools/video_to_flow/insert.py`，命令列 `insert <計畫> <流程資料夾>`。量測跟 `assemble` 走同一個 `measure.measure`（原點推算、固定矩形、拾取檢查、忙碌兩向）。原點來源比對用 app 新增的 `runner.origin_step`（`origin_source` 改成由它推）。`expect` 的格式是第 N 步的開頭鍵＋值（找圖比範本名，`branch` 只比鍵）；N 指到區段結尾或「或」報錯；`into` 只收重複區段（分岔要插在分支裡就 `after` 分支條件）。幾乎一樣的範本：大小差 25% 內的既有範本在新範本取材處附近查得到就建議改用。寫回：新範本用 `xb` 獨佔建立 → flow.yaml（`dump_flow`，順便標準排版）→ 交付報告，中途失敗把寫過的還原；**不刪 templates/ 裡沒被引用的圖**（`write_flow` 會刪，補充不經它）。報告：插入處那份與總覽的「## 補充」節加一行（沒有日期），待重拍、待確認加在對應節；沒有 `交付報告/` 的舊流程會建一份最小的。測試 `tools/tests/test_vtf_insert.py`，每種報錯都比對整個資料夾逐位元不變。
