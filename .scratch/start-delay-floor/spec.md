# 開始延遲改為時間下限,範本預載在倒數中進行(start-delay-floor)

Status: ready-for-agent

詞彙見 `app/CONTEXT.md` 的「啟動與就緒」(範本預載、引擎就緒)與「尺度與畫面倍率」(開頭校準);本規格新增術語「開始延遲」。決策紀錄見 ADR 0004(範本預載的時機不變,只改它和開始延遲的關係)。

## Problem Statement

使用者按下「執行」後,要等兩段時間才會開始第 1 步:先等範本預載跑完,再整整等滿「開始延遲」設定的秒數(3、5 或 10 秒)。

開始延遲的用途是讓使用者有時間切到遊戲畫面。但預載也要花時間,兩段時間是加起來的。例如設定 3 秒、預載花 2 秒,實際要等 5 秒;那 2 秒本來就足夠使用者切畫面,卻被白白疊上去。

## Solution

開始延遲改成**時間下限**:從按下「執行」那一刻算起,到開頭校準之前,至少要經過設定的秒數。範本預載在倒數期間同時進行。

- 預載提早完成(例如設 3 秒、預載花 2 秒):再等 1 秒,到期就開始。
- 預載超過設定(例如設 3 秒、預載花 4 秒):預載一完成就開始,不再額外等。
- 開頭校準仍排在倒數到期**而且**預載完成之後,所以使用者切畫面的時間有保障。

執行紀錄依序寫:

1. `3 秒後開始執行 (按 F12 可隨時停止)`(延遲選「無」時不寫這行)
2. `準備範本中…(N 張)`
3. `等待準備範本完成`(只有到期時預載還沒完成才寫,寫一次;延遲選「無」時一律會寫)
4. `範本就緒`

主視窗與迷你狀態視窗的狀態字跟紀錄一致:到期前顯示「倒數啟動中…」,到期後預載還沒完成就顯示「等待準備範本完成…」。延遲選「無」時,一開始就是「等待準備範本完成…」。

## User Stories

1. 身為使用者,我想要開始延遲從按下「執行」那一刻起算,這樣預載花掉的時間不會再疊加到等待上。
2. 身為使用者,我想要預載提早完成時只再等到設定的秒數,這樣第 1 步開始的時間跟我設定的一樣。
3. 身為使用者,我想要預載超過設定秒數時一完成就直接開始,這樣不會被多等一輪延遲。
4. 身為使用者,我想要開頭校準一定在倒數到期之後才截圖,這樣我按完執行切到遊戲畫面的時間有保障,校準不會截到 AutoClick 自己或桌面。
5. 身為使用者,我想要紀錄一開頭就告訴我「N 秒後開始執行」,這樣我一按下執行就知道有多少時間切畫面。
6. 身為使用者,我想要紀錄仍然寫出「準備範本中…(N 張)」與「範本就緒」,這樣出問題時看得到範本張數和預載何時完成。
7. 身為使用者,我想要倒數到期但預載還沒完成時,紀錄寫一行「等待準備範本完成」,這樣我知道為什麼時間到了還沒開始。
8. 身為使用者,我想要「等待準備範本完成」只寫一次,這樣紀錄不會被洗版。
9. 身為使用者,我想要狀態字在倒數期間顯示「倒數啟動中…」,這樣跟紀錄的「N 秒後開始執行」對得上。
10. 身為使用者,我想要狀態字在到期後仍在預載時顯示「等待準備範本完成…」,這樣迷你視窗上一眼看得出卡在哪裡。
11. 身為使用者,我想要延遲選「無」時紀錄不寫「0 秒後開始執行」,這樣不會多一行沒有意義的訊息。
12. 身為使用者,我想要延遲選「無」時照樣寫「等待準備範本完成」、狀態字一開始就顯示它,這樣規則跟其他設定一致:到期了還在預載就是在等範本。
13. 身為使用者,我想要預載失敗(例如缺圖)時立刻停止並報錯,這樣不用空等倒數結束才知道跑不了。
14. 身為使用者,我想要倒數剩下的等待時間仍然可以按 F12 停止,這樣行為跟現在一樣。
15. 身為使用者,我想要「測試選取步驟」也套用同一套時間下限,這樣測試和正式執行等待的方式一致。
16. 身為使用者,我想要無限模式仍然只在開頭倒數一次,這樣每輪之間不會多出等待。
17. 身為同時跑多份流程的使用者,我想要排隊上台仍然在倒數到期之後,這樣並行的行為不變。
18. 身為維護者,我想要「開始延遲」寫進 app 的詞彙文件並註明它是下限,這樣之後的 agent 不會把它改回預載完再整整等滿的固定等待。

## Implementation Decisions

- **計時起點**:執行器的啟動介面多一個可選參數「按下執行的時間」(monotonic 時鐘)。主視窗在按下「執行」的處理一開始就記下時間並傳入;沒傳時以執行器啟動的當下為準。到期時間＝按下執行的時間＋開始延遲秒數。主視窗的檢查(含登錄剛存的範本)因此也算在下限之內。
- **開跑前順序**(執行緒內):
  1. 延遲大於 0 時,記「N 秒後開始執行 (按 F12 可隨時停止)」(沿用現行文字,只是提前到預載之前)。
  2. 範本預載:記「準備範本中…(N 張)」後開始載入。開始載入前檢查一次是否已到期,之後每載完一張範本再檢查一次;第一次發現已到期而預載還沒完成時,記「等待準備範本完成」並把開跑前階段切成「等待範本」。
  3. 預載完成,記「範本就緒」。
  4. 還沒到期就用可中斷的等待等到到期(F12 可停,同現行)。
  5. 上台(並行時)→ 開頭校準 → 第 1 輪。這段與現行相同。
- **引擎的預載介面**:預載多一個可選的回呼,每載完一張範本呼叫一次。執行器用它在預載進行中檢查到期。「到期即寫」的粒度因此是一張範本的載入時間,通常是毫秒級。真引擎(逐張載入的那個迴圈)與測試用的假引擎都要支援。
- **沒有範本要預載時**:沒有「準備範本中…」也沒有「等待準備範本完成」,只等到期。實務上有校準對就一定有範本,這是防禦性的分支。
- **預載失敗**:維持現行,預載丟錯就立刻停止並報錯,不等倒數。
- **開跑前階段**:執行器的狀態回報多一個欄位,值為「倒數中」「等待範本」或無(已開跑或開跑前的其他時刻)。它取代現有的「預載中」旗標;那個旗標只有狀態字在用。
- **狀態字對照**:主視窗在輪次仍為 0 時,把「等待範本」顯示成「等待準備範本完成…」,其餘(倒數中、上台、校準的那一瞬間)顯示「倒數啟動中…」。迷你狀態視窗沿用同一個字。「準備範本中…」不再出現在狀態字,只留在紀錄。
- **測試選取步驟**走同一條執行路徑,自動適用,不另外處理。
- **不變的**:F12 在預載途中按下的反應(預載本身不可中斷,維持現狀)、無限模式只在開頭倒數一次、並行時的排隊上台在倒數之後、開頭校準失敗的處理。
- **詞彙文件**:`app/CONTEXT.md` 的「啟動與就緒」在「範本預載」旁加入「開始延遲」:從按下執行到開頭校準的時間下限,範本預載在這段時間內進行;Avoid 寫「固定等待(它是下限,不是預載完再額外等的時間)」。
- **ADR 0004** 第 3 點寫的「執行視窗顯示『準備範本中…』」被本規格取代,只動這句的顯示文字,預載時機的決策不變。在 ADR 0004 補一行後記指向本規格即可,不另開 ADR。

## Testing Decisions

- **只有一個接縫**:現有的執行器 harness(虛擬時鐘＋假引擎)。測試只看外部行為:執行紀錄的內容與順序、開頭校準那次截圖發生的虛擬時間、狀態回報的開跑前階段。不測內部怎麼算到期。
- **假引擎的預載加一個「每張成本」設定**:每載一張範本把虛擬時鐘往前推指定秒數,並呼叫預載回呼。這樣就能模擬「預載花 2 秒」或「預載花 4 秒」。預設成本為 0,既有測試不受影響。
- **要涵蓋的情境**:
  - 延遲 3 秒、預載共 2 秒:校準在按下執行後 3 秒;紀錄沒有「等待準備範本完成」;順序為 N 秒後 → 準備範本中 → 範本就緒。
  - 延遲 3 秒、預載共 4 秒:校準在預載結束當下(按下執行後 4 秒);「等待準備範本完成」只出現一次,夾在「準備範本中」與「範本就緒」之間。
  - 延遲「無」:沒有「0 秒後開始執行」;有「等待準備範本完成」。
  - 按下執行的時間早於執行器啟動(例如早 1 秒):到期時間從按下執行起算。
  - 預載失敗:立刻結束為錯誤,不等倒數,也沒有校準截圖。
  - 開跑前階段:預載途中、到期前回報「倒數中」;到期後預載還沒完成時回報「等待範本」。可在預載回呼裡讀狀態回報取得。
  - 倒數剩餘等待中停止:不做校準、不送任何輸入(既有行為的回歸)。
- **前例**:`test_flow_preload.py`(預載名單與失敗不開跑)、`test_runner_calibrate.py`(開頭校準的截圖與失敗)、`test_runner_runlog.py`(紀錄內容)。新測試放成一個獨立的執行器測試檔。
- 主視窗把階段對照成狀態字只是幾行對照,不另開 GUI 測試。

## Out of Scope

- 讓 F12 在預載途中立即中斷(預載本身維持不可中斷)。
- 狀態字顯示倒數剩餘秒數。
- 開始延遲的選項(無、3、5、10 秒)與預設值。
- 無限模式每一輪之間的等待。
- 並行執行時排隊上台的時機。
- 加快範本預載本身。

## Further Notes

- 起因:2026-10-05 實跑時使用者提出,開始延遲應該是「從按下執行到開始的最少時間」,不是預載完再整整等滿。
- 預載通常在一秒內完成(ADR 0004 的估計,熱快取),所以設 3 秒以上時,多數情況是「預載提早完成、再等到到期」;「等待準備範本完成」主要出現在延遲選「無」或冷快取時。
