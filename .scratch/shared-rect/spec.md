# Spec：共用矩形

Status: ready-for-agent

`影片轉流程`的固定矩形規則補一種：一組同類找圖目標共用一個固定矩形。來源是 v2f-rules-agent-docs 票 12 的發現（商店格子兩排、每天換位置，捲動軸只能宣告一個方向）。詞彙以 `app/CONTEXT.md` 為準，`共用矩形`已在 2026-10-11 寫入；決策都在 2026-10-11 的 grilling 定案。

## 需要你決定的

### 共用矩形的範圍從哪裡來？

決定（2026-10-11）：agent 在一幀上框容器，工具再每邊外推成員圖框的一半，讓倍率縮放後靠邊那格不會被裁掉。

- (a) agent 在一幀上框出整個容器（建議）：涵蓋影片裡沒用到的格子；代價是多量一個框。
- (b) 成員位置聯集再外推：不用多量，但影片只買一種時只剩一格大小。
- (c) 兩者皆可：彈性大，規則變兩套。

### 容器框每邊外推多少？

決定（2026-10-11）：每邊加最大成員圖框寬高的 50%。

- (a) 每邊加成員圖框的 50%（建議）：靠邊那格的餘裕跟單一目標規則一樣，不用新數字。
- (b) 照支援倍率範圍推算：剛好夠，但多一套算法。
- (c) 容器寬高的 10%：簡單，但大容器外擴過多、小容器不夠。

### 哪些目標算同一組，誰判斷？

決定（2026-10-11）：agent 判斷，交付報告列出給使用者確認。

- (a) agent 判斷、報告列出（建議）：使用者錄影前不用先交代。
- (b) 使用者事先指定：最準，但每次都要多交代。
- (c) 工具自動分組：規則難寫準。

### 共用矩形要不要在 flow.yaml 留名字？

決定（2026-10-11）：只在計畫裡，組裝時展開成各步驟的 `within`；flow.yaml 格式與 app 不動。

- (a) 只在計畫裡（建議）：格式不改；代價是 flow.yaml 看不出分組，改框要逐步改。
- (b) flow.yaml 加具名區域：改一處全組生效，但要改格式規範、app 讀寫、編輯器與檢查指令。

### 共用矩形跟捲動軸是什麼關係？

決定（2026-10-11）：可並存，共用矩形宣告了捲動軸就沿那一軸拉到影片兩端。

- (a) 互斥：規則最單純。
- (b) 可並存：給會捲動的多排格子用。
- (c) 共用矩形取代捲動軸：概念統一，但要改已上線的計畫格式。

### 成員挑到的框有一部分在容器外怎麼辦？

決定（2026-10-11）：工具錯誤，擋下組裝。

- (a) 工具錯誤（建議）：容器是 agent 量的，框錯就是量錯，不該帶到交付報告。
- (b) 自動擴大包住成員：不擋，但可能還是漏了沒拍到的格子。
- (c) 列進報告待確認：等於把量錯的決定交給使用者。

### 補充時新成員怎麼沿用既有那一組的框？

決定（2026-10-11）：補充計畫寫「跟第 N 步同框」加範本核對，工具照抄那一步的 `within`。

- (a) 步號加範本核對（建議）：跟 `after`／`expect` 同一套習慣，步號錯了會被擋下。
- (b) 只寫範本名：好寫，但跟插入點的寫法不一致。
- (c) 從補充影片重框容器：同一組會變成兩個差幾 px 的框。

### 測試接縫用哪幾個？

決定（2026-10-11）：只用工具既有的兩個公開入口（新流程組裝、補充插入）配合成影片，不另開接縫。

- (a) 只用兩個公開入口（建議）：跟現有工具測試同一套，實作怎麼拆都不影響測試。
- (b) 另加算框函式的單元測試：定位錯誤較清楚，但綁住內部函式，重構要跟著改。

## Problem Statement

`影片轉流程`現在替每個找圖目標各算一個`固定矩形`：挑中的框每邊外推 50%，宣告了捲動軸的那一軸拉到影片兩端。這套規則假設目標要嘛位置固定，要嘛只沿一個方向移動。

商店（採購中心）的商品格兩個假設都不成立：商品排成兩排，每天換位置。demo2 重轉時只能宣告 `horizontal`，每個商品的框是影片那天它所在的那一整排。哪天它換到另一排，那一輪就找不到、買不到。

在用的早_繁中沒有這個問題，是因為當初加固定矩形的一次性腳本替 23 個商品寫了特例，共用一個涵蓋兩排的商品區框。新的通用規則表達不出這種「整個容器」的框，之後轉出含類似格子的流程都會重現這個問題。

## Solution

轉換計畫可以宣告有名字的`共用矩形`：agent 在影片某一幀上框出整個容器（例如整片商品區），工具把容器每邊外推成員圖框的一半（需要時再沿捲動軸拉長），組裝時把同一個框寫進每個成員步驟的 `within`。流程存檔格式與 app 都不變。

哪些目標算同一組由 agent 判斷，交付報告在那一段列出共用矩形的名字、理由與成員，讓使用者確認。

補充（把影片插進既有流程）時，新步驟可以宣告「跟既有第 N 步同框」，工具核對那一步的範本後照抄它的 `within`。這樣在早_繁中補一種新商品，新步驟會拿到跟其他商品一模一樣的框。

## User Stories

1. 身為使用者，我想要流程裡每天換位置的商品不管落在哪一格都找得到，這樣採購不會因為商品換排就漏買。
2. 身為使用者，我想要影片那天沒買過的格子也被涵蓋，這樣之後加商品不用重錄影片。
3. 身為使用者，我想要交付報告列出每個共用矩形的名字、為什麼這幾個目標算同一組、成員是哪幾步，這樣我能確認 agent 的判斷。
4. 身為使用者，我想要報告列出共用矩形有沒有宣告捲動軸，這樣我知道它會不會跟著清單捲動拉長。
5. 身為使用者，我想要共用矩形的成員不出現在「有拖曳但沒宣告捲動軸」的待確認清單，這樣待確認清單少一些我已確認過的雜訊。
6. 身為使用者，我想要產出的 flow.yaml 跟以前一樣只是各步驟上的固定矩形，這樣 app 與編輯器不用改、我照常能編輯。
7. 身為使用者，我想要在早_繁中補一種新商品時，新步驟的框跟其他商品完全一樣，這樣同一組不會出現幾個差幾 px 的框。
8. 身為使用者，我想要補充計畫指錯步驟時工具擋下、流程資料夾不變，這樣插錯的框不會進到我在用的流程。
9. 身為使用者，我想要支援倍率範圍兩端執行時靠邊那格還在框裡，這樣視窗模式與最大化都找得到。
10. 身為 agent，我想要在計畫頂層宣告有名字的共用矩形（取材幀、容器框、可選的捲動軸、一句理由），這樣容器只量一次。
11. 身為 agent，我想要找圖步驟、分岔條件、生效確認的確認圖、忙碌指示都能引用共用矩形，這樣只有一條規則要記。
12. 身為 agent，我想要容器框用影片像素寫、跟其他證據欄位一樣，這樣不用自己換算座標基準點或流程尺度。
13. 身為 agent，我想要工具自己決定外推量（最大成員圖框寬高的一半），這樣我只負責框準容器。
14. 身為 agent，我想要容器超出影片的部分被裁掉、裁過的一側不算矩形餘裕沒過，這樣貼邊的容器照常可用。
15. 身為 agent，我想要共用矩形宣告了捲動軸時那一軸拉到影片兩端，這樣會捲動的多排格子也涵蓋得到。
16. 身為 agent，我想要成員步驟同時寫了共用矩形與自己的捲動軸時報錯，這樣捲動軸只有一個出處。
17. 身為 agent，我想要引用不存在的共用矩形名字時報錯並指出名字，這樣打錯字立刻知道。
18. 身為 agent，我想要宣告了卻沒有任何成員引用的共用矩形報錯，這樣計畫裡不留沒用到的東西。
19. 身為 agent，我想要成員在它自己那一幀挑到的框只要有一部分超出容器就是工具錯誤，這樣框錯的容器不會帶到交付報告。
20. 身為 agent，我想要只有一個成員的共用矩形也可以，這樣影片只買一種商品時照樣能涵蓋整個容器。
21. 身為 agent，我想要套上共用矩形後照樣跑「加上固定矩形後要挑到同一個」與唯一檢查，這樣容器裡有同款時照樣被提醒要設挑選規則。
22. 身為 agent，我想要有設挑選規則的成員照現有規則略過唯一檢查，這樣同一格出現兩個同款不會被誤報。
23. 身為 agent，我想要計畫的共用矩形裡寫 `within`、`offset` 這類流程鍵時報錯，這樣計畫跟 flow.yaml 的分工不亂。
24. 身為 agent，我想要補充計畫的共用矩形可以寫成「跟第 N 步同框」加 `expect` 核對，這樣新成員沿用既有那一組的框。
25. 身為 agent，我想要「跟第 N 步同框」的 N 跟 `after` 一樣是 flow.yaml 行尾的 `# N`、核對失敗的訊息也一樣，這樣只要記一套。
26. 身為 agent，我想要「跟第 N 步同框」指到的步驟沒有固定矩形時報錯，這樣不會抄到空的框。
27. 身為 agent，我想要照抄來的框原樣寫入（已經是流程尺度、相對座標基準點），不再外推，這樣新舊成員逐字相同。
28. 身為 agent，我想要照抄來的框也驗證新成員在補充影片的那一幀落在框內，這樣錄影畫面對不上時會被擋下。
29. 身為 agent，我想要補充計畫裡也能用影片像素宣告新的共用矩形（工具除以影片倍率、換成相對座標基準點），這樣補充一個全新的格子區也能用。
30. 身為 agent，我想要補充後的交付報告在插入處那一份記下新成員沿用了哪一步的共用矩形，這樣下一個 agent 看得懂框從哪來。
31. 身為 agent，我想要 video-measure skill 寫明什麼時候用共用矩形、什麼時候用捲動軸、容器怎麼框，這樣判斷有準則。
32. 身為 agent，我想要 edit-flow skill 寫明手動加一個同組成員時照抄同組既有步驟的 `within`，這樣不用影片也能加商品。
33. 身為 agent，我想要計畫格式文件寫明共用矩形的鍵、`same_as` 的寫法與報錯情況，這樣寫計畫時查得到。

## Implementation Decisions

### 計畫格式

- 計畫最外層新增 `shared_rects`：名字 → 宣告。新流程組裝與補充插入都認得。
- 新流程的宣告：`frame`（容器完整可見的那一幀）、`box`（容器框，影片像素 `[x, y, w, h]`）、可選的 `scroll`（`vertical`／`horizontal`）、`why`（一句話：為什麼這幾個目標算同一組，進交付報告）。
- 補充的宣告二選一：同上的影片像素宣告；或 `same_as: N` 加 `expect`（N 與 `expect` 的寫法、核對規則、錯誤訊息都跟插入點的 `after`／`expect` 相同）。兩種都要 `why`。
- 引用：找圖步驟的 `rect: "<名字>"`；生效確認 `appear` 的確認圖寫在確認那一層；忙碌指示寫在忙碌宣告那一層。`gone` 與 `next` 本來就沿用別步的目標，不另寫。
- `rect` 跟其他證據欄位一樣在組裝前被剝掉，不進 flow.yaml。
- 報錯（全部是工具錯誤，資料夾不變）：
  - 引用不存在的名字。
  - 宣告了沒有任何成員引用。
  - 成員同時寫 `rect` 與 `scroll`。
  - 共用矩形宣告裡出現 `within`、`offset` 或不認得的鍵。
  - `same_as` 核對不符，或指到的步驟沒有固定矩形。

### 共用矩形的算法

- 外推量：取所有成員在各自那一幀挑中的框，以最大的寬、高各取一半（無條件進位），容器每邊各外推這麼多。只有一個成員就用它的框。
- 有捲動軸：那一軸拉到影片兩端（跟單一目標規則同一套）。
- 超出影片的部分裁掉；裁過的一側不算矩形餘裕沒過，沒裁卻沒過照舊是工具錯誤。
- 最後換成相對座標基準點的流程尺度矩形，寫進每個成員目標的 `within`（同一組逐字相同）。
- 成員在框內檢查：成員在它自己那一幀挑中的框，必須整個落在容器框裡（外推前的容器）；`same_as` 時改成落在照抄來的框裡（換回影片座標比）。不符＝工具錯誤，訊息指出成員、幀與兩個框。
- 成員套上共用矩形後照跑現有的「加上固定矩形後挑到的不是同一個」與唯一檢查；有挑選規則的照現有規則略過唯一。

### 補充插入

- `same_as` 照抄的框已是流程尺度、相對座標基準點，原樣寫入，不除影片倍率、不外推、不加對齊位移。
- 影片像素宣告的共用矩形：容器框與成員框先除以影片倍率，再照上面的算法；座標基準點用補充時量到的那一個。

### 待確認清單

- 「同段有拖曳、找圖沒宣告捲動軸」的判斷把共用矩形的成員視為已宣告，不列。新流程與補充都一樣。
- 拖曳影響範圍的改進不在這次（見 [Out of Scope](<#Out of Scope>)）。

### 交付報告

- 區段報告新增 `## 共用矩形`：列共用矩形所屬那一段的每一個——名字、理由、成員步驟（用步驟內容指稱，不寫編號）、有沒有捲動軸。成員跨段時列在第一個成員所在那一段，其他段寫一行指過去。
- 總覽列出所有共用矩形的名字與所在區段的連結。
- 補充：插入處那一份與總覽用現有的「附加到某個標題底下」方式加一筆；`same_as` 寫「沿用『某範本』那一步的共用矩形」。

### Skill 與文件

- video-measure：什麼時候宣告共用矩形（同一個容器裡、每次出現在哪一格不一定的目標，例如商店商品格）；什麼時候只用捲動軸（內容會捲動的單排清單）；容器要框整個容器的所有格子、挑容器完整可見的那一幀；`why` 怎麼寫；讀驗證結果時「成員超出容器」怎麼處理（重框容器）。
- 計畫格式文件：新增 `shared_rects`、`rect`、`same_as` 的鍵與報錯情況。
- edit-flow：補充時新成員用 `same_as`；不靠影片手動加同組成員時照抄同組既有步驟的 `within`，並照現有規定同步交付報告。
- `app/CONTEXT.md` 的`共用矩形`已寫好；`docs/flow-format.md` 不動（flow.yaml 格式不變）。

## Testing Decisions

- 好的測試只看外部結果：產出 flow.yaml 各步的 `within`、結果的待確認清單、交付報告文字、報錯訊息與「資料夾不變」，不測內部函式。
- 接縫只用工具的兩個公開入口：新流程組裝（計畫, 引擎）與補充插入（計畫, 流程資料夾, 引擎），配既有的合成影片產生器。計畫寫錯的檢查也從這兩個入口打。app 不動，不跑 app 的測試。
- 新流程組裝要涵蓋：
  - 兩個成員共用一個框，逐字相同，等於容器每邊外推最大成員框的一半。
  - 單一成員可用。
  - 帶捲動軸時那一軸到影片兩端。
  - 容器貼邊被裁、裁過一側不報錯。
  - 確認圖與忙碌指示引用共用矩形。
  - 成員超出容器是工具錯誤且資料夾不變。
  - 名字不存在、沒人引用、`rect` 與 `scroll` 同寫、宣告裡寫 `within` 都報錯。
  - 成員不列進捲動待確認。
  - 區段報告與總覽有共用矩形的段落。
- 補充插入要涵蓋：
  - `same_as` 照抄既有那一步的 `within` 逐字相同。
  - `expect` 不符、超出流程、指到沒有固定矩形的步驟都報錯且資料夾不變。
  - 新成員在補充影片上落在照抄的框外是工具錯誤。
  - 影片倍率 ≠ 1 時影片像素宣告換回流程尺度。
  - 插入處報告記下沿用來源。
- 前例：
  - 固定矩形外推、捲動軸、裁切、確認圖與等待消失的規則測試；矩形餘裕工具錯誤的測試。
  - 捲動待確認的兩個測試；總覽與各段內容的報告測試。

## Out of Scope

- 「同段有拖曳、沒宣告捲動軸」改成只看拖曳之後到下一次重新定位之前的步驟（待確認雜訊的根本改進）：另外處理。
- flow.yaml 記錄分組或具名區域；app、編輯器、檢查指令的任何改動。
- 在用的四份流程：不重算、不改框（早_繁中的商品區框本來就涵蓋兩排）。
- 工具自動判斷哪些目標同組。
- code review 留下的重複程式整理。
