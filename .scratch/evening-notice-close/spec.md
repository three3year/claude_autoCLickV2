# 晚班開頭關公告(evening-notice-close)

Status: ready-for-agent

決定(2026-10-07):只加一個步驟,找公告的 X。

- (b)迴圈只留公告那一支:簽到、活動彈窗出現時,流程會卡在找基建那一步。
- (c)只加一個步驟找公告 X,逾時就跳過:最快;但如果先跳出別的彈窗,公告約 4 秒後才出來,這一步會漏關。

### 找公告 X 的逾時要多長?

決定(2026-10-07):2 秒。

- (a)2 秒(建議):公告已在畫面上時,第一輪就找到;已經在主畫面時,白等 2 秒。
- (b)5 秒(跟早班一樣):按下執行後公告才跳出也接得住;已經在主畫面時,白等 5 秒。
- (c)1 秒:白等最短;但公告還在淡入時,可能漏關。

### 晚_繁中的忙碌指示要不要一起換?

- (b)一起換:晚班換班、開頭也有忙碌暫停;代價是新圖還沒在實機上驗證過。

## Problem Statement

使用者晚上用 AutoClick 跑明日方舟晚班,繁中、簡中兩個客戶端各有一份流程(`晚_繁中`、`晚_簡中`)。遊戲登入後會跳出公告。早班兩份流程的開頭有清彈窗步驟,會順手關掉公告;晚班兩份沒有,第 1 步就直接找基建入口。公告蓋著畫面時,基建入口找不到,30 秒後流程停止。使用者只好手動關掉公告再重跑。

使用者按下晚班時,遊戲畫面不一定在哪:有時剛登入、公告還在,有時已經在主畫面。

## Solution

- 晚班兩份流程的開頭各加一步:找公告的 X → 點擊,點到消失;2 秒內找不到就跳過,接著照原本的第 1 步找基建入口。
  - 用早班已經驗證過的範本,連同它的固定矩形一起搬過來。簡中用「公告关闭」,繁中用「圓形叉叉」。繁中公告的 X 就是圓形叉叉。
  - 公告在畫面上:約一輪就點掉。
  - 已經在主畫面:多花 2 秒。
- `晚_繁中` 的忙碌指示改用 `早_繁中` 那張新圖,讓晚班繁中也有忙碌暫停。

## User Stories

1. 身為晚上跑基建的玩家,我想讓晚班流程自己關掉登入後的公告,這樣我登入完就能直接按執行,不用先手動關。
2. 身為晚上跑基建的玩家,我想讓遊戲已經在主畫面時,流程只多等 2 秒就往下走,這樣不管我從哪個畫面開跑都能用同一份流程。
3. 身為簡中客戶端(視窗模式)的使用者,我想讓 `晚_簡中` 用早班同一張「公告关闭」範本和同一個固定矩形,這樣晚班不用重新截圖、重新框範圍。
4. 身為繁中客戶端(最大化)的使用者,我想讓 `晚_繁中` 用早班同一張「圓形叉叉」範本和同一個固定矩形,這樣兩班的關公告行為一致。
5. 身為使用者,我想讓公告的 X 點了之後確認公告真的消失,點擊被吃掉就補做,這樣下一步找基建時畫面已經乾淨。
6. 身為使用者,我想讓「找不到公告」是正常結果(跳過),不讓流程停止,這樣沒有公告的晚上也能一路跑完。
7. 身為使用者,我想讓主畫面上長得像 X 的東西不會被誤點,這樣流程不會在主畫面亂點、跑進別的頁面。
8. 身為繁中使用者,我想讓 `晚_繁中` 的忙碌指示換成早班那張新圖,這樣晚班網路慢的時候,找圖等待也會等忙碌結束,不會提早逾時。
9. 身為使用者,我想讓晚班原本的步驟內容完全不變、只是編號往後推一號,這樣以前的實跑紀錄和報告裡的位置還對得起來。
10. 身為使用者,我想讓 app 啟動時讀到的草稿也有這一步,這樣在編輯器裡打開就看到新開頭,不會被舊草稿蓋回去。
11. 身為使用者,我想讓改動前留一份備份,這樣實跑出問題時可以換回舊版。
12. 身為使用者,我想讓晚班兩份的交付報告各記一節這次改了什麼、怎麼驗的、還有什麼風險,這樣以後回頭查有據可循。
13. 身為使用者,我想讓實跑後的日誌看得出這一步是找到點掉,還是逾時跳過,這樣能確認行為對不對。
14. 身為使用者,我知道如果先跳出的是簽到或活動彈窗,這一步會漏關公告,流程會在找基建那步停止;我接受這個風險,實跑真的遇到再處理。

## Implementation Decisions

- **只改流程存檔,不改程式碼**:執行器、找圖目標、存檔格式都不動。改的是兩份晚班流程存檔,以及目前的草稿與工作區範本。草稿目前內容是 `晚_簡中`。
- **新增的步驟**(插在兩份晚班的最前面,成為第 1 步):
  - 類型:找圖點擊,左鍵一下,偏移 (0, 0),更新原點。步驟設定都從早班的同一步原樣複製,只把逾時改成 2 秒。
  - 生效確認:點到消失。
  - 找不到時:跳過。
  - 找圖目標:
    - 簡中:範本「公告关闭」,限定範圍是固定矩形,比例 x 0.8597、y 0.0598、w 0.0792、h 0.1478。
    - 繁中:範本「圓形叉叉」,限定範圍是固定矩形,比例 x 0.6917、y 0.0674、w 0.2453、h 0.2344。
- **範本直接搬,不換算**:早晚班同一個客戶端的校準對基準距離相同(簡中 1650、繁中 1868),搜尋範圍也相同(簡中 [87, 57, 1718, 920]、繁中 [0, 0, 1920, 1024])。所以範本圖與固定矩形的比例都原樣使用。晚班沒有同名範本,不會衝突。
- **晚_繁中的忙碌指示**:範本圖換成 `早_繁中` 的「忙碌指示」;限定範圍不變,兩邊都是九宮格 [8, 9]。
- **其餘步驟**:內容一字不改,編號全部 +1(兩份都是 63 → 64 步)。
- **建構方式**:跟前幾張票一樣,寫一支可以重跑的腳本放在本功能的 `.scratch` 資料夾,從早班存檔讀出來源步驟與範本,寫進晚班存檔與草稿。不在編輯器裡手動改。
- **備份**:改之前,把整個 profiles 流程資料夾複製一份到 dist 底下的新備份資料夾,命名照前例(日期+功能名)。
- **交付報告**:兩份晚班的報告最上面各加一節,寫改了什麼、驗證結果、已知風險、備份位置。報告後面的步驟清單同步更新。

## Testing Decisions

- 好的驗證只看外部行為:找圖有沒有找到、找到的位置、執行時點了哪裡、什麼時候逾時、走了哪個「找不到時」處置。不檢查存檔內部以外的實作細節。
- 不加 pytest:流程存檔不進版控,這次也沒改程式碼。驗證腳本放在本功能的 `.scratch` 資料夾,可以重跑。

### 接縫一:真引擎+影片影格(一次性腳本)

- 用 app 的真實偵測路徑和 arknights profile 的門檻,影格換成實機搜尋範圍的畫布。
- 正例:新步驟的找圖目標,在早班影片有公告的影格上要找得到,位置在固定矩形內。簡中用 demo6,繁中用 demo2,影格挑早班固定矩形驗證時用過的那幾張。
- 反例:在晚班示範影片的主畫面影格上要找不到。簡中用 demo4,繁中用 demo3,各挑數張分散的主畫面影格。
- 晚_繁中換上的忙碌指示:沿用票 06 的結果,不重驗。
- 先例:busy-pause-fixed-rect 票 08 的固定矩形驗證腳本(真引擎+影格,加框前後各找一次)。

### 接縫二:無頭執行器(一次性腳本)

- 用 app 測試用的無頭 harness:假畫面、假輸入、虛擬時鐘。
- 從改好的存檔讀出晚班的前幾步(新的第 1 步到找基建入口那一步),跑兩個劇本:
  - 公告在:點公告的 X → 確認消失 → 接著找基建入口並點擊。
  - 公告不在:2 秒逾時、跳過 → 接著找基建入口並點擊。
  - 兩個劇本裡,找基建入口之後的事件序列要一樣。
- 先例:busy-pause-fixed-rect 票 05 的 `sim_busy` 腳本(從存檔切片段、兩個劇本比事件序列)。

### 接縫三:讀回檢查

- 兩份晚班存檔和草稿讀回後確認:
  - 第 1 步的設定和上面寫的一樣。
  - 原本的步驟依序原封不動地接在後面。
  - 第 1 步用到的範本在存檔裡。
  - `晚_繁中` 的忙碌指示圖和 `早_繁中` 相同。

### 最終驗收

使用者用打包版實跑兩份晚班,我看 `autoclick.log`,確認以下幾點:

- 公告在時,第 1 步找到並點掉,公告消失只點了一下;找基建入口正常。
- 已在主畫面時,第 1 步約 2 秒後跳過,沒有誤點。
- 晚_繁中的找圖步驟出現 `busy_pause` 大於 0 的紀錄,表示新的忙碌指示比得到;沒遇到網路慢就看不到,不算失敗。

## Out of Scope

- 早班兩份流程不動。
- 晚班不搬簽到、活動、今日配給、獲得物資這些彈窗的處理,只處理公告。
- 「先跳出別的彈窗、公告晚約 4 秒才出來」的情況不處理,實跑遇到再說。
- 晚班其他已知問題這次都不處理,例如忙碌暫停後「點擊緊接點擊」不等忙碌、找圖速度。
- 不重新打包;流程存檔就在打包版資料夾裡,改完直接生效。

## Further Notes

- 繁中忙碌指示新圖還沒在實機驗證過(票 06 發現舊圖在影片上其實也比得到,繁中一直 not_appeared,可能只是 1 秒內沒出現忙碌)。晚班實跑如果發現新圖誤判,例如沒忙碌卻一直暫停,就換回舊圖。備份裡有舊圖。
- 實跑時使用者常在玩遊戲:冒煙或實跑前先確認使用者在不在、前景是哪個視窗。
