# Spec: 啟動提速——視窗先開、引擎背景載入、範本執行前預載

Status: implemented (2026-08-16；ADR 0004；打包版實測熱啟動開窗 1.4–1.6s、
冷 3.3s——目標 <3s 達成，詳見 issues/07 Comments)

## Problem Statement

打包版從點兩下 exe 到主視窗可操作太慢:熱啟動實測 3.1–4.4 秒、乾淨環境
冷啟動歷史紀錄 15.3 秒,而且開窗前全黑、沒有任何回饋,使用者只能盯著螢幕
等。使用者每次開啟都感受到慢,不限冷啟動。

量測與調查確認成本依序為:

1. 主視窗映射前同步建引擎——import torch + 反序列化 84MB DINOv2 驗證
   模型權重,全部做完視窗才出現(最大單項)。
2. 啟動時對 profile 全部範本(現況 87 個)逐一登錄載入:每個算 SHA-1、
   讀 3–4 個檔,每次啟動都做。
3. 打包開了 UPX,366MB 的 torch DLL 群每次載入都要先解壓。

## Solution

視窗先開、重活挪走:

1. 主視窗建好立即顯示並可操作;驗證模型改由背景執行緒載入。「視窗可操作」
   與「`引擎就緒`」自此是兩個時間點(詞彙見 app/CONTEXT.md「啟動與就緒」)。
2. 引擎就緒前的辨識類操作(執行流程、F12、比對測試、即時找圖、校準、
   範本登錄)一律 modal 對話框提示並拒絕,使用者稍後自行重試;背景載入
   失敗維持現行為——modal 警告後降級粗篩模式。編輯流程、管理範本等
   不需辨識的操作完全不受影響。
3. 範本改為「`範本預載`」:啟動時完全不載;按下執行後、流程開跑前,一次
   掃描載入該流程引用的全部範本,執行視窗顯示「準備範本中…」;單一範本
   的辨識操作在使用當下載那一張。
4. 關閉 UPX,用磁碟空間(dist 約 700MB → 900MB–1GB)換每次啟動的解壓成本。

驗收:熱啟動下,點擊 exe 到主視窗出現且按鈕可按 < 3 秒;冷啟動盡量改善
(不設硬指標,受防毒掃描等外部因素影響)。

## User Stories

1. 身為使用者,我想在點開執行檔後 3 秒內看到主視窗並能開始操作,讓開啟程式不再是一段呆等。
2. 身為使用者,我想在開機後第一次開啟(冷啟動)也明顯變快,讓每天第一次使用不再等十幾秒。
3. 身為使用者,我想在視窗開啟後立刻編輯流程、瀏覽範本、調整設定,讓不需要辨識的操作不被模型載入擋住。
4. 身為使用者,我想在引擎還在載入時於狀態列看到「引擎載入中」的提示,讓我知道辨識功能何時可用。
5. 身為使用者,我想在引擎就緒前按「執行流程」時得到明確的對話框提示,讓我知道是引擎還沒好、稍後重按即可,而不是以為程式壞掉。
6. 身為使用者,我想在引擎就緒前按 F12 也得到同樣的對話框提示,讓熱鍵與按鈕的行為一致、不必記兩套規則。
7. 身為使用者,我想在引擎就緒前使用比對測試、即時找圖、校準或新增範本時同樣被提示並擋下,讓所有辨識類操作有一致的就緒規則。
8. 身為使用者,我想在驗證模型載入失敗時看到警告並自動降級粗篩模式,讓程式在模型壞掉時仍然可用(與現行為相同)。
9. 身為使用者,我想在按下執行後於執行視窗看到「準備範本中…」,讓範本掃描載入的那一小段不會像按了沒反應。
10. 身為使用者,我想讓範本準備完成後流程自動接著現有的倒數開跑,讓預載不需要我再按一次。
11. 身為使用者,我想讓流程執行中每一步的辨識即時性與現在相同(不因懶載入在步驟中途頓一下),讓自動化節奏可預期。
12. 身為使用者,我想在流程引用的範本缺失或損壞時,於預載階段就得到明確錯誤,而不是跑到一半才炸。
13. 身為使用者,我想讓比對測試等單範本操作在使用當下才載入那一張範本,讓沒用到的範本不拖慢任何操作。
14. 身為使用者,我想在新增或修改範本後,下一次預載或單張載入自動反映最新內容,讓我不需要手動觸發重登錄。
15. 身為使用者,我想讓範本瀏覽器在視窗開啟後就能看到清單,讓啟動提速不犧牲瀏覽功能。
16. 身為使用者,我想讓切換 profile 的行為維持現狀(清單與引擎查詢對象一致跟隨),讓提速改動不影響 profile 語意。
17. 身為使用者,我願意用幾百 MB 磁碟空間換啟動速度(關閉 UPX),讓每次開啟都更快。
18. 身為使用者,我想讓既有流程檔、範本庫、profile 資料完全不受此改動影響,讓升級後不需要遷移任何東西。

## Implementation Decisions

- **引擎生命週期介面**:把既有的引擎邊界(runner 注入的偵測器,`query`)
  擴充為生命週期介面——就緒狀態查詢(載入中/就緒/失敗降級)+ 範本預載
  + 單範本載入 + `query`。App 與 runner 都只透過這個介面;這是全 repo
  唯一假件點的自然延伸,不新開假件點。
- **背景載入**:App 啟動即建視窗進主迴圈,驗證模型於背景執行緒載入;
  完成/失敗以事件回到 UI 執行緒更新狀態(失敗跳 modal 警告並降級粗篩)。
  不加 splash。
- **就緒 gating**:「哪個狀態下哪些操作被拒絕」收成純決策邏輯,UI 只是
  薄執行層(沿用 0003「純狀態機+薄執行層」前例)。拒絕一律 modal 對話框
  (含 F12 觸發),不排隊自動開始、不置灰按鈕。
- **範本預載**:啟動不再全庫登錄;執行前從流程步驟收集全部範本引用——
  找圖範本、確認圖、「點到下一步的圖出現」所指的下一步範本、分岔各分支
  條件——一次載入。預載沿用既有登錄快取有效性檢查(SHA-1 機制不變)。
  同一次執行內載入結果駐留記憶體;每次按執行都重新掃描一遍。
- **單範本載入**:比對測試、即時找圖各載當下那一張;校準載校準對兩張。
- **重登錄語意**:範本增刪改後不再立即整庫重登錄,改為標記失效,由下次
  預載或單張載入補跑——「引擎查詢前必須先確保登錄」的既有契約由預載承接。
- **開窗關鍵路徑**:重量級套件(torch、cv2 等)不得在開窗前同步 import,
  隨背景載入或首次使用載入;範本瀏覽器的清單掃描維持啟動時(輕量),
  縮圖影像的建立不得擋住開窗(視窗顯示後補建)。熱鍵註冊、profile 列舉、
  自動存檔載入等輕量啟動工作維持現狀。
- **打包**:關閉 UPX;維持 onedir 與現有交付形式,部署慣例不變。
- **啟動計時**:引擎背景載入的起訖寫進既有檔案日誌,供驗收與日後回歸
  對照;不做常駐的效能遙測。

## Testing Decisions

- 好測試只驗外部行為:給定引擎狀態與使用者操作,斷言「被拒絕(含提示)
  /被放行」「預載收集到哪些範本名」「預載完成才開跑」,不驗執行緒細節
  或內部旗標。
- **假件點不變**:沿用 tests/harness.py 的引擎假件(全 repo 唯一假件點),
  擴充為生命週期介面後,測試直接把狀態撥成載入中/就緒/失敗,不碰 torch、
  不開執行緒、不真的睡。
- **純邏輯直測**:就緒 gating 決策、預載範本名收集(含確認圖、「點到下一步
  的圖出現」、分岔條件的邊界情形)以 pytest 直測;prior art:
  `window_coord.py` 純狀態機測試、`app/tests/` 的 runner 回歸網。
- **runner 路徑**:用既有 harness 驗「預載發生在第一步之前、恰好一次」
  「預載失敗走明確錯誤不開跑」;prior art:`app/tests/` 既有 runner 測試。
- **GUI 抽測**:狀態列文字、拒絕對話框、執行視窗「準備範本中…」用既有
  GUI 測試手法(event_generate/PrintWindow)抽測少量。
- **不自動化**:真實 torch 載入、打包產物、實際啟動秒數——以打包後實測
  計時驗收(啟動 exe 量測開窗時間,熱啟動 < 3 秒),沿用打包冒煙慣例。

## Out of Scope

- splash 畫面、開機自動預熱、常駐背景程序等其他啟動策略。
- 就緒前操作的排隊自動開始或按鈕置灰(拍板為提示並拒絕)。
- 登錄快取機制的改動:mtime+size 取代 SHA-1、單一彙總快取檔(討論過,
  未採)。
- 打包形式變更(onefile/onedir 已定,ADR 0002 時代拍板 onedir)與
  UPX 以外的 dist 瘦身(excludes、刪多餘 DLL 等)。
- 逐步驟懶載入範本(拍板為整份流程一次預載)。
- 冷啟動的外部因素(防毒掃描、磁碟快取)——盡力而為,不設硬指標。
- 並行執行相關(未移植,接縫不動)。

## Further Notes

**實作期拍板的偏差(code-review 後回寫,原委見 issues/03 Comments):**

- 「範本登錄」不做就緒 gating:登錄本就延後到使用時,截圖存檔不需要
  引擎——新增範本在引擎載入中照常可用,體驗優於擋下(user story 7 的
  「範本登錄」以此語意收斂)。
- 即時找圖在**清場進行中**不彈 modal(清場中彈 modal 會隱形卡死,
  見 app/CLAUDE.md 踩坑),改 silent 回 None 走「截圖當下位置」備援;
  非清場時照「提示並拒絕」。
- 新增 FAILED 永久拒絕態:引擎本體載入炸掉(非驗證模型降級)時
  modal 錯誤、辨識類操作永久拒絕——規格原文只涵蓋降級粗篩,此為
  防禦性補全。

- 架構決策與取捨記錄在 ADR 0004(`docs/adr/0004-background-engine-load-and-flow-preload.md`);
  「引擎就緒」「範本預載」詞彙已入 app/CONTEXT.md「啟動與就緒」。
- 本 spec 推翻 app/CLAUDE.md 記載的「app 啟動建立一次 Engine、load_profile
  自動登錄」契約,實作收尾時需同步改寫該檔(含 ensure_registered 相關
  踩坑條目)。
- 量測基準(2026-08-16,使用者機器):熱啟動開窗 3.1–4.4 秒;冷啟動
  歷史紀錄 15.3 秒(見 autoclick-port issues/07)。改動後以同法重測對照。
- 依部署慣例,實作完成後必須重新打包(app\build.bat)並部署,dist 沒跟上
  原始碼＝修正等於沒送達。
