# Spec：流程存放區搬進專案

Status: ready-for-agent

流程存放區從使用者資料夾底下的 `AutoClick` 搬進 repo 根目錄的 `flows/`，整個資料夾用 `.gitignore` 排除。詞彙以 `app/CONTEXT.md` 為準（「流程存放區」這次新增）。前身是 project-cleanup 票 09 的佈局決定（流程放 `%USERPROFILE%\AutoClick\`）；這份取代其中「流程放哪」那一條，其餘佈局不變。

決定（2026-10-18）：(a) 取消範例，只搬位置；流程全部不進 git。

- (a) 取消範例，只搬位置（建議）：之後要範例另開需求。

- (c) 搬位置，範例另放 `examples/`：多一份要跟格式轉。

### 流程存放區放專案內哪個資料夾？

決定（2026-10-18）：(a) repo 根目錄 `flows/`。

- (a) `flows/`（建議）：一眼看得到，路徑短。
- (b) `.local/flows/`：不用改 `.gitignore`，但跟可丟的本機狀態混在一起。
- (c) `app/flows/`：使用者資料混在程式碼與 build、dist 旁。

### 打包版怎麼找到專案內的流程存放區？

決定（2026-10-18）：(a) 從 exe 往上找 repo，找不到退回 `%USERPROFILE%\AutoClick\`。

- (a) 往上找、找不到退回舊位置（建議）：這台電腦上打包版與原始碼執行看到同一組流程；整包拿到別台電腦照樣能用。
- (b) 只有原始碼執行搬進專案：兩邊各一組流程，平常用打包版的話等於沒搬。
- (c) 打包版一律用 exe 旁的 `flows\`：重新打包會整個換掉 dist，流程被刪。

## Problem Statement

流程資料夾現在放在使用者資料夾底下的 `AutoClick`，跟專案分開。使用者想把日常在用的流程集中在這個專案裡管理（開專案就看得到、跟程式碼在同一處），但流程含範本圖與快取、屬於個人使用資料，不想上傳到 git。

## Solution

流程存放區改成 repo 根目錄的 `flows/`，`.gitignore` 排除整個資料夾。

- 從原始碼執行：存放區就是 `<repo>/flows/`。
- 打包版：從 exe 所在位置往上找這個 repo；找到就用同一個 `<repo>/flows/`，找不到（整包拿到沒有 repo 的電腦）退回 `%USERPROFILE%\AutoClick\`。
- 開檔對話框、新流程第一次存檔的對話框、影片轉流程的預設輸出都從存放區開始；存放區不存在就建。流程資料夾仍可存在任何位置，存放區只是預設。
- 現有 6 份流程一次搬進 `flows/`，打包版的上次流程改成新路徑；舊位置清空。

## User Stories

1. 身為使用者，我想在專案資料夾裡直接看到我所有的流程資料夾，這樣管理流程不必另外記一個位置。
2. 身為使用者，我想讓流程資料夾不被 git 追蹤，這樣範本圖、快取和我個人的流程調整不會出現在 git 狀態或被上傳。
3. 身為使用者，我想在打包版按「開檔」時對話框直接開在專案的 `flows/`，這樣不用每次切資料夾。
4. 身為使用者，我想讓新流程第一次存檔時的對話框開在專案的 `flows/`，這樣新流程自然存進存放區。
5. 身為使用者，我想讓打包版和從原始碼執行的 app 看到同一組流程，這樣不會改了一邊、另一邊還是舊的。
6. 身為使用者，我想讓搬家後第一次開打包版時自動開上次的流程（新位置的晚_簡中），這樣搬家不打斷日常使用。
7. 身為使用者，我想讓現有 6 份流程原封不動搬過去（含範本、快取、交付報告、備份檔），這樣搬家後流程行為完全一樣。
8. 身為使用者，我想讓搬家後舊位置不再有同名流程，這樣不會開錯、改錯那一份。
9. 身為使用者，我想把打包版整個資料夾拿到沒有這個 repo 的電腦上時照樣能開檔存檔，這樣可攜交付不受影響。
10. 身為使用者，我想讓重新打包（整個換掉 dist）不會碰到我的流程，這樣部署不必先搬使用者資料。
11. 身為使用者，我想讓專案裡還沒有 `flows/` 時 app 自己建，這樣乾淨 clone 下來的專案也能直接用。
12. 身為使用者，我想照樣能開存放區以外的流程資料夾，這樣臨時放在別處的流程也能用。
13. 身為修改流程的 agent，我想讓影片轉流程工具沒指定輸出位置時把流程建在存放區，這樣轉出來的流程跟 app 看到的在同一處。
14. 身為修改流程的 agent，我想讓 skills 與 README 寫的預設位置跟實際行為一致，這樣不會把流程建到舊位置。
15. 身為開發者，我想讓測試不讀寫真的 `flows/`，這樣跑測試不會污染使用者的流程。
16. 身為未來讀程式的人，我想在 ADR 讀到為什麼流程在 repo 裡卻不進 git、打包版為什麼往上找 repo，這樣不會把它當成錯誤「修正」掉。

## Implementation Decisions

- **單一來源**：流程存放區只由 app 的路徑模組的 `flows_root()` 決定；app（開檔、存檔對話框、清單）與影片轉流程工具的預設輸出都呼叫它，工具裡寫死的預設輸出刪掉。命令列 `--out` 與計畫的 `out` 照舊優先。
- **原始碼執行**：`flows_root()` 回 `<repo 根>/flows`；repo 根沿用路徑模組現有的 repo 根常數。
- **打包版找 repo**：從 exe 所在資料夾逐層往上，找到某層底下有本專案的路徑模組原始檔（`app` 底下那支）就認定為 repo 根，回 `<repo 根>/flows`。用專案自己的原始檔當記號，不用 `.git`：別的 git repo 不會誤認，沒有 `.git` 的專案複本也認得。找到磁碟根都沒有就回 `%USERPROFILE%\AutoClick`（現在的行為）。
- **存放區不存在就建**：沿用現有開檔／存檔對話框的行為，不變。
- **本機狀態不變**：打包版的本機狀態與日誌仍在 `%LOCALAPPDATA%\AutoClick\`，原始碼執行仍在 repo 的 `.local/`。只有流程存放區搬。
- **`.gitignore`**：加 `flows/`（根目錄）。
- **搬家（一次性，不寫通用遷移，同 ADR 0009 的做法）**：
  - 6 份流程資料夾從 `C:\Users\three\AutoClick\` 整份搬進 `<repo>\flows\`（同一顆磁碟，搬移＝改名，內容不動），搬完舊資料夾是空的就刪掉。
  - `%LOCALAPPDATA%\AutoClick\state.json` 的 `last_flow` 改成 `<repo>\flows\晚_簡中`。
  - 順序：先改程式並重新打包（照 memory 的打包方式：打到 dist-new 再換上），再搬流程、改 state.json。反過來的話，搬完到重新打包之間舊打包版的對話框開在舊位置、找不到流程。
  - 搬家與打包會動到使用者正在用的東西：動手前確認使用者不在玩遊戲、打包版沒開著。
- **文件與 agent 文件同步**：README、打包腳本與打包設定檔的註解、路徑模組的說明、`video-to-flow` skill 與轉換計畫格式的預設輸出、`app/CONTEXT.md`（已更新）。相關 memory 裡寫到舊位置的一併更新。
- **ADR 0017**：記錄存放區在 repo 內但不進版控、打包版往上找 repo、找不到退回使用者資料夾，以及這取代了票 09 的位置決定。

## Testing Decisions

- 好的測試只看外部行為：給定執行模式與資料夾配置，`flows_root()` 回哪個路徑；不測它怎麼往上走。
- **路徑模組**（既有的路徑模組測試檔，同檔已用 monkeypatch `sys.frozen`、環境變數、`importlib.reload` 測本機狀態位置）：
  - 原始碼執行 → `<repo 根>/flows`。
  - 打包版、exe 在暫存目錄裡的假專案樹底下（假的 `app` 路徑模組原始檔＋幾層 dist 資料夾）→ 假專案根的 `flows`。
  - 打包版、exe 所在的暫存目錄往上沒有專案記號 → 使用者資料夾底下的 `AutoClick`（取代現有「流程預設位置在使用者資料夾」那支測試）。
- **影片轉流程工具**：沒給 `--out`、計畫沒寫 `out` 時，輸出位置＝`flows_root()`（monkeypatch 成暫存目錄驗證）。前例：工具既有的組裝測試。
- 測試共用的 conftest 已把 `flows_root` 換成暫存目錄，所有測試不碰真的 `flows/`；不用改。
- 對話框從存放區開已有測試（開存檔測試檢查 `initialdir == flows_root()`），不另加 GUI 測試。
- 搬家不寫測試：驗收＝使用者用新打包版開 app，自動開到 `flows\晚_簡中`，開檔對話框開在 `flows\`，跑一輪正常。

## Out of Scope

- 範例流程進 git（先前討論過，這次取消；之後要再另開需求）。
- 流程資料夾格式、app 其他行為、本機狀態與日誌的位置。
- 給其他電腦的搬家工具或 app 自動對應舊路徑。
- 改寫票 09 或其他歷史 `.scratch` 文件、一次性腳本裡的舊路徑。

## Further Notes

- repo 不在 OneDrive 底下，票 09 當初避開「文件」資料夾的理由（上傳鎖檔、雲端佔位檔）不受影響。
- 打包版在 `app\dist\AutoClick\`，往上三層就是 repo 根；打包時暫時的 `dist-new` 也在 repo 裡，同樣找得到。
