# 02 — 辨識五格:渲染範本、格子版面、嚴格判定

**What to build:** 使用者給一張繁中招募畫面截圖,工具印出五個`標籤格`各是什麼`招募標籤`、本尊分數、次高他者與差距、每格「通過/混淆/未辨識」與整張是否通過嚴格標準,並可寫成 JSON(此票尚無保底組合)。範本是從招募池快照的標籤字面、用近似遊戲字型渲染的 29 張只含文字的圖;只在五格內找;截圖長寬比不對時明確拒絕。

規格:`.scratch/recruit-tags/spec.md`「範本渲染」「標籤格與查詢」「輸出」節。原型數據與真截圖在 `.scratch/recruit-tags/prototype/`。

**Blocked by:** 01 — 建池(範本字面與 tagId 來自快照)

**Status:** done (2026-10-10)

- [x] Pillow 加為工具的 optional extra(不加進 app 依賴);渲染器用本機 Noto Sans TC 可變字型為預設,字重、字高、字色、底色集中在渲染設定,CLI 可覆寫字重與字高;渲染設定隨輸出印出。
- [x] 範本只含文字(緊貼字形外框留少量邊、白字深底),以 1.0 尺度(1920 寬客戶區)渲染,字高基準由 grill 截圖換算;29 張在同一模板庫登錄一次,登錄產物放暫存目錄。
- [x] 五格版面模型以 1.0 尺度、相對招募視窗表示(從 grill 截圖量);截圖尺度 = 寬 ÷ 1920,格子按尺度換算;CLI 可整組覆寫;長寬比差太多時拒絕(stderr 說原因、結束碼 1)。
- [x] 辨識入口函式:輸入截圖、客戶端、快照、引擎、可選格子覆寫;每格的搜尋區域 = 格子外擴少量邊,對 29 張範本各查一次,`expected_scale` = 截圖尺度;每格記錄每張範本的 found、最佳候選的粗篩與驗證分數。
- [x] 判定:本尊 = found 且分數最高;嚴格通過 = 恰一張 found 且本尊粗篩分數 − 其他 28 張最佳候選粗篩分數的最大值 ≥ 0.1;兩張以上 found 標「混淆」並列出;沒有 found 標「未辨識」;整張通過 = 五格都通過。
- [x] stdout 摘要與 `--json` 輸出含:五格結果、整張是否通過、渲染設定、快照資訊。
- [x] 測試用 session 共用真引擎與合成畫面(工具自己的渲染器畫深色格子白字標籤,格外放含「幹員」的干擾文字):五格全對且通過、某格非標籤文字 → 未辨識且整張不通過、尺度 0.886 與 1.0 都認得、長寬比不對 → 拒絕、格子覆寫生效。

**合成畫面的發現(重要,影響 04 的解讀)**:用工具自己的渲染器畫假畫面(範本與畫面同一個渲染器 = 最理想的範本),
29 個標籤逐一放進格子:
- 1.0 尺度:9 個「X幹員」(含資深幹員)與近戰位/遠程位共 11 個**全部混淆**——同族範本粗篩 0.70–0.74、
  驗證 0.94–0.98 都過門檻;其餘 18 個通過(差距 0.45–0.53,高級資深幹員 1.0)。
- 0.886 尺度(假畫面字級 21):X幹員族 8 個(含資深幹員)與遠程位混淆,近衛幹員、近戰位通過;其餘全部通過。
- 每一格粗篩最高的都是本尊(1.0 時差距 0.26–0.30;0.886 時 0.07–0.19)。
所以混淆來自引擎分不開共用兩個字的標籤,不是渲染問題;改用真截圖裁切也一樣會撞上。
測試的「五格全對且通過」因此選不含這兩族的標籤,另有一個測試釘住「重裝幹員格 → 混淆、最佳仍是本尊」。
