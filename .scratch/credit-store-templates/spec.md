# 採購中心商品範本:從倉庫素材圖切出 PNG(credit-store-templates)

Status: ready-for-agent

詞彙見 `app/CONTEXT.md` 的「找圖語意」(範本、匹配、比色)、「尺度與畫面倍率」(流程尺度)與「影片轉流程」(待重拍、影片與實際畫面同尺度)。本規格不新增 app 術語;「採購中心」「倉庫」是遊戲畫面的名稱。

## Problem Statement

使用者想做一份明日方舟採購中心(信用交易所)的流程,依白名單與優先順序決定要點哪一張商品卡。要做到這件事,每一種商品都需要一張範本,用來認出畫面上的卡是什麼商品。

使用者手上有六張素材圖:pic1 是繁中採購中心的畫面,pic2~pic6 是倉庫裡各種物品的圓形圖示。這些圖示不能直接拿來當範本:

- 每個圖示右下角疊著庫存數字(例:622、907),跟採購中心卡片上的販售數量(例:「2」)不同。
- 採購中心卡片左上角有折扣標籤(例:-75%)。龍門幣卡片還有一條「3600」橫跨圖示下半部。
- 實測後發現,倉庫圖示比採購中心卡片上的同款圖示大約 2.6%。
- 使用者有兩個客戶端(繁中最大化、簡中視窗),尺度不同。一份流程只有一個尺度,所以兩邊各要一組範本。

使用者要的是**能直接匯入流程使用的 PNG**,並且事先知道每一張在實際商店畫面上認不認得出來。

## Solution

從倉庫素材圖切出採購中心會賣的每一種商品,繁中、簡中各輸出一組 PNG,並逐張用專案的引擎驗證。

- 輸出到 `oCam Video\採購中心範本\繁中\` 與 `oCam Video\採購中心範本\簡中\`。兩組檔名相同,例如 `採購_糖.png`;檔名就是日後的範本名稱。
- 切的範圍避開數字、折扣標籤與龍門幣的數量條。框法有兩個候選,實測後擇一套用到整組:
  - 只框圓圈裡面中央偏上的方塊。
  - 連外環一起框的上半圓。
- 繁中組縮成 ×0.975,也就是採購中心畫面的尺度。簡中組的倍率從簡中影片的商店畫面實際量出來。
- 每張範本在有它的商店畫面上驗證:要在自己那張卡上有匹配,在其他商品的卡上都沒有。比色關、比色開各驗一次。
- 沒通過的,檔名加 `待重拍_` 前綴。沒有任何商店畫面出現它(沒得驗)的,照常命名,在報告裡列為「未驗證」。
- 附一份交付報告,分「通過 / 待重拍 / 未驗證」三類列出,並列出素材裡沒有、這次沒做的商品。

## User Stories

1. 身為使用者,我想要每一種採購中心會賣的商品都有一張獨立的 PNG,這樣日後做流程時一個商品對應一張範本。
2. 身為使用者,我想要檔名是 `採購_物品名`,這樣在範本面板一眼看出是採購中心那一組,匯入已有很多範本的流程時也不會撞名。
3. 身為使用者,我想要物品名用遊戲裡的繁中名稱(例:糖、固源岩、加急許可),這樣跟商店卡片的標題對得起來。
4. 身為使用者,我想要範本不含倉庫的庫存數字,這樣不論商店卡上寫賣幾個都認得出來。
5. 身為使用者,我想要範本不含商店卡片左上的折扣標籤區域,這樣有沒有折扣、折扣多少都不影響辨識。
6. 身為使用者,我想要龍門幣的範本避開商店卡上那條「3600」,這樣龍門幣卡也認得出來。
7. 身為使用者,我想要範本不含圓圈外的背景,因為倉庫背景和商店卡片背景不同,會拉低分數。
8. 身為使用者,我想要框法(只框圈內,或連外環一起框)由實測決定、整組一致,這樣日後哪張出問題都容易比較。
9. 身為使用者,我想要報告列出兩種框法的實測分數,這樣我知道為什麼選了這一種。
10. 身為使用者,我想要繁中那組的尺寸等於繁中採購中心畫面的尺度,這樣放進繁中流程時分數最高。
11. 身為使用者,我想要另有一組簡中尺度的範本,這樣簡中流程也能用,不必再自己截一次。
12. 身為使用者,我想要簡中的縮放倍率從我錄的簡中影片的商店畫面實際量出來,而不是用視窗寬度硬算。
13. 身為使用者,我想要繁中組用 pic1 與 demo2 的商店畫面驗證,這樣驗的是我機器上真正的畫面。
14. 身為使用者,我想要簡中組用所有拍到採購中心的簡中影片(demo1、demo5、demo6)驗證,這樣涵蓋到的商品最多。
15. 身為使用者,我想要驗證用的是專案的引擎和 arknights profile 的門檻,這樣驗證結果等於流程實際執行時的結果。
16. 身為使用者,我想要每張範本都確認在自己那張卡上找得到,這樣我知道它認得出來。
17. 身為使用者,我想要每張範本都確認不會在別的商品卡上找到,這樣白名單流程不會點錯商品。
18. 身為使用者,我想要同系列不同階的商品(例:代糖/糖、異鐵碎片/異鐵、源岩/固源岩)也被檢查不會互相認錯,因為點錯這種的代價最直接。
19. 身為使用者,我想要比色關、比色開的結果都列在報告裡,這樣日後流程要不要開比色有數據可依。
20. 身為使用者,我想要售完的卡不算進驗證,因為「售完」橫幅蓋住了圖示,本來就不該點。
21. 身為使用者,我想要沒通過的範本檔名加 `待重拍_`,這樣匯入後在範本面板一眼可見,和影片轉流程的慣例一致。
22. 身為使用者,我想要沒機會驗證的範本照常命名、在報告裡列為「未驗證」,這樣 `待重拍_` 只代表真的測過而失敗。
23. 身為使用者,我想要報告寫出每張範本是在哪些畫面上驗的、分數多少,這樣出問題時知道從哪裡查。
24. 身為使用者,我想要報告列出採購中心會賣、但素材裡沒有的商品(基礎/初級作戰記錄、技巧概要·卷1/卷2、家具零件),這樣我知道之後要補截哪些。
25. 身為使用者,我想要碳類三階都切,因為不確定商店賣哪幾階,切了不用也沒有損失。
26. 身為使用者,我想要這次不動任何專案程式、流程存檔與打包版資料,這樣不會影響我正在用的流程。
27. 身為使用者,我想要切圖與驗證的腳本留在這個功能的資料夾裡,這樣之後補素材時可以重跑。
28. 身為使用者,我想要重跑腳本時會重新產生整組 PNG 與報告,而不是把舊結果和新結果混在一起。

## Implementation Decisions

### 商品清單(19 種)

| 來源 | 商品 |
|---|---|
| pic2(只取一階灰圈、二階黃綠圈) | 源岩、固源岩、代糖、糖、酯原料、聚酸酯、異鐵碎片、異鐵、雙酮、酮凝集、破損裝置、裝置 |
| pic4 | 招聘許可、加急許可 |
| pic5 | 碳、碳素、碳素組 |
| pic6 | 龍門幣、赤金 |

- pic2 的三、四階(藍圈、紫圈)和 pic3 整張都是採購中心不賣的,不切。
- pic2 各圖示是哪一種商品,由執行者看圖對照遊戲物品辨認,寫進驗證用的資料。碳類三階的名稱同樣要確認。

### 切法

- 切取來源一律是倉庫素材圖(pic2、pic4~pic6),不從商店畫面切。
- 範本是長方形,要避開:
  - 圓圈外的背景
  - 右下角的數字框(倉庫多為 3~4 位數,框較寬)
  - 商店卡左上的折扣標籤可能蓋到的區域
  - 龍門幣在商店卡上的數量條
- 兩個候選框法都實測,依驗證結果選一種套用到整組:
  - 圈內中央偏上的方塊。
  - 含外環的上半圓。外環顏色可以幫忙分階級,但四個角會帶到背景。
- 判斷順序:先看哪一種通過的張數多;張數一樣時,看「本尊分數 − 最高的別種商品分數」的最小值,大的勝。

### 尺度

- **繁中**:由倉庫圖示縮 ×0.975。實測依據見 [Further Notes](<#Further Notes>)。
- **簡中**:同一張倉庫切圖縮到簡中商店畫面的尺度,倍率從簡中影片量。量法是在 demo1、demo5、demo6 的商店畫面上,量已知商品的圓圈直徑,和繁中商店上的直徑相比。
- 兩組都在對應的商店畫面上以預期尺度 1 查詢。這相當於流程在建立時的視窗大小下執行(畫面倍率 1)。

### 驗證畫面與標註

- **繁中**:pic1,加上 demo2 約 140~157 秒的商店畫面。
- **簡中**:demo1 約 223~278 秒、demo5 約 159~198 秒、demo6 約 152~178 秒的商店畫面。
- 從這些時段挑商店卡片完整、沒有購買彈窗遮擋的影格。購買確認框、購買動畫的影格不用。
- 每張驗證畫面要標註每張卡的商品名稱、圖示所在位置,以及是否售完。標註由執行者看卡片標題文字完成,存成驗證腳本讀的資料檔。
- 影片影格是 1:1 的遊戲畫面,參見 `影片與實際畫面同尺度`。

### 驗證規則

- 用跟 `影片轉流程` 自我驗證同一組引擎公開 API:先建範本庫並逐張登錄,再以整張驗證畫面為搜尋區域查詢,預期尺度 1。
- 門檻用 arknights profile 的引擎參數(匹配門檻、比色門檻),不另訂。
- 每張範本在比色關、比色開各驗一次。
- 範本 X 在某張驗證畫面上**通過**的條件:
  - 畫面上每一張未售完的 X 卡,都有匹配落在它的圖示位置附近。容許偏離沿用影片轉流程的位置容許值。
  - 沒有任何匹配落在別種商品的卡上(不論那張卡是否售完)。
  - 售完的 X 卡上有沒有匹配都不計。
- 範本整體的判定:
  - **通過**:在所有含它(未售完)的畫面上都通過。
  - **待重拍**:任一畫面不通過,或引擎無法登錄這張範本。
  - **未驗證**:沒有任何畫面出現它的未售完卡。
- 比色關、比色開分開判定,報告兩欄並列。檔名前綴 `待重拍_` 只看比色關的結果,因為比色關是找圖目標的預設。

### 交付物

- `採購中心範本\繁中\`、`採購中心範本\簡中\`:各 19 張 PNG,依判定命名。
- `採購中心範本\報告.md`,內容:
  - 兩種框法的比較,以及選中的是哪一種
  - 簡中量出的倍率
  - 每張範本在每張畫面上的本尊分數、最高別種商品分數及其名稱,比色關與比色開各一份
  - 三類清單(通過 / 待重拍 / 未驗證)
  - 這次沒做的商品清單
- 腳本、驗證畫面標註資料、挑出的驗證影格都放在這個功能的 `.scratch` 資料夾。重跑時清空兩個輸出子資料夾再重新產生。

## Testing Decisions

- 只有一個接縫:引擎公開 API 的「登錄 → 查詢」。驗收就是上述驗證規則在真實商店畫面上的結果,不看切圖程式的內部步驟。
- 不加 pytest。這是一次性腳本,不進 app、不進打包版、不進 `tools/`。
- 先例是影片轉流程的自我驗證:同樣先建範本庫並逐張登錄、對影格以預期尺度 1 查詢、用同一個位置容許值。可以直接沿用它的作法,但不修改它。
- 標註資料本身也要核對:執行者把標註框疊回驗證畫面存成圖,目視確認每張卡的名稱與位置正確,再跑驗證。

## Out of Scope

- 採購中心流程本身:白名單、優先順序、購買步驟、信用點不足的處理、刷新。
- 把 PNG 匯入任何流程存檔,或改動 profile、打包版資料。
- 在倉庫畫面上找圖(這組範本是商店尺度,在倉庫畫面上會小 2.6%)。
- 素材裡沒有的商品:基礎/初級作戰記錄、技巧概要·卷1/卷2、家具零件,以及其他偶爾上架的商品。
- 三階以上材料(pic3、pic2 的藍圈與紫圈)。
- 折扣標籤、售完狀態、價格的辨識。
- 正式化成 `tools/` 底下的工具或 app 功能。

## Further Notes

grill 期間用 OpenCV 實測過(還不是專案引擎)的數據:

- pic1 與 demo2 第 144 秒的商店畫面同尺度,最佳比例 1.00:
  - 聚酸酯標題列分數 0.959,圓圈圖示 0.970。
  - 卡片間距兩邊都是 312 px。
  - 所以 pic1 是繁中最大化客戶端的 1:1 截圖。
- 倉庫圖示比商店圖示大 2.6%:
  - 黃圈直徑,商店 151.2 px、倉庫 155.2 px。
  - 糖、固源岩、聚酸酯、異鐵四種完全一致。
- 倉庫切圖(中心上方 120×80)對 pic1 的分數:

| 倉庫圖示 | 縮 ×0.975 左右 | 原尺寸 | 最高的別種商品 |
|---|---|---|---|
| 糖 | 0.993 | 0.940 | 約 0.43 |
| 固源岩 | 0.986 | 0.915 | 約 0.53 |
| 聚酸酯 | 0.994 | 0.921 | 約 0.58(龍門幣) |

- 倉庫與商店的圓圈顏色相同,圈內紋理底相同。不同的地方:
  - 圈外背景不同。
  - 數字框的寬度不同。
  - 商店有折扣標籤與「售完」斜帶。
- 影片解析度:
  - demo2 是 1920×1024(繁中)。
  - demo1、demo5、demo6 是 1696×912(簡中)。
  - 所有影片都沒有倉庫畫面。
- 風險:之前試過把繁中範本拿到簡中畫面用,深度驗證只有 0.5~0.8(門檻 0.8)。那次的範本含文字。這次的物品圖示不含語系文字,但縮放失真仍可能讓簡中組分數不夠。驗不過的照規則標 `待重拍_`,之後改從簡中客戶端的倉庫截。
