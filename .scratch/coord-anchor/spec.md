# 存下的座標改以座標基準點為原點(coord-anchor)

Status: ready-for-agent

## 需要你決定的

### 開啟舊格式存檔時,存成搜尋範圍比例的座標怎麼辦?

決定(2026-10-09):(c)拒絕開啟。

舊格式＝座標空間標記仍是「相對搜尋範圍」的存檔。四份在用流程會一次性換算,所以這裡只影響舊流程(你準備刪掉)與外面帶進來的舊檔。受影響的有:固定矩形、絕對座標、以搜尋範圍為基準的指定點、範本拍攝位置。

- (a)可開可看,受影響的步驟標警告、執行前擋下(建議):同「找圖相連」不成立的處理;使用者重拾那幾個座標就能跑。範本拍攝位置直接丟掉(之後比對測試會補記)。
- (b)開檔時用當下畫面找校準對自動換算:不必重拾;但存檔沒記當時視窗在哪,視窗挪過就靜靜換錯。
- (c)拒絕開啟:最簡單;舊檔完全不能看。

決定(2026-10-09):只處理兩次執行之間的挪位與縮放;執行中不重量。

### 座標基準點取哪一點?

決定(2026-10-09):校準對第一張圖的中心。

## Problem Statement

流程裡的固定矩形存成「搜尋範圍的比例」,絕對座標以搜尋範圍左上角為原點,範本拍攝位置直接存螢幕座標。搜尋範圍是使用者每次執行前手框的,框不精準:同一個遊戲視窗,今天框寬 5 像素、明天框高 3 像素,四份流程裡上百個固定矩形就一起偏掉,找圖變慢或找不到。簡中客戶端是視窗模式,挪了位置就得重框,重框又引入新的誤差。視窗縮放也一樣:步驟座標會乘上畫面倍率,但固定矩形是比例,跟著手框的範圍走,而不是跟著遊戲畫面走。

使用者的期待是:不管遊戲視窗擺在螢幕哪裡、範圍框得鬆一點緊一點,從流程的角度看,步驟都不受影響。

## Solution

每次執行開頭校準時,校準對第一張圖(標題列圖示)的中心就是這次的**座標基準點**。存檔裡所有的座標數值——固定矩形、絕對座標、範本拍攝位置——都改存成相對座標基準點的偏移,單位是流程尺度;執行時 ×畫面倍率再加上座標基準點的螢幕位置。搜尋範圍只剩「在哪裡截圖找圖」一個用途,框得比遊戲畫面大一點也沒關係。

編輯器每次拾取時,用拾取的那張截圖找校準對,當下就得出座標基準點與倍率,存的時候換回流程尺度、相對基準點的偏移;不必再手動按「校準」。

九宮格退場;最接近指定點只以原點為基準。四份在用流程用執行紀錄的校準位置一次性換算。

## User Stories

### 執行

1. 身為流程使用者,我希望簡中視窗挪了位置、重框搜尋範圍之後,固定矩形還框在遊戲畫面上同一處,這樣我不必重設上百個框。
2. 身為流程使用者,我希望搜尋範圍框得比遊戲畫面大一點(多框到桌面)也不影響任何步驟,這樣我框的時候不必對準到像素。
3. 身為流程使用者,我希望兩次框的範圍差幾個像素時,同一份流程的落點完全一樣,這樣流程行為可以重現。
4. 身為流程使用者,我希望簡中視窗被拉大或縮小後,固定矩形跟著遊戲畫面等比縮放,這樣不必因為縮放而重設。
5. 身為流程使用者,我希望絕對座標的座標點擊與拖曳也以座標基準點為原點,這樣它們跟固定矩形一樣不受視窗位置影響。
6. 身為流程使用者,我希望開頭校準只在搜尋範圍內找校準對,這樣兩個客戶端同時開著時不會認錯另一個視窗的標題列。
7. 身為流程使用者,我希望忘了重框、校準對不在搜尋範圍內時,流程一個輸入都不送並說明原因,這樣不會在錯的位置亂點。
8. 身為流程使用者,我希望執行紀錄寫出這次量到的座標基準點位置與倍率,這樣出問題時可以對照。
9. 身為流程使用者,我希望固定矩形有一部分落在搜尋範圍外時照常裁掉、照常找,這樣行為跟現在一樣。
10. 身為流程使用者,我希望以原點為基準的限定範圍、相對座標、找圖偏移的行為都不變,這樣既有流程的其他部分不必重新驗證。
11. 身為流程使用者,我希望確認圖、忙碌指示這些找圖目標的固定矩形也照同一套基準,這樣所有找圖的地方一致。
12. 身為流程使用者,我希望最接近指定點以原點加偏移為準,偏移 (0,0) 就是最接近原點,這樣它也不受搜尋範圍影響。
13. 身為流程使用者,我希望沒有原點時,用到最接近指定點的步驟無法執行並提示,同相對座標。

### 編輯器拾取

14. 身為流程作者,我希望在畫面上框固定矩形時,app 用那張截圖找校準對、存成相對座標基準點的偏移,這樣我框的當下視窗在哪裡都沒關係。
15. 身為流程作者,我希望拾取時自動用當下量到的倍率換回流程尺度,這樣在縮小的視窗上編輯、忘了按校準也不會存錯尺度。
16. 身為流程作者,我希望截範本時也用當下量到的倍率縮放、用當下的基準點記下拍攝位置,這樣範本與它的拍攝位置都對。
17. 身為流程作者,我希望拾取絕對座標、拖曳端點時也同樣換算,這樣所有拾取一致。
18. 身為流程作者,我希望拾取當下在搜尋範圍內找不到校準對時,app 不存並提示我重框,這樣不會靜靜存下錯的座標。
19. 身為流程作者,我希望流程還沒設校準對時,拾取固定矩形、絕對座標會被擋下並提示先設校準對,這樣不會存出沒有基準的座標。
20. 身為流程作者,我希望相對座標、以原點為基準的限定範圍在沒有校準對時仍可拾取,這樣新流程可以先做這些。
21. 身為流程作者,我希望預設原點 ◎ 退用範本拍攝位置時,依當下的座標基準點換到螢幕上,這樣視窗挪過之後 ◎ 仍標在圖實際的位置。
22. 身為流程作者,我希望比對測試找到圖時補記的拍攝位置也存成相對座標基準點,這樣補記的資料與其他座標同一套。
23. 身為流程作者,我希望比對測試套用固定矩形時,用當下截圖的座標基準點換算,這樣測試結果與執行時一致。
24. 身為流程作者,我希望「校準」鈕只顯示目前量到的倍率,這樣我能確認畫面大小,但不必為了存對座標而去按它。
25. 身為流程作者,我希望編輯器裡把存下的座標畫回螢幕的預覽(例如固定矩形的框)也用當下的座標基準點,這樣預覽跟執行時的位置一致。
26. 身為流程作者,我希望限定範圍的選項不再有九宮格,這樣不會做出受手框影響的設定。
27. 身為流程作者,我希望最接近指定點的設定只剩「相對原點的偏移」,拾取時點的位置自動減掉原點並換回流程尺度。

### 校準對

28. 身為流程作者,我希望換校準對時,app 在同一張畫面上同時找新舊兩對,把所有存下的座標依兩個基準點的差平移,這樣換對之後每個落點都不變。
29. 身為流程作者,我希望換校準對時舊對找不到就不能換並說明原因,這樣不會在不知道差多少的情況下換掉基準。
30. 身為流程作者,我希望第一次設校準對時,當下畫面就是流程尺度、當下的第一張圖中心就是座標基準點,這樣新流程可以直接開始拾取。

31. 身為流程作者,我希望存檔標記新的座標空間,這樣 app 分得出哪些存檔已是相對座標基準點。

35. 身為流程作者,我希望拷貝一份存檔到另一台電腦、視窗擺在不同位置,框好範圍就能跑,這樣搬遷不必重設座標。

## Implementation Decisions

### 座標基準點與校準

- 校準量測回傳的結果除了兩張圖的中心與倍率,也明確提供座標基準點(第一張圖中心)的螢幕位置;執行與編輯共用同一個量測函式。
- 執行器開頭校準後保存這次的座標基準點,執行中不重量。校準只在搜尋範圍內查(搜尋範圍未設＝全螢幕,沿用現有語意)。
- 檔案日誌的 calibrate 紀錄已含兩個中心,保持不變;執行紀錄(UI)多寫一行座標基準點位置。

### 座標換算

- 存檔座標 → 螢幕:座標基準點 + 偏移 ×畫面倍率(四捨五入,同現有 scale_px)。螢幕 → 存檔座標:(螢幕 − 座標基準點) ÷ 倍率。這一對換算是共用的純函式,執行器、編輯器、換算工具都用它。
- 絕對座標(座標點擊、拖曳兩端點)的基準從搜尋範圍左上角改成座標基準點。
- 固定矩形改存相對座標基準點的偏移與寬高(流程尺度,整數像素);限定範圍算螢幕矩形時換算後再裁到搜尋範圍內(裁的行為不變)。
- 九宮格從限定範圍移除;限定範圍剩三選一。
- 挑選規則「最接近指定點」只剩相對原點的偏移;拿掉基準欄位。
- 範本拍攝位置(工作區與存檔裡的範本元資料)改存相對座標基準點的偏移(流程尺度)。

### 存檔格式

- 存檔版本升一號,座標空間標記換成新值(例如「anchor」)。步驟草稿同一套。
- 舊格式一律拒絕開啟:座標空間標記不是新值的存檔、步驟草稿、舊 JSON、舊流程包都不讀,提示原因;既有的舊格式遷移(螢幕→搜尋範圍座標空間、範本收進找圖目標、去副檔名、丟每步門檻)隨之退場。步驟草稿是舊格式時不復原、開空白並提示。
- 因為舊檔不再能開,九宮格與以搜尋範圍為基準的指定點不需要讀檔遷移,只要從寫入與 UI 移除。

### 編輯器

- 所有在螢幕座標與存檔座標之間換算的地方(拾取固定矩形、絕對座標、拖曳、指定點、截範本、記拍攝位置、預設原點推算、比對測試、預覽),都用「這次拾取或這次操作用的那張截圖」量座標基準點與倍率;不再有跨操作保存的編輯器倍率。
- 量不到(搜尋範圍內找不到校準對、兩張重疊)＝該次操作不存,提示原因。流程沒有校準對時,需要座標基準點的拾取直接擋下並提示先設校準對;只依原點的拾取不受影響。
- 「校準」鈕改成只量測並顯示目前倍率,不影響任何存下的值。
- 換校準對:同一張截圖裡新舊兩對都要找到;新對的基準距離沿用現有算法(量到的距離 ÷ 舊對量出的倍率);所有存下的座標(固定矩形、絕對座標、範本拍攝位置)依兩個座標基準點的差(換回流程尺度)平移。

### 影片轉流程工具

- 範本拍攝位置改成相對影片裡量到的座標基準點(影片尺度＝流程尺度,倍率 1);存檔蓋新版本與新座標空間標記。工具仍只產出找圖與相對座標、以原點為基準的限定範圍。

### 一次性換算(.scratch 工具)

- 對象:早_簡中、早_繁中、晚_簡中、晚_繁中四份存檔,與 profile 的步驟草稿(若對應其中一份)。
- 輸入:各存檔的搜尋範圍,與 10/08 執行紀錄量到的座標基準點——簡中兩份範圍 [87,57,1718,920]、基準點 (115,76);繁中兩份範圍 [0,0,1920,1024]、基準點 (20,19);倍率都是 1。
- 換算:固定矩形比例 → 依存檔搜尋範圍還原成螢幕矩形 → 減座標基準點;範本拍攝位置 → 減座標基準點;流程裡若有九宮格或以搜尋範圍為基準的指定點,列出來不換(四份目前都沒有)。
- 先備份到 .scratch,遵守「重新打包前把使用者資料移出 dist」的既有做法。

## Testing Decisions

好測試只看外部行為:送出的點擊落點、每次查詢實際截的範圍與裁的矩形、存下的步驟資料、對話框的提示;不看內部欄位。

### 接縫一:執行器 harness

- 沿用 harness 的假偵測器與假輸入。把校準對擺在不同螢幕位置、搭配不同倍率與不同的搜尋範圍,斷言:絕對座標落點＝基準點+偏移×倍率;固定矩形查詢的裁切矩形跟著基準點走、與搜尋範圍框法無關;超出範圍的部分照裁;最接近指定點以原點+偏移挑;校準只在搜尋範圍內查、範圍內找不到就一個輸入都不送。
- harness 預設把校準對擺在搜尋範圍左上附近;不在意校準的既有測試照舊寫。test_coord_space 的語意改成「以座標基準點為準」並改寫;test_runner_scale 的絕對座標案例跟著改。
- 前例:test_runner_calibrate、test_runner_findtarget、test_coord_space、test_runner_scale。

### 接縫二:編輯器對話框

- 沿用 `_Driver` 真按按鈕、拾取覆蓋層樁;假截圖裡擺校準對的位置與距離。斷言:框固定矩形存下的偏移;縮放的視窗上拾取自動除以當下倍率;找不到校準對時不存並提示;沒校準對時擋下;換校準對後重新換算出的螢幕位置不變;「校準」鈕只顯示倍率;九宮格不在選項裡;指定點只存相對原點的偏移。
- 會開 Tk 視窗,照既有做法在隱藏桌面跑。
- 前例:test_editor_scale、test_fixed_rect_ui、test_calibration_ui。

### 接縫三:存檔格式

- 純函式:新格式寫讀往返;舊格式存檔、舊 JSON、舊流程包、舊草稿一律拒絕並帶原因;草稿同一套。既有的舊格式遷移測試改成斷言拒絕或刪除。
- 前例:test_flow_open_save 與既有的格式遷移測試。

### 換算工具驗證與實跑驗收

- 換算工具自我驗證:每個固定矩形新舊螢幕矩形差 ≤1 像素;再照 fixed-rect-sweep 的手法,用示範影片影格把影格擺回實機搜尋範圍位置,新舊存檔逐個找圖目標比對命中。
- 實跑驗收:簡中視窗挪位置、重框範圍後跑一份簡中流程到完;繁中照常跑一份。實跑前先確認使用者在不在(會搶前景)。

## Out of Scope

- 執行中視窗挪動的追蹤(執行中不重量)。
- 自動找出遊戲視窗、讀視窗代號、全螢幕找校準對。
- 跨流程拷貝步驟時的座標換算(兩份流程的流程尺度與基準點不同,這是既有問題,本規格不處理)。
- 舊流程(日常_影片、arknight*、舊_早_簡中)的換算;使用者準備刪除。
- 並行執行(本輪未移植)。

## Further Notes

- 原點、預設原點的螢幕位置是執行期或拾取當下才有的值,不存檔,不受「存下的座標都相對基準點」的限制。
- 搜尋範圍是存檔裡唯一的螢幕座標(要先有它才找得到基準點),仍存在流程裡當上次框的預設值。
- 實作順序建議:共用換算函式與存檔格式 → 執行器 → 編輯器 → 影片轉流程工具 → 一次性換算 → 實跑。
