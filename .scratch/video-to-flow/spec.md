# 影片轉流程(video-to-flow)

Status: ready-for-agent

>    錄影程式畫不出點擊特效;改用遊戲游標本身的動作判定點擊——游標停著時,它在
>    按下、放開各抖一下。新增`游標樣本`(游標長相＋熱點,由 Claude 在幾幀標出游標尖端、
>    工具學出)與掃描的游標模式;畫面切換前沒看到特效的地方補低信心候選。學樣本是
>    掃描的輔助入口(`learn_cursor` / `learn-cursor`),測試也打它。

## Problem Statement

現在建一份`流程`只能在編輯器裡一步一步手動加:每個找圖步驟都要切到遊戲、`拾取`
截一張`範本`、設偏移、設`點擊後確認`、排順序。一份明日方舟日常流程動輒幾十步,
建一次要花很久,而且使用者本來就會在遊戲裡把整套操作親手走一遍——那一遍的資訊
(點了哪裡、按了什麼、畫面怎麼變)全都浪費了。

使用者想要的是:把自己操作一遍的錄影交出去,拿回一份**盡量能直接跑**的流程存檔;
它同時就是一般的步驟清單,有問題直接在編輯器裡修。

難處在於錄影只是像素:影片裡的位置不等於螢幕座標(只錄遊戲視窗、尺寸可能不同),
影格經過壓縮、畫面上有游標與錄影程式的`點擊特效`,鍵盤按鍵也看不到。

## Solution

**`影片轉流程`由 Claude 依專案 skill 完成,不是 app 功能。** 使用者:

1. 在 app 裡把`搜尋範圍`框在遊戲畫面上(步驟草稿會自動存下來)。
2. 用自己的錄影程式**只錄遊戲視窗**,開著點擊特效,完整操作一遍——這就是`示範影片`。
3. 把影片交給 Claude,視需要口頭補充「這裡按了 Esc」之類影片看不出來的事。

Claude 依 skill 跑一套固定程序:先用工具**掃描**影片找出每一次點擊的候選
(時間、位置、前後影格縮圖),逐一覆核、判斷每次點擊的語意,寫出一份
`轉換計畫`;再用工具**組裝**:依`影片換算比`換算座標、從乾淨影格裁範本、用引擎對
影格**自我驗證**每張範本、把驗證沒過的標成`待重拍`,最後寫出一份一般的流程存檔
放進 profile 的流程清單,另附`交付報告`。

產出的流程以找圖為主、座標為輔:有辨識度的按鈕/圖示一律找圖;點空白處或格狀清單
某一格才用相對於`原點`的座標點擊,沒有可用原點時自動插入`定位找圖`。過場等待靠
下一步找圖的輪詢,不寫死等待;明顯重複的動作序列收成`重複區段`;影片裡沒看到的
彈窗不會被發明成`分岔`,只在報告裡建議。

## User Stories

1. 身為使用者,我想把一段自己操作遊戲的錄影交給 Claude 就拿回一份流程存檔,這樣我不必在編輯器裡一步一步手動建。
2. 身為使用者,我想產出的流程盡量能直接跑,這樣我只需要修少數有問題的步驟。
3. 身為使用者,我想產出的就是一般的流程存檔,這樣我能用既有的編輯器檢查、修改、排序、存檔。
4. 身為使用者,我想產出的存檔直接出現在目前 profile 的流程清單裡,這樣我不必另外搬檔或匯入。
5. 身為使用者,我想產出的存檔絕不覆蓋我現有的任何流程,這樣轉換出錯也不會毀掉我已經調好的流程。
6. 身為使用者,我想只用 app 既有的「框搜尋範圍」動作告訴 Claude 遊戲畫面的大小,這樣我不必自己量或算視窗客戶區尺寸。
7. 身為使用者,我想錄影視窗大小與執行時視窗大小不同時也能轉換,這樣舊影片在我換了視窗大小後仍可用。
8. 身為使用者,我想在影片與搜尋範圍的長寬比對不上時被明確告知並停下來,這樣不會拿到每個偏移都差幾個百分點的流程。
9. 身為使用者,我想新流程沿用我框好的搜尋範圍,這樣找圖只在遊戲畫面內進行、比較快也比較少誤判。
10. 身為使用者,我想點擊在有辨識度的按鈕上時被轉成找圖步驟,這樣遊戲 UI 位移或載入時間變化時流程仍然點得準。
11. 身為使用者,我想點在空白處或一排長得一樣的卡片其中一張時被轉成相對座標點擊,這樣不會因為找圖找錯同款圖示而點錯。
12. 身為使用者,我想第一個動作就是點空白處時,前面自動多一個定位找圖,這樣相對座標點擊一定有原點可依。
13. 身為使用者,我想原點來自很久以前(中間畫面早已換過)的座標點擊也自動補一個定位找圖,這樣點擊前畫面一定已經到位。
14. 身為使用者,我想流程裡不出現絕對座標點擊,這樣我日後搬動遊戲視窗、重框搜尋範圍都不會讓流程點歪。
15. 身為使用者,我想相對座標的偏移由工具依引擎在影格上實際找到的位置推算,這樣偏移與執行時`原點`的定義完全一致。
16. 身為使用者,我想拖曳也被辨識並轉成相對座標的拖曳步驟,這樣捲動清單之類的操作也能重現。
17. 身為使用者,我想過場與載入用「下一步找圖輪詢」等待而不是寫死毫秒數,這樣遊戲慢一點也不會點空。
18. 身為使用者,我想影片裡載入明顯很久的地方,對應找圖步驟的逾時被放寬,這樣不會因為預設逾時太短而在正常載入中失敗。
19. 身為使用者,我想找圖點擊後、下一步也是找圖時預設用「點到下一步的圖出現」確認,這樣點擊沒生效會自動補點。
20. 身為使用者,我想下一步不是找圖時點擊後確認改用「目標圖消失」,這樣與我現有流程的慣例一致。
21. 身為使用者,我想「找不到時」預設是停止,這樣流程不會在錯誤的畫面上繼續亂點。
22. 身為使用者,我想完全一樣的動作序列連續出現時被收成重複區段,這樣「連領 5 個獎勵」不會變成 5 段重複的步驟。
23. 身為使用者,我想影片裡沒出現的彈窗不被憑空加成分岔,這樣流程裡不會有沒有範本、不會被驗證的猜測步驟。
24. 身為使用者,我想在交付報告裡看到「這裡可能需要分岔」的建議,這樣我知道哪裡日後可能卡住、要自己補。
25. 身為使用者,我想範本取自按鈕已出現、游標還沒移過來、沒有點擊特效的乾淨影格,這樣範本不被游標、hover 反白或特效污染。
26. 身為使用者,我想範本保持影格原尺寸、不被縮放,這樣不會因為插值再損一次畫質;尺度交給引擎的尺度搜尋處理。
27. 身為使用者,我想`影片換算比`超出引擎設定的尺度範圍時被警告或拒絕,這樣我不會拿到一份引擎根本找不到範本的流程。
28. 身為使用者,我想每張範本交付前都用引擎對影格驗證過——該點的那一幀找得到且位置對、還沒出現的那幾幀找不到,這樣能直接跑的機率大幅提高。
29. 身為使用者,我想驗證沒過或找不到乾淨影格的範本名稱帶`待重拍`前綴,這樣我在範本面板一眼就看得出哪些要重拍。
30. 身為使用者,我想待重拍的範本仍然放進存檔、步驟仍然建好,這樣我只要重拍那張圖,不必重建步驟。
31. 身為使用者,我想範本用按鈕上的中文命名(例如「開始行動」),這樣與我現有流程一致、看得懂。
32. 身為使用者,我想一份流程內範本名不重複,同一個按鈕多次出現共用同一張範本,這樣存檔不囤積重複的圖。
33. 身為使用者,我想一份交付報告列出每張待重拍範本的原因與重拍建議,這樣我知道該怎麼補救。
34. 身為使用者,我想交付報告列出「畫面變化無法用點擊解釋」的時間點,這樣我能補上影片看不到的按鍵步驟。
35. 身為使用者,我想交付時可以口頭補充「某處按了 Esc」,讓 Claude 把它變成按鍵步驟放在正確位置,這樣按鍵也能進流程。
36. 身為使用者,我想交付報告寫明這次用的影片換算比、搜尋範圍、步驟數與範本數,這樣我能判斷轉換條件是否正確。
37. 身為使用者,我想 profile 已校準且畫面倍率不是 1 時,座標先換回基準尺度再存,這樣產出的存檔符合「流程座標永遠是當前基準機器的尺度」的規則。
38. 身為使用者,我想轉換不改動 profile 的任何既有資料(草稿、校準、其他存檔、工作區),這樣轉換是純新增、隨時可丟。
39. 身為使用者,我想每次轉換都照同一套 skill 程序進行,這樣不同 session 的產出品質一致、規則可以迭代。
40. 身為 Claude,我想掃描工具替我找出每一次點擊的候選與前後影格縮圖,這樣我不必逐幀看數千張影格。
41. 身為 Claude,我想第一次處理某位使用者的影片時能從影片學到點擊特效的長相,這樣掃描能適應使用者用的錄影程式。
42. 身為 Claude,我想掃描結果附上候選的信心與影片像素位置,這樣我能快速剔除誤報、補上漏抓。
43. 身為 Claude,我想在轉換計畫裡用影片像素寫點擊位置與範本框,這樣我只描述「看到什麼」,換算與原點推算交給工具。
44. 身為 Claude,我想在轉換計畫裡用流程的步驟詞彙(找圖三態、點擊後確認、找不到時、重複區段…)描述步驟,這樣產出與編輯器裡建的一樣。
45. 身為 Claude,我想組裝工具在計畫有誤(引用不存在的範本、區段不成對、找圖不相連卻要「點到下一步的圖出現」)時清楚報錯,這樣我能修計畫重跑。
46. 身為 Claude,我想組裝可以重跑而不留下半成品,這樣修計畫後再組一次是安全的。
47. 身為 Claude,我想組裝寫存檔時走 app 既有的存檔寫入,這樣存檔格式只由一個地方決定。
48. 身為維護者,我想工具只有掃描與組裝兩個對外入口,這樣測試只打這兩處、內部怎麼拆都可以重構。

## Implementation Decisions

**整體形狀**

- 新增一個「影片轉流程」工具模組(放在 repo 的工具區,與既有一次性轉換工具同類),
  加上一個專案 skill(名稱 `video-to-flow`)描述 Claude 的完整程序。工具不進 app、
  不進打包版;app 程式碼不變。
- 工具對外只有兩個入口,中間由 Claude 判斷:
  - **掃描**:示範影片 → 候選點擊清單 + 每個候選前後數幀的縮圖。
  - **組裝**:轉換計畫 + 目標 profile → 自我驗證 → 流程存檔 + 交付報告。
- 兩個入口都提供命令列介面供 skill 呼叫,同時是可被測試直接呼叫的函式。

**掃描**

- 讀影片逐幀(或依步長)偵測`點擊特效`,輸出候選:影格編號/時間、影片像素位置、
  信心、可分辨時的種類(點擊/拖曳起訖)。
- 特效長相因錄影程式而異:掃描接受一個「特效樣本」描述(由第一次處理時從使用者
  影片學到、存在 skill 旁的設定裡);沒有樣本時退回以「局部短暫劇烈變化」偵測,
  寧可多報(誤報由 Claude 覆核剔除)。
- 縮圖輸出到 session 暫存目錄,不進 repo。

**轉換計畫(Claude 寫、組裝讀的介面)**

- 一份 JSON:示範影片路徑、目標 profile、步驟清單、範本清單。
- 步驟用流程既有的步驟種類與欄位詞彙;**點擊/拖曳位置一律寫影片像素的畫面位置**,
  不寫偏移、不寫相對座標——由組裝依`原點`規則推算。
- 每個找圖步驟引用一個範本名;範本清單給每張範本:取自哪一幀、影片像素裁切框、
  驗證用的「該找得到的幀」與(可選)「該找不到的幀」。
- 計畫可標示「此處需定位找圖」與要用哪張範本;組裝也會在「相對座標點擊前沒有原點」
  時拒絕並要求補上,而不是自己發明範本。

**組裝**

- **影片換算比**:從目標 profile 的步驟草稿讀`搜尋範圍`寬高,除以影片畫面寬高。
  寬、高兩個比值差距超過約 2% → 停止並報錯(不硬算)。換算比超出 profile 引擎設定
  的尺度範圍 → 報錯。沒有搜尋範圍 → 報錯並提示先在 app 框範圍。
- **裁範本**:依計畫從指定影格裁切,保持原尺寸寫成 PNG;不縮放。
- **自我驗證**:用引擎公開 API(`Engine.load_templates` 收`範本清單` + `query`)把
  計畫的範本登錄,對每張範本在指定影格上查詢:該找得到的幀要匹配且中心落在預期
  位置附近;該找不到的幀要不匹配。搜尋區域就是整張影格(影片＝遊戲畫面＝搜尋範圍)。
  驗證失敗或計畫標示無乾淨影格 → 範本名加`待重拍`前綴並同步改寫步驟引用。
- **原點推算**:依 runner 的原點規則模擬執行順序——找圖的原點＝引擎在該幀實際找到
  的框中心 + 偏移;座標點擊的原點＝落點;拖曳的原點＝終點;`更新原點`取消者不更新。
  每個座標點擊/拖曳的影片像素位置減去當下原點得到相對偏移;找圖點擊的偏移＝點擊
  位置減找到框中心。
- **座標換算**:所有偏移乘以影片換算比;若目標 profile 已校準且`畫面倍率`≠1,再除以
  畫面倍率,使存檔座標落在當前基準尺度(ADR 0005)。換算重用校準模組既有的步驟
  縮放函式,不另寫一份「哪些欄位是像素」的清單。
- **點擊後確認與找不到時**:計畫未指定時,組裝依規則補預設——下一步是找圖則
  「點到下一步的圖出現」,否則「目標圖消失」;找不到時預設停止;逾時預設 10 秒,
  計畫可依影片觀察到的載入時間放寬。組裝後檢查`找圖相連`,不相連卻要求「點到下一步」
  → 報錯。
- **寫存檔**:走 app 既有的流程存檔寫入(含格式標記);流程層級設定帶上草稿的搜尋
  範圍;不寫校準資料(校準屬於 profile)。檔名由計畫給,用 app 既有的「不撞名」規則
  落在 profile 的流程目錄;絕不覆蓋。先寫完整檔再落地,失敗不留半成品。
- **交付報告**:Markdown,與存檔同名並排(或寫到 Claude 指定位置):影片換算比、
  搜尋範圍、步驟數、範本數、待重拍清單(原因 + 重拍建議)、分岔建議、無法用點擊
  解釋的畫面變化時間點、Claude 寫入的口頭補充按鍵。

**skill 程序(video-to-flow)**

- 前置檢查:確認 profile 草稿有搜尋範圍、影片可讀。
- 掃描 → 覆核候選(看縮圖、剔誤報、補漏抓)→ 判斷每次點擊的語意與步驟種類
  (找圖為主、座標為輔)→ 為每張範本挑乾淨影格 → 收明顯重複為重複區段 →
  插入使用者口頭補充的按鍵 → 寫轉換計畫 → 組裝 → 讀驗證結果,能修的(換一幀、
  調框)修完重組,修不了的留`待重拍` → 交付存檔路徑與報告摘要。
- 範本命名用按鈕上的中文;同一按鈕多次出現共用一張範本。
- 不推測影片裡沒出現的分岔;不產出絕對座標。

**詞彙**

- `示範影片`、`影片轉流程`、`點擊特效`、`影片換算比`、`定位找圖`、`交付報告`、
  `待重拍` 已寫入 app 詞彙表。`轉換計畫` 是工具與 Claude 之間的介面,不是領域詞彙。

## Testing Decisions

- 好的測試只驗外部行為:給影片/計畫,看候選清單、存檔內容與報告;不驗內部怎麼切
  偵測、裁切、驗證。
- **只打兩個入口**:掃描、組裝。輸入一律在 tmp_path 用 OpenCV 的影片寫入合成小
  影片——畫幾個有紋理的假按鈕,在指定幀畫假點擊特效、在點擊前幾幀畫假游標。
- 掃描測試:合成影片中 N 次特效 → 候選含這 N 個時間/位置(容許誤差);沒有特效的
  影片 → 沒有高信心候選。
- 組裝測試(用真引擎,比照引擎端以合成 profile 跑真引擎的既有測試做法):
  - 搜尋範圍是影片的 1.5 倍 → 存檔中偏移與相對座標皆 ×1.5;範本 PNG 尺寸等於裁切框。
  - 長寬比不符、無搜尋範圍、換算比超出尺度範圍 → 報錯且 profile 流程目錄沒有新檔。
  - 相對座標點擊的偏移等於「點擊位置 − 前一個找圖在該幀實際找到的中心」×換算比。
  - 相對座標點擊前沒有原點 → 報錯。
  - 範本在該找得到的幀找不到(例如框到空白處)→ 名稱帶待重拍前綴、步驟引用同步改寫、
    報告列出。
  - 預設補值:下一步是找圖 → 點到下一步的圖出現;否則 → 目標圖消失;找不到時 → 停止。
  - 目標檔名已存在 → 另取不撞名的檔名,原檔內容不變。
  - profile 已校準且畫面倍率≠1 → 座標再除以畫面倍率。
  - 產出的存檔能被 app 既有的存檔讀取正常開啟,且帶搜尋範圍。
- 先例:app 端流程存檔讀寫測試(驗存檔內容)、校準換算測試(驗座標縮放)、引擎端
  合成影像 + 真引擎的測試輔助。

## Out of Scope

- app 內建的錄製功能(自己掛滑鼠/鍵盤事件)或 app 內「匯入影片」選單。
- 別人的攻略影片、不同語系或不同解析度機器錄的影片。
- 從影片辨識鍵盤按鍵(按鍵只靠使用者口頭補充)。
- 自動推測影片沒出現的彈窗分岔。
- 絕對座標點擊。
- 範本縮放到目標尺寸。
- 流程存檔格式或步驟欄位的任何變更(待重拍只靠範本名前綴與報告)。
- 轉換後實際開遊戲跑一遍的自動化驗收(由使用者實跑)。

## Further Notes

- 第一次實作時需要使用者的第一支示範影片來確定點擊特效長相;掃描在沒有特效樣本時
  的退路偵測只求不漏,誤報交給 Claude 覆核。
- 影片檔、縮圖、轉換計畫都放 session 暫存目錄或 `.scratch/**/tmp/`(已被忽略),
  不進版控。
- 自我驗證需要完整引擎(含深度驗證模型);在只能粗篩的環境下組裝應明說驗證不完整,
  而不是靜靜放行。
- 使用者常在玩明日方舟:skill 程序裡任何會動到真實螢幕或輸入的步驟都不該存在——
  影片轉流程全程只讀影片與 profile 檔案。
