# 流程存檔自包自足(self-contained flow file)

Status: ready-for-agent

## Problem Statement

`流程`與它用到的`範本`目前分家:步驟只存範本名,圖片存在 profile 的範本庫裡。
把流程檔複製到另一台電腦(或另一個 profile)時,對方沒有那些圖,流程一執行就
KeyError;必須另外記得走匯出流程包這條路,漏了就是缺圖跑不動。使用者要的是
「一份流程就是一個檔案,拿到哪台電腦都能跑」。

同時,本機上多出一個範本庫要維護:資料夾層級、命名空間、哪張圖還有沒有人用,
都變成使用者要管的事。使用者不想要本機有這麼一塊圖片存放區域;圖應該跟在流程
檔案裡面。

而選範本時又只看得到本 profile 範本庫裡的圖——想沿用另一份流程已經拍好的圖,
沒有入口。

## Solution

**一份流程＝一個自包自足的檔案。** 存檔是一個 zip,裡面同時裝著步驟清單、這份
流程引用到的每一張範本圖、`校準對`資料與範本元資料。複製這個檔案給任何人、放到
任何一台裝了同版 app 的電腦,直接開直接跑,不會缺圖。

**本機不再有範本庫。** profile 只剩`匹配門檻`設定、校準資料與流程存檔;app 端與
引擎端的 templates 目錄一起消失。編輯與執行時,app 把存檔解到一個可重建的**工作區**
給引擎讀,切換流程時整個清掉。

**選範本時看得到別份流程的圖。** 找圖步驟選範本的對話框列出本 profile 內每一份
流程存檔、可展開看裡面的範本縮圖,也可以直接從磁碟挑任意 PNG。**按下確定的那一刻**
才把選中的圖複製一份進本流程;取消就什麼都沒發生。撞到同名時自動加序號並改寫引用,
所以複製進來永遠不會蓋掉本流程已有的圖。

引擎那邊同步脫鉤:不再假設有一個 templates 目錄可掃,改成由呼叫端交付**範本清單**
(範本名 → 圖檔路徑)。`基準測試集`每個 case 自帶自己的模板圖,不再依賴 profile 的
範本庫。

## User Stories

### 搬遷與自包自足

1. 身為要把流程給另一台電腦用的使用者,我想要只複製一個檔案就搬完整份流程,這樣不會因為忘了帶圖而在對方機器上跑不動。
2. 身為收到別人流程檔的使用者,我想要直接開啟就能執行,這樣不必先問對方要範本圖。
3. 身為使用者,我想要存檔只包含被步驟引用到的範本,這樣流程檔不會隨著時間囤積用不到的圖而膨脹。
4. 身為使用者,我想要刪掉一個找圖步驟並存檔後,它專用的那張圖也跟著離開存檔,這樣檔案內容始終等於流程真正需要的東西。
5. 身為跨機器搬遷的使用者,我想要存檔繼續攜帶`校準對`兩張圖與`基準距離`,這樣`匯入換算`三分支(採用/換算/`來源基準`)照舊運作,座標不會落在錯的尺度上。
6. 身為開啟一份不在本 profile 裡的流程存檔的使用者,我想要系統複製一份副本進本 profile 再開,這樣原始檔不會被動到、`匯入換算`也只在這一刻做一次。
7. 身為使用者,我想要流程存檔沿用既有的 `.autoclickpack` 副檔名,這樣不必記兩種檔案類型。

### 選範本與複製

8. 身為建立找圖步驟的使用者,我想要在選範本時看到本流程已有的範本,這樣重複用同一張圖不必重拍。
9. 身為建立找圖步驟的使用者,我想要展開本 profile 內其他流程存檔、看到它們的範本縮圖,這樣可以沿用先前拍好的圖。
10. 身為選範本的使用者,我想要能直接從磁碟挑任意 PNG,這樣手邊已有的圖檔可以直接拿來當範本。
11. 身為選範本的使用者,我想要只有在按下確定時圖才被複製進本流程,這樣按取消就等於什麼都沒發生。
12. 身為從別份流程複製圖進來的使用者,我想要遇到同名時自動加序號並同步改寫步驟引用,這樣本流程原有的圖絕對不會被蓋掉。
13. 身為複製進圖之後的使用者,我想要本流程的那份副本從此獨立,這樣來源流程日後改圖不會偷偷改變我的流程行為。
14. 身為在找圖對話框裡現場截圖的使用者,我想要按取消時那張新截圖被丟棄,這樣取消就是取消,不會留下我沒要的範本。
15. 身為剛加入一張範本(上傳或截圖)的使用者,我想要看到「建議跑一次`比對測試`」的提示,這樣我會記得確認這張圖在畫面上真的找得到。
16. 身為使用者,我想要選範本的對話框在`引擎就緒`之前也能開、只是比對相關動作被擋,這樣單純挑圖不必等模型載入。

### 本流程的範本面板

17. 身為編輯流程的使用者,我想要主視窗的範本面板只列出**本流程**的範本,這樣我一眼看得出這份流程到底帶了哪些圖。
18. 身為使用者,我想要在面板上預覽、重新命名(同步改寫所有引用)、刪除範本,這樣管理範本的動作與現在一樣順手。
19. 身為使用者,我想要面板不再有資料夾層級,這樣一份流程幾十張圖不需要命名空間也不會混亂。
20. 身為使用者,我想要在面板上對單一範本跑`比對測試`,這樣確認某張圖在當前畫面找不找得到的路徑沒有消失。

### 本機檔案與工作區

21. 身為使用者,我想要本機不再有一個範本庫資料夾要維護,這樣圖片只存在於流程檔裡。
22. 身為使用者,我想要 profile 只剩`匹配門檻`設定、校準資料與流程存檔,這樣 profile 的職責一目了然。
23. 身為使用者,我想要 app 自動把存檔解到可重建的工作區給引擎讀,這樣我完全不必知道工作區的存在。
24. 身為使用者,我想要切換流程時工作區被清空(解出來的圖與`登錄產物`都清),這樣磁碟上不會殘留任何一張我沒在用的圖。
25. 身為使用者,我想要工作區毀損或被手動刪掉時能自動重建,這樣它永遠只是快取、不是真相來源。
26. 身為編輯到一半還沒存檔的使用者,我想要自動存檔只寫步驟草稿、不重壓整包 zip,這樣拖曳排序步驟時不會因為重寫幾十張圖而卡頓。
27. 身為當機後重開 app 的使用者,我想要草稿與工作區裡的圖一起被復原,這樣還沒存檔的編輯不會白做。

### 執行

28. 身為執行流程的使用者,我想要`範本預載`從工作區一次載齊本流程的範本,這樣執行期行為與現在完全一致。
29. 身為執行流程的使用者,我想要`急停`、`找不到時`、`區段`、`點擊後確認`等所有執行語意一字不變,這樣換存檔格式不會弄壞已經調好的流程。
30. 身為在倍率≠1 的機器上存檔的使用者,我想要`重定基準`照舊改寫 profile 內所有流程存檔的座標,這樣流程檔永遠維持單一尺度。

### 引擎與基準測試集

31. 身為引擎的呼叫端,我想要直接交付`範本清單`(範本名 → 圖檔路徑),這樣不必為了配合引擎而偽造一個 profile 目錄結構。
32. 身為引擎維護者,我想要引擎只剩一條取得範本的路徑,這樣不會有兩套讀取邏輯長期共存。
33. 身為引擎維護者,我想要`基準測試集`每個 case 自帶自己的模板圖,這樣 benchmark 完全不依賴 profile 的範本庫。
34. 身為引擎維護者,我想要 benchmark case 的新增方式仍然是「丟檔案就好、不改程式」,這樣加案例的成本不變。
35. 身為引擎維護者,我想要 bench 量到的登錄品質與 app 實際執行時相同(都是單張模板),這樣 benchmark 成績仍然代表使用者的真實體驗。

### 一次性轉換

36. 身為既有使用者,我想要程式碼完成後立刻有一次性轉換把我現有的流程與範本轉成新格式,這樣我不必手動重建任何一份流程。
37. 身為既有使用者,我想要開發用的 repo 資料與我實際在用的打包版資料都被轉換,這樣兩邊不會一新一舊。
38. 身為既有使用者,我想要轉換前先整包備份打包版的使用者資料,這樣轉壞了隨時能還原。
39. 身為既有使用者,我想要看到一份轉換報告(哪些範本因為降為單張而受影響、哪些被改名、哪些因為沒有被任何流程引用而消失),這樣我知道發生了什麼事。
40. 身為既有使用者,我想要範本名裡失去意義的前綴被拉平,這樣新的範本面板上的名字乾淨好認。
41. 身為既有使用者,我想要轉換完成後舊的範本庫與登錄產物目錄被刪除,這樣不會有人(或程式)不小心又去讀它們。

## Implementation Decisions

### 存檔格式

- **一份流程＝一個 zip 檔**,副檔名沿用 `.autoclickpack`。內容:步驟與流程層級設定的 JSON、本流程引用的範本圖、校準資料(`校準對`名稱與`基準距離`,以及那兩張校準圖)、範本元資料(`pos`)。
- **範本引用鍵是名稱**,與現行流程檔一致(正式名稱＝不含副檔名)。名稱在一份存檔內唯一,不再有子路徑/命名空間層級。
- **一個範本一張圖**。放棄多截圖範本;引擎的 `multi_capture` 登錄能力本身不移除,只是 app 不再產生多截圖範本。
- **存檔只寫入被步驟引用的範本**(含`確認圖`)。未被引用的範本不進 zip。
- **`pos` 只記本流程自己拍的圖**。跨流程複製進來的圖與從磁碟上傳的圖沒有 `pos`(與現行「上傳的範本沒有記錄」一致)。
- **校準資料照舊隨存檔攜帶**,ADR 0005 的`匯入換算`三分支(採用 / 依基準距離比值換算 / 標記`來源基準`並警告)語意完全不變。

### 本機檔案配置

- **profile 保留**,內容剩下:引擎參數設定(含`匹配門檻`)、校準資料(校準對兩張圖與基準距離、本機`畫面倍率`與`機器指紋`)、流程存檔目錄。
- **profile 的範本庫目錄與登錄產物目錄移除**。判定一個資料夾是不是 profile,改看引擎參數設定檔是否存在(原本看範本庫目錄)。
- **`校準對`的兩張圖由 profile 自己存一份**(指定校準對時把選中的圖複製進去),與流程存檔解耦——刪任何一份流程都不會弄壞校準。
- **工作區**是 profile 底下可重建的快取:存放當前流程解出來的範本圖與引擎的登錄產物。**切換流程時整個清空**(圖與登錄產物一起刪),是刻意選擇的取捨:磁碟上不留任何非當前流程的圖,代價是切回去時該流程的範本要重新登錄。
- **工作區是快取、存檔是真相來源**。工作區被刪或毀損時自動重建。

### 存檔與工作區的純邏輯模組(接縫 1)

- 新增/擴充**一個**資料進資料出的模組,統包:存檔的讀寫、打包範圍(只包被引用的)、跨流程複製與撞名加序號並改寫引用、工作區的解壓與清空、以及一次性轉換所需的規則。UI 與 runner 只呼叫它。
- 現行的舊格式匯入邏輯(舊 autoClick flow JSON、舊流程包、座標空間遷移、每步 `threshold` 丟棄、範本引用去副檔名)併入同一個模組,不另立門戶。
- **匯出動作移除**(存檔本身就是可搬移的檔);**匯入保留**,職責是舊格式的單向轉換與外來檔的複製落地。
- 開啟不在本 profile 內的存檔＝複製副本進 profile 後開啟,之後的存檔寫進副本。
- **自動存檔只寫步驟草稿**(輕量 JSON),圖留在工作區;按存檔才打包成 zip。
- **`重定基準`改寫 profile 內所有流程存檔的步驟座標**(zip 內的圖不動),含草稿。漏改任何一份就會出現混尺度,這條規則不變。
- 撞名自動改名只寫進執行紀錄,不彈對話框。

### 引擎接口(接縫 3)

- **引擎改收`範本清單`**:呼叫端交付「範本名 → 圖檔路徑」與登錄產物的存放位置,引擎不再掃描目錄、不再假設 profile 的範本庫佈局。
- **舊的「掃目錄」入口取代掉、不保留**,避免兩條讀取路徑長期共存。app 與 bench 都改走新入口。
- 引擎參數設定的載入方式不變(仍讀 profile 的設定檔覆蓋預設值)。
- **`基準測試集`的 case 契約改為自帶模板圖**:每個 case 資料夾放一張自己的模板圖,不再以範本名引用外部範本庫。新增 case 仍然是「丟檔案就好、不改程式」。
- 引擎與 app 的依賴方向不變(單向:app → 引擎)。辨識仍然只有一條路徑(ADR 0002)。

### app 與引擎之間(接縫 2)

- **`enginehub` 對外形狀一個字不改**(`query` / `preload` / `ensure_template` 與生命週期狀態)。改的只是它內部如何取得範本:從「探索 profile 目錄」換成「以當前流程的工作區組出範本清單交給引擎」。
- 範本增刪改後的輕量重探索入口保留,語意改成「重新掃工作區並讓登錄產物失效」。
- runner 的偵測接縫與注入方式不變,執行期一行不改。

### UI

- **主視窗範本面板 → 本流程的範本清單**:預覽、重新命名(同步改寫引用)、刪除、`比對測試`。資料夾層級移除。
- **選範本對話框**:左側樹狀列出「本流程」與本 profile 內其他流程存檔(可展開看各自的範本,含縮圖),右側預覽(名稱、尺寸、來源);另有一個從磁碟挑 PNG 的入口。**按確定才複製**。
- **上傳或截圖新範本後,提示建議跑`比對測試`**,不自動比對(自動比對需要`清場`截圖與`引擎就緒`,成本與時機都不合適)。
- **在找圖對話框現場截圖後按取消＝丟棄該圖**。現行`確認圖`「截圖即時存檔、取消對話框圖仍留下」的行為一併改成丟棄。
- 選範本對話框在引擎未就緒時仍可開啟,只有比對類動作走既有的就緒 gating。

### 一次性轉換

- 轉換在程式碼完成後**立刻執行一次**,不是 app 內建的長期遷移路徑(app 只讀新格式)。
- 涵蓋開發用資料與打包版的使用者正式資料;**動打包版之前先整包備份**。
- 每份舊流程 JSON → 一個新存檔,收進它引用的範本。
- **多截圖範本取登錄基準張(排序後第一張)**,其餘丟棄。
- **範本名拉平**(去掉子路徑前綴),撞名依既定規則加序號並改寫引用。
- 轉換完成後刪除舊的範本庫與登錄產物目錄。
- 產出轉換報告:降為單張的範本、被改名的範本、未被任何流程引用而消失的範本。

### 文件

- `app/CONTEXT.md`:刪除 flow pack 詞條(它與`流程`合一了),改寫`流程`與`範本`詞條,新增「工作區」等新詞;`CONTEXT-MAP.md` 的詞彙界線段落同步更新(app 的範本不再是 profile 範本庫裡的檔案)。
- 新增一篇 ADR(編號接續現有),涵蓋兩件事:流程存檔自包自足、引擎改收範本清單。記下取捨:放棄多截圖登錄品質與跨流程共用同一份圖,換得「一個檔案就能搬」。

## Testing Decisions

**好的測試只驗對外行為。** 這裡的對外行為是:存檔檔案的內容(裡面有哪些範本、步驟引用指向誰)、開啟後得到的流程資料、工作區在各操作之後的狀態、以及執行器實際做出的動作序列。不要斷言內部欄位、不要斷言私有函式被呼叫。

**接縫 1(存檔與工作區,主戰場)**
- 用暫存目錄真測、不 mock,沿用現行純檔案邏輯測試的既有手法(舊格式匯入/匯出與 profile 管理的測試就是這樣寫的)。
- 覆蓋:存檔只包被引用的範本;刪步驟後存檔那張圖離開;跨流程複製撞名加序號並改寫引用;確定前不複製、取消後檔案系統無變化;工作區解壓與切流程清空;草稿只寫步驟不重壓 zip;校準資料隨存檔攜帶並在三種匯入分支下正確落地;`重定基準`改寫 profile 內每一份存檔(含草稿)。
- 舊格式匯入的既有測試全部保留當回歸線(座標空間遷移、每步 `threshold` 丟棄、範本引用去副檔名)。

**接縫 2(app ↔ 引擎)**
- `enginehub` 的既有測試沿用:生命週期狀態、就緒 gating、`範本預載`、單張載入的 KeyError 語意。
- **執行器整張回歸網(runner 的步驟/區段/原點/倍率/舞台測試與流程預載測試)一行不改就要能通過**——假件形狀不變是這次改動的硬性驗收條件。任何需要改 harness 假件形狀的設計都是走錯了。

**接縫 3(引擎)**
- 引擎既有測試改走範本清單入口,斷言不變(登錄產物重用、遮罩、多尺度、驗證)。
- bench 測試改成 case 自帶模板圖,並在轉換後跑一次完整`基準測試集`,把總體成績與轉換前對照記錄下來——多截圖降為單張的實際影響必須量出來,不能只是推測。

**GUI**
- 沿用既有手法:`event_generate` 走互動路徑(選範本對話框的展開/選取/確定/取消)、PrintWindow 擷取畫面驗證版面、色票與樣式名稱靠既有的掃描測試當靜態防線。
- 「按取消不留下任何檔案」這種只有互動才會執行到的路徑,必須真的用事件走一遍,不能只拍靜態畫面。
- modal 對話框的 grab 行為若有變動,依既有紀律用真實輸入注入驗證(合成事件繞過 grab 路由,測不出卡死)。

**打包版冒煙**
- 轉換與改動完成後重新打包,並在打包版上實際開啟一份轉換後的流程、執行一小段,確認範本預載與點擊落點正常。真實輸入的冒煙要先確認使用者不在使用電腦。

## Out of Scope

- **多截圖範本的 UI 與登錄品質改善**:本次明確放棄 app 端的多截圖範本。引擎的 `multi_capture` 能力保留但不再被 app 使用。日後若要恢復,是另一個題目。
- **跨流程共用同一張圖(參照而非複製)**:本次確定採快照語意,複製後各自獨立。
- **上傳/截圖後自動即時比對並在清單顯示比對值**:本次只做提示,不做自動比對。
- **並行執行**:未移植,本次不碰。
- **profile 的改名與刪除 UI**:仍然交給檔案總管。
- **流程存檔的版本控制策略**:範本圖搬進存檔後不再進版控,本次不處理「如何讓範本圖回到版控」這個問題。
- **舊的 `_orig`、旋轉、翻新解析度等已移除功能**:不恢復。

## Further Notes

- **已知並接受的代價**(在需求釐清時逐項確認過):
  - 現有約 40 個雙截圖範本降為單張,`可變區`(計數文字、半透明卡片透出的底色)的遮罩品質會退步,`基準測試集`成績可能下滑。**必須實測並記錄**。
  - 早晚兩份流程共用的十幾張圖變成各存一份,日後在一邊重拍不會同步到另一邊。
  - 切換流程清空工作區＝每次切換都要重跑該流程全部範本的登錄。
  - 兩個未被任何流程引用的範本會在轉換中消失。
- **最重要的回歸線**:執行期行為零變化。存檔格式與範本來源全都改了,但`找不到時`、`區段`、`點擊後確認`、`更新原點`、`畫面倍率`換算等執行語意一個都不能動。
- 引擎與 app 是兩個 bounded context:同一次改動橫跨兩邊,但依賴方向仍是單向,且辨識只有一條路徑。做引擎那側的改動時不要讓引擎知道 app 的存檔格式。
