# 03 — 流程存檔(zip)與工作區的純邏輯模組

**What to build:** 一個資料進資料出的模組,統包新存檔格式的全部規則與工作區的生命週期。這是本 feature 的主接縫:整套格式規則不必開 GUI 就能驗。

一份`流程`＝一個 zip(副檔名沿用 `.autoclickpack`),內容:步驟與流程層級設定、本流程引用的範本圖、校準資料、範本元資料(`pos`)。

工作區是 profile 底下可重建的快取:當前流程解出來的範本圖與`登錄產物`都放這,**是快取不是真相來源**,被刪或毀損時自動重建。

現行的舊格式匯入邏輯(舊 autoClick flow JSON、舊流程包、座標空間遷移、每步 `threshold` 丟棄、範本引用去副檔名)一併併入本模組,不另立門戶。

**Blocked by:** 無 — 可與 01/02 並行。

**Status:** resolved

- [x] 能把「步驟＋範本圖＋校準資料＋範本元資料」寫成一個存檔,並讀回等價的資料
- [x] 存檔**只寫入被步驟引用的**範本(含`確認圖`);刪掉引用它的步驟後再存,那張圖離開存檔
- [x] 範本引用鍵是名稱,名稱在一份存檔內唯一、沒有子路徑層級
- [x] 從另一份存檔複製範本進來時,撞名自動加序號並**同步改寫**本流程的步驟引用
- [x] 複製進來的圖是獨立副本(來源日後改圖不影響本流程)
- [x] `pos` 只記本流程自己拍的圖;複製進來的與磁碟上傳的沒有 `pos`
- [x] 能把存檔解到工作區、能清空工作區、工作區不存在時自動重建
- [x] 舊格式匯入的既有測試全數保留為回歸線並通過
- [x] 一次性轉換所需的規則(多截圖取登錄基準張、範本名拉平、撞名加序號)以可單獨呼叫的形式存在本模組,供票 04 與 09 使用
- [x] 全部以暫存目錄真測、不 mock,沿用現行純檔案邏輯測試的手法
