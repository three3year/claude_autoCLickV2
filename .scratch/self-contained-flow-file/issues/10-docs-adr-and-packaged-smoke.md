## code-review 後的修正（2026-08-18）

`/code-review` 的兩軸審查抓到三個**真的 bug**（都沒有測試覆蓋，所以先前全綠是假象）：

1. **`匯入換算`的「採用」與「來源基準」分支落地後校準是死路** —— 存檔帶來的校準圖
   從來沒有被寫進 profile 自存位置，所以「請按『校準』量測本機倍率」這句建議做不到、
   `來源基準`流程也永遠歸不了位。修法：`_apply_import_calibration` 一併落地校準圖
   （採用＝整批取代；不同對＝**併入**，本 profile 自己那一對不能被蓋掉）。
2. **指定校準對失敗會摧毀舊校準** —— 先 `store_calibration_images`（會 rmtree）再量測，
   量測失敗就留下「calibration.json 指名一對圖、圖卻已被刪」的殘局。修法：改成
   **先用本流程工作區裡那兩張量**，量成功了才複製進 profile。
3. **`重定基準`遇到壞掉的存檔會中斷** —— `zipfile.BadZipFile` 不在 catch 的例外清單裡，
   一份壞檔就會讓迴圈在改寫到一半時拋出＝**混尺度**（正是這條規則要防的事）。

另外補上兩處與 spec 有落差的地方：

4. **選範本對話框左側現在每一列都有縮圖**（spec：「可展開看裡面的範本縮圖」）。
   改用 `ttk.Treeview`，展開某個來源時才去讀它的圖（沒展開就完全不碰那份存檔）。
5. **取消整個找圖對話框時，這次加進來卻沒被引用的範本一併丟棄**（spec：「現行`確認圖`
   『截圖即時存檔、取消對話框圖仍留下』的行為一併改成丟棄」）——先前只有選範本
   對話框自己的取消符合，外層對話框取消仍會留下圖。

以及 Standards 軸的修正：一次性轉換的規則（校準對拉平、舊 meta 讀取）搬回
`flowfile`（「不另立門戶」）、選範本對話框的來源改成一個小型別（收掉三處重複的
三分支）、`ui_dialogs` 不再越過 `App` 的接縫去戳 `app.ws` 與私有方法、
一行 no-op、兩個誤導的名字。

**測試紀律修正**：測試跑到一半彈出了真的 modal 對話框、蓋在使用者畫面上等人按
（測試時間 42s→3.3s 就是證據）。`app/tests/conftest.py` 加了 autouse fixture，
任何 app 測試都不准彈出真的對話框；詢問類一律回「否」，要「是」的測試自己覆蓋。

重新打包並再跑一次不注入輸入的冒煙：引擎 5.54s 就緒、本流程 17 個範本、
全套 365 個測試綠燈、`基準測試集`仍是 38/38。

## 真實輸入冒煙（打包版，2026-08-18）

**設計成只碰兩個視窗**：自己開的靶視窗、以及 AutoClick 自己的「開始執行」按鈕；
不會點到使用者其他任何東西。注入前再查一次 idle（實測 461 秒）。

作法：開一個置頂靶視窗（畫獨特圖案）→ 截靶標當範本 → 用 `flowfile` 組出一份
**新格式存檔**並解到工作區 → 臨時 profile 啟動打包版 exe → 用 `PrintWindow` 取
視窗點陣圖找出綠色「開始執行」鈕 → `win.click` 真的按下去 → runner 找圖點擊 →
靶視窗記錄落點。

| 項目 | 結果 |
|---|---|
| 引擎載入 | 2.34s，非 coarse-only |
| 流程載入 | 新格式存檔 → 工作區 → `smoke_target` 範本就位 |
| `範本預載` | 通過（找圖步驟查得到範本，沒有 KeyError） |
| **點擊落點** | 實際 `(-940, 329)` vs 預期 `(-940, 330)` → **誤差 (0, −1) px** |
| 多螢幕負座標 | 靶視窗在左螢幕（x 為負），落點照樣正確 |
| 收尾 | exe 關閉、`app_state.json` 還原成 arknights、臨時 profile 刪除 |

那 1px 是匹配框中心 `w // 2` 的整數捨入，與既有行為一致。

過程中踩到、值得記下的兩件事（都不是產品的 bug）：
- Windows 會把新視窗開在「前景視窗那一台螢幕」——靶視窗置頂在左螢幕時，
  AutoClick 會跟著開過去而且尺寸怪掉（444×353），「開始執行」被擠出可視範圍。
- 用 `capture.grab` 截視窗會受 z-order 影響（截到蓋在上面的視窗）；
  找自家視窗裡的元件要用 `PrintWindow`。
