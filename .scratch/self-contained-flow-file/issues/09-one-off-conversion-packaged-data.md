# 09 — 一次性轉換(打包版正式資料)

**What to build:** 把使用者**實際在用的打包版資料**轉成新格式。開發用資料已在票 04 轉過,這張票負責正式資料,並補正兩邊落差。

轉換不是 app 內建的長期遷移路徑——app 只讀新格式,轉換跑完就功成身退。

**動打包版之前先整包備份。** 打包版有三個 profile,其中的流程存檔與部分 profile 不在版控裡,轉壞了只能靠備份救。

**Blocked by:** 05, 08

**Status:** ready-for-agent

- [ ] 轉換前把打包版的整個使用者資料目錄複製一份備份到旁邊,並在報告裡寫明備份位置
- [ ] 每份舊流程 JSON 轉成一個新存檔,收進它引用的範本(含`確認圖`)
- [ ] 多截圖範本取登錄基準張(排序後第一張),其餘丟棄
- [ ] 範本名拉平(去掉子路徑前綴),撞名加序號並同步改寫引用
- [ ] `校準對`兩張圖依票 05 的規則落到 profile 自存位置,基準距離與倍率／指紋原樣保留
- [ ] 轉換完成後刪除舊的範本庫目錄與登錄產物目錄
- [ ] 產出轉換報告:降為單張的範本、被改名的範本、未被任何流程引用而消失的範本、每份流程的步驟數與範本數對照
- [ ] 轉換後在打包版資料上實際載入每一份流程,確認範本數與步驟引用都對得起來
- [ ] repo 開發資料與打包版資料兩邊格式一致,沒有一新一舊
