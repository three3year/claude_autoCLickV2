# Spec：文件階段——README 與 app/CLAUDE.md 重寫

Status: ready-for-agent

專案整理地圖的最後一個階段（地圖票 01 的階段 5）。範圍只剩 README 與 `app/CLAUDE.md` 其餘部分（執行語意已在階段 2 搬進 `docs/flow-format.md`）；驗收是「文件裡每個指令與路徑實際跑得通」。寫法依 `writing-for-agents` 的原則：單一正本、環境能查的不抄、過期的刪、只有部分情境才需要的東西放到指標後面。詞彙以根目錄 `CONTEXT.md`、`app/CONTEXT.md` 為準。

## 需要你決定的

### app/CLAUDE.md 要分層還是原地修整？

決定(2026-10-21)：(a) 分層。

現在 354 行、8 節：架構 127 行、踩過的坑 66 行、測試手法 46 行、UI 慣例 27＋14 行、建置 27 行、座標 13 行、執行語意指標 28 行。每一行都還活著，但每次開 session 都整份載入，改一個對話框也要讀完 ttk 的坑與執行器的函式表。

- (a) 分層（建議）：`app/CLAUDE.md` 只留每個改動都要知道的——架構地圖、契約（辨識單一路徑、啟動契約、流程資料夾、一份流程一個尺度、座標系統）、建置與部署、已移除清單；「踩過的坑」「測試手法」「UI 慣例」各成一份 `docs/agents/` 底下的檔案，`CLAUDE.md` 每份一行指標，寫清楚什麼時候要讀（改 Tk／覆蓋層／grab 的程式碼、寫或改 app 測試、改版面或樣式）。代價：坑在指標後面，agent 沒照指標讀就撞到；指標的措辭要盯緊。目標 `app/CLAUDE.md` 約 150 行。
- (b) 原地修整：節不動，只刪過期、合併重複、把長段落收短。代價：仍是三百多行、每輪都載入。
- (c) 只修事實：內容與結構都不動，只改錯的路徑與符號。代價：這階段等於沒做「重寫」。

### README 的定位？

決定(2026-10-21)：(a) 一份 README、兩大段。

現在是引擎 README（使用、接呼叫端、調參、基準測試集、架構）前面插一段 AutoClick。讀者有兩種：要跑 AutoClick 的人、要改引擎的 agent。

- (a) 一份 README、兩大段（建議）：上半「AutoClick」給使用者（安裝、啟動、流程資料夾、打包、常見問題指向），下半「主體偵測引擎」給開發者（公開 API、引擎參數與調參表、基準測試集、兩階段架構、測試）。代價：README 仍約 150 行。
- (b) 拆兩份：README 只有總覽與指向，引擎細節搬到引擎自己的說明檔。代價：多一份檔、多一個指標。

## Problem Statement

README 與 `app/CLAUDE.md` 是六個整理階段一路改出來的：每階段只改自己動到的句子，沒有人從頭讀過一遍。結果是文件裡混著三種東西：還對的、已經錯的（README「調參」說「只改 `config.yaml`」，設定檔早就沒了；`CONTEXT-MAP.md` 還指著剛刪掉的 `library.load_config`）、以及對但沒人需要每次都讀的（ttk 樣式的坑、雙擊事件要連發兩次）。agent 開 session 讀到過期的指令會照做然後失敗；讀到三百多行的坑清單會漏掉真正要守的契約。沒有任何東西擋文件過期：函式改名、檔案搬家，文件照樣綠。

## Solution

把兩份文件各自重寫一次：事實逐條對照現在的 repo，過期的刪或改；每個意思只留一個正本，環境能查到的（pyproject 的 testpaths、目錄佈局）不抄；只有部分情境才需要的參考資料移到指標後面，正文只留每個改動都要知道的契約與地圖。加一支「文件對照」pytest 當靜態防線：文件裡每個反引號路徑、指令、`模組.符號`、md 連結都要在 repo 裡找得到，找不到就紅。驗收時文件裡每個指令手動各跑一次。

## User Stories

1. 身為要跑 AutoClick 的使用者，我要 README 開頭就是「怎麼裝、怎麼啟動、流程放哪、怎麼打包」，這樣不必先讀引擎原理。
2. 身為使用者，我要 README 裡每個指令貼到終端機就能跑，這樣不必猜它是不是過期的。
3. 身為使用者，我要 README 說清楚打包版與原始碼版各把使用者資料放哪，這樣知道流程與日誌去哪找。
4. 身為改引擎的 agent，我要 README 的引擎段給我公開 API 的呼叫方式（範本清單、引擎參數、登錄產物位置、預期尺度、比色）與各參數的意義，這樣不必翻原始碼才知道怎麼接。
5. 身為改引擎的 agent，我要「症狀 → 參數」的調參表仍然在，而且說的是現在的調法（流程 `engine:` 段覆蓋、內建預設在哪），這樣遇到漏抓誤判知道動哪一個。
6. 身為改引擎的 agent，我要 README 的基準測試集一段跟根目錄 `CLAUDE.md` 的「必跑」規則只有一個正本、另一邊指過去，這樣改規則只改一處。
7. 身為改引擎的 agent，我要 README 的兩階段架構描述跟現在的程式一致（單張遮罩、登錄產物住呼叫端指定的位置），這樣不會被舊的「跨拍攝穩定度」誤導。
8. 身為改 app 的 agent，我要 `app/CLAUDE.md` 開頭是模組地圖與必守的契約，這樣讀前一百行就知道改哪裡、不能破什麼。
9. 身為改 app 的 agent，我要契約（辨識單一路徑、啟動契約與 gate、流程資料夾與唯一入口、一份流程一個尺度、座標一律偏移量、清場中不辨識）每條一個段落、定義與坑放在一起，這樣讀一段就拿到那個概念的全部。
10. 身為改 app 的 agent，我要「踩過的坑」依主題分組（Tk／grab／覆蓋層、Windows API 與截圖、執行器與輸入），這樣改哪一塊只讀那一組。
11. 身為改 app 的 agent，我要只有改 Tk／覆蓋層／grab 才需要的坑放在指標後面，指標寫明觸發條件，這樣改執行器時不必載入它們。
12. 身為寫 app 測試的 agent，我要「測試手法」自成一份，指標說「寫或改 `app/tests` 時讀」，這樣寫測試時找得到假件點、隱藏桌面、stub_dialogs 這些做法。
13. 身為改 UI 的 agent，我要「UI 慣例（已拍板）」自成一份且只有一份（現在拆在兩節），這樣不會改回已經拒絕的設計。
14. 身為 agent，我要已移除的功能清單只有一份、且不用反引號寫（它們不存在），這樣文件對照測試不會把它們當成要存在的符號。
15. 身為 agent，我要 `app/CLAUDE.md` 的「建置與部署」寫清楚打包指令實際怎麼跑（`build.bat` 由程式呼叫會壞編碼，agent 要直接跑 PyInstaller 打到新資料夾再換名）與打包後的冒煙怎麼做（noUAC 版、隱藏桌面），這樣收尾打包不用再翻 memory。
16. 身為 agent，我要文件不再重述環境能查到的事（pytest 的 testpaths、打包產物結構、流程資料夾佈局——後者的正本是 `docs/flow-format.md`），這樣那些東西不會在文件裡過期。
17. 身為 agent，我要文件裡每個反引號的 repo 路徑都真的存在，這樣照著路徑開檔不會撲空。
18. 身為 agent，我要文件裡每個 `模組.符號`（函式、類別、方法、常數）都在那個模組裡找得到，這樣函式改名時文件會紅、不會靜靜過期。
19. 身為 agent，我要文件裡每個指令（`python -m …`、腳本路徑、`.bat`）都能解析到 repo 裡的模組或檔案，這樣指令不會指向刪掉的工具。
20. 身為 agent，我要文件裡每個 md 連結的目標檔都存在，這樣指標不會斷。
21. 身為 agent，我要文件對照測試隨根目錄 `pytest` 一起跑、不載引擎不開視窗，這樣全套測試不變慢。
22. 身為 agent，我要測試紅的時候訊息指出哪份文件、哪個片語、用哪條規則解析失敗，這樣修文件不用猜。
23. 身為 agent，我要文件裡的佔位寫法（`<範本名>`、`%LOCALAPPDATA%`、`tmpl_NNN`）有固定格式讓測試跳過，這樣不必為了測試把例子寫死。
24. 身為 agent，我要「流程資料夾裡的名字」（`flow.yaml`、`templates/`、`.cache/`）以 app 程式裡的佈局常數為準來解析，這樣佈局改了文件會紅。
25. 身為使用者，我要 `CONTEXT-MAP.md` 指向的引擎 API 清單跟現在一致（`load_config` 已退場），這樣詞彙表不指向不存在的符號。
26. 身為使用者，我要驗收時文件裡每個指令手動各跑一次（含打包、啟動原始碼版、基準測試集、檢查指令），這樣「跑得通」不是只有靜態檢查。
27. 身為使用者，我要這次打包順便把刪多張圖路徑後的引擎帶進打包版，第一次開流程會自動重建登錄快取、照常能跑，這樣基準集階段的改動真的送達。
28. 身為使用者，我要 `app/CLAUDE.md` 的每一段都還能回答「這改變 agent 的行為嗎」，模型本來就會做的句子刪掉，這樣文件不長出沒用的沉積。
29. 身為使用者，我要重寫後的文件用根目錄 `CONTEXT.md`、`app/CONTEXT.md` 的詞（範本清單、流程尺度、座標基準點、清場、辨識中），不用它們標為「避免」的詞，這樣文件跟程式碼講同一種話。
30. 身為使用者，我要根目錄 `CLAUDE.md` 這階段不加新指標（寫流程靠 skill 觸發、開發靠 `app/CLAUDE.md`，地圖票 10 已定），這樣根檔不長。
31. 身為使用者，我要專案整理地圖在這階段結束時註記六個階段全部完成，這樣地圖收尾。

## Implementation Decisions

- **文件對照測試**（接縫一，唯一的新接縫）：一支 app 測試，沿用格式規範對照測試的寫法。輸入是 README、`app/CLAUDE.md`、從它分出去的 `docs/agents/` 檔、三份 CONTEXT；對每份文件抽出四類片語並解析：
  - 反引號路徑：含 `/` 或 `\`、或以已知副檔名結尾的片語。依序對 repo 根、`app/`、`app/automation/`、`app/tests/`、`tests/`、`tools/` 解析，任一存在即通過。流程資料夾內的名字（`flow.yaml`、`templates/`、`.cache/` 與其子目錄、`交付報告/`）對 app 的佈局常數解析，不對磁碟。
  - 指令：bash 區塊的每一行與反引號裡以 `python`、`.venv/Scripts/python`、`tools/`、`app\` 開頭的片語；`-m 模組` 要能 `find_spec`，路徑要存在；指令的參數不檢查。
  - `模組.符號`：模組名在 app 頂層、`automation/`、`subject_detection/` 之一時，符號要是該模組頂層的 def／class／大寫常數；`App.x`、`Runner.x`、`hub.x`、`store.x`、`win.x` 對應到固定的類別或模組（App→`app.py`、Runner→`runner.py`、hub→`EngineHub`、store→`FlowTemplates`），符號要是該類別的方法或在 `__init__` 設定的屬性。
  - md 連結：目標去掉 `#` 片段後要存在；`http(s)` 不檢查。
  - 跳過規則固定三條：含 `<…>` 的佔位、含 `%…%` 的環境變數、含 `*`／`NNN` 的樣式。「已移除」的名字一律不用反引號寫——文件的寫法規則，不是測試的例外清單。
  - 失敗訊息格式：`文件:行號 片語 — 規則名`，一次列出全部失敗。
- **`app/CLAUDE.md`**（依「需要你決定的」第一題；以下照 (a) 寫，選 (b) 則同樣內容留在原檔）：
  - 正文順序：一句定位 → 架構地圖（模組一行一個，只寫職責，不寫慣例）→ 契約（每條一段：辨識單一路徑、啟動契約與 gate、流程資料夾與唯一入口、範本與引用、一份流程一個尺度、存檔座標一律偏移量、清場中不辨識／背景辨識、拾取檢查）→ 建置與部署（含 agent 打包法與冒煙法）→ 已移除清單（不用反引號）→ 指標三行（坑、測試手法、UI 慣例）。
  - 分出去的三份住 `docs/agents/`，各自開頭一句「什麼情況讀」；內容逐條檢查相關性，過期的刪（例：`App.editor_scale` 已移除就不再提它），重複的（UI 慣例兩節）合併。
  - 執行語意一節維持「正本在 `docs/flow-format.md`，這裡只留哪個函式負責」，併進契約。
  - 建置與部署補上 memory 裡的兩條：`build.bat` 由程式呼叫會壞編碼、agent 直接跑 PyInstaller 到新資料夾再換名；冒煙用 noUAC 版在隱藏桌面啟動。這階段打包一次，帶上 ADR 0016 之後的引擎（打包前確認使用者資料不在 dist 裡——現在設計上就沒有）。
- **README**（依第二題；以下照 (a) 寫）：
  - 上半 AutoClick：安裝、啟動、流程資料夾與流程存放區（只指向 `docs/flow-format.md`，不重述佈局）、使用者資料位置、打包與部署、哪裡看日誌。
  - 下半引擎：定位一句、公開 API 範例（現在的 `load_templates`／`query`）、接呼叫端三條、引擎參數與調參表（改「只改 config.yaml」為「內建預設＋流程 `engine:` 段覆蓋」，表格內容逐列核對門檻與方向）、基準測試集（格式與指令留在這裡當正本，根目錄 `CLAUDE.md` 的「必跑」段改成規則＋指向 README 的格式）、兩階段架構（單張遮罩、登錄產物位置由呼叫端指定）、測試指令（一行，涵蓋 pyproject 的三個 testpaths）。
  - 「驗收紀錄」不恢復；舊集數字不再出現。
- **`CONTEXT-MAP.md`**：引擎 API 清單拿掉 `library.load_config`，改成「引擎參數由 app 合併內建預設與流程覆蓋後交付」。其他 CONTEXT 檔只在對照測試紅時改。
- **根目錄 `CLAUDE.md`**：「引擎基準測試集」段保留規則（前後必跑、基線比對、已知失敗可少不可多），案例格式指向 README；不加其他指標。
- **地圖**：Notes 註記文件階段完成、六階段全部結束。
- **順序**：對照測試先寫（紅：現在的文件就會抓到 `load_config` 等）→ 修事實與重寫 → 測試綠 → 手動跑每個指令 → 打包 → 地圖註記。

## Testing Decisions

- 好的測試只看文件對外的承諾：寫的路徑在不在、寫的符號在不在、寫的指令能不能解析。不測文件的措辭、長度、節的順序。
- **接縫一：文件對照測試**。先例是格式規範對照測試（`docs/flow-format.md` 的欄位表對 flowfile／flowdefaults）。要有的案例：
  - 現有文件每個片語都解析得過（主測試；重寫完成的定義）。
  - 四類片語各一個反例：不存在的路徑、不存在的符號、指向已刪模組的指令、斷掉的連結——用暫存 md 餵給同一個解析函式，斷言紅且訊息含行號與規則名。
  - 三條跳過規則各一個例子不會紅。
  - 流程資料夾內的名字對佈局常數解析：改常數（monkeypatch）文件就紅。
- 不寫測試的部分：文件內容的正確性靠逐條對照原始碼＋手動跑指令；分層後指標措辭是否讓 agent 真的去讀，沒有自動化驗證。
- 全套測試要綠（app 全套在隱藏桌面跑）。
- 最後驗收：文件裡每個指令手動各跑一次——安裝指令跳過（已裝），其餘：原始碼啟動 app（隱藏桌面冒煙）、打包、noUAC 冒煙、基準測試集、pytest、`tools/flow_check` 對一份在用流程、影片轉流程的 `--help`。

## Out of Scope

- `docs/flow-format.md`、三個 skill、`docs/agents/` 既有三份（issue-tracker、triage-labels、domain）的內容。
- 根目錄 `CLAUDE.md` 加指標或改結構。
- ADR 內容（歷史文件，過期的提法不改）。
- `flows/*/交付報告/` 裡的舊說法。
- 文件對照測試檢查指令的參數、連結的 `#` 片段、`http(s)` 連結是否可達。
- 英文版文件。

## Further Notes

- `app/CLAUDE.md` 現有內容絕大多數仍正確（每階段都有同步），這階段的主要工作是分層、去重、補打包法，不是重查每一條。真正過期的已知有：README 的「只改 config.yaml」「測試只跑 tests/」、`CONTEXT-MAP.md` 的 `load_config`、README 架構段的登錄描述（已在基準集階段改）。
- 一次性的文件稽核腳本（抓反引號片語對 repo 解析）在基準集階段的 scratchpad 試過：README 6 個可疑、`app/CLAUDE.md` 32 個，其中真的錯的只有上面那幾條，其餘是解析規則太窄（`capture.py` 要對 `app/automation/` 解析、`App.dirty` 是屬性）——對照測試的解析規則就是照這些誤報定的。
- 打包這次會帶上基準集階段的引擎改動；舊打包版的登錄快取在流程資料夾的 `.cache/registered/`，第一次開流程會自動重建（約 82 張 7.5 秒，之後沿用）。
- 地圖票 10 的決定：根 `CLAUDE.md` 不加指標。本階段遵守。
