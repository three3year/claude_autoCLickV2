# Spec：畫面倍率超出支援範圍時不執行

Status: ready-for-agent

決策正本：ADR 0013 決策 1（2026-10-11 修正為區間外不執行）。詞彙以 `app/CONTEXT.md` 為準（`支援倍率範圍`詞條已是目標狀態）。

## 需要你決定的

### 支援倍率範圍要不要擴大到 ×0.70？

決定（2026-10-11）：不擴大；縮到範圍外只要明確告知不能用。

- 擴大到約 ×0.65–1.15：要多尺度範本或引擎改成放大截圖，拾取檢查與驗收也要跟著擴。
- 不擴大，只告知不能用（建議）：沒有額外代價；使用者平常不會縮到那麼小。

### 執行時量到區間外怎麼辦？

決定（2026-10-11）：拒跑並說明。

- 拒跑並說明（建議）：開頭就擋，不會半途點錯。
- 警告一次後照跑：保留彈性，但繼續之後一樣不保證。
- 維持照跑、只記一行紀錄：改動最少，半途出錯一樣難看。

### 編輯器量到區間外怎麼辦？

決定（2026-10-11）：只警告、不擋。

- 只警告、不擋（建議）：跟拾取檢查「只警告不擋存檔」一致。
- 拒絕拾取：不會混進壞範本，但想看一下、測一下都不行。
- 編輯器不動：小視窗下編輯沒有任何提示。

### 確認圖認不出時補做要不要加上限？

決定（2026-10-11）：不改，交給區間外不執行。

- 補做次數上限（全流程共用常數）：認不出時頂多多點幾次。
- 步驟可勾「開關類：不補做」：要逐步設定，網路吃掉點擊時就沒救。
- 不改：10/11 鈴鐺補做 8 次是倍率出界才認不出確認圖，區間外不執行後就擋掉。

### 測試接縫用哪幾個？

決定（2026-10-11）：執行器 harness 與編輯器 UI 測試兩個現有接縫，見 [Testing Decisions](<#Testing Decisions>)。

## Problem Statement

2026-10-11 使用者把繁中客戶端的遊戲視窗縮到畫面倍率 ×0.700 執行早_繁中。座標都點對了，但十多張範本粗篩只有 0.14–0.53，全卡在粗篩；第 9 步鈴鐺的確認圖「待辦事項」認不出，於是補做了 8 次，待辦面板被開開關關，後面整串步驟跟著逾時或跳過。

ADR 0013 定了`支援倍率範圍` ×0.85–1.15，但當時決定「不擋執行、區間外照跑」。結果使用者只會看到一路逾時，看不出根本原因是視窗太小，而且流程在半途靜靜做錯。編輯器那邊也一樣：在範圍外截的範本會被放大回`流程尺度`再存，變糊，拾的座標誤差也跟著放大，卻沒有任何提示。

## Solution

開頭`校準`量到的`畫面倍率`落在支援倍率範圍外時，流程不執行，跟校準對找不到一樣。執行紀錄寫明這次量到的倍率、支援範圍，以及遊戲視窗該調大還是調小。測試選取也走同一條路。

編輯器在拾取當下或按「校準」鈕量到範圍外時，介面紀錄印一行警告，說明在這個大小拾取的範本與座標不可靠；拾取照做、資料照存。

支援範圍本身不變，補做規則也不變。

## User Stories

1. 身為使用者，我要遊戲視窗縮得太小時流程開頭就不執行，這樣才不會半途點錯、把遊戲狀態弄亂。
2. 身為使用者，我要遊戲視窗放得太大時流程開頭就不執行，理由同上。
3. 身為使用者，我要不執行時的訊息寫出這次量到的倍率，這樣我知道現在的視窗離可用的大小差多少。
4. 身為使用者，我要訊息寫出支援的倍率範圍，這樣我知道要調到哪裡。
5. 身為使用者，我要訊息直接說「把遊戲視窗調大」或「調小」，這樣不必自己判斷方向。
6. 身為使用者，我要倍率剛好是 ×0.85 或 ×1.15 時照常執行，這樣範圍的兩端都算支援。
7. 身為使用者，我要「測試選取」也照同一條規則擋，這樣測一小段時不會出現跟正式執行不同的行為。
8. 身為使用者，我要主校準對找不到、改用備用校準對量到範圍外時也一樣不執行，這樣規則不因用哪一組而不同。
9. 身為使用者，我要倍率出界時一個輸入都不送（不點、不拖、不移游標），這樣遊戲畫面維持原狀。
10. 身為使用者，我要執行多輪時，開頭那一次校準（整次執行只量一次）出界就整次不執行，這樣不會跑了幾輪才發現。
11. 身為維護者，我要檔案日誌在倍率出界時記一筆校準事件，寫明量到的倍率與結果，這樣事後查 `autoclick.log` 看得出這次為什麼沒跑。
12. 身為使用者，我要按「校準」鈕量到範圍外時介面紀錄印一行警告，這樣編輯時就知道目前視窗大小不能用來跑流程。
13. 身為使用者，我要按「校準」鈕量到範圍外時仍顯示倍率與基準點，這樣我還是看得到量測結果。
14. 身為流程作者，我要在範圍外拾取範本、座標、矩形時介面紀錄印一行警告，說明這個大小拾取的東西不可靠，這樣我知道要把視窗調回來再拾取。
15. 身為流程作者，我要範圍外的拾取照樣完成、資料照存，這樣我想在小視窗下看一下、測一下也可以。
16. 身為流程作者，我要拾取檢查（縮放餘裕、矩形餘裕、唯一）的行為不因這次改動而改變，這樣既有的警告照舊。
17. 身為維護者，我要支援倍率範圍的兩端只定義在一個地方，執行端、編輯器、拾取檢查共用，這樣日後改範圍只改一處。
18. 身為使用者，我要倍率在範圍內時，執行、校準鈕、拾取的行為與訊息跟現在完全一樣。

## Implementation Decisions

- **範圍常數搬到校準模組**：支援倍率範圍兩端（0.85、1.15）目前定義在拾取檢查模組，改成定義在校準模組；拾取檢查改用校準模組的常數。範圍是閉區間，端點算支援。
- **校準結論多一個「在不在範圍內」的判斷**：成功的校準結論（`Calibrated`）提供是否在支援倍率範圍內，以及範圍外時該調大或調小的說明文字。這不是新的失敗種類：`ok`／`problem` 的意義不變，因為編輯器在範圍外仍要照常拾取。判斷用校準算出的倍率（含量測抖動貼齊 1 之後的值）。
- **執行端**：開頭校準成功之後、寫入倍率與基準點之前，查是否在範圍內。範圍外時：
  - 檔案日誌寫一筆校準事件，結果為範圍外，帶量到的倍率、用的是哪一組校準對、距離與基準距離（欄位比照現有的成功與找不到）。
  - 照現有「開頭校準失敗：… → 不執行」的方式丟出錯誤，訊息寫倍率（三位小數）、支援範圍 ×0.85–1.15、「請把遊戲視窗調大」或「調小」。
  - 不送任何輸入。用備用校準對量到的也一樣。
  - 開頭校準在哪裡做，這條規則就套在哪裡：包括測試選取；多輪執行只在整次執行開頭量一次，就在那裡擋。
- **編輯器「校準」鈕**：量到範圍外時照常更新校準鈕文字、印出倍率與基準點，再多印一行警告（例如「目前畫面倍率 ×0.700 不在支援範圍 ×0.85–1.15，用這個大小執行會被擋、拾取的範本與座標不可靠；請把遊戲視窗調大」）。不彈 modal。
- **編輯器拾取**：所有拾取共用的「拾取當下量測」入口（含拾取檢查的安靜量測）在量測成功、倍率在範圍外時印一行警告，拾取照做、資料照存。警告寫在清場之外（清場中彈東西會卡死）；用介面紀錄，不彈 modal，避免每次拾取都要按一次確定。
- **補做、引擎、拾取檢查的門檻都不動**：ADR 0008 的補做規則、引擎粗篩與驗證、拾取檢查的三項判斷都不改。

## Testing Decisions

好的測試只看外部行為：送出了哪些輸入、執行紀錄與檔案日誌寫了什麼、介面紀錄有沒有警告、存下的資料是什麼；不測內部函式怎麼呼叫。

- **執行器 harness**：跟現有開頭校準測試同一組，用假偵測器擺出兩張校準圖的距離，造出想要的倍率。
  - ×0.70、×1.20 不執行：一個輸入都不送；紀錄有倍率、範圍、調大／調小；檔案日誌有一筆範圍外的校準事件。
  - ×0.85、×1.15 照常執行。
  - 主對找不到、備用對量到範圍外，也不執行。
  - 前例：「其中一張找不到 → 一個輸入都不送、紀錄寫明是哪一張」與「檔案日誌記兩張圖位置、距離、倍率」。
- **編輯器 UI 測試**：在現有校準鈕與拾取的 Tk 測試裡加案例（在隱藏桌面跑，見 memory `gui-tests-hidden-desktop`）。
  - 按「校準」量到範圍外：照常顯示倍率，另有一行警告，步驟資料不變。
  - 範圍外拾取一個座標：照存（值照樣除以倍率），另有一行警告。
  - 範圍內：沒有這行警告。
  - 前例：「按校準只顯示倍率與基準點、步驟資料不變」「拾取值反除倍率換回流程尺度」。
- **拾取檢查**：既有測試照過即可，確認常數搬家沒有改到行為。

## Out of Scope

- 擴大支援倍率範圍、多尺度範本、引擎改成放大截圖。
- 補做次數上限、開關類步驟不補做（ADR 0008 補做規則不動）。
- 執行中途偵測視窗大小改變（開頭量過之後才縮放視窗，不會被擋）。
- 早_簡中 ×1.132 換班段點錯：已在 2026-10-11 用加寬類別標題窄帶修好（流程資料，見 flow-folder-format 票 13 的 Comments）。
- 流程存檔格式：不升版、不加欄位。
