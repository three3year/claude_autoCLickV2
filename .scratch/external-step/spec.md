# Spec：外部步驟

Status: ready-for-agent

來源：2026-11-03 grilling。使用者要在早／晚四份流程的最後接上公開招募，公開招募已在另一個專案（`claude_arknightAecruit`）做好，那邊會另做一個單入口單出口的執行檔給點擊程式呼叫。決策正本是 [ADR 0018](../../docs/adr/0018-external-step-single-entry-contract.md)，介面正本是[外部步驟串接介面](../../docs/external-step-api.md)。詞彙以 `app/GLOSSARY.md` 為準：`外部步驟`、`外部工具`、`外部工具登錄`、`預期時間`四條已是目標狀態。

## 需要你決定的

### 外部步驟做成通用的，還是專用的公開招募步驟？

決定（2026-11-03）：通用的外部步驟。

- 通用外部步驟（建議）：點擊程式只負責啟動、等待、看結束碼，不認識公招。
- 專用公招步驟：編輯器有公招選項，但兩個專案會綁在一起。

### 接在哪幾份流程？

決定（2026-11-03）：四份正式流程都接。插入要等公招執行檔做好，不在本規格範圍內，見 [Out of Scope](<#Out of Scope>)。

### 外部工具失敗時，這次執行算什麼？

決定（2026-11-03）：整次執行算失敗，跟找不到圖而停下一樣。

### 逾時怎麼來？

決定（2026-11-03）：正式執行前，先用同一組參數加 `--expected-time` 問工具。這次詢問限 10 秒，問不到就整次失敗。正式執行的上限＝預期時間＋10 秒。預期時間必須由工具用更快的方法估出來，不能真的跑一遍。

- 先問執行檔（使用者選）：工具最清楚這次要跑多久，代價是多啟動一次。
- 啟動後在輸出裡回報：工具卡在載入時拿不到上限。
- 流程裡寫死：工具變慢時要改四份流程。

### F12 時怎麼對待還在跑的外部工具？

決定（2026-11-03）：往工具的標準輸入寫一行 `stop`，讓工具自己收尾並回報失敗；不理會就等到逾時再結束它。這兩種情況執行紀錄都記 stopped。問預期時間那一次照約定不做事，F12 時直接結束它（Claude 補的，沒有另外問）。

### 遊戲視窗怎麼交給工具？

決定（2026-11-03）：參數可以寫 `{hwnd}` 佔位符，點擊程式代入`搜尋範圍`所在的頂層視窗。

### 外部工具的輸出記多少？

決定（2026-11-03）：只記結束碼和最後 5 行。

### 外部工具執行期間迷你窗怎麼辦？

決定（2026-11-03）：照舊顯示。點的位置不被迷你窗擋住，是工具自己的責任。

### 外部工具登錄放在哪裡？

決定（2026-11-03）：放在流程資料夾裡、`flow.yaml` 以外的另一份檔，內容是「名稱 → 資料夾＋入口檔名」，各流程各自一份。複製流程資料夾就是完整的一包。

- 流程資料夾內（使用者選）：工具搬家要改每份流程。
- 流程存放區底下共用一份：只要改一處，但流程不再自包自足。

### 工具沒登錄或找不到時，什麼時候發現？

決定（2026-11-03）：按開始時就擋下，跟範本檢查一樣，不開始執行。

### 編輯器支援到什麼程度？

決定（2026-11-03）：可以新增，也可以簡單編輯：工具名下拉、參數、備註。

### 外部工具開始前，誰等畫面就緒？

決定（2026-11-03）：工具自己等。公招會為這個用途另做入口，流程不另加步驟。

### 細節約定

決定（2026-11-03）：以下由 Claude 提出、使用者沒有異議：

- 工作目錄是登錄的資料夾。
- 標準輸入被關掉（EOF）也當作 `stop`。
- 輸出用 UTF-8。
- 入口打包成主控台程式，用 `asInvoker`。
- 登錄檔叫 `external_tools.yaml`。

### 測試接縫用哪幾個？

決定（2026-11-03）：三個，見 [Testing Decisions](<#Testing Decisions>)。

- 照這樣切（建議）：只新增一個接縫，就是「啟動外部工具」小模組。
- 只要 runner 與既有接縫：管線、行程樹這些底層問題要到實跑才會暴露。
- 全用真程序：測試慢，而且跟時間有關，容易偶發失敗。

## Problem Statement

早班和晚班流程跑完後，停在「公開招募」畫面。使用者要另外打開公招工具、點縮圖選視窗、按開始，等它跑完再關掉。點擊程式沒辦法把一段工作交給別的程式做，所以公招沒辦法接在流程後面自動跑。以後別的工具想串進來，也會卡在同一個地方。

## Solution

新增一種步驟：`外部步驟`。流程裡寫工具名稱和參數，名稱到實際位置的對應記在流程資料夾裡的`外部工具登錄`。執行到這一步時，點擊程式依序：

1. 先問工具這次的`預期時間`。
2. 正式啟動工具，一路等到它結束。
3. 結束碼 0 就繼續下一步，其他結束碼就整次失敗；超過預期時間＋10 秒也算失敗，並結束工具。

這段期間按 F12，點擊程式會通知工具停下。工具需要知道操作哪個遊戲視窗時，點擊程式會把視窗交給它。

介面寫成文件給外部工具的作者看。點擊程式這一側先完成，用一支照介面寫的假工具驗收。公招執行檔做好之後，再插進四份流程。

## User Stories

1. 身為使用者，我想在流程最後加一個外部步驟呼叫公開招募，讓早班跑完就自動接著做公招，不用另外開工具。
2. 身為使用者，我想在流程裡只寫工具名稱（例如「公開招募」），不寫一長串路徑，讓流程好讀。
3. 身為使用者，我想讓工具名稱到資料夾、入口檔的對應記在流程資料夾裡，讓複製流程資料夾就能完整帶走。
4. 身為使用者，我想讓存檔重寫 `flow.yaml`、清理範本時，外部工具登錄完好保留，不會因為存檔而遺失。
5. 身為使用者，我想在按開始時就知道外部工具沒登錄、資料夾不存在或入口檔不存在，不會跑了十幾分鐘才在最後一步失敗。
6. 身為使用者，我想讓開始前的檢查用跟範本檢查一樣的警告方式，說清楚是哪個工具、缺了什麼。
7. 身為使用者，我想讓「測試選取」執行時，對外部步驟做同樣的檢查，測試和正式執行行為一致。
8. 身為使用者，我想讓點擊程式把遊戲視窗交給工具（`{hwnd}`），即使兩個客戶端同時開著，公招也不會操作錯視窗。
9. 身為使用者，我想讓點擊程式先問工具這次要跑多久，再據此設逾時，讓工具卡住時流程不會永遠等下去。
10. 身為使用者，我想在工具超過預期時間＋10 秒還沒結束時，讓點擊程式結束它和它開的所有子程序，整次記為失敗。
11. 身為使用者，我想在問預期時間超過 10 秒、結束碼不是 0、或印出的不是數字時，讓整次記為失敗、不啟動正式執行，讓介面壞掉時馬上被發現。
12. 身為使用者，我想在工具以非 0 結束時，讓整次執行記為失敗，執行紀錄寫明是哪個外部步驟、結束碼多少。
13. 身為使用者，我想讓執行紀錄收工具輸出的最後 5 行，失敗時不用去另一個專案找紀錄，就看得到原因。
14. 身為使用者，我想在工具以 0 結束時，讓流程繼續往下走，外部步驟可以放在流程中間，不限最後一步。
15. 身為使用者，我想在外部步驟執行中按 F12 時，讓點擊程式通知工具停下，讓公招有機會停在乾淨的地方。
16. 身為使用者，我想在工具不理會停止時，讓點擊程式等到逾時再結束它，執行不會一直掛著。
17. 身為使用者，我想讓 F12 造成的結束在執行紀錄記為 stopped，不記 failed，跟平常急停一致。
18. 身為使用者，我想在問預期時間的那 10 秒內按 F12，也能立刻停下。
19. 身為使用者，我想讓外部步驟執行期間迷你窗照常顯示，看得到流程還在跑。
20. 身為使用者，我想在編輯器的新增列直接加入外部步驟，不用手改 `flow.yaml`。
21. 身為使用者，我想在外部步驟的編輯窗從下拉選單挑工具名稱（來自這份流程的登錄），再填參數和備註。
22. 身為使用者，我想在步驟清單一眼看出這是外部步驟、呼叫哪個工具。
23. 身為使用者，我想讓外部步驟能放進重複區段，或當分支裡非開頭的步驟，跟其他動作步驟一樣搬移、刪除、複製。
24. 身為使用者，我想讓 `flow_check` 檢查外部步驟的寫法，以及引用的工具有沒有登錄，手改或影片轉流程產生的流程都能事先抓到錯。
25. 身為流程作者，我想讓 flow.yaml 格式規範寫明外部步驟的欄位和登錄檔的格式，手改流程時有唯一的正本可查。
26. 身為外部工具的作者，我想有一份串接文件，寫明呼叫順序、參數、標準輸入輸出、結束碼、執行環境和畫面狀態，照著做就能接上。
27. 身為外部工具的作者，我想讓工作目錄是登錄的資料夾，工具可以用相對路徑讀自己的檔案。
28. 身為外部工具的作者，我想讓點擊程式啟動工具時不跳主控台視窗，讓工具打包成主控台程式也不會干擾畫面。
29. 身為外部工具的作者，我想在標準輸入被關掉時也當作收到停止，讓點擊程式自己掛掉時工具不會繼續亂點。
30. 身為維護者，我想讓點擊程式不認識任何特定工具，讓以後再接別的工具不用改點擊程式。
31. 身為維護者，我想有一支假工具能演出成功、失敗、卡住、收到 stop、開子程序，驗收點擊程式這一側時不用等公招做好。

## Implementation Decisions

- **步驟種類**：新增 `external`。yaml 寫法是 `{external: <工具名>, args: [...], note: ...}`；`args` 沒寫就等於空清單。跟其他動作步驟一樣，可以放在區段裡，但不能當分支開頭，因為分支開頭必須是找圖。新增步驟種類要接上所有現有分派點：讀寫 yaml、預設值表、步驟標籤、runner 分派、新增列、步驟描述、編輯窗。
- **外部工具登錄**：放在流程資料夾裡、`flow.yaml` 旁邊的 `external_tools.yaml`，格式是 `{工具名: {dir: 絕對路徑, exe: 入口檔名}}`。
  - 讀流程時一起讀進記憶體的流程，存檔時原樣寫回或保留。
  - 存檔清理只動 `templates/`，不會刪它。
  - 流程沒有任何外部步驟、又沒有登錄檔時，不產生這個檔。
- **開始前檢查**：開始執行和測試選取都要過這道檢查，放在現有的範本檢查旁邊。列出每個被引用的工具哪裡有問題：沒登錄、資料夾不存在、入口檔不存在、登錄檔格式錯。有任何一項就不開始執行。
- **啟動外部工具小模組**：新增一個 automation 子模組，地位跟截圖、滑鼠模組一樣，runner 只透過它碰行程。它提供：
  - 啟動：給入口檔、參數、工作目錄。用管線接標準輸入，標準輸出和錯誤合併、以 UTF-8 解讀，不開主控台視窗。
  - 查詢是否已結束、取結束碼。
  - 寫一行到標準輸入。
  - 取輸出的最後 N 行。
  - 結束整個行程樹。
  - harness 換掉這個模組，就能用虛擬時鐘測 runner。
- **runner 執行外部步驟**：
  1. 代入佔位符。
  2. 啟動 `--expected-time` 詢問，最多 10 秒。期間照常檢查急停，急停就結束詢問程序、記 stopped。
  3. 解析輸出成正數秒，失敗就丟出執行錯誤（failed），訊息寫明原因。
  4. 啟動正式執行，上限＝預期時間＋10 秒，從啟動算起。每次輪詢都檢查是否已結束、是否急停、是否逾時。
     - 急停：寫 `stop` 一次，之後繼續等到結束或逾時，結果記 stopped。
     - 逾時：結束行程樹，未急停記 failed，已急停記 stopped。
     - 結束碼非 0：未急停記 failed。
  5. 最後 5 行和結束碼寫進執行紀錄和 autoclick.log。
  - 兩個 10 秒都是固定常數，不是設定。
- **`{hwnd}`**：runner 用`搜尋範圍`中心點找所在的頂層視窗，取得十進位 handle。找不到視窗就丟出執行錯誤。只在參數真的含 `{hwnd}` 時才找。
- **結束後**：runner 不重新校準，也不重設`原點`。流程作者要在後面放`定位找圖`；這條寫在串接文件，程式不強制。
- **迷你窗**：外部步驟期間不改迷你窗的行為。迷你窗的步驟進度照常顯示外部步驟。
- **編輯窗**：
  - 工具名是下拉，選項來自這份流程的登錄，也可以直接打字，以便先寫步驟再補登錄。
  - 參數是多行文字框，一行一個參數，存檔時去掉空行。
  - 步驟清單的描述寫成「外部 <工具名>」，參數有內容時接在後面。
- **flow_check**：檢查 `external` 步驟的鍵、`args` 是字串清單、工具名有登錄。登錄的資料夾和入口檔存不存在只是警告，因為換電腦檢查時路徑可能不同；開始前檢查才把它當錯。
- **文件**：
  - flow.yaml 格式規範補上外部步驟和登錄檔。
  - 流程資料夾結構圖加上 `external_tools.yaml`。
  - 串接文件和 ADR 0018 已寫好；實作與文件不一致時，以串接文件為準，並回頭確認。
- **假工具**：放在測試資料，是一支 Python 腳本。用參數選擇演出：
  - 報預期時間、報非數字、詢問卡住；
  - 成功、失敗並印多行、卡住不理 stop、收到 stop 以非 0 結束、開一個孫程序後卡住。
  - 收到 EOF 時以非 0 結束。

## Testing Decisions

- 好的測試只驗看得到的行為：執行紀錄的狀態（done／failed／stopped）與訊息、是否點擊或繼續下一步、寫進 `flow.yaml`／登錄檔的內容、開始前警告的內容。不驗內部呼叫順序。
- **接縫 ①：runner＋harness（主接縫）**。沿用現有 runner 測試的虛擬時鐘與假畫面，加上一個假的啟動模組，可以指定詢問結果、結束碼、輸出行、什麼時候結束、收到 stop 怎麼反應。驗下列行為，都不真的等：
  - 詢問成功、非數字、非 0、超過 10 秒；
  - 正式執行成功後繼續、非 0 失敗、逾時失敗並結束行程樹；
  - F12 寫 stop 後工具非 0 結束記 stopped、F12 後不理會到逾時記 stopped、詢問期間 F12；
  - 紀錄只收最後 5 行；`{hwnd}` 代入；外部步驟在重複區段內。
  - 前例：runner 步驟測試、執行紀錄測試、區段測試。
- **接縫 ②：啟動模組＋真的假工具**。驗管線、UTF-8 中文輸出、合併輸出的最後 N 行、寫 stop、關掉標準輸入（EOF）、結束含孫程序的整個行程樹、工作目錄、不開主控台視窗。這組真的開程序，每個案例限幾秒。
- **接縫 ③：既有接縫**。
  - flowfile 讀寫測試：外部步驟往返、登錄檔讀進來並在存檔後保留、沒有外部步驟時不產生登錄檔、存檔清理不刪登錄檔。
  - flow_check 測試：鍵錯、args 型別錯、沒登錄。
  - app 的 Tk 測試，在隱藏桌面跑：開始前檢查擋下並列出缺什麼、測試選取一樣擋、新增列加外部步驟、編輯窗下拉與參數存回、步驟清單描述。
  - 前例：flowfile／flowfolder 測試、範本缺圖的開始前檢查測試、步驟編輯窗測試。
  - 格式規範的文件測試，如果它檢查步驟種類列表，也要更新。
- 本規格不動 `src/subject_detection/`，不需要跑基準測試集。

## Out of Scope

- 公招專案的新執行檔（單入口單出口、`--expected-time`、`{hwnd}`、stdin stop），由公招專案另開工作。那邊原本的規格把「整合進 AutoClick 流程」列為不做，開工時要先改掉這一條。
- 把外部步驟插進四份正式流程並實跑，要等公招執行檔做好再另開票。
- `{hwnd}` 以外的佔位符。
- 依外部工具的結果分岔。分支開頭仍然只能是找圖。
- 外部步驟期間隱藏或移動迷你窗。
- 影片轉流程自動產生外部步驟。
- 工具的即時輸出串流顯示在面板上。
