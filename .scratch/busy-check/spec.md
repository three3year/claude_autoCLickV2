# 忙碌檢查:勾選的步驟輸入後等忙碌消失(busy-check)

Status: ready-for-agent

詞彙見 `app/CONTEXT.md`:忙碌指示、忙碌檢查、忙碌出現等候、生效確認、補做、補做間隔、出現等候上限、分岔、找不到時。相關決策:ADR 0011(本規格的決策,取代 ADR 0010)、ADR 0008(補做前查忙碌指示,不變)。

來源:2026-10-07 22:24 `晚_簡中` 實跑,使用者回報進駐換班的滑動和點擊都沒等忙碌指示就直接操作。日誌在 `app/dist/AutoClick/autoclick.log`,22:24–22:25。

## Problem Statement

使用者每天用 AutoClick 跑明日方舟早晚班,繁中、簡中兩個客戶端各兩份流程。

10/07 下午做了「忙碌暫停」(ADR 0010):找圖等待時看到忙碌指示就不計逾時,並把四份流程裡「忙碌指示 → 等待消失」的步驟拿掉,交給下一步的忙碌暫停。當晚實跑發現這樣擋不住:

- 換班時忙碌指示只蓋在畫面下方,列名一直看得到。找圖第一輪就找到並馬上操作,忙碌暫停只延長「找不到」的等待,完全沒作用(換班段每一步 `busy_pause=0.00`)。
- 點 ⇄ 是座標點擊,不找圖,本來就不會查忙碌。
- 第一次拖曳被遊戲吃掉,靠補做第二次才生效(步驟 32,`inputs=2`)。這次流程有跑完,但輸入被吃掉的風險回來了。

## Solution

- **忙碌檢查(步驟選項)**:送出輸入的步驟可以勾「忙碌檢查」。勾了的步驟送出輸入後,先等忙碌指示消失,再做生效確認;沒設確認的,等完就結束。
- **忙碌出現等候(流程設定)**:忙碌指示常在點擊後慢一點才出現,所以送出後最多等這麼久看它會不會出現,預設 1000ms。沒看到就放行;看到就等它消失,最多 60 秒,等不到就停止流程。
- **移除忙碌暫停**:找圖等待不再看忙碌指示,逾時照常計時。補做前查忙碌指示的那道門不變。
- **四份流程勾上會讓遊戲忙的步驟**:換班的 ⇄ 與拖曳、開頭清彈窗的關閉、傳遞線索、可收獲、幹員信賴、確定等。

## User Stories

1. 身為使用者,我想要換班點完 ⇄ 後流程等忙碌指示消失才點下一個 ⇄,這樣點擊不會被遊戲吃掉。
2. 身為使用者,我想要換班的每次拖曳後都等忙碌消失才往下走,這樣捲動不會被吃掉、後面的相對點擊不會點錯列。
3. 身為使用者,我想要關掉簽到等彈窗後先等忙碌消失,才回頭找下一個彈窗,這樣清彈窗不會在遊戲等網路時提早結束。
4. 身為使用者,我想要傳遞線索點下去後先等忙碌消失再做生效確認,這樣確認的逾時不會被忙碌吃掉。
5. 身為使用者,我想要可收獲、幹員信賴、確定這幾步也等忙碌,這樣它們的確認不會被忙碌拖到逾時。
6. 身為使用者,我想要沒勾的步驟行為跟以前一樣、不多等,這樣不會讓遊戲忙的步驟不會變慢。
7. 身為使用者,我想要忙碌指示一直不消失(例如斷線)時,一個步驟最多等 60 秒就停止流程,這樣不會在斷線時白點一堆東西。
8. 身為使用者,我想要停止時日誌與執行紀錄寫清楚是「忙碌指示 60 秒沒消失」,這樣我知道是網路問題不是流程問題。
9. 身為使用者,我想要送出輸入後如果 1 秒內沒看到忙碌就放行,這樣網路正常時勾了的步驟只多等約 1 秒。
10. 身為使用者,我想要即使確認圖已經成立,也照順序等滿忙碌出現等候,這樣換班這種「畫面先變、忙碌才出來」的情況不會提早放行。
11. 身為使用者,我想要補做重送之後不另外再等忙碌,這樣補做的行為跟以前一樣,仍由補做的門擋住忙碌時重送。
12. 身為使用者,我想要日誌記下每個勾了的步驟等忙碌的結果與秒數,這樣實跑回報慢或被吃掉時查得到原因。
13. 身為使用者,我想要找圖等待不再因忙碌延後逾時,這樣行為只有一套規則、好預測。
14. 身為使用者,我想要改完後打包版就生效,這樣我照平常的方式執行就好。
15. 身為使用者,我想要改流程前先備份,這樣改壞了可以還原。
16. 身為流程作者,我想要在座標點擊、拖曳、按鍵、找圖點擊的編輯對話框裡勾「忙碌檢查」,這樣自己決定哪些操作會讓遊戲忙。
17. 身為流程作者,我想要找圖選「不點擊」或「等待消失」時看不到這個勾選,這樣不會勾到沒有輸入的步驟。
18. 身為流程作者,我想要分岔開頭的找圖點擊(分岔條件本身會點擊時)也能勾,這樣清彈窗的關閉鈕可以勾。
19. 身為流程作者,我想要等待、區段標記這些步驟沒有這個勾選,這樣介面只出現有意義的選項。
20. 身為流程作者,我想要步驟清單上勾了的步驟顯示〔忙碌檢查〕,這樣一眼看得出哪些步驟會等。
21. 身為流程作者,我想要重新打開步驟編輯時看到原本的勾選狀態,這樣可以確認或取消。
22. 身為流程作者,我想要在主視窗的流程設定(補做間隔旁)設定「忙碌出現等候」毫秒數,這樣可以依遊戲調快或調慢。
23. 身為流程作者,我想要流程沒設忙碌指示卻有步驟勾了忙碌檢查時,按執行就被擋下並說明原因,這樣不會以為有在等其實沒有。
24. 身為流程作者,我想要「測試選取」也照同樣規則擋下與執行,這樣測試片段跟正式執行一致。
25. 身為流程作者,我想要舊存檔讀進來沒有任何步驟勾忙碌檢查、忙碌出現等候是預設 1000ms,這樣舊流程行為不變、不必遷移。
26. 身為流程作者,我想要忙碌檢查與忙碌出現等候隨流程存檔保存,這樣存檔搬到別台電腦也一樣。
27. 身為使用者,我想要四份流程勾的位置照實跑經驗挑好,這樣我不必自己一步一步找。
28. 身為使用者,我想要流程改動在另一個 session(evening-notice-close)收尾後、以那時的流程為底再做,這樣兩邊的改動不會互相蓋掉。
29. 身為使用者,我想要每份流程的交付報告寫清楚勾了哪些步驟,這樣實跑時知道要看哪裡。

## Implementation Decisions

### 執行器:忙碌檢查

- 適用步驟:座標點擊、拖曳、按鍵、找圖(動作為點擊時)。步驟上沒有這個鍵或為否,行為與現在完全相同。
- 順序:送出第一次輸入 → 忙碌檢查 → 生效確認(有設的話)。
  - 找圖點擊:找到 → 點擊 → 忙碌檢查 → 確認。找圖階段本身不變。
  - 座標點擊、拖曳的原點更新規則不變(有確認＝生效後才更新)。
  - 補做發生在確認階段,重送後不再做忙碌檢查,照舊由補做的兩道門擋(補做間隔、畫面上沒有忙碌指示)。
- 等法:
  - 送出後,在忙碌出現等候內輪詢忙碌指示;一次都沒看到＝放行(結果 `not_appeared`)。即使生效確認的條件在這段時間內已成立,也等滿。
  - 看到之後等它消失(結果 `gone`)。「消失」比照等待消失:先前挑中的位置不再有匹配。
  - 從送出輸入起算,等忙碌消失最多 60 秒(常數,不做設定);超過＝停止流程(結果 `timeout`),不走該步的「找不到時」。
- 輪詢間隔沿用流程的找圖輪詢節奏,截圖時避開游標的處理比照現有找圖。
- 執行器的建構參數多一個「忙碌出現等候」(秒),由主視窗從流程設定帶入。
- 停止時執行紀錄寫一行警告,說明是忙碌指示 60 秒沒消失。

### 執行器:移除忙碌暫停

- 拿掉 ADR 0010 的忙碌暫停:分岔、一般找圖、生效確認、等待消失、出現等候上限都不再因忙碌延後逾時。
- 生效確認裡,補做的門照舊在「這一輪沒生效」時用同一張截圖查一次忙碌指示(ADR 0008 決策 3)。
- 共用的等待時鐘(busy-pause-fixed-rect 票 01)保留,只拿掉暫停的部分;沒有其他用途的參數與欄位一併清掉。
- 日誌:`find.target`、`input.confirm` 拿掉 `busy_pause` 欄位;`busy_delay`(補做被忙碌延後的時間)保留。

### 日誌

- 忙碌檢查每次寫一筆 `busy.check`:步驟號、結果(`not_appeared` / `gone` / `timeout`)、從送出輸入起等了幾秒、輪詢次數、看到時挑中的框。
- 寫在該步驟的 `input` / `input.confirm` / `find.target`(點擊那筆)之後、確認那筆之前,讀日誌時順序就是實際順序。

### 流程存檔

- 步驟多一個布林鍵(建議 `busyCheck`),只在勾了時寫入;缺鍵＝沒勾。
- 流程層級多一個毫秒值(建議 `busyAppearMs`),存法比照補做間隔:缺鍵或壞值＝預設 1000。
- 存檔格式版本不變,舊檔不必遷移。
- 被引用的範本定義不變(忙碌指示本來就算在內)。

### 編輯器

- 座標點擊、拖曳、按鍵、找圖的步驟編輯對話框加一個勾選「忙碌檢查(送出後等忙碌指示消失)」。
  - 找圖只在動作為點擊時顯示,選「不點擊」或「等待消失」時隱藏並存為沒勾,比照生效確認的顯示規則。
- 步驟清單摘要:勾了的步驟顯示〔忙碌檢查〕,位置比照〔限定〕等既有標示。
- 主視窗流程設定列(補做間隔、忙碌指示那一列)加「忙碌出現等候」毫秒欄位,改了寫進草稿與存檔,比照補做間隔。
- 執行前檢查(整份執行與測試選取共用的那一道):有步驟勾了忙碌檢查,但流程沒設忙碌指示 → 擋下,訊息說明要先設忙碌指示或取消勾選。

## Testing Decisions

- 好的測試只看外部行為:
  - 執行器看**事件序列與時間**:什麼時候送出哪個輸入、什麼時候開始確認、什麼時候停止、走了哪個處置。
  - 存檔看**存檔內容**;編輯器看**存回步驟的值與畫面上的標示**。
  - 不檢查內部欄位或私有方法。

### 接縫一:執行器(pytest)

- 用 `app/tests` 的 harness:假畫面(安排第幾次查詢才找到忙碌指示、第幾次消失)、假輸入、虛擬時鐘。
- 劇本至少包含:
  - 座標點擊勾了、忙碌在送出後 0.5 秒出現、3 秒後消失 → 下一步的輸入時間點在消失之後。
  - 拖曳勾了、有生效確認 → 確認的第一次查詢在忙碌消失之後;確認逾時從那時起算。
  - 找圖點擊勾了 → 點擊 → 等忙碌 → 確認的順序;找圖階段不查忙碌。
  - 按鍵勾了 → 等忙碌。
  - 忙碌出現等候內都沒看到 → 等滿 1000ms 放行;設成別的值時照新值。
  - 確認條件在出現等候內已成立 → 仍等滿才開始確認。
  - 忙碌 60 秒不消失 → 停止流程,不走「找不到時」,後面沒有任何輸入。
  - 補做重送後不再等忙碌;補做的門照舊在忙碌時不重送。
  - 沒勾的步驟:事件與時間點跟現在相同,也不查忙碌指示。
  - 分岔開頭的找圖點擊勾了 → 選中該分支、點擊後等忙碌。
  - 日誌 `busy.check` 的結果、秒數、順序正確。
- 忙碌暫停的既有測試改寫成反向:分岔、一般找圖、生效確認、等待消失、出現等候上限在忙碌時**照原本時間**逾時;日誌沒有 `busy_pause`。補做門的測試保留。
- 先例:補做門檻、出現等候上限、生效確認(座標點擊/拖曳)、忙碌暫停的測試。

### 接縫二:流程存檔(真檔案)

- 先例:補做間隔與忙碌指示的存檔往返測試。

### 接縫三:編輯器(介面測試)

- 執行前檢查:有勾、沒設忙碌指示 → 整份執行與測試選取都被擋下並有訊息。

## Out of Scope

- 自動判斷哪些步驟會讓遊戲忙(由作者勾)。
- 每個步驟各自設忙碌出現等候(流程一個值)。
- 60 秒上限做成設定。
- 確認期間忙碌第二次出現的處理(使用者判斷通常不會發生,先不處理)。
- 等待、區段標記、找圖「不點擊」「等待消失」的忙碌檢查。
- 舊流程(`舊_早_簡中` 等)。
- 繁中忙碌指示範本重截(兩份繁中已換成票 06 的新圖,這次只做實機確認)。
