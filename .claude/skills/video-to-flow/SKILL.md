# 影片轉流程（新流程）

把一段`示範影片`變成一份**新的**流程資料夾（`flow.yaml`＋`templates/`＋`交付報告/`）。影片怎麼量全在
`video-measure` skill；這裡只管新流程才有的事：輸出位置、校準對、組裝、交付。產出只放新資料夾——撞名時工具
自動加序號（`_2`…），既有流程一律不動。

## 1. 前置檢查

- **輸出位置與流程名**：流程資料夾建在 `<輸出位置>/<流程名>/`，輸出位置預設 `%USERPROFILE%\AutoClick\`
  （使用者要放別處就寫計畫的 `out` 或組裝時給 `--out`）。流程名就是資料夾名，跟使用者確認（哪個客戶端、做什麼）。
- 影片路徑確定（使用者常只講檔名：示範影片都在 oCam Video 資料夾）。

完成：輸出位置、流程名、影片路徑三者確定。

## 2. 量影片

照 `video-measure` skill 第 1–6 節量完，得到 `<W>/plan.json`。

完成：計畫寫好。

## 3. 補校準對與流程設定

- **校準對**（`calibration`，新流程必填）：從影片挑**遊戲畫面內**兩張開頭畫面一定同時看得到、相距夠遠、
  不會動、邊緣清楚的固定圖（例：主畫面左上的設定鈕與右下的倉庫），各框一張範本、名字寫進 `pair`，
  `frame` 寫兩張都在的那一幀。再把**標題列的圖示＋關閉鈕**各框一張寫進 `fallback.pair`（任何畫面都在；
  主對被彈窗蓋住時執行改用它）。全螢幕沒標題列 → 只有主對。候選圖要畫面上唯一、縮放後還找得到。
- **忙碌指示**（`busy`）：有步驟勾 `busy_check` 就必填；`frame` 寫字樣清楚可見的那一幀。
- `name`、`out` 照第 1 節。

完成：計畫有 `calibration`（與 `fallback`，錄到標題列時）、`name`；有勾忙碌檢查就有 `busy`。

## 4. 組裝

```
.venv/Scripts/python tools/video_to_flow assemble <W>/plan.json [--out <輸出位置>]
```

組裝報錯（計畫有誤、舊鍵、相對座標前沒有原點、校準對量不到……）→ 照訊息修計畫重跑；拒絕時輸出位置不會多任何
檔案。組裝寫完會自己跑檢查指令；印出流程資料夾、`交付報告/` 與待重拍、待確認。

完成：組裝成功。

## 5. 讀驗證結果，能修就修

照 `video-measure`「讀驗證結果」一節處理每張待重拍與每個待確認；重跑前刪掉上一次產出的流程資料夾。

完成：每張待重拍、每個待確認都試過修或寫明修不了的原因；輸出位置裡只留最後一份產出。

## 6. 交付

告訴使用者：流程資料夾路徑、`交付報告/總覽.md`、步驟數、範本數、校準對與基準距離（備用對量不到也要說）、
忙碌指示、待重拍清單與重拍建議、待確認（捲動、忙碌兩向）、分岔建議、需要他改用點擊的按鍵；搜尋範圍沒寫（全螢幕），
要框就在 app 裡框。請他在 app 開啟這個流程資料夾、檢查後實跑，回饋卡住或點錯的步驟。

## 規則

- 流程裡只有找圖與相對座標；每個找圖目標都有工具算的固定矩形。
- 影片與實際畫面同尺度：影片像素就是流程尺度（ADR 0009）。用哪個客戶端錄，產出的流程就屬於那個客戶端。
- 特效樣本或規則依實跑回饋調整時，改 `video-measure` 與工具，讓下一次照新規則走。
