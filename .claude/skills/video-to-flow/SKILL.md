# 影片轉流程

把一段`示範影片`變成一份一般的流程存檔（`.autoclickpack`）＋`交付報告`。
詞彙見 `app/CONTEXT.md`「影片轉流程」一節；工具在 `tools/video_to_flow/`，
兩個入口：**掃描**（`scan`）與**組裝**（`assemble`），外加給掃描用的**學游標樣本**
（`learn-cursor`）；中間的判斷是你的事。

全程**只讀影片與 profile 檔案、只寫新的流程存檔與報告**。使用者常在玩明日方舟，
螢幕、滑鼠、鍵盤都是他的；驗收由他自己實跑。

所有指令在 repo 根目錄以 `.venv/Scripts/python` 執行。輸出（縮圖、影格、計畫）
放 **工作目錄** `W`＝session 暫存目錄（系統提示有列出時）或
`.scratch/video-to-flow/tmp/<日期-名稱>/`（已被 git 忽略）。

## 1. 前置檢查

- **目標 profile**：使用者平常用打包版，正式資料在
  `app/dist/AutoClick/profiles/<名稱>/`（目前 profile 記在同層 `app_state.json`）；
  repo 根目錄的 `profiles/` 是開發用。不確定就問使用者要放哪個 profile。
- **搜尋範圍**：讀 `<profile>/flows/_autosave.json` 的 `scanRegion`。沒有 → 請使用者
  在 app 裡把搜尋範圍框在遊戲畫面上（草稿會自動存），框好再繼續。
- **影片**：在執行流程的這台機器上、只錄遊戲視窗、**以實際畫面尺度錄**（不縮放；
  影片像素＝螢幕像素，工具不換算）。點擊要看得出來：錄影程式的點擊特效，或遊戲
  自繪游標本身的抖動（遊戲換了自訂游標時錄影程式畫不出特效）。問使用者有沒有影片
  看不出來的事（「這裡按了 Esc」），記下來。

完成：profile 路徑、搜尋範圍、影片路徑三者確定，口頭補充已記下。

## 2. 掃描

- 特效樣本在 `.claude/skills/video-to-flow/effect-sample.json`（兩種：錄影程式畫的
  色圈 `{"bgr": ...}`，或遊戲自繪游標 `{"kind": "cursor", ...}` 加旁邊的游標圖）。
  **不存在、使用者換了錄影程式、或換了遊戲/游標** → 先照
  [learn-effect-sample.md](learn-effect-sample.md) 學一份，再回來。
- 執行：

  ```
  .venv/Scripts/python tools/video_to_flow scan <影片> --out <W>/scan --sample .claude/skills/video-to-flow/effect-sample.json
  ```

  產出 `<W>/scan/candidates.json`（每個候選：幀、時間、影片像素位置、信心、
  種類 click/drag；游標樣本模式另有 `cue`：`effect`＝看到游標抖動、`screen`＝畫面
  切換前沒看到特效、以游標停留處補上的低信心候選）與每個候選一張縮圖
  `c###_f#####.jpg`（前後 ±1 秒共數格，紅圈＝候選位置，標籤＝幀號與相對時間）。
  影片幾分鐘長時掃描要跑好幾分鐘，用背景執行。

完成：`candidates.json` 寫出，候選數量與影片長度相稱。

## 3. 覆核候選，寫下每次點擊的語意

**每一個**候選都打開縮圖看過，逐一判定：真點擊／誤報（剔除）／拖曳。候選之間
畫面有變化、卻沒有候選解釋它的地方 → 漏抓：用 `scan --frames` 輸出那幾幀查看，
補上。仍無法用點擊解釋的畫面變化（多半是按鍵）記進報告的 `unexplained`。

需要精確座標時用 `--frames 120,130,...` 輸出原尺寸影格與座標格線版
（`f#####.png`／`f#####_grid.png`），從格線版讀影片像素位置。

游標樣本模式另外注意：

- `cue: effect` 的候選多半是真點擊（按下、放開兩次抖動已併成一個）；畫面隨後
  有反應（按鈕反白、跳頁）就確定。游標停著但畫面本身在動的地方（角色動畫、
  輪播）偶爾會被誤認，看縮圖剔除。
- `cue: screen` 是「畫面切換前沒看到特效」：可能是漏抓的點擊（位置＝切換前游標
  停的地方，多半對）、按鍵、或遊戲自己跳的（載入完成、自動播放）。逐一判斷。
- 拖曳（捲清單）抓不到：清單內容整片平移、游標同時移動的地方自己補 `drag`。
- 游標停在畫面外（藏到視窗邊）時追不到，那段若有畫面變化多半是按鍵。

完成：每個候選都有判定，每段畫面變化都有點擊或 `unexplained` 對應。

## 4. 決定步驟（判斷規則）

逐次點擊套用，**找圖為主、座標為輔**：

- **點在有辨識度的按鈕／圖示上** → 找圖點擊（`find_click`），範本就是那個按鈕。
- **一排長得一樣的卡片／格子裡特定的一格** → 找圖點擊，用挑選規則或限定範圍
  指定是哪一格（第 5 節「找圖目標的設定」）。
- **點空白處** → 座標點擊（`click`），相對`原點`。前面沒有可用原點（流程第一步、或原點來自畫面早已換過的步驟）→
  在它前面插一個`定位找圖`：`find_click`、`action: "none"`，範本選該畫面上
  有辨識度、不會動的東西。
- **拖曳**（捲清單等）→ `drag`，寫起訖。前面同樣要有原點；原點來自找圖時組裝
  自動設`原點的圖離開`（捲動被吃掉就重拖、確認不到就停止），前面的定位找圖要框
  會被捲走的東西（清單第 1 列），不要框固定的標題。
- **過場／載入**：交給下一個找圖步驟的輪詢等過去；載入明顯超過 10 秒的地方，
  下一個找圖步驟的 `timeout` 放寬到觀察到的秒數 ×2。
- **重複**：完全一樣的動作序列連續出現 → `loop_start`（`count`＝次數）＋序列一次＋
  `loop_end`。區段內的相對座標要有**區段內**的原點（區段開頭先找圖）。
- **口頭補充的按鍵** → `key` 步驟放在使用者說的位置，並記進報告的 `keys`。
- **彈窗與分岔**：只建影片裡走過的那一條路，不發明影片裡沒出現的彈窗或分支。
  影片裡**出現過**、但明顯不是每天都會出現的東西（每日彈窗、當天商品），可以包成單分支的
  分岔讓它沒出現時跳過（見第 5 節）——這不是新的路，只是讓走過的路容許少一段。可能跳出的彈窗、可能卡住的地方寫進
  報告的 `branches`（建議），步驟裡只用影片裡看得到的東西。
- **送伺服器的操作**（換班 ⇌、收取、確定購買……）：遊戲畫面畫好了、伺服器還沒回應時
  輸入會被吃掉。影片裡看得到`忙碌指示`（明日方舟：底部半透明帶＋「正在提交反饋至神經……」
  字樣，點擊後 0.3–0.8s 出現、約 1s 消失）→ 截字樣那段當範本，寫進計畫的 `busyTarget`
  （不寫限定範圍；要縮小找圖範圍請事後在 app 的找圖設定裡框`固定矩形`），並在這類操作後放
  `find_click` 等待消失（`action: "wait_gone"`、範本＝忙碌指示、`appearLimitMs: 1000`）
  取代固定等待：網路慢就等它消失，網路快約 1 秒放行。
- **點了沒反應會卡住的座標點擊**（關彈窗、切頁籤）：寫 `confirm: "appear"`＋點完才會出現的
  `confirmTemplate`，或下一步就是找圖時寫 `confirm: "next"`——沒生效會在補做間隔後重點。
- 位置一律寫**影片像素的畫面位置**（`at`／`from`／`to`）；偏移、相對座標、
  `生效確認`的預設由組裝推算。只有與預設不同時才寫 `confirm`／`onNotFound`／`timeout`。

完成：每一次真點擊都對應到一個步驟，每個座標點擊／拖曳前都有原點來源。

## 5. 挑範本

- **乾淨影格**：按鈕已出現、畫面已穩定、游標還沒移過來、沒有點擊特效與 hover
  反白的那一幀——通常是點擊前 0.3–1 秒、游標還在別處的時候。框按鈕本體
  （文字＋邊框），保持影格原尺寸。找不到這種幀 → 仍建範本，標 `"clean": false`。
  **游標停在按鈕上的範本驗證照樣會過**（影片裡游標就在那裡）——組裝後一定要把
  每張範本圖打開看過；有游標的換一幀（同一畫面稍早、或之後畫面還在時的幀），
  真的沒有才標 `"clean": false`。
  遊戲自繪游標時，掃描的 `candidates.json` 旁邊沒有逐幀游標位置；挑幀時用
  `--frames` 輸出幾幀比對，或在 W 裡自己用游標樣本逐幀追蹤（第一支影片就是這樣做的）。
- **同款不只一格**（一排一樣的卡片、商店同款商品）：哪一格都行的（商店同款）不寫
  `at`、不設挑選規則，點找到的那一格；要特定一格的見下面「找圖目標的設定」。
- **每天不一定出現的東西**（每日彈窗、當天商品）：包成單分支的分岔
  （`branch_start`＋條件找圖 `onNotFound: skip`＋…＋`branch_end`），沒出現整段跳過；
  分岔裡後續步驟失敗用 `onNotFound: break` 跳出該分岔，不要停掉整個流程。
- **點完不會消失的定位物**（列名、標題）：用定位找圖（`action: none`）＋相對座標點擊，
  不要寫遠離範本框的 `at`（驗證會判位置不符，執行時「點到目標圖消失」也會一直補點）。
- **找圖目標的設定**（欄位見 plan-format.md「找圖目標屬性」）：工具不替你判斷、
  也不給提示，逐個找圖步驟與確認圖照下列規則決定：
  - **比色**（`colorCheck`）：同一形狀只差顏色的東西會出現在畫面上——可按的橘色
    按鈕 vs 停用的灰色按鈕、同列名但顏色不同的設施列；或 `absent` 幀被匹配、而那一幀
    上的東西只是顏色不同。範本要框乾淨，不含會變的數字、動畫或透出的背景（比色不套遮罩）。
    一模一樣的同款（同色卡片）比色分不開，交給挑選規則或限定範圍。
  - **挑選規則**（`pick`）：畫面上同時有好幾個匹配、要的是特定一個——一欄／一列同款
    用 `top`／`left` 第 N 個（數的是那一幀上全部的匹配，比色不符的不算）；位置固定
    相對定位物的用 `near` 最接近指定點（指定點＝`原點`加偏移，前面要有定位找圖當原點；
    沒有「以搜尋範圍為基準」這回事）。
  - **限定範圍**（`limit`）：目標只會出現在定位物附近、別處有相似的東西——用
    `kind: origin` 框定位物旁的那一塊（前面要有定位找圖當原點），目標不在時就是
    「沒找到」而不是點到別處；固定在畫面角落的按鈕不要用九宮格（已退場），事後在 app
    的找圖設定裡框`固定矩形`（相對`座標基準點`，視窗挪位置也不用重設）。
- **驗證幀**：`absent` 放 1–2 個按鈕還沒出現的幀（上一個畫面）；按鈕會在別的
  時間點重複出現時，`present` 放那幾幀（位置變了就寫 `{"frame": N, "at": [x, y]}`）。
  找圖步驟的 `frame` 是它點擊那一刻之前、按鈕清楚可見的那一幀。
- **命名**：用按鈕上的中文（「開始行動」「確認」）；沒有字就用描述（「右上角叉叉」）。
  同一個按鈕多次出現共用一張範本。名稱用平面文字（工具會擋下路徑符號）。
- **校準對**（計畫的 `calibration`）：從影片挑**遊戲畫面內**兩張開頭畫面一定同時看得到、
  相距夠遠、不會動、邊緣清楚的固定圖（例：主畫面左上與右下的圖示），各框一張範本放進
  `templates`、名字寫進 `calibration.pair`——量到的才是遊戲畫面本身的倍率（ADR 0013）。
  再把**標題列的圖示＋關閉鈕**各框一張，寫進 `calibration.fallback.pair` 當`備用校準對`
  （任何畫面都在；主對被彈窗蓋住時執行會改用它，倍率偏小約 0.4% 靠拾取檢查的餘裕吸收）。
  組裝在同一幀上量兩組——影片尺度就是這份流程的尺度。全螢幕沒標題列 → 只有主對。
  候選圖先用拾取檢查的標準看：畫面上唯一、縮到 ×0.85 與放大到 ×1.15 都找得到。

完成：計畫裡每個找圖步驟引用的範本都有取材幀、裁切框與至少一個 `absent` 幀；
`calibration` 指名了主對兩張範本（錄到標題列時 `fallback` 也指名了備用對）。

## 6. 寫轉換計畫並組裝

照 [plan-format.md](plan-format.md) 寫 `<W>/plan.json`，然後：

```
.venv/Scripts/python tools/video_to_flow assemble <W>/plan.json
```

組裝報錯（計畫有誤、相對座標前沒有原點……）→ 照訊息修計畫重跑；拒絕時 profile
不會多任何檔案，重跑是安全的。組裝輸出的「提醒」（例如影片比搜尋範圍大）不擋
組裝，但要轉告使用者：多半是錄影縮放過或錄到範圍外的東西。

完成：組裝成功，印出存檔與報告路徑。

## 7. 讀驗證結果，能修就修

組裝輸出列出`待重拍`的範本與原因（報告裡也有）。逐一處理：

- 「找不到」「位置不符」「出現前就匹配」→ 先試換一幀或調框（框按鈕本體、
  避開會變的數字），或照第 5 節補比色／挑選規則／限定範圍（挑中的不是 `at` 那一個＝
  規則或範圍設錯），**刪掉上一次產出的存檔與報告**後重組。
- 「縮放餘裕」（`拾取檢查`：取材幀縮到 ×0.85／放大到 ×1.15 找不到、或粗篩 < 0.7／驗證 < 0.85）
  → 範本在視窗模式／最大化會縮放的畫面上會失手：裁小（只框按鈕本體、避開透出的背景）或換一幀；
  原因文字寫明哪一關、分數與倍率，粗篩貼門檻多半是框太大或含會變的東西，驗證貼門檻多半是框到
  邊緣或背景。
- 「唯一」（`拾取檢查`：照步驟的找圖目標在那一幀上有兩個以上匹配）→ 這張圖不能當參考點：
  加限定範圍（`limit` 以原點為基準）、換畫面上唯一的圖當定位物，或要的是一排同款裡特定一格就設
  挑選規則（設了「第 N 個」「最接近」的目標不查唯一）。
- 修不了的留著：範本仍在存檔裡、步驟照建，使用者在編輯器重拍那張圖即可。
- 輸出「驗證不完整」（深度驗證模型沒載入）→ 一定要告訴使用者。
- 輸出「沒有校準對」→ 補或修 `calibration`（量不到＝那一幀上兩張圖沒同時找到）後重組；
  沒有校準對的流程不能執行。

完成：每張待重拍範本都試過修或寫明修不了的原因；`flows/` 裡只留最後一份產出。

## 8. 交付

告訴使用者：存檔路徑（已出現在 profile 的流程清單）、報告路徑、步驟數、範本數、
校準對與基準距離、忙碌指示（有／沒有、範本名）、待重拍清單與重拍建議、分岔建議、
需要他補的按鍵。請他在 app 開啟、檢查後實跑，
回饋卡住或點錯的步驟。

## 規則與坑

- 產出只放新檔：檔名撞名時工具自動加序號，既有流程、草稿、工作區一律不動。
- 流程裡只有找圖與相對座標，沒有絕對座標（搜尋範圍重框或視窗搬動都不會點歪）。
- 影片與實際畫面同尺度：影片像素直接當螢幕像素、就是流程尺度，搜尋範圍大小不參與換算
  （ADR 0009）。用哪個客戶端錄，產出的流程就屬於那個客戶端的尺度。
- 特效樣本或規則依實跑回饋調整時，改這個 skill 與工具，讓下一次轉換照新規則走。
