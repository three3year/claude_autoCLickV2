# 改流程

改一份**既有**的流程資料夾（新流程走 `video-to-flow`，或使用者在 app 建）。格式、執行語意、常見寫法全在
[docs/flow-format.md](../../../docs/flow-format.md)——動手前讀它，不讀 app 的開發文件。直接改既有資料夾、不備份。

流程裡永遠沒有猜的數字：座標、拖曳起訖、固定矩形只來自量測（影片或使用者在 app 裡拾取）。

## 1. 先問 app 開著沒

問使用者：app 是否開著這份流程、有沒有未存的改動。有 → 請他先存檔或關掉這份。app 不偵測外部修改，
舊視窗之後一存檔就會整份蓋掉你的改動。

完成：使用者確認 app 沒開著這份，或已存檔、不會再從舊視窗存。

## 2. 讀流程、改結構與選項

讀 `<流程資料夾>/flow.yaml` 與格式規範，直接改文字：增刪搬步驟、包成 `branch`／`repeat`、
`on_fail`／`on_break`／`busy_check`／`timeout`／`confirm`／`update_origin`、改範本引用。
步驟編號是行尾的 `# N`（＝app 清單的編號）；使用者說「第 30 步」就找 `# 30`。

- 搬動、包區段後，照格式規範核對**原點**：每個 `click`／`drag`／`pick: {near}` 前面最近的原點來源還是
  原本那一步（`update_origin`、拖曳終點都會改變它）；`confirm: next` 的下一步仍是找圖。
- 新增找圖步驟要用的圖還沒有 → 寫新範本名（範本命名規則見規範），圖由使用者在 app 截（缺圖的流程照樣開得起來，
  執行時擋下，安全）。

完成：要求的改動都在 flow.yaml 裡，原點與找圖相連都核對過。

## 3. 要像素值時

新的 `click` 偏移、`drag` 起訖、`within` 這類只能量的值，依序：

1. **能改成找圖就改成找圖**：寫 `find_click`＋新範本名（點的是按鈕、圖示），或定位找圖＋相對座標裡的
   定位那一步。圖缺著，交付時請使用者截。
2. **使用者願意錄一段影片**（或已經有一段）：錄影要求照 `video-measure` 第 1 節的判斷問題——固定介面從哪開始錄
   都行；只差在清單捲到哪就寫 `align` 讓工具對齊；其他落差照那裡的退路，最後一條才是請使用者從插入點的畫面重錄。
   照 `video-measure` skill 量成補充計畫（插入點 `after`／`into`＋`expect` 由你定：
   N 與第 N 步的開頭鍵＋值照現在的 flow.yaml），然後

   ```
   .venv/Scripts/python tools/video_to_flow insert <W>/plan.json <流程資料夾>
   ```

   工具量`影片倍率`、換回流程尺度、產固定矩形與新範本、寫回 flow.yaml、更新 `交付報告/` 插入處那份與總覽，
   寫完自己跑檢查指令。有 `align` 時先量`對齊位移`：第一次拖曳之前的位置照它平移、第一次拖曳的距離吸收它。
   報錯（插入點對不上、插入段沒有原點、改變後面舊步驟的原點來源、新範本撞名、倍率超出範圍、量不到校準對又沒有
   `scale_image`、該寫 `align` 沒寫或對不上）都在寫檔前，資料夾不變——照訊息修計畫重跑。跑完照 `video-measure`
   「讀驗證結果」處理待重拍與待確認。
3. **都不行**：不寫那一步，記進交付清單，請使用者在 app 新增或拾取。

`within` 不寫（＝整個搜尋範圍），需要時列為建議請使用者在 app 框。不寫佔位座標、不寫 `[0, 0]` 湊數。

完成：每個需要像素值的地方都落在上面三條之一。

## 4. 檢查

```
.venv/Scripts/python tools/flow_check <流程資料夾>
```

有錯誤（以 1 結束，列出步驟與原因）→ 修 flow.yaml 重跑。沒有錯誤後收尾排版（更新行尾步驟編號；這是檢查指令
唯一會寫檔的模式，只動 flow.yaml）：

```
.venv/Scripts/python tools/flow_check <流程資料夾> --normalize
```

「要在 app 截的範本」不算錯，列進交付清單。

完成：檢查指令沒有錯誤，`--normalize` 跑過。

## 5. 交付報告

手改了結構（增刪搬步驟、包區段、範本改名）就更新 `交付報告/` 受影響的那幾份：「這段做什麼」照改完的流程重寫，
說明寫進那份的內容（不加日期分節）；區段開頭找圖的範本換了或改名，照 `交付報告/總覽.md` 的命名規則把檔名改掉、
總覽的連結跟著改。沒有 `交付報告/` 的流程不用補建。走 `insert` 的補充工具已經自己更新，不必再改。

完成：受影響的那幾份與總覽描述的是改完的流程。

## 6. 交付

告訴使用者：

- 改了哪幾步（用改完的編號與內容說：「第 31 步 找圖點擊『确定』：找不到時改成跳過」）。
- 要在 app 截的範本（檢查指令的缺圖清單）。
- 要在 app 新增或框什麼（第 3 步記下的、建議框的 `within`）。
- 補充時：影片倍率、對齊位移與拖曳距離的改動、待重拍、待確認、`交付報告/` 更新了哪一份。
- 遇到工具沒涵蓋的落差（`video-measure` 第 1 節第 3 種）：是什麼情況、這次怎麼退的，請使用者決定要不要擴充工具。
- 請他在 app **重新讀取**這份流程再看、再執行（別用改之前開著的舊視窗存檔）。
