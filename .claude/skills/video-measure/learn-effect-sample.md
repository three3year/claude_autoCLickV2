# 學點擊特效樣本

第一次處理某位使用者的影片、或他換了錄影程式／遊戲游標時做一次。先看影片判斷
點擊長什麼樣子，再走對應的那一條：

- **遊戲自繪游標**（游標是遊戲畫的一張圖，不是系統箭頭；錄影程式畫不出特效）→ A。
  明日方舟換了自訂游標就是這種：白色骷髏頭＋長矛，點擊時它自己抖一下。
- **錄影程式畫的特效**（點擊處出現色圈／光暈）→ B。

不確定時：用 `scan --frames` 輸出幾個「畫面剛有反應（按鈕反白、跳頁）」之前的幀，
看點擊處有沒有色圈；沒有色圈、游標又是一張自訂圖 → A。

## A. 遊戲自繪游標（游標樣本）

樣本＝游標長相（帶透明度的圖）＋熱點（尖端＝實際點擊的位置），工具從幾幀學出來。

1. **挑幀**：6–12 幀，游標**停著**、**完整在畫面內**、**背景各不相同**（暗的、亮的、
   有字的、彩色的都要有）。避開點擊當下那幾幀（游標在抖）與移動中的幀（模糊）。
   先用 `scan --frames` 輸出候選幀的格線版挑。背景太像 → 工具會拒絕。
2. **讀尖端位置**：從各幀格線版（`f#####_grid.png`）讀游標尖端的影片像素位置；
   誤差幾 px 沒關係（工具會互相對齊），但每幀都要指同一個點（尖端）。
3. **學**：

   ```
   .venv/Scripts/python tools/video_to_flow learn-cursor <影片> --at "幀:x,y;幀:x,y;..." --out .claude/skills/video-measure/effect-sample.json
   ```

   寫出樣本 JSON 與旁邊同名的 `.png`（游標圖）。輸出各幀相似度；某幾幀被指名「不是
   游標」→ 那幾幀位置讀錯或剛好在抖，換幀重學。學出來的圖要看一眼：應該是游標本身
   （背景透明），只有一小塊（例如只剩尖端）代表幀太少或背景太像——多挑幾幀重學。
4. **補註記**：在樣本 JSON 加 `"game"`（遊戲與游標設定），方便日後認得。
5. **驗收**：帶 `--sample` 掃同一支影片——畫面有明顯反應的點擊（按鈕反白、跳頁）
   大多要有 `cue: effect` 的高信心候選；`cue: screen` 的低信心候選是補漏用的。
   漏抓很多 → 學樣本的幀多挑一些不同背景重學。

## B. 錄影程式畫的特效（顏色樣本）

樣本描述錄影程式畫的`點擊特效`顏色，讓掃描只追那個顏色——誤報大減、還分得出拖曳。

1. **退路掃描**（不帶 `--sample`）：

   ```
   .venv/Scripts/python tools/video_to_flow scan <影片> --out <W>/learn
   ```

   退路偵測找「局部、連續幾幀在原地變化」的地方，寧可多報。（遊戲畫面本身一直
   在動的話會多報到不能用——那多半該走 A。）
2. **認出真點擊**：打開信心最高的幾張縮圖，挑出確定是點擊特效的 3–5 個候選
   （特效在點擊處出現、幾幀後消失；游標移動與畫面切換不是）。
   需要看清楚時用 `--frames <候選幀>,<候選幀+1>` 輸出原尺寸影格。
3. **取顏色**：這幾個候選在 `candidates.json` 的 `color`（BGR）取中位數。顏色
   被背景沖淡、各候選差很多時，改從原尺寸影格上特效本體的像素讀 BGR。
4. **寫樣本** `.claude/skills/video-measure/effect-sample.json`：

   ```json
   {"bgr": [0, 220, 255], "tolerance": 60, "recorder": "錄影程式名稱與特效設定"}
   ```

   `tolerance` 是每個色版容許的差（壓縮失真大就放寬到 80）。
5. **驗收**：帶 `--sample` 重掃同一支影片——第 2 步挑出的每一個點擊都要有高信心
   候選（信心 ≥ `highConfidence`），而且高信心候選裡沒有明顯的誤報。漏抓 → 放寬
   `tolerance`；誤報多（遊戲畫面本身有同色東西）→ 收窄，或請使用者把特效換成
   遊戲裡少見的顏色。

完成：樣本檔（A 另有 `.png`）存在，且驗收通過。把樣本一起提交進 repo。
