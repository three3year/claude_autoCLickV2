# 影片量測

把一段`示範影片`量成一份**轉換計畫**（步驟、範本、影片證據），交回呼叫你的入口 skill：

- **video-to-flow**（新流程）：計畫交給 `assemble`，產一份新的流程資料夾。
- **edit-flow**（`補充`）：計畫交給 `insert`，插進一份既有流程。

寫不寫檔、寫到哪由入口決定；這裡只管影片。flow.yaml 的鍵、執行語意、常見寫法（定位找圖、
可選彈窗分岔、忙碌檢查該勾哪些步驟、比色與挑選規則）都在 [docs/flow-format.md](../../../docs/flow-format.md)，
計畫格式在 [plan-format.md](plan-format.md)；詞彙見 `app/CONTEXT.md`。

全程**只讀影片**：使用者常在玩明日方舟，螢幕、滑鼠、鍵盤都是他的。所有指令在 repo 根目錄以
`.venv/Scripts/python` 執行；縮圖、影格、計畫放**工作目錄** `W`＝session 暫存目錄（系統提示有列出時）
或 `.scratch/video-to-flow/tmp/<日期-名稱>/`（git 忽略）。影片路徑含中文時 `cv2.imread` 讀不了，用工具輸出的圖。

## 1. 錄影要求

- 在執行流程的這台機器上、**只錄遊戲視窗**。點擊要看得出來：錄影程式的點擊特效，或遊戲自繪游標的抖動。
- 新流程：以實際畫面尺度錄（影片尺度就是流程尺度）。
- 補充：視窗大小可以跟建流程時不同（工具量`影片倍率`換算，要在支援倍率範圍 ×0.85–1.15 內）；
  但影片裡要看得到既有流程的`校準對`或`備用校準對`（標題列圖示＋關閉鈕通常一直在）。看不到 → 請使用者
  另給一張**同取景、同視窗大小與位置**的圖片（同一個錄影框截一張主畫面），寫進計畫的 `scale_image`。
  不收口頭說的倍率。
- 問使用者有沒有影片看不出來的事（「這裡按了 Esc」）。

完成：影片符合上面幾點，口頭補充已記下。

## 2. 掃描

特效樣本在 `.claude/skills/video-measure/effect-sample.json`（錄影程式的色圈 `{"bgr": ...}`，或遊戲自繪游標
`{"kind": "cursor", ...}` 加旁邊的游標圖）。**不存在、換了錄影程式、或換了遊戲/游標** → 先照
[learn-effect-sample.md](learn-effect-sample.md) 學一份。

```
.venv/Scripts/python tools/video_to_flow scan <影片> --out <W>/scan --sample .claude/skills/video-measure/effect-sample.json
```

產出 `<W>/scan/candidates.json`（每個候選：幀、時間、影片像素位置、信心、種類 click/drag；游標樣本模式另有
`cue`：`effect`＝看到游標抖動、`screen`＝畫面切換前沒看到特效的低信心補漏）與每個候選一張縮圖
`c###_f#####.jpg`（前後 ±1 秒，紅圈＝候選位置）。影片幾分鐘長時掃描要好幾分鐘，用背景執行。

完成：`candidates.json` 寫出，候選數量與影片長度相稱。

## 3. 覆核候選

**每一個**候選都打開縮圖看過，判定：真點擊／誤報（剔除）／拖曳。候選之間畫面有變化、卻沒有候選解釋它的
地方＝漏抓：用 `scan --frames 120,130,...` 輸出那幾幀（原尺寸與座標格線版 `f#####_grid.png`）查看、補上；
精確座標也從格線版讀。仍無法用點擊解釋的畫面變化（多半是按鍵）記進 `report.unexplained`。

游標樣本模式：

- `cue: effect` 多半是真點擊；畫面隨後有反應（反白、跳頁）就確定。游標停著但畫面自己在動（動畫、輪播）偶爾誤認。
- `cue: screen`：可能是漏抓的點擊（位置＝切換前游標停的地方）、按鍵、或遊戲自己跳的。逐一判斷。
- 拖曳（捲清單）抓不到：清單內容整片平移、游標同時移動的地方自己補。
- 游標藏到視窗外時追不到，那段若有畫面變化多半是按鍵。

完成：每個候選都有判定，每段畫面變化都有點擊或 `unexplained` 對應。

## 4. 把點擊寫成步驟

逐次點擊套用，**找圖為主、座標為輔**；判斷規則與寫法照 flow-format.md「常見寫法」：

- 點在有辨識度的按鈕／圖示上 → `find_click`，範本就是那個按鈕；一排同款裡特定一格 → 加 `pick`。
- 點空白處、只差數字的列 → `click`，前面要有原點：沒有就插一個定位找圖（`find`，範本選該畫面上唯一、
  不會動的參考點）。拖曳同樣要有原點；捲清單的定位找圖框會被捲走的第 1 列，不框固定的標題。
- 點完不會消失的參考點（列名、標題）用定位找圖＋相對座標，不要寫遠離範本框的 `at`。
- 過場／載入交給下一個找圖的輪詢；明顯超過 10 秒的，下一個找圖的 `timeout` 放寬到觀察秒數 ×2。
- 完全一樣的動作序列連續出現 → `{"repeat": N, "steps": [...]}`，區段內先找圖取得自己的原點。
- 只建影片裡走過的路；影片裡出現過、但不是每天都有的東西（每日彈窗、當天商品）包成一個分支的分岔。
  可能跳出的彈窗寫進 `report.branches`。
- 按鍵：流程不支援。能用點擊做到同一件事（Esc 關彈窗 → 點叉叉）就照影片建點擊，否則記進 `report.unexplained`。
- `confirm` 明寫（工具不推）：找圖點擊的下一步是找圖 → `next`，否則 `gone`；拖曳的原點來自找圖 → `gone`；
  點了沒反應會卡住的座標點擊 → `{"appear": 點完才會出現的圖}` 或 `next`。
- `busy_check` 照 flow-format.md 的標準判斷、明寫：影片裡那步之後看得到忙碌指示（明日方舟：底部
  「正在提交反饋至神經……」，點擊後 0.3–0.8s 出現、約 1s 消失），或那步是送伺服器的操作。
  新流程有勾就要設 `busy`（截字樣那段當範本）；補充沿用既有流程的。
- 座標點擊與拖曳寫 `frame`（送出輸入的那一幀，掃描候選的幀）。

完成：每一次真點擊都對應到一個步驟；每個座標點擊／拖曳前都有原點來源；`confirm` 與 `busy_check` 都想過一遍。

## 5. 挑幀取材

- **乾淨影格**：按鈕已出現、畫面已穩定、游標還沒移過來、沒有點擊特效與 hover 反白——通常是點擊前
  0.3–1 秒。框按鈕本體（文字＋邊框），避開會變的數字與透出的背景。真的找不到就標 `"clean": false`。
  遊戲自繪游標時用 `--frames` 輸出幾幀比對游標在哪。
- **驗證幀**：`absent` 放 1–2 個按鈕還沒出現的幀（同款在別處仍看得到的幀不要列——absent 要求整張影格沒有匹配）；
  按鈕在別的時間點重複出現時，`present` 放那幾幀（位置變了寫 `{"frame": N, "at": [x, y]}`）。
- **步驟的 `frame`**：找圖是它點擊那一刻之前、按鈕清楚可見的那一幀——工具在**這一幀**上照步驟的設定挑框，
  `固定矩形`就是挑中的框每邊外推 50%。同一張範本在不同步驟各用各的幀。
- **捲動軸**：找圖的目標在內容每次會變的清單裡（好友列表、每輪換一列）→ 寫 `"scroll": "vertical"`
  （或 `horizontal`），框沿那一軸拉到影片兩端。同段有拖曳卻沒宣告的找圖，報告會列「請確認是否在捲動清單裡」。
- **命名**：用按鈕上的中文（「開始行動」）；沒有字就用描述（「右上角叉叉」）。同一個按鈕共用一張範本。
  補充時先看既有流程 `templates/` 有沒有同一張：有就直接在步驟裡引用它的名字（不寫進 `templates`，
  步驟要寫 `frame`），沒有才裁新的、名字不能跟既有的撞。

完成：每個找圖步驟引用的範本都有取材幀、裁切框、至少一個 `absent` 幀（或是引用既有範本）；
清單裡的找圖都想過要不要宣告捲動軸。

## 6. 寫計畫

照 [plan-format.md](plan-format.md) 寫 `<W>/plan.json`（新流程的校準對、名稱與位置由 video-to-flow 補；補充的
插入點 `after`／`into`＋`expect` 由 edit-flow 定），交回入口 skill 去跑 `assemble` 或 `insert`。

完成：計畫寫好，入口 skill 知道它的路徑。

## 讀驗證結果（`assemble`／`insert` 跑完後）

工具輸出與交付報告列出`待重拍`與`待確認`。入口 skill 跑完工具後回到這裡逐一處理：

- 「找不到」「位置不符」「出現前就匹配」→ 換一幀或調框，或補比色／挑選規則（挑中的不是 `at` 那一個＝規則設錯），
  改計畫重跑。新流程重跑前**刪掉上一次產出的資料夾**（否則變成 `<流程名>_2`）；補充已經寫回既有流程，
  要重來先請使用者確認再手動復原（工具不備份）。
- 「縮放餘裕」（取材幀縮到 ×0.85／放大到 ×1.15 找不到或貼門檻）→ 裁小、只框按鈕本體，或換一幀。
- 「唯一」（固定矩形裡有兩個以上匹配）→ 不自動縮框：換畫面上唯一的參考點，或設挑選規則；都不行就留著，
  交付時說明。
- 「加上固定矩形後挑到的不是同一個」→ 框附近有同款；同上處理。
- 待確認「捲動清單」→ 確實在捲動清單裡就補 `scroll` 重跑，否則告知使用者不用管。
- 待確認「忙碌檢查」兩向 → 勾了沒看到：確認真的會讓遊戲忙，不會就取消；沒勾看到了：考慮勾。
- 補充的「新範本跟既有的幾乎一樣」→ 改成引用既有的重跑（補充重跑見上）。
- 修不了的留著：範本在流程資料夾裡、步驟照建，使用者在 app 重截同名範本即可。
- 「驗證不完整」（深度驗證模型沒載入）一定要告訴使用者。

完成：每張待重拍、每個待確認都試過修或寫明修不了的原因。
