# AutoClick 按鍵精靈（自動化應用）

在螢幕畫面中尋找範本圖並自動點擊、以步驟序列描述自動化流程的桌面工具。
本詞彙表定義的是**平台無關的核心語意**——即使 UI 重寫或移植到其他平台，這些定義依然成立。
詞條以中文為正式名稱，`code:` 標註程式碼中的對應識別字。

本 repo 有兩個 context（自動化應用／主體偵測引擎），對照與詞彙界線見根目錄 `CONTEXT-MAP.md`。

## Language

### 流程與執行

**流程**（code: 一個資料夾＝`flow.yaml`＋`templates/`）:
一份依序執行的步驟清單。**一份流程＝一個自包自足的資料夾**（ADR 0014）：步驟清單、
流程層級設定、校準資料都在 `flow.yaml`，引用到的每一張範本圖在 `templates/`；複製這個
資料夾就搬完整份流程，拿到任何一台裝了同版 app 的電腦直接開直接跑。「存檔」指的就是
這個資料夾。
_Avoid_: 腳本、巨集、flow pack、.autoclickpack（舊的 zip 封裝，ADR 0006，已退場）

**步驟**（code: `step`，各類型見下）:
流程中的一個單位——一個動作（點擊、拖曳、找圖…）或一個區段標記。

**輪**（code: `round`、`run`：輪數或 `forever`）:
整份流程從頭到尾完整執行一遍。執行設定指定總輪數或無限輪。
_Avoid_: 重複（與「重複區段」混淆）

**測試選取**（code: `start_run(steps=…, test=True)`）:
只執行清單中選取片段的單次執行；跳選會補滿頭尾、收合區段算整段。

**急停**（code: `hotkey`，F12）:
執行中隨時中止整個流程的全域快速鍵。

### 啟動與就緒

**引擎就緒**:
驗證模型於背景載入完成、辨識功能可用的狀態；應用視窗可操作不代表引擎就緒，
就緒前的辨識類操作一律提示並拒絕。
_Avoid_: 啟動完成（視窗可操作與引擎就緒是兩個時間點）

**範本預載**:
讀取流程時在背景一次載入該流程引用的全部範本登錄產物（引擎還沒就緒就等就緒後開始，
包括 app 啟動時自動開的上次流程）；不是執行中用到哪張才載哪張。載過的留在記憶體，
新增或重截範本只換掉那幾張。按「執行」時再補齊還缺的；背景那份還沒做完就接著等它。
驗證模型不另外暖機：實測第一次推論沒有可察覺的額外成本。
_Avoid_: 懶載入（預載以整份流程為單位，不是逐步驟延後）、執行前預載（舊說法：按執行才開始載）

**開始延遲**（固定 3 秒，不是設定）:
從按下「執行」到開頭校準之前的**時間下限**；還沒做完的範本預載在這段時間內繼續進行。
預載提早完成就等到到期，超過了就預載一完成就開始，到期時仍在預載會提示正在等範本。
_Avoid_: 固定等待（它是下限，不是預載完再額外等的時間）、啟動延遲設定（已退場：四份流程都用 3 秒）

### 存檔與快取

**流程存放區**（code: `apppaths.flows_root()`）:
放流程資料夾的預設位置：開檔與新流程第一次存檔的對話框從這裡開，影片轉流程預設輸出到這裡。
在專案裡、不進版控；打包版拿到沒有專案的電腦上時改用使用者資料夾底下的固定位置。
流程資料夾也可以存在別處，存放區只是預設。
_Avoid_: 執行區（容易跟`搜尋範圍`、`固定矩形`混淆）、流程的預設位置（舊說法）

**快取**（code: 流程資料夾內的 `.cache/`）:
流程資料夾裡可重建的部分：引擎的`登錄產物`（參考圖、遮罩、向量、meta）與還沒存檔的
暫存截圖。過期自動重算；重開 app 或讀取流程時暫存截圖清掉。隨資料夾一起複製，
到新電腦不必等預載。還沒第一次存檔的新流程沒有資料夾，它的快取放本機狀態資料夾裡
固定的「未存檔」快取，第一次存檔時搬進新資料夾；開新流程、讀取流程或重開 app 時清空。
_Avoid_: 工作區（舊名：profile 底下解壓存檔用的快取，已退場）、暫存目錄

**引擎參數覆蓋**（code: `flow.yaml` 的 `engine:` 段，可不寫）:
一份流程對引擎參數（`匹配門檻`、比色門檻等）的局部覆蓋；沒寫就用引擎內建預設
（ADR 0015）。它是「換遊戲要變的東西」唯一的落點。
_Avoid_: profile、config.yaml（已退場的遊戲層級容器）

**存檔**:
把記憶體裡的流程寫回它的資料夾：`flow.yaml` 整份重寫，`templates/` 只留被引用的範本
（被移除步驟的圖一併移除，`templates/` 永遠等於引用集合）。改動在存檔前只在記憶體；
關閉 app 時提示未存檔；開啟 app 讀上次開的流程；新流程在第一次存檔時才選資料夾。
_Avoid_: 自動存檔、草稿（已退場）

已退場（ADR 0014、0015）：**profile**（遊戲層級的資料包：引擎參數、流程資料夾、工作區）、
**工作區**、**步驟草稿**（自動存檔的落點）。

### 步驟種類

**座標點擊**（code: `click`）:
在`原點`加一段偏移的位置左鍵單擊的步驟；只有`相對座標`一種基準。
_Avoid_: 點擊（單獨使用時與找圖的點擊動作混淆）、絕對座標點擊（已退場）

**拖曳**（code: `drag`）:
從起點按住滑鼠移動到終點放開的步驟；終點一律成為新的原點。

**等待**（code: `wait`）:
純粹停留指定秒數的步驟。

**找圖**（code: 步驟 `type` 為 `find_click` / `find` / `wait_gone` 三者之一）:
在畫面中輪詢等待它的`找圖目標`出現或消失的步驟；找到後的動作由三態決定。
_Avoid_: 找圖點擊（僅指動作為「點擊」的找圖步驟，不是整個步驟類型）

已退場（2026-10-10，ADR 0014）：**按鍵**步驟（送出鍵盤按鍵或組合鍵）——四份在用流程
0 次使用，影片也看不到按鍵。鍵盤只剩`急停`。

### 找圖語意

**找圖三態**（code: 步驟 `type`: `find_click` / `find` / `wait_gone`）:
找圖步驟找到圖之後的三種動作——點擊（找到就點）、僅等待出現（不點）、等待消失。

**等待消失**（code: `wait_gone`）:
找圖三態之一：必須先看到圖至少一次、之後消失才算通過；從未出現＝逾時失敗。
「消失」＝先前被`挑選規則`挑中的那個位置不再有匹配；畫面別處的同款圖不影響。

已退場（2026-10-10，ADR 0014）：**出現等候上限**（等待消失「沒看到也通過」的選項）
——它的用途被`忙碌檢查`取代（ADR 0011），四份在用流程 0 次使用。

**範本**（code: `template`）:
用於畫面辨識的截圖影像，**屬於某一份流程**。**一範本一張圖**；名稱是平面名稱
（沒有資料夾層級），在一份流程內唯一。實體就是流程資料夾裡的 `templates/<名稱>.png`，
檔名即範本名。跨流程複製進來的是獨立副本——來源流程日後改圖
不會偷偷改變這份流程的行為（快照語意）。
_Avoid_: 模板（保留給引擎 context 的 Template 一詞）、圖片、多截圖範本（已退場）

**確認圖**（code: `confirm_target`；yaml 為 `confirm: {appear: …}`）:
`生效確認`選擇「確認圖出現」時，用來判定操作已生效的另一個`找圖目標`
（自帶範本、限定範圍、挑選規則、比色）。

**匹配門檻**（code: 引擎參數 `match_threshold` / `verify_threshold`）:
辨識「找到與否」的兩關門檻（粗篩、深度驗證），由引擎內建預設統一管理、流程可用
`引擎參數覆蓋`改，按「基準測試集總體成績」的紀律調參。步驟層級沒有門檻欄位（ADR 0002）。
_Avoid_: 相似度門檻（舊模板比對的語意，分數體系不同、無可靠換算）

**找圖目標**（code: 步驟的 `target`、`automation/findtarget.py`）:
「找一張圖」的通用單位：範本＋`限定範圍`＋`挑選規則`＋`比色`。凡是要在畫面上找圖的
地方都是一個找圖目標——找圖步驟本身（含當作分支條件時）、`確認圖`；
「點到下一步的圖出現」直接沿用下一步的找圖目標。三個屬性屬於找圖目標，
不屬於範本：同一張範本在不同地方可以有不同設定。
_Avoid_: 找圖條件（「條件」保留給分支）、查詢（引擎詞彙）

**匹配**:
畫面上符合找圖目標的一處（沿用引擎詞彙）。同款圖可能同時有好幾個匹配；
開了`比色`時顏色不符的不算匹配。

**挑選規則**（code: 找圖目標的 `pick`）:
找圖目標有多個`匹配`時取哪一個：分數最高（預設，與舊行為相同）、由上到下第 N 個、
由左到右第 N 個、最接近指定點（指定點＝`原點`加一段偏移，隨`畫面倍率`換算；偏移 (0,0)＝最接近原點；
沒有原點＝無法執行，同`相對座標`）。
排序時中心高度差不到半個框高視為同一列。匹配不足 N 個＝這次沒找到，繼續輪詢到逾時——
絕不退而點別個。
_Avoid_: 選擇規則（易與測試選取、下拉選擇混淆）

**比色**（code: 找圖目標的 `color`、引擎參數 `color_threshold`）:
找圖目標的開關：找到後再以顏色確認一次，顏色不符就不算`匹配`。用來分開形狀相同、
只有顏色不同的圖（可按的橘色按鈕 vs 停用的灰色按鈕、同列名不同顏色的設施列）。
門檻是引擎參數的一個值（同`匹配門檻`的紀律）；步驟不各自設門檻。
只用在色差大的地方：開了比色的找圖目標，在`支援倍率範圍`兩端本尊與他者的顏色分數
都要差 0.1 以上；差不到就不是比色該解的題（換`參考點`或挑選規則）。
_Avoid_: 嚴格比對（易誤解為拉高匹配門檻）、彩色比對

**搜尋範圍**（code: `scan_region`）:
找圖時只擷取與比對的螢幕區域；使用者執行前手動框（框得大一點、不必精準）。
**不是任何座標的基準**——座標一律以`座標基準點`為原點，所以框得鬆緊、視窗擺在螢幕
哪裡都不影響步驟。開頭`校準`也只在它裡面找校準對。
單一找圖步驟要再縮小時用`限定範圍`，不是另設一個搜尋範圍。
_Avoid_: 搜尋區域（保留給引擎 context 的 Search Region——查詢輸入的裁切影像）

**限定範圍**（code: 找圖目標的 `within`）:
`找圖目標`只在`搜尋範圍`的一部分裡找圖的設定，二選一：
- 不限定。
- `固定矩形`。

以`原點`為基準的矩形已退場（2026-10-10，ADR 0014：四份在用流程 0 次使用；
`影片轉流程`改直接產固定矩形）。

用途：排除畫面上別處的同款或相似圖，也讓找圖變快（範圍越小越快）。
九宮格（把搜尋範圍切 3×3）已退場：它跟著手框的搜尋範圍走，違反`座標基準點`。
_Avoid_: 搜尋區域（引擎詞彙）、找圖範圍、步驟範圍、region（舊版已廢除的步驟欄位）、九宮格

**固定矩形**（`限定範圍`的一種）:
在畫面上拖框選出的矩形，存成相對`座標基準點`的偏移（`流程尺度`，執行時 ×`畫面倍率`），
所以視窗挪位置、縮放、搜尋範圍重框都不用重設。
用在位置固定的圖；會捲動的清單則把框沿捲動方向拉長，涵蓋它可能出現的整段。
框要留`矩形餘裕`（見`拾取檢查`），不是貼著圖框。
落在`搜尋範圍`外的部分照裁掉（範圍框太小時，被裁掉那塊裡的圖就找不到）。
_Avoid_: 自訂區域、ROI

**共用矩形**:
`影片轉流程`裡，一組同類`找圖目標`共用的一個`固定矩形`：目標落在同一個容器裡、每次出現在哪一格
不一定（例：商店的商品格每天換位置、有兩排）。框＝整個容器每邊再外推成員圖框一半，所以靠邊那格的餘裕
跟單一目標的固定矩形一樣；容器會捲動時再沿捲動方向拉長。哪些目標算同一組由 Claude 判斷、`交付報告`
列出來給使用者確認。存進流程後就是各步驟上一模一樣的固定矩形，流程存檔不記組別；`補充`的新成員
照抄既有成員那一步的固定矩形。
_Avoid_: 整區、格子區、容器框（容器是畫面上的東西，共用矩形是由它算出的範圍）

**生效確認**（code: `confirm`: `none` / `gone` / `appear` / `next`）:
送出輸入後判定「遊戲真的接受了這個操作」的機制，適用於`找圖`（動作為點擊時）、
`座標點擊`、`拖曳`三種步驟。生效條件四選一（或不確認）：目標圖消失（只限找圖：被點的
那個位置不再有匹配）、`原點的圖離開`（只限座標點擊與拖曳）、`確認圖`出現、下一步的圖出現。
未生效時依`補做`規則重送同一個輸入，逾時走「找不到時」處置。
存在的理由：遊戲畫面畫好了（圖找得到）不代表遊戲已經接受輸入——伺服器還沒回應時輸入會被
靜靜吃掉。
_Avoid_: 點擊後確認（舊名，只涵蓋找圖點擊）、拖曳後確認（同一件事不另取名）

**原點的圖離開**（code: `confirm: "gone"`，用在座標點擊與拖曳）:
生效確認的一種：產生目前`原點`的那個找圖步驟，它的`找圖目標`在它當時挑中的位置不再有
`匹配`＝生效（例：找「發電站1列」→ 拖曳捲動清單，1 列離開原本的框＝有捲動）。
不必另選確認圖、操作前也不必多找一次。前提是操作前的原點來自找圖步驟；來自點擊或拖曳
（或沒有原點）＝該步驟無法執行，介面以警告標記提示，同`找圖相連`。
_Avoid_: 確認圖離開原位（確認對象不是另選的圖，而是原點的來源）

**點到下一步的圖出現**（code: `confirm: "next"`）:
生效確認的一種：以「找圖相連」的下一步的`找圖目標`找得到為生效條件（限定範圍、
挑選規則、比色都照下一步的設定，原點用操作後的）。確認對象依清單位置跟隨（不記名），排序後自動指向新的下一步。

**找圖相連**:
「點到下一步的圖出現」的前提——緊接的下一個步驟必須是找圖步驟（三態皆可）。不相連（最後一步、下一步是區段標記或其他類型）＝該步驟無法執行；可先存檔，介面以警告標記提示，執行時擋下。

**補做**:
生效確認還沒通過時，重送同一個輸入（再點一次、再拖一次）。只在兩個條件都成立時才補：
距離上一次輸入已過`補做間隔`，且畫面上沒有`忙碌指示`（流程沒設忙碌指示就只看間隔）。
理由：遊戲只是慢、不是吃掉輸入時，太早補做會重複操作——拖曳捲過頭、開關被點回關閉。
_Avoid_: 補點（拖曳也會補做）、重試

**補做間隔**（固定 1000ms，不是設定）:
上一次輸入之後，至少要隔多久才允許`補做`。所有流程、所有步驟共用這個常數
（原本是流程層級設定，從未改過，2026-10-10 改常數）。

**忙碌指示**（流程層級設定，可不設）:
遊戲「正在等伺服器、暫時不接受輸入」時畫面上出現的指示，以一個`找圖目標`描述
（例：明日方舟底部的「正在提交反饋至神經……」字樣＋限定範圍）。範本住在流程存檔裡；
不同客戶端字樣不同，各流程自己設。兩個用途：
- `補做`之前查：畫面上有忙碌指示就不補做。
- `忙碌檢查`：勾了的步驟送出輸入後，等忙碌指示消失才往下走。
找圖等待期間不看忙碌指示：逾時照常計時。
_Avoid_: loading 圖、轉圈圖

**忙碌檢查**（步驟選項，預設不勾；清單標〔忙碌檢查〕）:
送出輸入的步驟（`座標點擊`、`拖曳`、`找圖`點擊）可勾。勾了的步驟順序是：
輸入 → 等`忙碌指示`消失 → `生效確認`（沒設確認就到此結束）。
等法：`忙碌出現等候`內一次都沒看到＝放行（就算確認其實已經成立也等滿）；看到就等它消失，
最多 60 秒，等不到＝停止流程。`補做`重送後不再另等，照舊由補做的門擋。
流程沒設忙碌指示卻有步驟勾了＝執行前擋下。
存在的理由：忙碌時畫面上的圖常常還看得到（例：換班清單的列名），找圖第一輪就找到、馬上操作，
輸入被遊戲吃掉。會讓遊戲忙的操作要由作者勾起來，引擎不自己猜。
例：換班點 ⇄ → 等忙碌消失 → 才點下一個 ⇄；關掉簽到 → 等忙碌消失 → 才回頭找下一個彈窗。
_Avoid_: 忙碌暫停（ADR 0010 的舊機制，已移除）、做完等忙碌、等網路

**忙碌出現等候**（固定 1000ms，不是設定）:
`忙碌檢查`送出輸入後，最多花多久等忙碌指示出現；這段時間內沒看到就當這次不會忙。
忙碌指示通常在點擊後慢一點才出現，所以不能只看一眼。所有流程共用這個常數
（原本是流程層級設定，從未改過，2026-10-10 改常數）。

**找不到時**（code: `on_fail`: `skip` / `break` / `stop`，沒寫＝`stop`）:
找圖逾時（或生效確認逾時）的處置——跳過、跳出目前區段、停止流程。

**避開游標**（一律開啟，不是設定）:
找圖截圖前先把滑鼠停到搜尋範圍左下角外側（夾在該螢幕內），不遮畫面也消除 hover 反白對比對的干擾。
原本是流程層級開關，四份流程都開著，2026-10-10 改為固定行為。

### 拾取與清場

**拾取**（code: `ui_overlay.pick`）:
從實際螢幕畫面上以框選、點選或拉線取得範圍、座標或截圖的互動過程。
_Avoid_: 截圖（截圖只是拾取的一種產物）

**清場**（code: `ui_overlay.screen_clear`）:
拾取前把應用自身所有視窗暫時隱藏、讓出螢幕，拾取結束後全數還原的過程——
避免自家視窗被拍進畫面。巢狀的拾取流程共用同一次清場，中途不還原。
清場只涵蓋截圖與使用者在覆蓋層上的操作；辨識（校準、找圖、拾取檢查）不在「視窗藏著、
畫面上什麼都沒有」的時候做——覆蓋層出現的同時在背景進行，或視窗還原後進入`辨識中`。
_Avoid_: 隱藏視窗（清場是含還原在內的完整過程，不只是隱藏）

**辨識中**:
視窗還原後、背景辨識還沒做完的狀態。介面照常重繪，發起的那個視窗顯示「辨識中…」；
與圖片或辨識有關的動作（存檔、開啟或新增流程、執行、截圖新增、重截、拾取、比對測試、
校準對的設定與測試）反灰，其他設定照常可改；發起辨識的對話框做完前不能關閉、確定或取消
（按確定本身觸發的`拾取檢查`例外：對話框照關，改由主視窗顯示）。關掉整個應用＝沒做完的結果丟棄。
_Avoid_: 忙碌（保留給遊戲的`忙碌指示`）、凍結

### 座標與原點

**座標基準點**:
流程裡所有存下來的座標數值共用的原點＝`校準對`第一張圖的中心，位置由`校準`量得
（執行時在開頭、編輯器在每次拾取當下）。存的座標都是相對它的偏移、`流程尺度`；
執行時 ×`畫面倍率`再加上它的螢幕位置才是落點。因此遊戲視窗在螢幕上的位置、
`搜尋範圍`框得準不準，都不影響步驟。執行期才知道的位置（`原點`）不存檔、不受此限。
_Avoid_: 錨點（保留不用）、視窗左上角（基準點不是視窗角）、搜尋範圍左上角（舊基準）

已退場（2026-10-10，ADR 0014）：**絕對座標**（以`座標基準點`為原點的點擊座標）——
四份在用流程 0 次使用，`影片轉流程`也不產出。`座標基準點`仍是`固定矩形`與範本拍攝位置的基準。

**相對座標**:
以`原點`為基準的偏移量；座標點擊與拖曳唯一的座標基準。
_Avoid_: mode/prev（舊格式的欄位值；新格式沒有基準欄位）
_Avoid_: 相對上一步點擊位置（原點來源不限點擊、也不限上一步）

**原點**（code: `_last_click`、歷史命名）:
相對座標的參考點＝最近一個「有更新原點」的步驟所產生的位置——點擊落點、拖曳終點、找圖找到（或最後看到）的位置。
來自找圖時，原點同時記得它的來源（哪個找圖目標、挑中哪個框），供`原點的圖離開`使用。
_Avoid_: 上一步點擊位置、上一次點擊（來源不限點擊、也不限上一步）

**更新原點**（code: `update_origin`）:
步驟是否把自己產生的位置設為新原點；所有產生原點的步驟皆可取消勾選，唯拖曳一律更新。

**預設原點**（code: `use_base`）:
截圖拾取相對座標時，由前面步驟推算並預先標示（◎）的原點位置。前面那個找圖步驟的
圖此刻不在畫面上時，退用該範本的**拍攝位置**（範本截圖當下的中心，相對`座標基準點`存）。

**偏移**（code: `offset`: `[x, y]`）:
找圖點擊時相對於「找到位置中心」的位移量。

### 尺度與畫面倍率

一份流程只有一個尺度；執行時只有一個倍率，座標與找圖共用（ADR 0009，取代 ADR 0005 的
profile 層級校準）。

**流程尺度**:
一份流程所有像素量的共同尺度＝**建立這份流程時的畫面大小**。步驟座標（找圖偏移、相對座標、
限定範圍、拖曳距離）與範本圖都是這個尺度；同一份流程裡不會混兩種尺度。
在建立時的視窗大小下執行，倍率就是 1。不同客戶端（簡中視窗、繁中最大化）的流程各有
各的尺度，互不影響。
_Avoid_: 基準機器、基準尺度（舊模型：profile 共用一個基準，座標與範本尺度不一致）

**校準對**（流程存檔內）:
流程自帶的兩張範本，作為這份流程的比例尺；兩張圖必須在執行開頭的畫面上同時看得到。
**選遊戲畫面內**的兩張、相距夠遠的固定圖（例：主畫面左上與右下的圖示）：量到的才是遊戲
畫面本身的倍率。標題列圖示＋關閉鈕量到的是「視窗寬減去固定裝飾」，裝飾不隨倍率縮，
倍率會偏小約 0.4%、座標誤差隨離基準點的距離增長（1500px 外約 5px），所以標題列只當
`備用校準對`（ADR 0013）。遊戲內的兩張要**不跟著滑鼠移動**：主畫面右側按鈕區會隨游標傾斜（視差），校準前游標停在
搜尋範圍左下，跟建立時游標位置不同就量偏（倉庫偏約 100px、倍率 ×1.063）。
例外：開頭會有彈窗或公告的流程（早班），主畫面被模糊 → 標題列當校準對、遊戲內那組當備用（c5f8a23）。住在流程存檔裡，跟流程一起搬。沒有校準對的流程不能執行。
_Avoid_: 比例尺（口語說明用）、錨點、主校準對（不加字首；加字首的是備用那組）、
profile 校準對（已退場）

**備用校準對**（code: `calibration.fallback`；流程存檔內，可不設；ADR 0013）:
`校準對`在執行開頭找不到（彈窗蓋住、不在主畫面）時改用的第二組兩張範本（例：標題列
圖示＋關閉鈕，任何畫面都在）。設定時兩組要同時在畫面上，記下它自己的`基準距離`與
「它第一張的中心 → `座標基準點`」的偏移（`流程尺度`）；用它量時基準點＝它第一張的中心
加上偏移×倍率，所以存下的座標一律仍相對`座標基準點`，不因用了備用而改變。
用到備用對時執行紀錄印一行警告、照跑（倍率略偏，靠`拾取檢查`的餘裕吸收）。
_Avoid_: 第二校準對、後備錨點

**基準距離**（流程存檔內）:
校準對兩張圖的匹配框中心在`流程尺度`下的直線距離，是畫面倍率的分母。

**校準**:
在`搜尋範圍`內找到校準對兩張圖的量測，一次得出兩個值：中心距離 ÷ 基準距離＝`畫面倍率`，
第一張的中心＝`座標基準點`的螢幕位置。**執行流程時每次開頭自動做**，執行中不再重量
（視窗在執行中途挪動不在處理範圍）；校準對任一張找不到＝改量`備用校準對`（有設的話，
印警告），備用也找不到＝不執行，報明原因；量到的倍率在`支援倍率範圍`外也不執行。
編輯器在**每次`拾取`當下**用拾取的那張截圖量（位置與倍率都是當下的），不必手動按校準；
找不到＝不存，提示重框搜尋範圍。
設定校準對：還沒有校準對的流程，設定當下的畫面就是流程尺度（倍率 1），直接量距離當
基準距離；已有校準對要換，先用舊對量出倍率，新對的基準距離＝量到的距離 ÷ 倍率。
換校準對＝換`座標基準點`：同一張畫面上新舊兩對都要找到，所有存下的座標依兩個基準點
的差（換回流程尺度）一次平移，落點完全不變；舊對找不到＝不能換。
還沒有校準對的流程沒有座標基準點：拾取固定矩形一律擋下，提示先設校準對。
_Avoid_: 翻新解析度（已移除的舊功能）、未校準（舊模型的狀態：不再有「沒量也照跑」）

**畫面倍率**:
目前畫面相對`流程尺度`的單一等比縮放倍數，由`校準`取得，只屬於這一次執行（或這一次
拾取）。兩個用途：步驟座標乘上它換算落點；找圖時引擎只在它附近的尺度找範本。
拾取時反過來：螢幕上取得的座標與截下的範本圖都除以它，換回流程尺度再存。
_Avoid_: DPI 縮放（OS 顯示設定，另一回事）、相似度（比對分數，無關）、
範本倍率（範本沒有自己的倍率——它就是流程尺度）

**支援倍率範圍**（ADR 0013）:
一份流程保證跑得完的`畫面倍率`區間：×0.85～×1.15，涵蓋兩個客戶端各自的最大化與視窗
模式（四組）。所有餘裕都以這個區間的兩端當最壞情況來定與驗收；流程不另外宣告自己的
範圍。範圍外不執行：開頭`校準`量到區間外＝不執行（同校準對找不到），說明目前倍率、
支援區間與視窗該調大或調小；編輯器拾取當下或按「校準」量到區間外只警告。
_Avoid_: 視窗模式支援（支援的是倍率區間，不是某一種視窗狀態）

**拾取檢查**（code: `automation/pickcheck.py`；ADR 0013）:
編輯器在拾取當下立刻做、**只警告不擋存檔**的一組檢查，目的是讓範本與限定範圍在
`支援倍率範圍`兩端都還找得到、挑得對。三項：
- `縮放餘裕`（截範本時）：同一張截圖縮到 ×0.85 與放大到 ×1.15 各找一次，粗篩或驗證
  分數貼近`匹配門檻`就警告——範本該重截，不是降門檻。
- `矩形餘裕`（拾取`固定矩形`時）：矩形每邊至少比該找圖目標的範本多 20%（`流程尺度`；
  50px 範本 → 至少 70px）。像素餘裕會隨倍率縮小、再被基準點量測誤差吃掉，所以用百分比。
- `唯一`（`找圖目標`設好之後，照它的限定範圍查）：引擎回報的`匹配`多於一個就不唯一。
  設了「第 N 個」「最接近」這類`挑選規則`的找圖目標已宣告會有多個，不查。
`影片轉流程`的自我驗證套同一套標準，沒過的標`待重拍`。三個常數（粗篩 0.7、驗證 0.85、20%）的由來在
ADR 0013，改動它們要改 ADR。
_Avoid_: 範本體檢、餘裕檢查（唯一不是餘裕）

**參考點**（找圖的用法，不是新的步驟種類；ADR 0013）:
畫面上**唯一**、位置與目標固定相對的一張圖，用`定位找圖`找到後以`偏移`或`相對座標`
點到真正的目標。目標本身在畫面上有同款分不開時（換班的設施列名只差數字）就改找
參考點，不靠`比色`硬分。
_Avoid_: 錨點（保留不用）、定位物（口語；正式用參考點）

已退場（ADR 0009）：profile 層級的校準資料、機器指紋、未校準狀態、重定基準、匯入換算
與來源基準標記——流程自帶尺度與比例尺，搬到哪台機器都只需要在執行開頭量一次。

### 區段與流程控制

**區段**（code: app 內是平面標記步驟；`flow.yaml` 內巢狀）:
以成對標記步驟包住的一段流程——重複區段或分岔區段；區段可巢狀但必須完整包含、不可交錯。

**重複區段**（code: `repeat_start` / `repeat_end`；yaml 為 `repeat:`＋`steps:`）:
執行指定次數的區段。
_Avoid_: 重複（與「輪」混淆）、迴圈

**分岔**（code: `branch_start` / `branch_or` / `branch_end`；yaml 為 `branch:`＋`if:`／`then:`）:
由多個分支組成的區段：執行時輪詢各分支的條件，先成立者走該分支；
同一張截圖裡有多個分支成立時，走排在最前面的那個——分支順序就是優先順序。
_Avoid_: 分支（分支指分岔內的單一路徑）

**分支**:
分岔內的一條路徑；開頭必須是找圖步驟，該步驟即此分支的條件。全部逾時時依條件步驟的「找不到時」決定跳過或停止。

**跳出**（code: `break`，「找不到時」的選項之一）:
跳到最內層所屬區段結尾之後；重複區段被跳出＝放棄剩餘次數。不在任何區段內時等同停止。
_Avoid_: continue 語意的誤解（跳出＝放棄整個區段，不是跳過本次進入下一次）

**跳出後動作**（code: `on_break`: `continue` / `break`，app 內設在區段結尾標記）:
因「找不到→跳出」抵達區段結尾時的行為——停在結尾之後繼續（預設），或連外層區段一起跳出（可連續傳播，跳出最外層＝停止流程）。正常走到區段結尾不受影響。

### 影片轉流程

**示範影片**:
使用者在執行流程的這台機器上**只錄遊戲視窗**（與實際畫面同尺度）、看得出`點擊特效`的一次完整操作錄影，是`影片轉流程`
的唯一輸入；`補充`用的是只錄一段的示範影片。它只示範「這一次」的走法：看不到鍵盤按鍵，也看不到這次沒出現的彈窗。
_Avoid_: 錄製（易誤解為 app 自己錄滑鼠事件——那條路已排除）、攻略影片（別人的畫面尺度與語系都不同）

**影片轉流程**:
由 Claude 依專案 skill 把一段`示範影片`變成一份`流程`存檔的過程；不是 app 內的功能。
產物是一般的流程存檔，盡量能直接跑，同時就是可編輯的步驟清單；另附`交付報告`。
_Avoid_: 自動錄製、巨集錄製

**點擊特效**:
影片裡看得出「這裡點了一下」的視覺效果；`影片轉流程`靠它找出每一次點擊的時間與位置。
可能是錄影程式畫的（點擊處的色圈），也可能是**遊戲自繪游標**本身的動作——遊戲把系統
游標換成自己畫的圖時錄影程式畫不出特效，但那個游標在按下、放開時會抖一下。
後者靠`游標樣本`（從影片學到的游標長相與熱點）追蹤。
同時也是範本的污染源——範本一律取自點擊前、游標尚未移到、沒有特效的乾淨影格。

**游標樣本**（code: `kind: "cursor"`，`tools/video_to_flow/cursor.py`）:
遊戲自繪游標的長相（帶透明度的圖）＋熱點（游標尖端，即實際點擊的位置），由 Claude
在幾幀游標停在不同背景上的影格標出尖端、工具對齊後學出；掃描靠它追游標、看游標抖動。
_Avoid_: 游標模板（「模板」是引擎詞彙）

**影片與實際畫面同尺度**:
`示範影片`在執行流程的這台機器上、以實際畫面尺度錄製（不縮放）：影片像素＝螢幕像素，
偏移原樣進存檔，範本圖也不縮放。`搜尋範圍`只決定執行時在哪裡找圖，不再拿來推算影片
尺度（舊稱「影片換算比」已退場）。影片的尺度就是產出流程的`流程尺度`，不再換算；
校準對也從影片裡挑、基準距離在影片上量。`補充`例外：影片尺度不一定等於既有流程的尺度，靠`影片倍率`換算。
_Avoid_: 影片換算比（已退場）、影片尺度

**補充**:
把一段只錄局部操作的`示範影片`量成步驟、插進一份既有`流程`；屬於修改既有流程，不產新流程。
插入段自己先`定位找圖`再用`相對座標`，插入後面舊步驟的`原點`來源不得被它改變。
影片從哪個畫面開始錄都可以；只差在清單捲到哪時靠`對齊圖`補上。
_Avoid_: 補充模式、補充流程（產物不是一份新流程）、追加錄影

**影片倍率**:
`補充`用的影片相對既有流程`流程尺度`的倍率：在影格上（量不到時改用使用者給的同取景圖片）量既有流程的`校準對`
（或`備用校準對`）得出，同時量到`座標基準點`在影格上的位置。影片量到的像素量 ÷ 影片倍率才進存檔，新範本也縮放到流程尺度。
跟執行時的`畫面倍率`是兩回事：前者把影片換到流程尺度，後者把流程換到此刻的畫面。
_Avoid_: 影片換算比（已退場，舊義是從搜尋範圍推算）

**對齊圖**（code: `align`）:
`補充`時，插入點前面既有流程已經用`固定矩形`定位過、補充影片裡也看得到的一張圖；拿它在影片裡的位置
跟它在執行時的位置（定位它的那一步——計畫裡叫參考步驟——固定矩形的中心）比，得出`對齊位移`。只在插入段牽涉捲動清單時需要
（例：add5 的對齊圖＝辦公室類別標題）；面板、彈窗這類固定介面的補充不用。
跟`參考點`、`校準對`不同：參考點是執行時定位目標用的圖，校準對是量倍率用的圖。
_Avoid_: 參考圖、對照圖

**對齊位移**:
`補充`影片開頭的畫面跟流程跑到插入點時的畫面，因清單捲在不同位置而差的距離（`流程尺度`）。
插入段第一次捲動之前的位置照它平移；第一次捲動的拖曳距離吸收它，讓清單停到影片裡拖完的狀態，之後的位置照影片。
_Avoid_: 畫面落差、捲動偏移

**定位找圖**:
為了讓後續`相對座標`有`原點`而插入的找圖步驟——動作為「僅等待出現」、更新原點。
不是新的步驟種類，只是找圖的一種用法；`影片轉流程`只產出找圖與相對座標，找圖的限定範圍直接產`固定矩形`。
_Avoid_: 錨點（保留不用：曾是`校準對`的避免用詞）

**交付報告**:
`影片轉流程`隨存檔附上的說明，住在流程資料夾裡（`交付報告/`：一份總覽＋每個頂層區段一份），跟著流程搬；app 不讀不寫，存檔也不動它：哪些範本`待重拍`、哪裡可能需要分岔、哪些畫面變化
無法用點擊解釋（流程不支援按鍵，請使用者改用點擊）、哪些找圖可能落在捲動清單裡。流程存檔格式不為它增加任何欄位。
`補充`把它的說明寫進插入處那個區段的那一份與總覽，不在尾巴累積歷史。

**待重拍**:
`影片轉流程`的自我驗證（用引擎對影格重跑，含`拾取檢查`三項：縮放餘裕、矩形餘裕、唯一）沒通過、或找不到乾淨影格的範本；
只列在`交付報告`裡，範本名與檔名都不帶標記；由使用者在 app 重截同名範本。
（舊做法「圖檔名加前綴 `待重拍_`」已退場，2026-10-10：檔名即範本名，前綴會變成範本名的一部分。）
