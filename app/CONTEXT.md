# AutoClick 按鍵精靈（自動化應用）

在螢幕畫面中尋找範本圖並自動點擊、以步驟序列描述自動化流程的桌面工具。
本詞彙表定義的是**平台無關的核心語意**——即使 UI 重寫或移植到其他平台，這些定義依然成立。
詞條以中文為正式名稱，`code:` 標註程式碼中的對應識別字。

本 repo 有兩個 context（自動化應用／主體偵測引擎），對照與詞彙界線見根目錄 `CONTEXT-MAP.md`。

## Language

### 流程與執行

**流程**（code: `steps`、`flows/*.autoclickpack`）:
一份依序執行的步驟清單。**一份流程＝一個自包自足的存檔**：步驟清單與這份流程
引用到的每一張範本圖、校準資料都在同一個檔案裡（ADR 0006），複製這個檔案就搬完
整份流程，拿到任何一台裝了同版 app 的電腦直接開直接跑。
_Avoid_: 腳本、巨集、flow pack（存檔就是流程的唯一實體，不再有另一種封裝）

**步驟**（code: `step`，各類型見下）:
流程中的一個單位——一個動作（點擊、拖曳、找圖…）或一個區段標記。

**輪**（code: `round`、`run_mode`、`run_count`）:
整份流程從頭到尾完整執行一遍。執行設定指定總輪數或無限輪。
_Avoid_: 重複（與「重複區段」混淆）

**測試選取**（code: `start_run(steps=…, test=True)`）:
只執行清單中選取片段的單次執行；跳選會補滿頭尾、收合區段算整段。

**急停**（code: `hotkey`，F12）:
執行中隨時中止整個流程的全域快速鍵。

### 啟動與就緒

**引擎就緒**:
驗證模型於背景載入完成、辨識功能可用的狀態；應用視窗可操作不代表引擎就緒，
就緒前的辨識類操作一律提示並拒絕。
_Avoid_: 啟動完成（視窗可操作與引擎就緒是兩個時間點）

**範本預載**:
執行流程前一次載入該流程引用的全部範本登錄產物的階段；應用啟動時不載入範本，
也不是執行中用到哪張才載哪張。
_Avoid_: 懶載入（預載以整份流程為單位，不是逐步驟延後）

**開始延遲**（code: `Runner.start(start_delay, pressed_at)`）:
從按下「執行」到開頭校準之前的**時間下限**；範本預載在這段時間內同時進行。
預載提早完成就等到到期，超過了就預載一完成就開始，到期時仍在預載會提示正在等範本。
_Avoid_: 固定等待（它是下限，不是預載完再額外等的時間）

### 設定檔

**profile**（code: `profiles/<game>/`、`profile_store.py`）:
一個遊戲（或同遊戲的一套設定）的資料包：引擎參數 `config.yaml`、流程存檔
`flows/`（含`步驟草稿`）、`工作區` `workspace/`（可重建）。校準對與基準距離住在
各流程存檔裡，profile 不存校準資料（ADR 0009）。**沒有範本庫**——範本圖住在
流程存檔裡。一個資料夾算不算 profile，看的是引擎參數設定檔在不在。應用一次連
一個 profile；切換 profile＝流程草稿、範本面板、引擎查詢對象一致跟隨。UI 只提供
切換與建立，改名/刪除交給檔案總管。
_Avoid_: 設定（與引擎參數 config 混淆）

**工作區**（code: `workspace/`、`flowfile.Workspace`）:
profile 底下可重建的快取：當前流程解出來的範本圖與引擎的`登錄產物`。編輯與執行
時 app 把存檔解到這裡給引擎讀，使用者完全不必知道它的存在。**存檔是真相來源，
工作區只是快取**——被刪或毀損時自動重建；**切換流程時整個清空**（圖與登錄產物
一起刪），磁碟上刻意不留任何非當前流程的圖。
_Avoid_: 範本庫（已退場的舊概念：本機一塊使用者要維護的圖片存放區）、暫存目錄

**步驟草稿**（code: `flows/_autosave.json`、`flowfile.write_draft`）:
自動存檔的落點，只有步驟與流程層級設定的輕量 JSON。圖留在`工作區`，按存檔才打包
成存檔——拖曳排序不會因為重寫幾十張圖而卡頓；當機重開時草稿與工作區的圖一起復原。
_Avoid_: 自動存檔的流程檔（草稿不是一份流程，不會出現在流程清單裡）

### 步驟種類

**座標點擊**（code: `click`）:
在指定座標按下滑鼠鍵的步驟；座標基準為絕對座標或相對座標兩種之一。
_Avoid_: 點擊（單獨使用時與找圖的點擊動作混淆）

**拖曳**（code: `drag`）:
從起點按住滑鼠移動到終點放開的步驟；終點一律成為新的原點。

**等待**（code: `wait`）:
純粹停留指定毫秒數的步驟。

**找圖**（code: `find_click`，歷史命名）:
在畫面中輪詢等待它的`找圖目標`出現或消失的步驟；找到後的動作由三態決定。
_Avoid_: 找圖點擊（僅指動作為「點擊」的找圖步驟，不是整個步驟類型）

**按鍵**（code: `key`）:
送出鍵盤按鍵或組合鍵（如 `ctrl+v`）的步驟。

### 找圖語意

**找圖三態**（code: `action`: `click` / `none` / `wait_gone`）:
找圖步驟找到圖之後的三種動作——點擊（找到就點）、僅等待出現（不點）、等待消失。

**等待消失**（code: `wait_gone`）:
找圖三態之一：必須先看到圖至少一次、之後消失才算通過；從未出現＝逾時失敗。
「消失」＝先前被`挑選規則`挑中的那個位置不再有匹配；畫面別處的同款圖不影響。
可另設`出現等候上限`，放寬「從未出現＝失敗」。

**出現等候上限**（等待消失的選項，預設不設）:
等待消失最多花多久等圖出現；這段時間內一次都沒看到＝通過（不是失敗）。
看到之後照常等它消失、受步驟逾時限制。用途是等「可能出現、也可能根本不出現」的圖。
等`忙碌指示`不用這個選項，改勾送出輸入那一步的`忙碌檢查`（ADR 0011）。
_Avoid_: 可略過的等待消失、未出現放行（說的是同一個選項，統一用此名）

**範本**（code: `template`）:
用於畫面辨識的截圖影像，**屬於某一份流程**。**一範本一張圖**；名稱是平面名稱
（沒有資料夾層級），在一份流程內唯一。實體住在流程存檔的 `templates/<名稱>.png`
裡，編輯與執行時解到`工作區`。跨流程複製進來的是獨立副本——來源流程日後改圖
不會偷偷改變這份流程的行為（快照語意）。
_Avoid_: 模板（保留給引擎 context 的 Template 一詞）、圖片、多截圖範本（已退場）

**確認圖**（code: `confirmTarget`）:
`生效確認`選擇「確認圖出現」時，用來判定操作已生效的另一個`找圖目標`
（自帶範本、限定範圍、挑選規則、比色）。

**匹配門檻**（code: profile `config.yaml` 的 `match_threshold` / `verify_threshold`）:
辨識「找到與否」的兩關門檻（粗篩、深度驗證），由 profile config 統一管理，
按「基準測試集總體成績」的紀律調參。步驟層級沒有門檻欄位（ADR 0002；
匯入舊 flow 時每步 `threshold` 安靜丟棄）。
_Avoid_: 相似度門檻（舊模板比對的語意，分數體系不同、無可靠換算）

**找圖目標**（code: 步驟的 `target`、`automation/findtarget.py`）:
「找一張圖」的通用單位：範本＋`限定範圍`＋`挑選規則`＋`比色`。凡是要在畫面上找圖的
地方都是一個找圖目標——找圖步驟本身（含當作分支條件時）、`確認圖`；
「點到下一步的圖出現」直接沿用下一步的找圖目標。三個屬性屬於找圖目標，
不屬於範本：同一張範本在不同地方可以有不同設定。
_Avoid_: 找圖條件（「條件」保留給分支）、查詢（引擎詞彙）

**匹配**:
畫面上符合找圖目標的一處（沿用引擎詞彙）。同款圖可能同時有好幾個匹配；
開了`比色`時顏色不符的不算匹配。

**挑選規則**（code: 找圖目標的 `pick`）:
找圖目標有多個`匹配`時取哪一個：分數最高（預設，與舊行為相同）、由上到下第 N 個、
由左到右第 N 個、最接近指定點（指定點以`原點`或`搜尋範圍`為基準，隨`畫面倍率`換算）。
排序時中心高度差不到半個框高視為同一列。匹配不足 N 個＝這次沒找到，繼續輪詢到逾時——
絕不退而點別個。
_Avoid_: 選擇規則（易與測試選取、下拉選擇混淆）

**比色**（code: 找圖目標的 `colorCheck`、profile 的 `color_threshold`）:
找圖目標的開關：找到後再以顏色確認一次，顏色不符就不算`匹配`。用來分開形狀相同、
只有顏色不同的圖（可按的橘色按鈕 vs 停用的灰色按鈕、同列名不同顏色的設施列）。
門檻是 profile 層級的一個值（同`匹配門檻`的紀律）；步驟不各自設門檻。
_Avoid_: 嚴格比對（易誤解為拉高匹配門檻）、彩色比對

**搜尋範圍**（code: `scan_region`）:
找圖時只擷取與比對的螢幕區域，同時也是`絕對座標`的基準；全域設定一個。
單一找圖步驟要再縮小時用`限定範圍`，不是另設一個搜尋範圍。
_Avoid_: 搜尋區域（保留給引擎 context 的 Search Region——查詢輸入的裁切影像）

**限定範圍**（code: 找圖目標的 `limit`）:
`找圖目標`只在`搜尋範圍`的一部分裡找圖的設定，四選一：
- 不限定。
- 以`原點`為基準的矩形：隨`畫面倍率`換算；沒有原點＝無法執行，同`相對座標`。
- 九宮格：把搜尋範圍切成 3×3 後勾選的格子；勾多格＝包住它們的最小矩形。
- `固定矩形`。

用途：排除畫面上別處的同款或相似圖，也讓找圖變快（範圍越小越快）。
_Avoid_: 搜尋區域（引擎詞彙）、找圖範圍、步驟範圍、region（舊版已廢除的步驟欄位）

**固定矩形**（`限定範圍`的一種）:
在畫面上拖框選出的矩形，存成`搜尋範圍`的比例，所以搜尋範圍重框也不用重設。
用在位置固定的圖；會捲動的清單則把框沿捲動方向拉長，涵蓋它可能出現的整段。
_Avoid_: 自訂區域、ROI

**生效確認**（code: `confirm`: `none` / `gone` / `appear` / `next`）:
送出輸入後判定「遊戲真的接受了這個操作」的機制，適用於`找圖`（動作為點擊時）、
`座標點擊`、`拖曳`三種步驟。生效條件四選一（或不確認）：目標圖消失（只限找圖：被點的
那個位置不再有匹配）、`原點的圖離開`（只限座標點擊與拖曳）、`確認圖`出現、下一步的圖出現。
未生效時依`補做`規則重送同一個輸入，逾時走「找不到時」處置。
存在的理由：遊戲畫面畫好了（圖找得到）不代表遊戲已經接受輸入——伺服器還沒回應時輸入會被
靜靜吃掉。
_Avoid_: 點擊後確認（舊名，只涵蓋找圖點擊）、拖曳後確認（同一件事不另取名）

**原點的圖離開**（code: `confirm: "gone"`，用在座標點擊與拖曳）:
生效確認的一種：產生目前`原點`的那個找圖步驟，它的`找圖目標`在它當時挑中的位置不再有
`匹配`＝生效（例：找「發電站1列」→ 拖曳捲動清單，1 列離開原本的框＝有捲動）。
不必另選確認圖、操作前也不必多找一次。前提是操作前的原點來自找圖步驟；來自點擊或拖曳
（或沒有原點）＝該步驟無法執行，介面以警告標記提示，同`找圖相連`。
_Avoid_: 確認圖離開原位（確認對象不是另選的圖，而是原點的來源）

**點到下一步的圖出現**（code: `confirm: "next"`）:
生效確認的一種：以「找圖相連」的下一步的`找圖目標`找得到為生效條件（限定範圍、
挑選規則、比色都照下一步的設定，原點用操作後的）。確認對象依清單位置跟隨（不記名），排序後自動指向新的下一步。

**找圖相連**:
「點到下一步的圖出現」的前提——緊接的下一個步驟必須是找圖步驟（三態皆可）。不相連（最後一步、下一步是區段標記或其他類型）＝該步驟無法執行；可先存檔，介面以警告標記提示，執行時擋下。

**補做**:
生效確認還沒通過時，重送同一個輸入（再點一次、再拖一次）。只在兩個條件都成立時才補：
距離上一次輸入已過`補做間隔`，且畫面上沒有`忙碌指示`（流程沒設忙碌指示就只看間隔）。
理由：遊戲只是慢、不是吃掉輸入時，太早補做會重複操作——拖曳捲過頭、開關被點回關閉。
_Avoid_: 補點（拖曳也會補做）、重試

**補做間隔**（流程層級設定，預設 1000ms）:
上一次輸入之後，至少要隔多久才允許`補做`。一份流程一個值，各步驟共用。

**忙碌指示**（流程層級設定，可不設）:
遊戲「正在等伺服器、暫時不接受輸入」時畫面上出現的指示，以一個`找圖目標`描述
（例：明日方舟底部的「正在提交反饋至神經……」字樣＋限定範圍）。範本住在流程存檔裡；
不同客戶端字樣不同，各流程自己設。兩個用途：
- `補做`之前查：畫面上有忙碌指示就不補做。
- `忙碌檢查`：勾了的步驟送出輸入後，等忙碌指示消失才往下走。
找圖等待期間不看忙碌指示：逾時照常計時。
_Avoid_: loading 圖、轉圈圖

**忙碌檢查**（步驟選項，預設不勾；清單標〔忙碌檢查〕）:
送出輸入的步驟（`座標點擊`、`拖曳`、按鍵、`找圖`點擊）可勾。勾了的步驟順序是：
輸入 → 等`忙碌指示`消失 → `生效確認`（沒設確認就到此結束）。
等法：`忙碌出現等候`內一次都沒看到＝放行（就算確認其實已經成立也等滿）；看到就等它消失，
最多 60 秒，等不到＝停止流程。`補做`重送後不再另等，照舊由補做的門擋。
流程沒設忙碌指示卻有步驟勾了＝執行前擋下。
存在的理由：忙碌時畫面上的圖常常還看得到（例：換班清單的列名），找圖第一輪就找到、馬上操作，
輸入被遊戲吃掉。會讓遊戲忙的操作要由作者勾起來，引擎不自己猜。
例：換班點 ⇄ → 等忙碌消失 → 才點下一個 ⇄；關掉簽到 → 等忙碌消失 → 才回頭找下一個彈窗。
_Avoid_: 忙碌暫停（ADR 0010 的舊機制，已移除）、做完等忙碌、等網路

**忙碌出現等候**（流程層級設定，預設 1000ms）:
`忙碌檢查`送出輸入後，最多花多久等忙碌指示出現；這段時間內沒看到就當這次不會忙。
忙碌指示通常在點擊後慢一點才出現，所以不能只看一眼。一份流程一個值，各步驟共用。

**找不到時**（code: `onNotFound`: `skip` / `break` / `stop`）:
找圖逾時（或生效確認逾時）的處置——跳過、跳出目前區段、停止流程。

**避開游標**（code: `avoid_hover`）:
找圖截圖前先把滑鼠移到遠處角落，消除 hover 反白對比對的干擾。

### 拾取與清場

**拾取**（code: `ui_overlay.pick`）:
從實際螢幕畫面上以框選、點選或拉線取得範圍、座標或截圖的互動過程。
_Avoid_: 截圖（截圖只是拾取的一種產物）

**清場**（code: `ui_overlay.screen_clear`）:
拾取前把應用自身所有視窗暫時隱藏、讓出螢幕，拾取結束後全數還原的過程——
避免自家視窗被拍進畫面。巢狀的拾取流程共用同一次清場，中途不還原。
_Avoid_: 隱藏視窗（清場是含還原在內的完整過程，不只是隱藏）

### 座標與原點

**絕對座標**（code: `mode: "abs"`）:
以`搜尋範圍`左上角為基準的座標；沒有`搜尋範圍`就沒有基準，此類步驟無法執行。
_Avoid_: 螢幕座標（基準不是螢幕，重新框範圍或換視窗時落點會跟著移動）

**相對座標**（code: `mode: "prev"`）:
以原點為基準的偏移量。
_Avoid_: 相對上一步點擊位置（原點來源不限點擊、也不限上一步）

**原點**（code: `_last_click`、歷史命名）:
相對座標的參考點＝最近一個「有更新原點」的步驟所產生的位置——點擊落點、拖曳終點、找圖找到（或最後看到）的位置。
來自找圖時，原點同時記得它的來源（哪個找圖目標、挑中哪個框），供`原點的圖離開`使用。
_Avoid_: 上一步點擊位置、上一次點擊（來源不限點擊、也不限上一步）

**更新原點**（code: `updateOrigin`）:
步驟是否把自己產生的位置設為新原點；所有產生原點的步驟皆可取消勾選，唯拖曳一律更新。

**預設原點**（code: `use_base`）:
截圖拾取相對座標時，由前面步驟推算並預先標示（◎）的原點位置。

**偏移**（code: `offsetX` / `offsetY`）:
找圖點擊時相對於「找到位置中心」的位移量。

### 尺度與畫面倍率

一份流程只有一個尺度；執行時只有一個倍率，座標與找圖共用（ADR 0009，取代 ADR 0005 的
profile 層級校準）。

**流程尺度**:
一份流程所有像素量的共同尺度＝**建立這份流程時的畫面大小**。步驟座標（找圖偏移、相對/
絕對座標、限定範圍、拖曳距離）與範本圖都是這個尺度；同一份流程裡不會混兩種尺度。
在建立時的視窗大小下執行，倍率就是 1。不同客戶端（簡中視窗、繁中最大化）的流程各有
各的尺度，互不影響。
_Avoid_: 基準機器、基準尺度（舊模型：profile 共用一個基準，座標與範本尺度不一致）

**校準對**（流程存檔內）:
流程自帶的兩張範本，作為這份流程的比例尺；兩張圖必須在執行開頭的畫面上同時看得到
（例：遊戲視窗的標題列圖示＋關閉鈕，兩者距離＝視窗寬）。住在流程存檔裡，跟流程一起搬。
沒有校準對的流程不能執行。
_Avoid_: 比例尺（口語說明用）、錨點、profile 校準對（已退場）

**基準距離**（流程存檔內）:
校準對兩張圖的匹配框中心在`流程尺度`下的直線距離，是畫面倍率的分母。

**校準**:
在目前畫面上找到校準對兩張圖、以中心距離 ÷ 基準距離得出`畫面倍率`的量測。
**執行流程時每次開頭自動做**；任一張找不到＝不執行，報明原因。編輯器不自動量：
倍率預設 1（＝視窗跟建立時一樣大），使用者按「校準」才更新，拾取座標與截範本都用
這個值——視窗大小變了要自己按。
設定校準對：還沒有校準對的流程，設定當下的畫面就是流程尺度（倍率 1），直接量距離當
基準距離；已有校準對要換，先用舊對量出倍率，新對的基準距離＝量到的距離 ÷ 倍率。
_Avoid_: 翻新解析度（已移除的舊功能）、未校準（舊模型的狀態：不再有「沒量也照跑」）

**畫面倍率**:
目前畫面相對`流程尺度`的單一等比縮放倍數，由`校準`取得，只屬於這一次執行（或這一次
編輯）。兩個用途：步驟座標乘上它換算落點；找圖時引擎只在它附近的尺度找範本。
拾取時反過來：螢幕上取得的座標與截下的範本圖都除以它，換回流程尺度再存。
_Avoid_: DPI 縮放（OS 顯示設定，另一回事）、相似度（比對分數，無關）、
範本倍率（範本沒有自己的倍率——它就是流程尺度）

已退場（ADR 0009）：profile 層級的校準資料、機器指紋、未校準狀態、重定基準、匯入換算
與來源基準標記——流程自帶尺度與比例尺，搬到哪台機器都只需要在執行開頭量一次。

### 區段與流程控制

**區段**（code: 平面標記步驟，非巢狀資料結構）:
以成對標記步驟包住的一段流程——重複區段或分岔區段；區段可巢狀但必須完整包含、不可交錯。

**重複區段**（code: `loop_start` / `loop_end`）:
執行指定次數的區段。
_Avoid_: 重複（與「輪」混淆）、迴圈

**分岔**（code: `branch_start` / `branch_or` / `branch_end`）:
由多個分支組成的區段：執行時輪詢各分支的條件，先成立者走該分支；
同一張截圖裡有多個分支成立時，走排在最前面的那個——分支順序就是優先順序。
_Avoid_: 分支（分支指分岔內的單一路徑）

**分支**:
分岔內的一條路徑；開頭必須是找圖步驟，該步驟即此分支的條件。全部逾時時依條件步驟的「找不到時」決定跳過或停止。

**跳出**（code: `break`，「找不到時」的選項之一）:
跳到最內層所屬區段結尾之後；重複區段被跳出＝放棄剩餘次數。不在任何區段內時等同停止。
_Avoid_: continue 語意的誤解（跳出＝放棄整個區段，不是跳過本次進入下一次）

**跳出後動作**（code: `onBreak`: `continue` / `break`，設在區段結尾）:
因「找不到→跳出」抵達區段結尾時的行為——停在結尾之後繼續（預設），或連外層區段一起跳出（可連續傳播，跳出最外層＝停止流程）。正常走到區段結尾不受影響。

### 影片轉流程

**示範影片**:
使用者在執行流程的這台機器上**只錄遊戲視窗**（與實際畫面同尺度）、看得出`點擊特效`的一次完整操作錄影，是`影片轉流程`
的唯一輸入。它只示範「這一次」的走法：看不到鍵盤按鍵，也看不到這次沒出現的彈窗。
_Avoid_: 錄製（易誤解為 app 自己錄滑鼠事件——那條路已排除）、攻略影片（別人的畫面尺度與語系都不同）

**影片轉流程**:
由 Claude 依專案 skill 把一段`示範影片`變成一份`流程`存檔的過程；不是 app 內的功能。
產物是一般的流程存檔，盡量能直接跑，同時就是可編輯的步驟清單；另附`交付報告`。
_Avoid_: 自動錄製、巨集錄製

**點擊特效**:
影片裡看得出「這裡點了一下」的視覺效果；`影片轉流程`靠它找出每一次點擊的時間與位置。
可能是錄影程式畫的（點擊處的色圈），也可能是**遊戲自繪游標**本身的動作——遊戲把系統
游標換成自己畫的圖時錄影程式畫不出特效，但那個游標在按下、放開時會抖一下。
後者靠`游標樣本`（從影片學到的游標長相與熱點）追蹤。
同時也是範本的污染源——範本一律取自點擊前、游標尚未移到、沒有特效的乾淨影格。

**游標樣本**（code: `kind: "cursor"`，`tools/video_to_flow/cursor.py`）:
遊戲自繪游標的長相（帶透明度的圖）＋熱點（游標尖端，即實際點擊的位置），由 Claude
在幾幀游標停在不同背景上的影格標出尖端、工具對齊後學出；掃描靠它追游標、看游標抖動。
_Avoid_: 游標模板（「模板」是引擎詞彙）

**影片與實際畫面同尺度**:
`示範影片`在執行流程的這台機器上、以實際畫面尺度錄製（不縮放）：影片像素＝螢幕像素，
偏移原樣進存檔，範本圖也不縮放。`搜尋範圍`只決定執行時在哪裡找圖，不再拿來推算影片
尺度（舊稱「影片換算比」已退場）。影片的尺度就是產出流程的`流程尺度`，不再換算；
校準對也從影片裡挑、基準距離在影片上量。
_Avoid_: 影片換算比（已退場）、影片尺度

**定位找圖**:
為了讓後續`相對座標`有`原點`而插入的找圖步驟——動作為「僅等待出現」、更新原點。
不是新的步驟種類，只是找圖的一種用法；`影片轉流程`只產出找圖與相對座標，不產出`絕對座標`。
_Avoid_: 錨點（保留不用：曾是`校準對`的避免用詞）

**交付報告**:
`影片轉流程`隨存檔附上的說明：哪些範本`待重拍`、哪裡可能需要分岔、哪些畫面變化
無法用點擊解釋（可能是按鍵）。流程存檔格式不為它增加任何欄位。

**待重拍**:
`影片轉流程`的自我驗證（用引擎對影格重跑）沒通過、或找不到乾淨影格的範本；
範本名加前綴 `待重拍_` 標示，在範本面板一眼可見，由使用者在編輯器重新拾取。

### 舞台（並行執行的接縫；並行執行本輪未移植）

`ParallelRun` 與並行 UI 未隨移植帶入（原實作有 bug、測試不完整，留待日後重做）；
執行器的`舞台`接縫（`automation/stage.py`）與其回歸測試保留。以下詞彙描述該接縫的語意。

**並行執行**:
多份流程分時共用同一組畫面與滑鼠、交錯推進的執行模式；同一時間只有一份流程真的在動作。
_Avoid_: 同時執行、多開（同一時間只有一份在動作，不是真的同時）

**舞台**:
畫面與滑鼠的獨佔權。持有舞台的流程才能截圖找圖與送出點擊；同一時間只有一份流程持有。
_Avoid_: 焦點（焦點是視窗的屬性，舞台是流程之間的權利）、鎖

**讓出點**:
持有舞台的流程主動交出舞台的時機——只有「進入等待步驟」一種；其他流程無法搶佔。
_Avoid_: 中斷點、切換點（不是被別人打斷，是自己交出）

**排隊**:
流程的等待已結束、但舞台仍被別人持有時的狀態。
