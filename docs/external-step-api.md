# 外部步驟串接介面

要做一個讓 AutoClick 流程呼叫的`外部工具`，或在流程裡接上一個外部工具時，讀這一份。
這是介面的正本；決策理由在 [ADR 0018](adr/0018-external-step-single-entry-contract.md)，
詞彙定義在 [`app/GLOSSARY.md`](../app/GLOSSARY.md)。

外部工具是**單入口、單出口**的程式：啟動後一路做完，以結束碼回報成敗，然後退出。
AutoClick 不知道工具在做什麼，只看下面這份合約。

## 一次外部步驟的經過

AutoClick 執行到外部步驟時，依序做下面四件事。工具的每個入口都要照這個順序寫。

1. **問預期時間**：執行 `<入口檔> <參數…> --expected-time`。
   - 工具要在 10 秒內，往標準輸出印一行正數（秒，可帶小數），並以 0 結束。
   - 這個數字靠估算得出：依參數算、查表或讀設定都可以，但不可以真的跑一遍，也不要先載入模型或連網。
   - 數字要涵蓋整趟正式執行，包含等開始畫面出現、啟動和載入的時間。
   - 超過 10 秒、結束碼不是 0、或印出的不是數字，都會讓 AutoClick 判這次執行失敗，
     不會進行正式執行。
2. **正式執行**：執行 `<入口檔> <參數…>`，參數跟第 1 步一樣，只是不帶 `--expected-time`。
   逾時上限＝預期時間＋10 秒，從這次啟動算起。
3. **等它結束**：
   - 結束碼 0 → 步驟完成，流程繼續。
   - 其他結束碼 → 整次執行記為失敗。
   - 超過逾時上限 → AutoClick 結束工具的整個行程樹（含工具自己開的子程序），整次執行記為失敗。
4. **急停**：使用者按 F12 時，AutoClick 往工具的標準輸入寫一行 `stop`。
   - 工具要在下一個安全點停手、收尾，並以非 0 結束。
   - 工具若不理會，AutoClick 就等到逾時上限再強制結束它。
   - 這兩種情況執行紀錄都記為 stopped。
   - 第 1 步問預期時間期間按 F12，AutoClick 直接結束詢問的程序，不寫 `stop`。

## 參考

### 參數與佔位符

參數清單寫在流程裡，原樣傳給工具，只有佔位符會先代換：

| 佔位符 | 代入的值 |
|---|---|
| `{hwnd}` | 遊戲視窗的 handle（十進位整數）：AutoClick 這份流程`搜尋範圍`所在的頂層視窗 |

需要知道「操作哪個視窗」的工具，就接收 `{hwnd}`。兩個客戶端的視窗標題相同（都是「明日方舟」），
所以工具不能靠標題自己找視窗。

### 標準輸入、輸出

- 標準輸入是一條一直開著的管線，只會收到一種內容：一行 `stop`。標準輸入被關掉（EOF）時，也要當作收到 `stop`，因為那代表 AutoClick 已經不在了。
- 標準輸出和標準錯誤用 UTF-8。正式執行時，AutoClick 只把最後 5 行和結束碼寫進`執行紀錄`。
  失敗時要讓最後一行說清楚原因，例如「錯誤：不在招募清單」。

### 執行環境

- 工作目錄是工具登錄的資料夾。
- AutoClick 啟動工具時不開主控台視窗，所以入口要打包成**主控台程式**（PyInstaller `console=True`）。
  視窗程式（`console=False`）的標準輸入和輸出可能接不上管線。
- 權限直接繼承 AutoClick：`AutoClick.exe` 是系統管理員權限，工具也會是；遊戲是以系統管理員權限執行，
  沒有提權的程序送出的滑鼠事件會被丟掉。入口的 manifest 要用 `asInvoker`。
  如果用 `requireAdministrator`，從沒提權的 `AutoClick-noUAC.exe` 會根本啟動不了。

### 畫面狀態

- 開始時：前一步可能剛點完、畫面還在切換。工具要自己輪詢，等開始畫面出現，這段時間算在預期時間裡。
- 執行中：AutoClick 的迷你窗一直置頂在螢幕右下角，遊戲最大化時會蓋住遊戲的一角。
  工具要確保自己點的位置沒有被它擋住。遊戲需要在前景的話，由工具自己帶到前景。
- 結束時：AutoClick 不重新校準。外部步驟後面若還有步驟，流程作者要在第一步放`定位找圖`。

### 登錄工具（流程作者）

流程資料夾裡、`flow.yaml` 旁邊放 `external_tools.yaml`，把工具名稱對到資料夾和入口檔：

```yaml
公開招募:
  dir: C:\Users\three\我的電腦\AiProject\claude_arknightAecruit\dist\RecruitHelper
  exe: recruit-step.exe
```

步驟寫法：

```yaml
- {external: 公開招募, args: [--hwnd, '{hwnd}']}
```

- 每份流程各有一份登錄，複製流程資料夾就一起帶走。工具搬家時，每份流程的登錄都要改。
- 按開始時，AutoClick 會檢查流程引用的工具名稱都已登錄、資料夾和入口檔都存在。少了任何一個，就不開始執行。

## 交付前的驗收

工具要逐項通過下面五項，才算可以交給流程用。每一項都要真的跑過，看結束碼和輸出確認：

1. `--expected-time` 在 10 秒內印出一個正數，並以 0 結束。
2. 正式執行成功時，以 0 結束。
3. 正式執行遇到錯誤時，以非 0 結束，最後一行寫明原因。
4. 執行中往標準輸入寫 `stop`，會以非 0 結束。
5. 執行中關掉標準輸入，會以非 0 結束。
