# ADR 0001:引擎/設定檔分離 + 兩階段查詢管線

Status: accepted(2026-08-15)

## 決策

1. **引擎與遊戲設定檔嚴格分離**。判準:「換一個遊戲要不要變」——要變的
   (模板庫、尺度範圍、閾值、遮罩策略、基準案例)住在 `profiles/<game>/`;
   不變的才進 `src/subject_detection/`。引擎內不得出現針對特定模板的特例。
2. **兩階段查詢**:梯度域多尺度帶遮罩模板匹配粗篩(門檻鬆、保召回)→
   DINOv2-S 嵌入相似度驗證(門檻嚴、保精確)。`found` 需兩關都過。
3. **登錄自動化**:`load_profile` 以內容 hash + 登錄相關 config 子集
   (`scale_range`、`mask_strategy`)判斷失效,自動補登錄;門檻類參數
   只在查詢時讀取。

## 理由

- 模板多為 25–100px 低紋理 UI 裁切:特徵點方法抓不到特徵,通用偵測器
  難以區分細粒度差異(線索 1–7)。模板匹配保留全部空間結構,配合多尺度
  掃描吸收 0.6x–1.5x 的解析度差。
- 梯度域(Scharr magnitude + zero-mean NCC)天然抗亮度平移與色偏,
  夜間模式/變灰不需要任何顏色處理。
- 半透明透出背景與可變計數文字是「登錄時可知」的雜訊:跨拍攝像素穩定度
  生成遮罩,一個機制同時處理兩種問題,不在引擎裡寫特例。
- 嵌入驗證擋粗篩假陽性:真實正樣本餘弦 ≥0.88,背景誤取 ≤0.66 量級,
  0.8 門檻有實測邊際。

## 踩過的坑(實作備忘)

- 梯度幅值非負:必須用 zero-mean 的 TM_CCOEFF_NORMED,否則平緩背景
  兩兩餘弦 ≈1。
- OpenCV 對「視窗變異數為零」回報 1.0(平面 UI 面板、遮罩下近零變異):
  需以(遮罩加權)視窗變異數下限濾除,下限相對模板自身變異數取。
- Windows 中文路徑:cv2.imread/imwrite 會失敗,一律走
  np.fromfile + imdecode(`imio.py`)。

## 替代方案(保留為升級路徑)

兩階段未達標時:以合成資料(隨機縮放/色偏/隨機背景)訓練 SiamFC 式
單樣本偵測網路。目前 bench 100%,未啟用。
