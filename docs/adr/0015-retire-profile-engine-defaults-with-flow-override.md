# ADR 0015：profile 退場；引擎參數改內建預設＋流程覆蓋

Status: accepted（2026-10-10）。修訂 ADR 0001 第 1 點（引擎／遊戲設定檔分離）：
「換遊戲要變的東西」改住在流程裡，不再有遊戲層級的容器。

## 背景

profile（`profiles/<game>/`）裝三樣東西：引擎參數 `config.yaml`、流程存檔 `flows/`、
快取 `workspace/`。實際上只有 arknights 一個 profile，兩個客戶端的流程都在裡面。
它的 `config.yaml` 與引擎內建預設只差一項（倍率搜尋範圍 0.6–1.5 對 0.5–2.0），而
ADR 0009 之後查詢都帶校準量到的預期尺度，這個範圍只剩登錄與無提示查詢在用；
`mask_strategy` 在一範本一張圖之下也形同無效。換句話說 profile 沒有任何真正的
遊戲專屬資訊，卻在主視窗佔一個下拉與一顆建立鈕、在程式裡佔一個模組與一套切換語意。
ADR 0014 把流程改成資料夾後，`flows/` 與 `workspace/` 兩個用途也消失了。

## 決策

1. **profile 概念、`profile_store` 模組、`profiles/` 目錄全部退場。** app「開檔」直接選
   任何位置的流程資料夾；app 本機狀態只記上次開的流程路徑與視窗位置。
2. **引擎參數＝內建預設＋流程覆蓋。** 引擎內建一份預設（`default_config.yaml`）；
   `flow.yaml` 可選填 `engine:` 段，用同樣的鍵名覆蓋其中幾項。沒寫就是預設。這是
   「換遊戲要變的東西」唯一的落點——範本、校準對、參數覆蓋都在那份流程裡。
3. **基準測試集搬到 repo 根目錄 `benchmark/`**（內容重製見 ADR 0016）。它是開發用資料，
   不進打包版。
4. 引擎的公開 API 不變形狀：仍收範本清單＋引擎參數＋登錄產物位置（ADR 0006）；
   只是「引擎參數」改由 app 從內建預設與流程覆蓋合併後交付。

## 取捨與已知代價

- 同一個遊戲有多份流程、都要同一組覆蓋時，各寫一次（目前零份流程需要覆蓋）。
- 引擎詞彙「遊戲設定檔（Game Profile）」退場，改稱「引擎參數」。

## 替代方案

- **app 旁一份全域參數檔。** 拒絕：所有遊戲共用，換遊戲要改來改去；使用者問的正是
  「別的遊戲能不能各自載參數」。
- **保留「流程資料夾」當容器、只是不叫 profile。** 拒絕：UI 仍要一個「選資料夾」，
  問題只是換名。
- **兩者都要（全域檔＋流程覆蓋）。** 拒絕：三層合併多一層要解釋，目前沒有需要。
