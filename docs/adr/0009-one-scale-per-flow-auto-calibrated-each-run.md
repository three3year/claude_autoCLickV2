# ADR 0009:一份流程一個尺度,每次執行開頭自動校準

Status: accepted(2026-10-05)。取代 ADR 0005。第 5 點(編輯器倍率)由 ADR 0012 修正。

## 背景

ADR 0005 讓 profile 共用一組校準對與基準距離,流程座標存「基準機器」尺度,執行時乘
畫面倍率;範本圖則維持拍下當時的尺度(ADR 0007 已註明兩者不同)。實際用起來:

- 同一 profile 有兩個客戶端(簡中視窗約 0.81、繁中最大化約 0.91),每次換客戶端都要
  重新校準;倍率是 profile 共用的一個值,只能對其中一邊正確。
- 座標與範本是兩種尺度:實跑的範本匹配尺度都在 1.00～1.06,但倍率是 0.805。所以
  倍率不能拿來縮小引擎的尺度搜尋範圍,引擎每次查詢都得掃 0.6～1.5(找圖慢的主因)。

## 決策

1. **一份流程一個尺度**(`流程尺度`):座標與範本圖都是建立流程時的畫面大小。
2. **校準對與基準距離住在流程存檔裡**;profile 不再有校準資料、機器指紋、未校準狀態、
   重定基準、匯入換算與來源基準標記。
3. **每次執行開頭自動校準**,得到這次執行的`畫面倍率`;校準對任一張找不到＝不執行
   (沒有「警告後以倍率 1 照跑」)。沒有校準對的流程(含舊格式)可以開、可以看,不能執行。
4. **一個倍率兩個用途**:步驟座標乘上它;引擎查詢收到它當預期尺度,只掃以它為中心的
   5 個尺度(左右各 2 格、每格 ×1.09,寬度寫死在引擎)。2026-10-05 用 demo1～5 影格實測:
   沒對準的窄範圍 [0.9,1.12] 因網格沒有一格落在 1.0,框偏 2～4px、比色掉到門檻下,
   換班定位整站失敗;以 1.0 為中心的網格無此問題,基建換班兩份流程 0 漏、約快 1.8 倍。
5. 編輯器不自動量:倍率預設 1,使用者按「校準」才更新;拾取的座標與截下的範本圖都
   除以倍率,換回流程尺度再存。
6. 設定校準對:新流程以當下畫面為流程尺度;換校準對要先用舊對量出倍率。
7. 現有四份在用流程一次性換算(座標乘上各自客戶端的倍率、各自帶校準對);
   日常_影片與 arknight* 三份舊流程廢棄,不寫通用自動遷移。

## 捨棄的方案

- **只收窄 profile config 的尺度範圍**:最便宜,但留著兩種尺度與「換客戶端要校準」的
  麻煩;視窗大小一變,找圖就掉出範圍。
- **保留 profile 校準、每張範本另記截圖倍率**:能讓引擎知道預期尺度,但同一份流程裡
  仍有兩種尺度,重定基準與跨流程複製都要同步維護範本倍率。
- **用引擎回報的匹配尺度當倍率**(不要校準對):ADR 0005 當初已捨棄——引擎要回報尺度、
  精度受精修步距限制;而且第一次找圖之前沒有倍率可用。
- **校準對找不到時以倍率 1 照跑或沿用上次值**:校準對是標題列這類幾乎一定看得到的圖,
  找不到多半代表畫面不對;照跑會靜靜點偏。沿用上次值還得多存機器指紋這份狀態。

## 影響

- 存檔格式升版(流程帶校準對、基準距離);引擎查詢多一個可選的預期尺度,沒給時
  照 profile config 的尺度範圍(基準測試集與沒有校準的呼叫端不受影響)。
- 每次執行多一次開頭校準(兩次查詢)。
- `影片轉流程`:影片尺度就是流程尺度,校準對從影片挑、基準距離在影片上量。
