# ADR 0010:忙碌指示在畫面上的時間不算進找圖逾時

Status: accepted(2026-10-07)。取代 ADR 0008 的決策 4、5;決策 1～3 不變。

## 背景

ADR 0008 只在補做前查忙碌指示,搜尋階段完全不看。2026-10-07 早班實跑出了兩次問題:

- `早_簡中` 開頭清彈窗:關掉簽到後,遊戲在等網路,底部顯示忙碌指示。開頭分岔的 5 秒逾時
  在這段時間用完,判定「沒有彈窗了」,跳出重複區段。下一個彈窗等網路回來才出現,這時流程
  已經往下走,使用者只能中斷重跑。
- 「传递线索」的生效確認逾時 3 秒,其中 2.5 秒在等忙碌指示消失,結果判定逾時。下一步立刻
  找到了,這次沒造成損害。

遊戲在等網路的時候,下一個畫面還沒出來,這時不能判定「找不到」。

## 決策

1. **`忙碌暫停`**:找圖在等待的期間,包括分岔條件、一般找圖、生效確認、等待消失,
   輪詢沒達成時(沒找到、還沒生效、圖還在)查一次忙碌指示。查到的那段時間不計入逾時,也不計入等待消失的出現等候上限。
2. **上限**:同一步驟累計最多暫停 60 秒,超過後照常計時。斷線時流程不會永遠卡住。
3. **移除「忙碌指示 → 等待消失」步驟**(取代 ADR 0008 決策 5):換班後那些專門等忙碌指示
   消失的步驟,早晚班四份流程都拿掉。等網路的時間交給下一步的忙碌暫停處理。
4. 補做前照舊要查忙碌指示(ADR 0008 決策 3)。

## 捨棄的方案

- **拉長逾時**:每天沒有彈窗、或網路正常時,都要白等到逾時結束。而且等網路的時間沒有上限,
  拉多長都可能不夠。
- **主畫面出現(基建入口)才算彈窗清完**:引擎沒有「直到某張圖出現」的結束條件。
  另外,彈窗之間的空檔可能已經看得到主畫面。
- **維持只在補做前查**(ADR 0008 原本的理由:每一步多一次查詢):忙碌指示的找圖目標有限定範圍,
  每次查詢很快。逾時被忙碌吃掉,代價是流程走錯路,比多一次查詢嚴重。

## 後果

- 流程沒設忙碌指示,或忙碌指示的範本比不到時,行為跟以前一樣。繁中的忙碌指示範本
  (best 約 0.19)要重新截,不然繁中沒有這個效果。
