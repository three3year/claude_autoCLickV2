# ADR 0006：一份流程＝一個自包自足的存檔；引擎改收範本清單

Status: accepted（2026-08-18）

## 背景

`流程`與它用到的`範本`原本分家：步驟只存範本名，圖存在 profile 的**範本庫**
（`<profile>/templates/`）裡。三個問題由此長出來：

1. **搬不動。** 把流程檔複製到另一台電腦（或另一個 profile），對方沒有那些圖，
   一執行就 KeyError。必須另外記得走「匯出流程包」這條路，漏了就是缺圖跑不動。
2. **多一塊要維護的東西。** 本機憑空多出一個圖片存放區：資料夾層級、命名空間、
   哪張圖還有沒有人用，全變成使用者要管的事。
3. **選範本時看不到別份流程的圖。** 想沿用另一份流程已經拍好的圖，沒有入口。

引擎那側也被這個佈局綁著：`Engine.load_profile(profile_dir)` 自己去掃
`<profile>/templates/`，於是「範本怎麼存」變成了引擎的知識——`基準測試集`為了
跑起來也得依賴一個 profile 的範本庫。

## 決策

### 一、一份流程＝一個自包自足的存檔

存檔是一個 zip（副檔名沿用 `.autoclickpack`），裡面同時裝著：

```
flow.json               步驟與流程層級設定（含 coordSpace / flowFormat / `校準對`與`基準距離`）
templates/<名稱>.png    這份流程引用到的每一張範本圖（含校準對的兩張）
templates/_meta.json    範本元資料：{"pos": {範本名: [x, y]}}
```

（2026-10-05 修訂，ADR 0009：校準對與基準距離改住在 flow.json，兩張圖就是流程的
範本；原本的 calibration.json、calibration/ 與 sourceBaseline 退場。）

- **只寫入被引用的範本**（步驟的找圖目標含`確認圖`，以及流程的校準對）。刪掉引用它的步驟再存檔，那張圖就
  離開存檔——檔案內容永遠等於流程真正需要的東西，不隨時間囤積用不到的圖。
- **一範本一張圖**，名稱是平面名稱（沒有資料夾層級），在一份存檔內唯一。
- **本機不再有範本庫。** profile 只剩引擎參數、流程存檔與`工作區`。
  判定一個資料夾是不是 profile，改看引擎參數設定檔是否存在。
- **`工作區`**（`<profile>/workspace/`）是可重建的快取：當前流程解出來的範本圖
  與引擎的`登錄產物`。**存檔是真相來源，工作區只是快取**——被刪或毀損時自動
  重建；**切換流程時整個清空**（圖與登錄產物一起刪）。
- **自動存檔只寫`步驟草稿`**（輕量 JSON），圖留在工作區；按存檔才打包成 zip。
- **匯出動作移除**（存檔本身就是可搬移的檔）；**匯入保留**，職責縮小成舊格式的
  單向轉換與外來檔的複製落地。開啟不在本 profile 內的存檔＝原樣複製一份副本
  進來再開，原始檔不被動到（流程自帶尺度與校準對，不換算，ADR 0009）。

格式規則、工作區生命週期、撞名加序號與引用改寫、舊格式匯入、一次性轉換規則
全部集中在 `app/flowfile.py` 一個資料進資料出的模組；UI 與 runner 只呼叫它。

### 二、引擎改收範本清單

`Engine.load_templates(templates, config, artifacts_dir)`：呼叫端交付
**範本清單**（範本名 → 圖檔路徑）、引擎參數，以及登錄產物要寫到哪裡。

- **舊的「掃目錄」入口整條移除**（`load_profile`／`load_profile_dir`／
  `discover_templates`／`Profile`），不留相容層——兩條讀取路徑長期共存會讓
  「範本怎麼存」這件事又漏回引擎裡。
- 引擎參數的載入方式不變（仍讀 profile 的 `config.yaml` 覆蓋預設值）。
- `基準測試集`的 case 契約改為**自帶模板圖**（`benchmark/<case>/template.png`），
  benchmark 因此完全不依賴任何範本庫；加 case 仍然是「丟檔案就好、不改程式」。
  benchmark 自己的來源截圖放在 `benchmark/_assets/templates/`（產生器用）。
- 依賴方向不變（單向：app → 引擎），辨識仍然只有一條路徑（ADR 0002）。
  `enginehub` 對外形狀一個字不改，改的只是它內部如何取得範本：從「探索 profile
  目錄」換成「把當前流程的工作區掃成範本清單交給引擎」。

## 取捨與已知代價

這個決策**買到的是**「一個檔案就能搬」與「本機沒有一塊圖片存放區要維護」，
**付出的是**：

- **放棄多截圖範本的登錄品質。** app 不再產生多截圖範本，既有 40 個雙截圖範本
  降為單張（取`登錄基準張`＝排序後第一張）。`可變區`（計數文字、半透明卡片
  透出的底色）原本靠「截圖之間不一致」算出遮罩，現在只剩單張梯度啟發式。
  引擎的 `multi_capture` 登錄能力保留，只是 app 不再用它。
  - **實測結果：`基準測試集` 38/38 → 38/38，沒有退步**（記錄見
    `.scratch/self-contained-flow-file/benchmark-after-single-capture.md`）。
    跌幅最大的 `f1_counter_5of7`（計數文字）0.933 → 0.908，離門檻仍有 0.108
    餘裕。查詢反而快了約 2.7 倍（遮罩較寬 → 過粗篩的候選變少）。
  - 但 benchmark 沒有覆蓋「同一元素在遊戲不同狀態下差異更大」的長尾情形——
    那正是雙截圖原本準備對付的。日後若某個範本在特定畫面狀態下抓不到，
    這是第一個該懷疑的地方。
- **放棄跨流程共用同一份圖。** 採快照語意：複製後各自獨立。早晚兩份流程共用的
  十幾張圖變成各存一份，日後在一邊重拍不會同步到另一邊。
- **切換流程要重跑登錄。** 工作區清空是刻意的取捨：磁碟上不留任何非當前流程的
  圖，代價是切回去時該流程的範本要重新登錄（實測 43 張約 3 秒）。
- **孤兒範本消失。** 一次性轉換時，沒有被任何流程引用的範本不會進任何存檔
  （repo 開發用資料 2 個、打包版 58 個）。

## 兩個容易被誤讀成疏漏的決定

- **`基準測試集`的來源截圖留在版控裡**（`benchmark/_assets/templates/`）。
  「刪除舊的範本庫」指的是 profile 底下那個使用者要維護的圖片存放區；benchmark
  的來源截圖是**測試資料**，不是流程的範本。留著它 `tools/build_arknights_benchmark.py`
  才重跑得起來——benchmark 是本專案的驗收關卡，沒有來源截圖就再也重建不了。
  Out of Scope 的「範本圖回版控」講的是流程的範本圖，不是這批。
- **工作區是 per-profile 的，切 profile 不清空。** 「切換流程時工作區整個清空」
  的範圍是同一個 profile 內換流程；工作區本來就定義成「profile 底下的快取」，
  每個 profile 各有一個、各自裝著自己當前的那份流程。切回某個 profile 時它的
  草稿與圖還在，正是「當機重開後未存檔的編輯不會白做」要的行為。

## 替代方案

- **維持範本庫、只把「匯出流程包」做得更顯眼。** 拒絕：漏掉匯出這一步的代價
  是「在對方機器上跑不動」，而使用者要的正是「複製一個檔案就好」。而且它完全
  不解決「本機多一塊圖片存放區要維護」。
- **存檔裡放範本的參照（雜湊/路徑）而不是圖。** 拒絕：那就還是需要一個共用的
  圖片存放區，自包自足直接落空。
- **保留多截圖範本（存檔裡一個範本放多張圖）。** 拒絕：多截圖的整套 UI 與
  「哪張是基準張」的心智負擔，換來的品質在驗收集合上量不出差別；真的需要時
  引擎能力還在，是另一個題目。
- **引擎保留掃目錄入口當方便方法。** 拒絕：兩條讀取路徑共存，「範本怎麼存」
  就會慢慢漏回引擎裡，`基準測試集`也會繼續綁在某個 profile 的佈局上。

## 後果

- 讀寫流程的路徑只有 `flowfile` 一個入口，格式規則不必開 GUI 就能驗
  （`app/tests/test_flowfile.py` 全以暫存目錄真測）。
- 主視窗的範本面板變成「本流程的範本清單」，資料夾層級整個移除。
- 選範本對話框可以跨存檔瀏覽（樹狀每列帶縮圖，展開某個來源時才去讀它的圖），
  **按確定才複製**、取消不留痕；取消整個找圖對話框時，這次加進來卻沒被引用的
  圖一併收回去。
- 主視窗步驟工具列多了一顆「新流程」：存檔格式改了之後，「開一份新的、順便把
  工作區清乾淨」沒有別的入口（讀檔只能切到既有的存檔）。
- 一次性轉換已對 repo 開發用資料與打包版正式資料各跑一次（報告在
  `.scratch/self-contained-flow-file/`），轉換工具 `tools/convert_to_flow_files.py`
  跑完即功成身退——app 只讀新格式，這不是內建的長期遷移路徑。
- 執行期行為零變化：`急停`、`找不到時`、`區段`、`點擊後確認`、`更新原點`、
  `畫面倍率`換算等執行語意一個字沒動，執行器整張回歸網與 `enginehub` 測試
  一行未改即通過（假件形狀不變是這次改動的硬性驗收條件）。
