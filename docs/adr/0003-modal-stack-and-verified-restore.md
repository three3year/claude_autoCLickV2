# ADR 0003：modal 堆疊取代輪詢協商，清場改驗證式還原

Status: accepted（2026-08-16）

## 背景

拾取（框選新增範本圖等）結束後，步驟編輯對話框偶發不重新顯示：畫面上只剩
被 modal grab 擋住的主視窗，按 Esc 能關掉看不見的對話框（子視窗活著、握著
鍵盤 grab，只是沒被畫出來），發生後往往「一直壞」，使用者只能重開程式。
打包版、雙螢幕環境實際回報。調查確認是清場（`ui_overlay.screen_clear`）
還原流程的結構缺陷，不是單一 bug：

1. 隱藏有保護（`update()` + 等待）、還原沒有——`deiconify()` 只是把 map
   請求排進佇列就繼續往下走，接著 overlay 被銷毀、前景讓給背後的應用程式。
2. 還原對象由 wm state 快照篩選，withdrawn 視為「刻意隱藏」永遠跳過——
   一次還原失手，之後每次清場都不再還原它（壞一次就一直壞）。
3. modal 沒有堆疊：各視窗各跑「100ms × 15 次逾時放棄」的 `_regrab` 輪詢
   互搶 grab，靠 `takeover` 白名單協商誰能從誰手上接走；存圖後同步整庫
   重登錄卡住主執行緒數秒即燒光重試預算，對話框回來也不再 modal。

## 決策

1. **明確 modal 堆疊**（`window_coord.WindowCoordinator` + `ui_grab`）：
   全域一個堆疊，開 modal 入堆、`<Destroy>` 出堆（含中途關閉非堆頂），
   grab 永遠歸堆頂；以事件驅動（堆頂變更、堆頂視窗 `<Map>`）奪回，
   取代輪詢逾時放棄與 takeover 白名單。Combobox popdown 之類過客 grab
   不入堆。清場期間堆疊暫停奪 grab（overlay 持有 grab 是拾取的必要條件），
   離場後 grab 歸堆頂。
2. **驗證式還原**：清場進場記錄「本次 withdraw 的視窗清單」（含 zoomed
   快照），離場照清單逐窗 `deiconify` → 以 `<Map>` 事件確認真的畫出來
   （逾時重試、記日誌）→ 依清單順序 lift → grab 交還堆頂 → 最後才銷毀
   overlay（巢狀拾取的覆蓋層暫存到最外層離場，維持「還原全程在覆蓋層
   後面、一次揭示」）。不在清單上的視窗一律不碰。
3. **決策邏輯與 Tk 分離**：堆疊與還原清單的決策收在純狀態機
   （`window_coord.py`，純 pytest 覆蓋），Tk 側只是薄執行層——這是本輪
   唯一新增的測試接縫。
4. **配套防線**：存圖後整庫重登錄延後到視窗確認可見之後（引擎查詢前以
   `ensure_registered()` 補跑）；全域保險絲低頻監控「grab 持有者不可見」
   超過門檻自動救回；清場進出、還原重試、grab 轉移、保險絲觸發、未攔截
   例外全部落地檔案日誌（`applog.py`），偶發問題不需重現也能查。

## 取捨

- **Tk 層對稱驗證 vs win32 API 直接控制**：曾考慮用 win32
  （SetForegroundWindow / ShowWindow）直接控制視窗顯隱與前景，繞開 Tk
  非同步映射的不確定性。拍板走 Tk 層——與 Tk 的視窗管理狀態（wm state、
  grab、事件佇列）保持單一事實來源，win32 只保留既有用途（點擊穿透、
  工作區查詢等）不擴大；代價是還原要自己等 map 確認，以逾時重試與保險絲
  兜底。
- **事件驅動 vs 輪詢**：輪詢「重試預算」在主執行緒被長工作卡住時必然失效
  （存圖重登錄數秒即燒光 15 次 ×100ms），且多個守護迴圈互搶需要白名單協商，
  每加一種視窗都要重新推演。堆疊語意讓 grab 歸屬變成單一決策點；代價是
  所有 modal 視窗必須走 `make_modal`（repo 慣例本就如此）。
- **保險絲是證據不是機制**：正常運作時永不觸發；觸發紀錄即機制有洞的
  證據，用日誌修洞，而不是把保險絲當第一道防線。

## 影響

- `ui_overlay._regrab`（輪詢守護）與 `make_modal(prev=)`／`show_match_test`
  的 prev 交接參數廢除；呼叫端的清場介面（context manager、可巢狀）不變。
- 「grab 還原後仍會被後續 Toplevel 打掉，_regrab 守護仍然必要」的舊踩坑
  紀錄隨本決策過時，app/CLAUDE.md 已同步改寫。
