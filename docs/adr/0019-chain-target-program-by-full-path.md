# ADR 0019：串接以完整路徑認出目標程式

Status: accepted（2026-11-11）。詞彙（`串接`、`串接檔`、`目標程式`）見 `app/GLOSSARY.md`。

## 背景

使用者要把多份流程串起來依序跑（例：早_繁中 → 早_簡中）。每份流程輪到時，app 要把它的遊戲移到最上層。
因此流程要記下「我操作的是哪個程式」。這台電腦上兩個客戶端能拿來分辨的東西幾乎都一樣：

- 遊戲本體都叫 `Arknights.exe`。
- 視窗標題都是「明日方舟」，簡中的啟動器 `Games.exe` 也用這個標題。
- 標題列圖示一樣，之前就發生過校準到錯的視窗。

只有安裝路徑不同：`GRYPHLINK\games\Arknights_TC\…` 與 `Arknights bilibili\games\Arknights Game\…`。

## 決策

`目標程式`以**完整路徑**記在 `flow.yaml`。這個欄位是選填，只有放進串接的流程必須有。
設定時從開著的程式中點選，不手打。「同一個目標程式」的定義是路徑相同。串接的失敗規則看的就是它：
一份失敗後，後面路徑相同的流程跳過，路徑不同的照跑。單獨執行一份流程時不讀這個欄位。

## 與 ADR 0014 的關係

ADR 0014 說流程資料夾拿到任何電腦都能直接開、直接跑。這個決定沒有破壞那個承諾：

- 單獨執行完全不看這個路徑。
- 只有串接會用到。換電腦後路徑不同，串接的準備檢查會說找不到這個程式在執行，重選一次就好。

前例是 ADR 0018 的`外部工具登錄`，它也在流程資料夾裡記本機路徑。

## 替代方案

- **只記程式名稱。** 拒絕：兩個客戶端同名，這台電腦就分不出繁中和簡中。
  四份流程也會全部被當成同一個程式，一份失敗會讓其他流程都被跳過。
- **名稱加標題，或名稱加視窗類別。** 拒絕：兩邊都一樣。
- **輪到時把同名的視窗逐一叫上來試校準，看哪個對得上。** 拒絕：標題列圖示一樣，會對到錯的視窗；
  每次也要多翻一輪視窗。
