# ADR 0018：外部步驟——呼叫單入口單出口的外部工具

Status: accepted（2026-11-03）。介面細節的正本是 [`docs/external-step-api.md`](../external-step-api.md)，
本篇只記決定與理由。詞彙（`外部步驟`、`外部工具`、`外部工具登錄`、`預期時間`）見 `app/GLOSSARY.md`。

## 背景

使用者想在早／晚四份流程的最後接上公開招募。公開招募已在另一個專案（`claude_arknightAecruit`）
實作，但那邊是常駐的 Tk GUI：要手動點縮圖選視窗、不會自己結束、結束碼一律 0、結果只寫在視窗裡。
那邊會另做一個專給點擊程式呼叫的執行檔：啟動後一路跑完，或中途回報錯誤。

## 決策

1. **通用的`外部步驟`，不是專用的公招步驟。** 點擊程式只負責啟動、等待、傳停止、看結束碼，
   不知道工具在做什麼。公招只是第一個`外部工具`。
2. **行程邊界，不 import。** 兩邊各自打包、各有自己的 Python 環境與相依套件（公招帶 OCR）。
   介面只用命令列參數、標準輸入、標準輸出和結束碼。
3. **逾時由工具先報`預期時間`**：正式執行前先跑一次「同參數＋`--expected-time`」，
   工具不實際執行，自己估出秒數。這次詢問限 10 秒，問不到就整次失敗。
   正式執行的上限＝預期時間＋10 秒，超過就結束工具的整個行程樹。
4. **F12 走標準輸入**：點擊程式寫一行 `stop`，工具收尾後以非 0 結束。工具若不理會，
   就等到逾時再強制結束。這種情況執行紀錄記 stopped，不記 failed。
5. **成敗只看結束碼**：0＝成功；其他（含逾時）＝整次執行失敗。執行紀錄只收結束碼與輸出的最後 5 行。
6. **`外部工具登錄`放在流程資料夾裡**（`flow.yaml` 以外的另一份檔），各流程各自一份。
   流程只寫工具名稱，登錄把名稱對到「資料夾＋入口檔」。按開始時就檢查登錄與檔案存在，
   有缺就不開始。
7. **點擊程式不替工具準備畫面**：迷你窗照常置頂顯示，前一步點完不另外等畫面就緒。
   開始畫面與避開迷你窗都由工具自己負責。

## 取捨與已知代價

- 每次外部步驟要啟動工具兩次。所以預期時間必須估出來，不能真的跑一遍，也不該先載入 OCR 這類重的東西。
- 登錄跟著流程走，複製一份流程資料夾就能完整帶走。代價是工具搬家時要改每份流程的登錄。
- 外部步驟結束後畫面已經變了，`原點`也不可信，點擊程式不會重新校準。
  後面若還有步驟，第一步要放`定位找圖`。

## 替代方案

- **專用的公開招募步驟，編輯器有公招選項。** 拒絕：兩個專案會綁在一起，
  公招改介面，點擊程式也得跟著改。
- **把公招當函式庫 import 進來。** 拒絕：相依套件與打包方式差很多，
  公招目前的函式也要呼叫端自己組好畫面來源、點擊端、OCR 和干員資料。
- **工具啟動後才在輸出裡報預期時間**，或**流程裡寫死逾時秒數**。拒絕：前者在工具卡在載入時拿不到上限；
  後者在工具變慢時要回來改四份流程。使用者選了「先問執行檔」。
- **F12 時立刻結束工具。** 拒絕：使用者要工具有機會停在乾淨的地方，並且自己回報失敗。
- **登錄放在 `flows/` 底下、所有流程共用。** 拒絕：使用者要流程資料夾自己就是完整的一包。
