# ADR 0005：流程檔座標以「當前基準機器」尺度儲存，存檔時重定基準

Status: superseded by ADR 0009（2026-10-05）；原 accepted（2026-08-16）

## 背景

找圖本身對縮放有抗性（引擎多尺度比對），但流程裡儲存的座標沒有：找圖偏移
（offsetX/Y）、相對座標（mode:prev）、絕對座標（mode:abs）都是建立流程那台
機器上的實體像素。flow pack 匯到另一台電腦（或同一台換螢幕）後，找圖找得到、
點擊卻點偏。

解法是校準功能（詞彙見 app/CONTEXT.md「校準與畫面倍率」）：使用者指定兩個
既有範本作為校準對（比例尺），量兩張圖匹配框中心距離；換機器後按一次校準，
以「當前距離 ÷ 基準距離」得出本機畫面倍率，執行期所有步驟偏移乘上倍率落點。

剩下的關鍵決策是：**流程檔裡的座標到底存什麼尺度**。這決策難回頭——它定義
跨機語意、影響所有讀寫存檔的路徑，選錯了要整批改寫使用者的流程檔。

## 決策

**流程檔座標永遠維持「當前基準機器」的尺度；在倍率≠1 的機器上存檔時自動
重定基準並告知。**

- 重定基準＝profile 內**所有**流程檔（含自動存檔）座標乘上現行倍率改寫、
  基準距離改為本機量值（舊基準 × 倍率）、倍率歸 1、機器指紋更新——本機
  成為新基準（`calibration.rebase()`）。
- 編輯期不混尺度：拾取到的本機像素先以現行倍率**反除**、歸一到現行基準
  暫存於步驟中；存檔時再整體重定。檔內與記憶體中任一時刻都只有單一尺度，
  重定改寫不需要分辨新舊步驟。
- 未校準（有校準對但無有效倍率：從未校準或指紋不符）時：執行＝警告後以
  倍率 1 代入；拾取＝擋下要求先校準（未知倍率下拾取的座標事後無法歸位）；
  存檔＝不觸發重定（亂乘未知倍率會毀掉座標）。
- flow pack 連校準對範本與基準距離一起帶。匯入時依兩邊基準比值換算：
  目標無校準資料＝採用 pack 的（倍率留空）；同一對＝座標 ×（目標基準 ÷
  pack 基準）落地；不同對＝照 pack 尺度落地、附「來源基準」標記，存檔前
  必須先對來源校準對量測換算、或明確確認以匯入基準存檔。帶標記的流程
  不隨 profile 重定基準（它的尺度由標記定義）。

## 取捨（對照被捨棄的方案）

- **對照「歸一化儲存」**（檔內存與機器無關的標準尺度，讀檔時換算）：
  歸一化方案不需要重定改寫，但每次讀檔/顯示/編輯都要換算，且既有流程檔
  全部要做一次性大遷移、檔案格式要新增座標空間標記。本方案檔內數字永遠
  就是「某台真實機器上的像素」，倍率 1 時所有路徑與現狀完全等價
  （最重要的回歸線：既有 profile 零影響），代價是存檔時要整批改寫。
- **對照「檔內標記尺度、執行時各自換算」**：不改寫檔案，但同一 profile 內
  會累積多種尺度的流程，pack 匯入、預設原點推算、重定語意都要處理
  N 種尺度組合；單一尺度把複雜度收在存檔的一個時間點。
- **重定基準的整數化改寫在多次重定後有 ≤1px 級的累積捨入**，接受之
  （點擊目標遠大於 1px）；進位規則統一走 `flowfmt.scale_px`
  （執行期與檔案改寫共用），兩邊不會各差 1px。
- **尺度來源採兩圖比例尺，不使用引擎匹配尺度**：引擎 QueryResult 不新增
  欄位、引擎 context 不動，校準完全在 app context 實作；量測走辨識單一
  路徑（ADR 0002 的 query 接縫），不開第二條比對路徑。
- 倍率是單一等比值，不分 x/y（非等比縮放、黑邊裁切不在本輪範圍）。

## 影響

- 所有讀存檔的路徑維持「先過 `flowpack.migrate_flow()`」的既有紀律；
  重定改寫也先遷移再乘倍率，否則舊格式（螢幕座標）會被當成新格式整批乘壞。
- 任何新增的「寫流程檔」路徑都要考慮：倍率≠1 時是否該先重定
  （目前唯一入口是 `App.save_flow` → `_maybe_rebase`）；自動存檔不觸發
  重定，但重定時會一併改寫 `_autosave.json`，漏一份＝混尺度。
- 拾取入口新增守門：未校準擋拾取（`ui_dialogs._cal_state`）。新增拾取
  類功能時要沿用同一道門與「反除歸一」的暫存規則。
- 校準資料（calibration.json）隨 profile 資料夾搬遷；機器指紋取自螢幕
  配置（`win.virtual_screen()`），整包複製到別台機器會被視同未校準。
