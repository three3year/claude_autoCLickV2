# ADR 0011:忙碌改由步驟勾選「忙碌檢查」,輸入後等忙碌消失

Status: accepted(2026-10-07)。取代 ADR 0010 全部。ADR 0008 決策 3(補做前查忙碌指示)不變。

## 背景

ADR 0010 讓找圖等待在「沒達成」的輪詢裡查忙碌指示,看到忙碌就不計逾時,並把四份流程裡
「忙碌指示 → 等待消失」的步驟拿掉,交給下一步的忙碌暫停。

2026-10-07 22:24 `晚_簡中` 實跑,換班段每一步都是 `busy_pause=0.00`,使用者看到滑動和點擊
都沒等忙碌就直接操作:

- 換班時忙碌指示只蓋在畫面下方,列名一直看得到。找圖第一輪就找到,馬上操作。
  忙碌暫停只延長「找不到」的等待,擋不住「已經找到」的操作。
- 座標點擊(點 ⇄)不找圖,本來就不會查忙碌。
- 第一次拖曳(步驟 32)被吃掉,靠補做第二次才生效(`inputs=2`)。

拿掉的那些等待步驟,才是真正讓換班等忙碌的東西。

## 決策

1. **`忙碌檢查`**:步驟選項,只有送出輸入的步驟能勾(座標點擊、拖曳、按鍵、找圖點擊)。
   勾了的步驟:輸入 → 等忙碌指示消失 → 生效確認。補做重送後不再另等,照舊由補做的門擋。
2. **`忙碌出現等候`**:流程層級設定,預設 1000ms。這段時間內沒看到忙碌就放行,
   即使生效確認其實已經成立也等滿。看到就等它消失,最多 60 秒,等不到就停止流程。
3. 有步驟勾了、流程卻沒設忙碌指示:開始執行時擋下。
4. **移除忙碌暫停**:找圖等待(分岔條件、一般找圖、生效確認、等待消失、出現等候上限)
   不再看忙碌,逾時照常計時。
5. 會讓遊戲忙的地方由流程作者勾,引擎不自己判斷。四份明日方舟流程要勾的地方:
   ADR 0010 拿掉等待步驟的位置、換班的每個拖曳、開頭清彈窗的關閉點擊、傳遞線索、
   今晚觸發過忙碌暫停的步驟(可收獲、幹員信賴、確定)。

## 捨棄的方案

- **保留忙碌暫停,兩個機制並存**:它管分岔條件、沒勾的步驟、確認期間忙碌再出現一次。
  使用者判斷:分岔前一個動作勾了就不會在分岔時還在忙;沒勾的步驟若會忙就該勾;
  一個操作通常不會忙兩次。兩個機制、兩套 60 秒規則(一個照常計時、一個停止)不值得。
- **所有送輸入的步驟都自動等**:每個輸入都多付最多 1 秒的出現等候,早班幾十個步驟,
  而且大部分操作不會讓遊戲忙。
- **輸入前查忙碌(而不是輸入後)**:忙碌指示在點擊後慢一點才出現,下一個輸入前查常常還沒冒出來。
- **流程加回「忙碌指示 → 等待消失」步驟**:可以用,但每份流程都要手動加步驟,而且等待步驟管不到
  同一步驟裡的生效確認(確認的逾時會被忙碌吃掉)。勾選式把等忙碌放在輸入與確認之間。

## 後果

- 沒勾到的地方遇到忙碌,逾時會被吃掉(ADR 0010 修的開頭清彈窗、傳遞線索確認問題),
  要靠勾對步驟。實跑發現就補勾。
- 勾了的步驟在網路正常時固定多等 `忙碌出現等候`(預設 1 秒)。
- 斷線時勾了的步驟 60 秒後停止流程,不會白點。
- 繁中流程的忙碌指示範本要比得到,這個機制在繁中才有效(2026-10-07 兩份繁中已換成同一張新圖,
  尚未實機確認)。
