# ADR 0007:比色、查詢回傳所有匹配、找圖目標

Status: accepted(2026-10-04)

## 決策

1. **比色是找圖目標的可選開關,不是全域行為**。引擎多一關可選的彩色比對:
   候選通過梯度粗篩與嵌入驗證後,以**候選自身的尺度**、**整張模板(不套遮罩)**
   做彩色 `TM_CCOEFF_NORMED`,未達 profile 的比色門檻就不算匹配。門檻是
   profile config 的一個值,不在步驟或範本上各自設(延續 ADR 0002 的門檻紀律)。
2. **查詢回傳所有匹配**。引擎不再只回傳分數最高的一個;多個匹配時挑哪一個由
   app 依`挑選規則`決定(分數最高/由上到下第 N/由左到右第 N/最接近指定點),
   引擎不帶位置偏好。粗篩不再「每個尺度只取一個峰」。
3. **找圖目標是通用單位**:範本+限定範圍+挑選規則+比色,用在找圖步驟、確認圖;
   「點到下一步的圖出現」沿用下一步的找圖目標。三個屬性屬於找圖目標,不屬於範本。
4. 存檔格式升到 `flowFormat` 3,讀舊檔時單向遷移。

## 理由

- ADR 0001 選梯度域是為了天然抗亮度與色偏;實跑證明代價是「形狀相同、只差顏色」
  分不開(停用的灰色按鈕被當成橘色可按、不同設施的同號列互認,驗證分數 0.86–0.89)。
  全域開比色會把夜間模式/變灰/半透明背景這些原本刻意容忍的變化變成漏抓,所以只在
  需要的找圖目標上開。
- 不用校準倍率鎖尺度:範本圖保持拍下當時的尺度,重定基準只改步驟座標不改圖,
  校準倍率不等於「範本對目前畫面的尺度」。
- 不套遮罩:單張範本的登錄遮罩只留強邊緣、排除平坦區,而顏色差異多半正在平坦底色上。
  開比色的範本因此要框乾淨,不能含會變的數字或透出的背景。
- 同款多張(一排相同的卡片)連比色也分不開,只能靠位置;位置偏好是流程語意,
  不是遊戲無關的偵測問題,所以放在 app。

## 後果

- 比色的邊際小(影片壓縮後正確 0.98–1.00、相似圖 0.88–0.945),門檻要以基準測試集
  與實跑紀錄調整。
- 一次查詢要驗證的候選變多,查詢時間會增加;依 ADR 0002「準確優先」,實測太慢再開票。
