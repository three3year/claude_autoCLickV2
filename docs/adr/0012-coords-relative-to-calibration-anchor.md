# ADR 0012：存下的座標一律以校準對第一張圖的中心為基準點

Status: accepted（2026-10-09）。修正 ADR 0009 第 5 點（編輯器倍率）。

## 背景

搜尋範圍是使用者手框的螢幕矩形，同時也是固定矩形（存成它的比例）、九宮格、絕對座標、
「最接近指定點」的基準，範本拍攝位置則直接存螢幕座標。使用者每次執行前會重框範圍，
但手框不精準、簡中視窗也會挪位置——框得鬆緊不同，四份流程的上百個固定矩形就一起偏掉。
校準對（標題列圖示＋關閉鈕）本來每次執行開頭就要找，位置是現成的、精準到匹配框中心。

## 決策

1. **座標基準點＝校準對第一張圖的中心**，由校準量得。所有存檔的座標數值都是相對它的
   偏移、流程尺度；執行時 ×畫面倍率再加上它的螢幕位置。
2. 搜尋範圍只剩「在哪裡截圖找圖」，仍存在流程存檔當上次框的預設值；它是唯一的螢幕座標。
   校準只在它裡面找（執行與編輯都是），所以雙開客戶端時不會認錯另一個視窗的標題列。
3. 九宮格退場；「最接近指定點」只以原點為基準（偏移 (0,0)＝最接近原點）。
4. 編輯器每次拾取都用那張截圖量校準對：位置與倍率都取當下的，不再要使用者按「校準」（該鈕改成只顯示倍率）。
   沒有校準對＝不能拾取需要基準點的座標；換校準對＝所有存下的座標依新舊基準點的差平移。
5. 只處理兩次執行之間的挪動；執行中不重量。
6. 四份在用流程用執行紀錄裡的校準位置一次性換算（同 ADR 0009，不寫通用自動遷移）。
7. 舊格式（座標仍相對搜尋範圍）的存檔、草稿、舊 JSON 一律拒絕開啟：存檔沒記當時視窗在哪，
   自動換算可能靜靜換錯；在用的只有四份，已一次性換算。既有的舊格式遷移隨之退場。

## 捨棄的方案

- **讀視窗代號的矩形**：兩個客戶端的 exe 與標題完全相同，每次都得手動指定視窗。
- **校準找全螢幕**：不必重框，但雙開時可能找到另一個客戶端的標題列。
- **另設一張定位圖**：多一份要維護的設定，實際上幾乎都會選標題列那張。
- **基準點取兩張中心的中點或第一張的框角**：中點不在任何圖上、不直覺；框角受尺度網格影響，
  比中心多抖幾 px。
