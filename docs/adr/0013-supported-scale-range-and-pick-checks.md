# ADR 0013：支援倍率範圍 ×0.85–1.15 與拾取檢查

Status: accepted（2026-10-09）。補充 ADR 0009（一份流程一個尺度）、ADR 0012（座標基準點）、ADR 0007（比色）、ADR 0002（引擎門檻只由 profile 管）。

## 背景

四份在用流程（早_繁中、晚_繁中、早_簡中、晚_簡中）的所有餘裕——比色門檻 0.95、固定矩形框得多緊、
範本粗篩分數離 0.6 多遠——都是在建立時的視窗大小下湊出來的。2026-10-09 傍晚繁中客戶端改成視窗模式
（畫面倍率 ×0.883）實跑，同一份流程在三個地方失手：

- 換班列名比色 0.942 跌破 0.95（最大化時 0.966、錯誤列 0.914，正確與錯誤只差 0.03），停在第 107 步。
- 「選中 1」的固定矩形 58×58 只比 50×50 的範本大 3–4px，被基準點誤差切到圓鈕，查線索整段跳出。
  重放確認：矩形與圓鈕錯位 6px、餘裕 4px 時粗篩掉到 0.44；餘裕 10px 時偏到 8px 仍找得到。
- 「基建BASE」範本粗篩 0.59 卡在門檻外（最大化時也只有 0.59–0.63，先前兩次通過是運氣）。

6px 錯位的來源：校準對選在標題列，圖示到關閉鈕的距離是「視窗寬減固定裝飾」，裝飾不隨倍率縮，
量到的倍率比遊戲畫面真正的縮放比小約 0.4%（擬合 0.887 對校準 0.883）；誤差隨離基準點的距離增長，
1500px 外約 5px，再加上找圖框本身 ±3px 的抖動。使用者從執行紀錄只看到「逾時未找到（最高相似度 0.991）」，
分不出是比色、驗證還是粗篩沒過。

## 決策

1. **支援倍率範圍 ×0.85–1.15**：一份流程保證跑得完的畫面倍率區間，涵蓋兩個客戶端各自的最大化與視窗
   模式（簡中視窗 ×1.0、簡中最大化約 ×1.13、繁中最大化 ×1.0、繁中視窗約 ×0.88）。所有餘裕以區間兩端
   當最壞情況來定與驗收。它是設計與驗收的常數：不進 profile、不進存檔、不擋執行——校準量到區間外照跑，
   日後要擋再議。
2. **拾取檢查**：編輯器在拾取當下自動做三項、只警告不擋存檔；影片轉流程的自我驗證套同一套標準，
   沒過的標待重拍。判斷只實作一次（`app/automation/pickcheck.py`，偵測器注入），兩邊都呼叫它。
   - 縮放餘裕（截範本時）：同一張截圖等比縮到（當下倍率×0.85）與（當下倍率×1.15）各找一次，
     找不到、粗篩最高分 < **0.7**、或驗證最高分 < **0.85** 就警告，寫明哪一關、分數與倍率。
   - 矩形餘裕（拾取固定矩形時）：矩形每邊至少比該找圖目標的範本多 **20%**（流程尺度；50px 範本 →
     至少 70px），不足就警告並給「至少 W×H」。用百分比不用像素：像素餘裕會隨倍率縮小。
   - 唯一（找圖目標設好之後，照它的限定範圍查）：引擎回報的匹配多於一個就不唯一。設了「第 N 個」
     「最接近」這類挑選規則的目標已宣告會有多個，不查；畫面上找不到時沉默。
3. **校準對搬進遊戲畫面，標題列對改為備用校準對**：主對選遊戲畫面內相距夠遠的兩張固定圖，量到的才是
   遊戲畫面的倍率。標題列圖示＋關閉鈕登記為備用對，主對找不到（彈窗蓋住、不在主畫面）時才用，用到時
   執行紀錄印一行警告、照跑。備用對記自己的基準距離與「備用第一張中心 → 座標基準點」的偏移（流程尺度），
   用它量時基準點＝備用第一張中心＋偏移×倍率，存下的座標一律仍相對同一個座標基準點。
4. **換班定位改用唯一參考點**：進駐總覽裡挑畫面上唯一、與目標列位置固定的圖當參考點（定位找圖），
   以相對座標點每一站；列名範本、比色、「類別標題＋首列」第二關退場。
5. **執行紀錄說清楚哪一關沒過**：逾時訊息印沒過的那一關與該關分數（粗篩最高 0.59／驗證最高 0.72／
   比色最高 0.942（圖形 0.974））；生效確認逾時、手動停止也寫檔案紀錄。
6. **比色維持 profile 的 0.95**：剩下的比色用途要求在 ×0.85 與 ×1.15 兩端本尊與他者的顏色分數差
   0.1 以上，由重放驗；差不到的個案改用別的辨識方式。
7. **引擎不改**：粗篩門檻 0.6、候選全驗、遮罩、比色演算法都不動；弱範本靠拾取檢查把關、重截。

## 數字的由來（改動它們要改這份 ADR）

| 常數 | 值 | 吸收的是什麼 |
|---|---|---|
| 支援倍率範圍 | ×0.85–1.15 | 兩客戶端×兩模式四組的實測倍率（0.883 / 1.0 / 1.13），兩端各再留一截 |
| 矩形餘裕 | 每邊 20% | 備用校準對（標題列）倍率偏小 0.4% 在 1500px 外約 5px，加找圖框 ±3px 抖動；10/09 重放：餘裕 4px 粗篩 0.44 找不到、餘裕 10px 偏到 8px 仍找到。用百分比：50px 範本在 ×0.85 下餘裕仍有 8.5px |
| 縮放餘裕粗篩門檻 | 0.7 | 引擎 match_threshold 0.6 之上再留一截：影格縮放模擬不到遊戲自己縮放時的渲染差異（字體、邊緣），實跑分數會比模擬低 |
| 縮放餘裕驗證門檻 | 0.85 | 引擎 verify_threshold 0.8 之上再留一截，理由同上 |
| 唯一 | 匹配數 > 1 | 不加新數字；次高候選差多少才算近，交給引擎門檻 |

## 捨棄的方案

- **降比色門檻（0.95 → 0.93）**：正確列與錯誤列只差 0.03–0.05；降到 0.93 在最大化時會收進錯誤列
  （曾 0.931、0.943）。比色不是縮放下該解的題，換參考點。
- **引擎候選全驗（有限定範圍時候選全送驗證，或改粗篩門檻）**：引擎多一個查詢提示或魔術數字；
  弱範本靠重截就夠，拾取檢查在建範本當下就擋下。
- **只保證建立時的模式（繁中必須最大化才能跑）**：使用者要兩個客戶端怎麼擺都行。
- **流程存檔宣告自己的倍率範圍**：多一個要維護的欄位，實際上四份流程都是同一個範圍。
- **只用標題列對、以 20% 餘裕吸收誤差**：餘裕能吸收，但倍率系統性偏小仍會讓離基準點遠的座標偏；
  改為「遊戲內為主、標題列為備」兩者都做。
- **「相似度近」用次高候選差 0.1 或粗篩過 0.6**：前者多一個數字，後者會把能用的圖也判掉。

## 影響

- `app/CONTEXT.md`：支援倍率範圍、拾取檢查（縮放餘裕、矩形餘裕、唯一）、參考點、備用校準對四條詞彙。
- 流程存檔：校準資料多可選的備用組（`calibration.fallback`），格式版本不升。
- 已知限制：新蓋設施讓進駐總覽排列改變時，相對座標會點錯列（列距固定）。
