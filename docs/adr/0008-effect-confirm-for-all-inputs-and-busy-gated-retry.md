# ADR 0008:生效確認擴及座標點擊與拖曳,補做受忙碌指示把關

Status: accepted(2026-10-05)

## 背景

網路延遲時,遊戲畫面已經畫好(找圖找得到),但伺服器還沒回應,遊戲不接受輸入,
點擊與拖曳被靜靜吃掉(2026-10-05 `基建換班_簡中` 實跑:鈴鐺點擊沒開待辦列、
發電站清單拖曳沒捲動,之後的相對點擊落空)。原本只有找圖點擊有「點擊後確認」,
座標點擊、拖曳沒有任何檢查,流程靠固定等待(換班後 1500ms)賭伺服器夠快。

## 決策

1. **`生效確認`一個機制涵蓋找圖點擊、座標點擊、拖曳**(取代只屬於找圖的
   「點擊後確認」)。生效條件:目標圖消失(只限找圖)、`原點的圖離開`
   (只限座標點擊與拖曳)、確認圖出現、下一步的圖出現。座標點擊與拖曳的
   生效確認逾時預設**停止流程**(找圖維持預設跳過):拖曳沒生效時跳過,
   後面的相對點擊會靜靜點錯。
2. **`原點的圖離開`隱式跟隨原點來源**:原點記得是哪個找圖目標、哪個框產生的,
   操作後查那個框還有沒有匹配。原點不是來自找圖＝無法執行(編輯器警告,同
   `找圖相連`)。
3. **`補做`有兩道門**:距上一次輸入已過`補做間隔`(流程層級,預設 1000ms),
   且畫面上沒有`忙碌指示`(流程層級找圖目標,可不設)。現有找圖點擊的補點
   一併改走這套規則。
4. **忙碌指示只在補做前查**,一般輸入前不查。
5. 換班這類「沒有可用確認圖」的輸入,以`等待消失`＋`出現等候上限`等忙碌指示,
   取代固定等待。

## 捨棄的方案

- **只改流程、用重複區段繞**(拖曳包成「找舊位置還在＝沒捲動→重拖」的 4～5 步):
  不改程式就能做,但每個拖曳都要手寫反推邏輯,新流程會一再重犯。
- **確認圖另選、或操作前多找一次記下原位**:另選確認圖可能選錯(圖本來就不在
  原點上＝永遠判定生效);多找一次讓每個拖曳多一次查詢(一次 0.3～1.3s)。
  流程本來就靠「找圖→相對操作」定位,原點來源已經是要確認的那張圖。
- **每次輸入前都查忙碌指示**:最保險,但每步多一次查詢;而且指示在點擊後
  0.3～0.8s 才出現,緊接的下一個輸入常常查不到它。只在補做前查,比對偶爾失準的
  代價只是補做時機差一點,不會讓流程出錯。
- **比對「畫面有沒有變化」(像素差)判定生效**:不用選圖,可以確認換班頭像換了,
  但等於開第二條比對路徑(違反 ADR 0002「辨識只有一條路」),動畫與心情條也會
  誤判成「有變」。
- **補做照每個輪詢間隔補**(原行為):遊戲只是慢、不是吃掉輸入時會重複操作——
  拖曳捲過頭、鈴鐺這種開關被點回關閉、⇌ 換到下一隊。
